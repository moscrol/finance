# Theme Radar 数据抓取需求清单

用途：给另一台电脑 / IMA / 数据抓取 Agent 使用，补齐 Theme Radar 底层数据库，使功能至少 1:1 覆盖截图中的题材分析能力，并进一步利用私有知识库做得更强。

更新时间：2026-06-01

## 总原则

本阶段暂不抓：

- 盘面行情异动
- 实时涨跌幅
- 今日公告机会榜
- 公告 × 产业 × 盘面三维共振

本阶段优先抓：

- 需求场景
- 工艺/材料/零部件扫描
- 产业链上下游
- 催化日历
- 验证清单
- 认知演变时间线
- 证据来源和原文定位

所有表都必须尽量保留：

- 来源标题
- 来源类型
- 发布日期 / 时间窗口
- 证据摘要
- 是否需要人工核验
- 可信度

## 输出格式要求

优先输出 Markdown 表格。每个题材一个 Markdown 文件，建议文件名：

```text
{题材名}_ThemeRadar_补充数据.md
```

每个表格必须独立成节，节标题固定，便于后续脚本解析。

建议结构：

```markdown
# {题材名} Theme Radar 补充数据

## 1. 概念定锚表

| 术语 | 一句话定义 | 技术本质 | 类比解释 | 相邻概念 | 与相邻概念区别 | 为什么重要 | 证据摘要 | 来源 | 日期 | 可信度 | 是否需核验 |
|---|---|---|---|---|---|---|---|---|---|---|---|

## 2. 需求场景表

...
```

## 优先级说明

- P0：必须抓。没有这些，截图核心功能无法复刻。
- P1：强烈建议抓。能显著提高报告质量。
- P2：可选增强。后续做 UI / 长期数据库时有价值。

# IMA 运行建议

## 最小必跑组合

如果时间有限，优先跑：

```text
1. 需求场景表
2. 工艺材料扫描表
3. 方向级验证清单
4. 催化日历
```

## 完整推荐组合

如果要完整覆盖截图非公告/非盘面功能，跑：

```text
1. 概念定锚表
2. 需求场景表
3. 工艺材料扫描表
4. 方向级验证清单
5. 催化日历
6. 产业链全景表
7. 认知演变时间线
8. 操作建议表
10. 相邻方向横向对比表
```

## 每条证据的质量要求

每条数据尽量做到：

```text
不写空泛判断
保留数字
保留公司名
保留时间
保留来源
标记是否需要核验
区分事实和推断
```

优先保留这些数字：

- 市场空间
- 价值量
- ASP
- 产能
- 出货量
- 收入占比
- 毛利率
- 市占率
- 订单金额
- 扩产金额
- 客户导入时间
- 量产时间
- 验证周期

## 可信度建议

```text
high：公告、年报、定期报告、官网、监管披露、招股书、明确引用官方文件
medium：券商研报、电话会、调研纪要、产业链访谈、可信财经媒体
low：论坛、传闻、未标来源文本、二手转述、无法确认出处
```

## 是否需核验建议

填“是”的情况：

- 非公告/非定报来源
- 涉及订单、客户、收入、产能、市占率但没有官方来源
- 涉及未来预测
- 来源是电话会、调研、网页二手整理
- 数字非常关键但缺原始出处

填“否”的情况：

- 明确来自公告、年报、半年报、招股书、官网、交易所问询回复
