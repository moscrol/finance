# Foresight 商业计划书

## 和你协同进化的 A 股投研 Agent

**每天带你复盘：研判大盘处在哪个阶段、哪些板块是主流、题材走到哪一步，给出明天该看什么、什么条件升级、什么条件放弃；记住你每一次判断，到期回检，告诉你对在哪、错在哪。**

小白学会自己看，高手的经验变成认知复利。不荐股，不提供个股买卖建议；Agent 在使用中改进带读、证据组织与回检，判断和规则库是你自己的。定位是研究与复盘工具，不是荐股 App。

v1.3 · 2026 年 9 月 15 日 · 创新国度 OPC 创业营申请材料

项目已有自用 Demo，正准备邀请制内测，尚无外部用户和产品收入；本阶段以产品验证为主。

### 项目摘要

**目标用户。** 以股票投资为副业、研究时间有限，却希望保有独立判断的个人投资者；以及已有研究框架，希望持续检验判断、积累方法的资深投资者。

**核心痛点。** 许多副业投资者把有限时间花在筛选信息上，难以持续理解和复盘，逐渐依赖外部结论，自己的认知却没有积累。我们将这一困境称为“认知投降”。资深投资者则需要持续检验经验，使每次研究都能为下一次判断提供依据。

**产品方案。** 终局是一个个人研究校准系统，而不是替用户提供个股交易结论的回答型 Agent。底座是“时间记忆长河”：把每个交易日的盘面、题材、舆论、资金、个股节点和用户判断，按当时能看到什么对齐保存，可计算、可回溯；研报知识库作为证据源另行挂载，创始人的授课框架决定“怎么读”。用户每天在带读中建立理解，只需确认或修改一条观察剧本（次日看哪些指数、板块和题材，什么条件升级，什么条件放弃），到期回检时对照事实。每一次回检都让系统更清楚这个用户哪类判断站得住，形成数据飞轮。用户获得研究坐标系，资深投资者把经验沉淀为可验证、可复用的方法，逐步形成认知复利。产品不是再加一个聊天入口，而是让同一条研究回路越来越少依赖外部答案。

**开发进展。** 已有自用工作台、市场数据仓、题材证据图谱、判断记录及回测组件。下一步将投教经验整理为可执行的带读框架，打通用户操作流程，并把基础设施收成可重放的研究环境：统一数据字典、时间语义、版本和证据收据，确保 Agent 只能在当时可见的数据条件下工作。多类数据的统一查询和完整个人框架功能仍在建设。

**创始人背景。** 林邦骞，浙江大学传播学本科，曾联合创办金融投教项目并负责内容交付，历史项目累计服务 1000+ 付费学员。学员两年里反复追问的三个问题——题材是什么、证据在哪、能不能信——原样成了本产品的出门纪律。原服务为课程与持牌投顾的组合，带读订阅本身的付费意愿将独立验证。

**近期计划。** 先邀请 3–10 人开展 Alpha 内测，检验产品能否帮助用户节省研究时间、说清判断依据并持续复盘。满足收费前置条件后，再测试 {{monthly_price}} 元/月订阅，观察付费与留存。

**社区支持。** 希望获得导师对产品定位、带读与校准体验、验证指标和商业化路径的具体建议；对接 3–10 名首批体验者，以及投教机构、研究团队、数据与合规服务等产业资源；同时获得算力、模型和一人创业者交流支持。前 3 个月项目预算约 {{alpha_budget_wan}} 万元，后续按验证结果分阶段投入。

## 1 目标用户与产品体验

### 副业投资者的认知投降

对目标用户而言，股票投资是副业。工作之余，需要从行情、消息和相互冲突的观点中筛选线索，留给理解和复盘的时间所剩无几。久而久之，判断越来越依赖别人，自己的研究框架却没有形成。“认知投降”描述的是这一过程：有学习意愿，却难以在有限时间里持续积累。

认知投降的人已经在把问题交给 AI：问“今天为什么跌”“这个题材还能不能看”，得到一段流畅的回答，明天再问一遍。通用 AI 助手不记得他昨天的判断，不区分“当时知道什么”和“后来才知道什么”（问历史上某一天的板块表现，会拿今天的数据作答），也不会告诉他自己哪类判断总是出错；决策型投研 Agent 直接给结论，把“学会看”这一步跳了过去。两者都让投降更顺手，而不是更少。主流行情与资讯平台已陆续上线 AI 问答和 Agent，“有没有 AI”不再是差异，“能不能带着你读、能不能校准你的判断”才是。自媒体内容能提供线索，但带着作者的视角和选材。用户需要的是一条能持续跟进、核对依据、检验自己判断的学习路径，而不是又一个信息来源。

另一类用户是已有框架的资深投资者，需要辨别经验的适用条件，保留判断依据与结果，把有效方法用于新的研究。两类用户共享底座，但分别验证“建立认知”和“认知复利”。

### 围绕每日复盘的使用流程

| 环节 | 用户拿到什么 | 当前状态 |
|---|---|---|
| 阅读自选简报 | 市场变化、关联线索和待核实信息 | 已有自用组件 |
| 追溯题材证据 | 出处、时间和证据充分度 | 已有自用流程 |
| 记录判断并回检 | 依据、条件、日期与实际结果 | 已有记录与回检组件 |
| 按框架理解市场 | 带读盘面，确认、修改或跳过观察剧本 | Alpha 前完成首版 |
| 积累个人方法 | 个人框架与历史记录结合使用 | 分阶段建设 |

### 底座：时间记忆长河，其余数据挂在它上面

所有数据挂在同一条底座上。时间记忆长河把盘面、题材、舆论、资金、个股节点、用户判断六类数据按交易日对齐，每条记录都标明“这是哪一天的数据、系统何时知道的、来源是什么、缺了什么”。读取路径上没有模型参与，同一天同一对象两次读取结果完全一致，历史查询因此可以重放“当时知道什么、为什么这样判断、后来发生了什么”。它不是聊天记录的堆积，也不是向量库。

研报知识库与题材证据图谱作为证据源另行挂载：向长河提供来源、证据硬度和覆盖密度，不充当事实主库，私有研报也因此可以按用户隔离访问。授课框架与用户私有框架是横切在六类数据之上的“读法”，决定 Agent 看什么、怎么解释，本身也版本化。终局提供今日带读、历史回放、判断台账和方法检验四个工作面，共用这一条时间索引。

当前状态：六类数据的联立读取面已有第一版，按板块解析；指数、题材与个股入口和舆论阶段词表仍在建设。简报和判断台账分别保留已核实变化、证据缺口、观察变量、成立或失效条件、回检日期及实际结果；用户能沿来源核对依据，系统不按事后结果改写原判断。

**服务范围。** 产品研判大盘所处阶段、主流板块与题材演变，给出次日观察重点与升级、放弃条件，并对每一次判断到期回检；不荐股，不提供个股目标价、买卖时点或自动下单。用户指定个股的提问只做事实、证据和风险核对，不给个股买卖建议；收费前将结合真实输出样本完成专业评估。

### 现在能展示什么

现场只演示已经走通的一环：用创始人自用账户登记一条带条件的次日观察剧本（看哪些指数、板块和题材，什么条件升级，什么条件放弃），再打开一条已到期的判断，看系统按当时可见事实给出的回检结果。演示同时呈现事实、推断和缺失信息，让评审看到产品如何处理不确定性。带读与「回检结果如何改变下一次带读」尚在建设，不作为成品演示；展示范围以当时可运行的功能为准。

### Alpha 前要补齐什么

2026-09-07 之后已合入主干的能力：内容版本冻结与历史重放、情景树首版、相关样本依赖检验、合取式标签三值逻辑；合入代码不等于对外可用。接下来将投教经验整理为首版带读框架，把已有回测组件接入用户的判断记录，并补齐邀请用户的权限隔离、数据脱敏和完整成本记录。多类数据的统一查询与个人框架功能按阶段交付。

首版框架首先用于组织学习和表达判断。涉及数值阈值的方法假设需经过历史检验，并标明样本量与不确定性；只有得到证据支持的规则，才进入后续方法验证。

本轮采用现场演示。私有知识库暂不对评审开放账号；录屏、截图与公开链接将在内容脱敏和权限核验后另行提供，不计入本次附件。

## 3 壁垒与持续使用价值

### 唯一不可复制的输入：一套被付费学员追问过两年的知识体系

壁垒不是“有人付过费”，而是这套知识体系本身。创始人两年投教里，1000+ 付费学员反复追问的问题收敛成一套底层看盘方法：指数处在哪个阶段、主流板块怎么认、题材从哪来到哪去、明天该观察什么。这套方法正在被代码化为可版本化、可回测的授课框架——每个概念对应数据仓里的字段，每条判读写成能在历史上重算的规则，首刀设计已落盘。通用 Agent 有模型没有框架；决策型 Agent 有结论没有教法；投教机构有框架但不接盘面数据、不能每天更新、也不能回测自己。这三样同时出现在一个人身上，是本项目起点不为零的原因。

学员付费证明的是这群人愿意为“学会看”付钱、付得起千元/月量级，学习需求真实存在；它不证明带读订阅本身的价格接受度——原服务是课程与持牌投顾的组合，本产品拆掉荐股只留方法，转化要重新测。

### 四层随时间积累的资产

| 资产 | 是什么 | 为什么后来者补不回 |
|---|---|---|
| 结构化时间资产 | 六类数据按交易日对齐、带来源和缺口的历史 | 逐日人审入库，供应商换过名单后这段历史无人能回填 |
| 领域框架资产 | 授课框架与用户私有框架编码成可检验的规则，而不是提示词里的散文 | 规则能在历史上重算、能版本化、能被自己的检验否定 |
| 判断与结果资产 | 用户留下的带条件判断和到期回检结果 | 只在持续使用中产生，通用 Agent 拿不到 |
| 验证收据资产 | 每条候选经验的通过、失败、失效和重新验证记录 | 研报和自媒体只发成功案例，没有人系统地攒“什么不灵” |

现在没有已验证的护城河；这四层只有在用户持续记录、回检和复用时才会变成切换成本。模型能力、提示词和单篇研报不作为壁垒。

### 数据飞轮：Agent 与用户协同进化

用户每天确认一条观察剧本，长河上就多一条带条件、带时间的判断样本；到期回检产出结果，结果生成候选经验；候选经验先在一段历史上发现，再在另一段没看过的历史上验证，与同期基准比较，记录样本量与不确定性，通过后进入个人方法库，改变下一次带读给模型看什么。Agent 在这个过程中改进带读、证据组织和回检方式；用户则积累判断与方法。带读更省时、更贴合这个用户，用户更愿意记录。飞轮转的是“带条件的判断”的数量与质量，不是聊天长度、点赞或召回次数。资深投资者的“认知复利”就落在这里——指方法与理解的累积，不指投资收益。

两条边界写进产品原则。第一，Agent 可以从反馈中改进带读、证据组织和回检；规则库（阈值、候选规则、检验结果）只有经过验证才沉淀，授课框架的母本由人写、人改、版本化，Agent 可以提议，不能改写；一次反馈只生成候选，跨用户复现后才考虑共享。第二，413 个交易日按市场阶段分开后样本稀缺，飞轮从每天数百个板块的横向样本和参数少的结构型规则起步，样本不足时如实显示“样本不足”，不阻塞带读。首批种子规则（现为四条）至今无一条获得与基准可区分的支持，均未对外提供。其中一条看似有 85 个历史信号，实际集中在 15 个交易日，扣除结果窗口重叠后只剩 3 个完整时间块，系统判为样本不足、没有当成有效方法；2026-09-11 首次得出，2026-09-15 在干净主干上复核读数一致。一个会否定自己方法的系统，才有资格校准用户的判断。

### 反定位

不荐股、不提供个股买卖建议、暴露自己的错误率、无证据即拒答——大厂不是做不到，是做了会伤自己的流量与交易模型；决策型 Agent 的卖点是给建议，改成只交观察剧本等于放弃卖点。这条差异在组织层面比在技术层面更难跨越。

## 5 验证计划与调整机制

前期以希望建立研究框架的进阶学习者为主要招募对象，同时记录资深用户的方法积累需求。以下指标用于决定下一步投入，是小样本阶段的经营判断标准，不作统计效果证明。

| 阶段 | 时间 | 交付与判断 |
|---|---|---|
| V1 Alpha | 0–3 个月 | 3–10 人；框架首版与回检入口；记录周活、同任务耗时和质量。周活达到 60%、至少半数登记过判断，才考虑扩大。 |
| V2 Beta | 3–6 个月 | 满足收费前置条件后，50–200 人测试。目标激活用户付费转化 10%、付费次月留存 70%，同步核验全口径成本。 |
| V3 订阅验证 | 6–12 个月 | 现金情景目标为 {{illustrative_month12_payers}} 名有效付费者。须连续 3 个月覆盖经营费用与税前收入目标，才称为可持续，人数本身不保证达标。 |
| V4 后续发展 | 12 个月后 | 在个人订阅验证、数据授权和交付成本可控后，评估面向投教机构、研究团队等垂直客户的 FDE 定制交付，不把它提前计入收入。 |

**V1 如何判断。** 周活分母为已获邀且完成首次使用的用户；活跃须完成一次简报阅读或研究任务。三个月后周活低于 30%或无人登记判断，停止扩招。介于 30%–59%时，最多追加四周做一次明确调整，再决定缩小范围或暂停。

**付费如何计数。** 转化分母为测试期内完成首次核心任务的独立激活用户；分子为其中实际付费者。次月留存按首次付费队列计算。有效付费数只计算当月仍有付费服务权益者，不用历史累计购买人数替代。

### 同时检验省时与认知积累

比较同一研究任务在原有流程和产品流程中的耗时、完成率与质量。认知积累则观察用户能否独立解释判断依据、将框架用于新案例，以及根据实际结果修正认识；资深用户另记录已验证方法的复用情况。用户体验效果与方法有效性分开评估：前者看省时、解释、迁移和重复错误，后者看规则在没见过的历史上是否也成立、是否好于同期基准、样本够不够、是否稳定、是否已经失效。评估采用一致的前后对照标准，不仅看提问方式是否变化。北极星不是“模型命中率”，而是用户是否更省时、能否说清依据、是否减少重复犯错，以及同一段历史能否稳定重放。目前尚无外部用户的省时或学习效果数据。

### 根据验证结果调整投入

若只有一类用户形成持续使用，将收拢产品范围，针对该人群继续测试付费意愿。若 Beta 转化低于 5%或收费条件无法满足，则停止扩招与新收费，回到自用，或另行验证工程服务需求。

如需停止商业服务，将提前通知用户，按合同处理未履约订阅与退款，提供个人判断记录导出，并明确数据保留和删除安排。

收费前将逐一核对自用数据源的取用、加工、引用与对外展示权限。免费接口或公开可访问的内容，不直接视为取得商业分发授权；没有明确许可依据的内容不进入收费服务。研报与私有笔记保持访问隔离，不向体验用户开放全量原文。
