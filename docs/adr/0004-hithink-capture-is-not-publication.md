# 同花顺采集版本不等于已发布板块宇宙

当前成员接口没有历史日期参数，也未提供独立完整分母。因此用真实接收时间和新 `capture_id` 记录每次目录/成员逻辑请求，在既有同步器的选定 DuckDB 内保留不可覆盖的终态版本；请求完成度与供应商完整性分开，后者无独立证据时恒为 `unverified`。批次可供只读验算，但不能据此发布 canonical（统一事实表）或认领生产就绪。

## 取舍

- **不只留每日最新表**：这种方案简单，但同日成员退出、目录标签重叠及目录头覆盖后，无法回答「那次用了哪一版名单」。旧表仍是兼容投影，新预览显式指定批次才获得版本语义。
- **不存供应商原始响应**：只存规范化白名单业务字段 JSON、计数、真实时刻、合同版本与指纹，避免未知调试字段、个股名及错误正文进入台账；代价是不能完整重放网络细节。客户端内部重试不冒充逐 HTTP 尝试审计。
- **不复用 `SectorUniverseStore` 的已发布身份**：采集批缺独立全集证据，也没有接通 canonical 行情/成员投影。提前发布会让消费者把「请求齐了」误认成「事实池可用」。正式切源仍须沿既有候选/发布接口，不写公开 VIEW。
- **不新建生产旁路写入口**：审计跟随既有同步器的连接，保留 staging（暂存库）边界；失败 staging 若被丢弃，其审计不承诺永久留存。SHA256 只检查内容一致性，不是防管理员篡改的签名或供应商完整性证明。

跨午夜批次保留各响应实际日期，单日预览不把它压成同一日期；旧名单可重放不意味着行情也已冻结。接口、状态及退出码见 [运行口径](../data-sources/runtime-and-pitfalls.md#目录成员采集版本与请求审计本分支代码未部署)，唯一落点及写者见 [台账地图](../learning/ledger-map.md)。
