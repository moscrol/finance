# Knevo 盘面研究维度：内部自检与交付要求分开

用户已在 10-07 授权执行。目标是比 Pi 提供更有价值的相关视角、证据、反证及遗漏检查；简化重复裁决和僵硬套版。此前两项投影只作消融，本设计保留研究维度，不能把交付底线当成产品覆盖上限。

## 本次范围

只改 `dated_market_review` 的默认装配。一个具体盘面问题被归为复盘后，目前会同时欠总览、主线、风险三项章节，缺任一项可影响完成判定。这把系统的研究建议升级成了用户义务。

沿用现有 `TaskFrame.required_outputs` 与 `RequiredOutput.required`，把默认交付要求与研究维度分开：

- 默认交付：直接回答完整用户原问，交代数据日期、口径及影响结论的证据缺口。
- 内部研究维度：市场总览、主线结构、风险信号。保留现有描述、授权工具与来源绑定；按其是否能改变核心判断选择展开，可合并进直接回答。
- 用户已有的具体输出要求、材料编号题及明确的多日比较契约继续优先。调用者通过 `required_outputs` 显式要求的维度仍为必需，不能靠维度 id 将它降级。

研究维度缺项不单独压掉直接回答。实际展开的维度仍须通过原证据绑定、来源身份、时点和语义检查。结构完成不认证原问已被完整回答，全文内容仍需独立验收。

默认 `user_goal` 保留本题原问，避免分类器的通用复盘目标再次把具体问题扩大为全市场研究；既有明确语义分支和后续目标对齐保留。
从其他题型重建为 dated 时，已有 `_GENERIC_GOALS` 中不含实质任务的占位目标同样恢复为原问；有内容的上下文目标继续保留。legacy Controller 与直接构建分别走真实入口验证。

模型输入只呈现一次：必需项留在 `research_contract.required_outputs`，可选的研究维度放到同一合同的 `research_dimensions`，附相关性、自检、反证及用户要求优先的说明。后端继续使用原有输出对象，避免新建路由、控制器或验证系统。

复审证明，调用者显式增加的要求可能与旧题型默认项同名，单看最终 id 集合不能分辨。TaskFrame 仅补 `required_output_additions` 记录实际调用参数，在重建及持久化恢复时保留；空值不进入旧序列化形状或哈希。它记录合同变动，不自证自然语言来自用户，也不改变权限；对齐模型不能写它。旧原件缺少该信息时不补造来源履历。
本轮调用者新增要求与跨轮活动合同分开传入 rebase；后者仅在当前没有明确子任务时沿用。用户明确收窄为失效条件等追问时，旧报告不重新变成必填章节；本轮新增的真实要求继续保留。全仓基准的单任务冻结反例验证此分界，不修改其验收断言。

## 保留的能力与边界

保留 `reading_baseline`、已选观点视角、研究纪律、取证计划和工具授权。保留原信息截止、取消、绝对 deadline（全链共用的截止时刻）、调用预算及来源身份检查。材料权限、编号交付和历史研究分支按原合同运行。

检查层删改正文、合并 controller、其他题型、数据回填与正式模型盲评不纳入此次改动，分别验证，避免把多个变量的效果混在一起。

## 验收

通过真实 `TurnControlCore → TaskFrame → build_episode_context → build_episode_input → validate_episode_finish` 路径验证：默认研究维度仍送达作者；无关维度未填不导致拒收；核心直接回答缺失仍拒收；显式必需维度及材料编号题仍拒漏；可选维度不能绑定伪证据。与原实现对照，取证计划、权限、时点、预算和既有判读方法相同。

定向回归、准确干净提交的全仓门禁与双轴代码评审分别留收据。冻结旧答卷回放只证明装配变化，不声称自然模型质量提高。相对 Pi 的新增视角和事实质量由另行冻结的全文评测判断。
