# S5 · 独立出题人：抗泄漏评测集 uq15

- 索引：`2026-08-15-bookgap-index.md` · 靶：第 6 章 🟡 · 仓：finance · 优先级 P1
- 并行安全：纯数据+文档，立即可开工

## 1. 背景（证据）

- 08-10 审计：书第 6 章强调数据集要经得起泄漏考验；我们的题集
  「题目我出、判分我判」（handoff 自陈），用户独立出题复测只有 8/10，
  自评自判口径已被抽查证伪过。**独立出题人这件事一直没解决。**
- qc28 已冻结且被 triage loop 用作回归基线（R-10 三批口径），
  **不能动它**——新题集另立。

## 2. 目标 / 非目标

- 目标：建 15 题独立评测集 `uq15`：出题人与实现/调参隔离，题目来自
  实现者**没见过**的素材面。
- 目标：每题带密封判分要点（ground truth 出处 + 判分 rubric），判分
  可由第三方（非出题、非实现）执行。
- 非目标：不跑批不出分（那是 loop 或后续轮的事）；不替换 qc28；
  本 spec 只交付题集+判分协议。

## 3. 出题协议（本 spec 的核心交付）

1. **出题人隔离**：执行本 spec 的 agent 不得读
   `intelligence/eval/cases/`、`docs/verification/`、runtime 源码——
   开工即声明遵守，交付物里附「我读过的路径清单」供抽查。
   素材面限定：`~/knowledge-base-private/wiki/`（sources/concepts）、
   公开行情事实（DuckDB 只读查询）、`.foresight/` 用户台账。
2. **题型配比**（对齐产品真实用途，不对齐现有题集）：
   盘面事实 4 / 归因分析 4 / 主题链条 4 / 反证与边界 3。
3. **判分要点密封**：每题 rubric 单独文件，PR 里放
   `sha256(rubric)`清单，rubric 本体加密或延迟提交（出分后公开），
   防实现方「看题优化」。
4. **可判定性**：每题 rubric 含 2–4 条可核对的关键点（带数据源出处），
   避免「答得像就给分」。

## 5. 验收判据（预注册）

1. 题集 15 题齐、tier 与配比符合 §3.2、每题素材出处在限定面内。
2. hash 清单与密封 rubric 一致（用户抽 2 题当场验 hash）。
3. 出题 agent 的「已读路径清单」不含隔离区路径。
4. 协议文档能让第三方 agent 不问人就执行判分。

## 6. 风险

- 出题质量参差：rubric 的可核对性判据（§3.4）是唯一防线，检阅方
  抽验 3 题 rubric 是否真可判定。
