## 问题与范围

当前生产 5a5e4cbb 的 Controller 提示词及重试提示要求六字段，解析器却要求五字段旧格式或七字段旧格式。遵守当前提示的回复被拒收，固定回复实验产生两次分类调用后降级。TaskFrame 已有检索下限，所以本次反例没有变成零检索。

实施基线为本次 fetch 后的 gitea/main=bdd19f416。它与生产快照不同，但本次 Controller 目标文件树间无差异。工作在 fix/8792-harness-0928 隔离树，不改变 8792。

## 方案取舍

采用：把当前回复格式、首次提示和重试提示收敛到同一协议定义；保留精确列明的旧格式兼容。六字段为 route_id、confidence、reason、user_goal、assumptions、ambiguities；required_outputs 仍由 TaskFrame/任务所有者提供，模型不得重写。未知字段、缺字段、错误类型和非法路由继续拒绝。

不采用只在 parser 临时添加一组字段：会留下首次提示和纠错提示的独立副本。不采用接受任意字典或取消校验：会失去权限和任务语义边界。不新增研究引擎、不增加模型/重试/预算、不关闭证据或判官规则。

回复是否能被协议接受与它是否能补充任务必须一致。无效回复不能借 user_goal、assumptions 或 ambiguities 改变任务；纠错后接受的回复应使用其有效补充，而不是留下被拒回复的补充。若这一接缝由冻结反例证明有错，一并修在 Controller 回复接收边界，不更改通用 TaskFrame 规则。

## 实现边界

- 新增纯函数协议模块 intelligence/services/controller_protocol.py，负责字段形状、类型及文本说明；无 IO、模型、存储或预算依赖。
- turn_controller.py 负责路由表合法性、策略和 TaskFrame 投影，调用共享协议；继续最多纠错一次，provider 未响应仍沿原错误分类。
- tests 在公开 decide_turn 调用点验证首次成功、错误后恢复、兼容、拒绝及检索下限；不只测试新辅助函数。
- 可靠输入、工具菜单与补查首先复验已有真实接线测试；只对可复现缺陷加改动，不以新增词表替代现有能力。
- 产品门文档更新合同变化；此处不宣称已部署或自然金融质量提高。

## 验收

1. 严格遵守当前六字段提示的有效回复一次通过，failure_reason 为空。
2. 首次坏回复、第二次有效六字段回复恰好两次调用；原始错误反馈仍入同会话，有效语义补充得到使用。
3. 原五字段、七字段兼容；七字段的 required_outputs 不改变任务必需输出；越界字段仍拒绝。
4. 两次坏回复或 provider 不可用时，需检索金融题保持检索义务、日期与主体；普通聊天仍不被强迫研究。
5. 无效回复的补充不污染 TaskFrame；非法路由/类型不能通过语义对齐绕过拒绝。
6. 精确板块与日期输入、已装配工具菜单、检索阶段传递、工具局部失败保留证据、同会话修复原有用例通过。
7. 同一固定回复在旧实现红、新实现绿；定向测试、质量检查、独立规格及质量审查留证，收据绑定代码版本。

自然题对照须使用相同模型、数据快照、授权与预算，并区分协议指标和金融质量；先通过上述确定性边界再启动。没有完成新题对照时不能声称追平历史 ReAct 均分。
