## 0. 一句话

预注册号的分配是 **check-then-act**：分支上「读当日 max」与「落盘占号」不原子，
从取号到合并的整个窗口内并发 session 都可能取到同一个号。修法 = **把「占号」
做成副作用前的原子预占**，不是合并后的事后发现。

---

## 1. 形状（为什么改号治标不治本）

撞号的处置成本每例都不小：改行首号 + 全部行内/工单/交接引用同步 + 短形式残留
排查（#476 实测抓到一处 `-08` 短形式漏改——完整号形 grep 抓不到它）。
更糟的是**双向避撞会再撞**：-12 那例里两个 session 都在礼貌地让路，
让到了同一条道上。没有仲裁者的避让不收敛。

这与 MOC 已确立原则同族：**「配额要在副作用前预占，不是事后计数」**——
事后扣费挡不住并发 check-then-act，两个请求同时看到「还剩 1」会双双执行。
把「配额」换成「编号」，一字不差。

**可迁移**：任何「从共享账本读 max+1 再回写」的分配器都有这个洞，
分布式 ID 生成（数据库自增 vs 雪花 ID vs 预分配号段）是同一道题。

---

## 2. 方案对比（选 a，其余为什么不选）

| 方案 | 原子性来源 | 代价 | 判定 |
|---|---|---|---|
| **a. 本机 claims 登记簿 + flock 预占** | 文件锁（单机内核仲裁） | 一个小脚本；成立边界=单机 | ✅ **推荐** |
| b. 先占号小 PR（占位行先合 main） | main 合并串行化 | 每单多一次 PR + 等待，重流程 | 备选（跨机时升级到它） |
| c. 时间戳号 `R-YYYYMMDD-HHMMSS` | 时间天然唯一 | 破坏 `R-\d{8}-\d{2}` 号形：crosswalk `_ID_RE`、超码后缀豁免、全部历史文档惯例都要迁移 | ✗ 成本大于收益 |
| d. 号内加 session 后缀 | 后缀唯一性 | 「当日第 N 单」序数语义丢失；后缀选择本身又是一个约定依赖 | ✗ |

选 a 的关键事实：**所有取号 session 都在同一台机器上**（本仓多 agent 共享一台
Mac，台账写入全部发生在本机 worktree）。flock 是内核级仲裁，覆盖全部本机进程。
这个成立边界必须写进脚本自述；若未来出现跨机取号，升级到方案 b。

## 3. P0 · `scripts/claim_ledger_id.py`（零运行时改动）

**交付**：一个 CLI，两个子命令。

```
claim --branch <branch> [--date YYYYMMDD]   # 原子取号，打印取到的号
list  [--date YYYYMMDD]                     # 查已预占未落盘的号
```

**机制**：

1. 登记簿 `~/.finance-runtime/ledger-id-claims.jsonl`（**仓外 runtime 目录**，
   不进 git——它是机器状态不是仓状态）。每行
   `{"id": "R-20260828-01", "branch": "...", "ts": "...", "base_rev": "..."}`
   （示例号即本单号；真实行由脚本追加）。
2. 取号 = `max(主干台账全文所有号, 登记簿已发号) + 1`，整个「读-算-追加」在
   **`fcntl.flock(LOCK_EX)`** 内完成。台账读 `git show gitea/main:docs/prediction-ledger.md`
   （**读主干不读工作树**——工作树可能是旧基座；取号前先 fetch）。
3. **号不回收**。放弃的单就让号烧掉——回收会造成「同号先后指两件事」，
   与重号同病。登记簿只追加不删改。

**硬性要求**：

- **fail-closed**：锁拿不到（超时）、登记簿损坏、`git show` 失败 → 报错退出，
  **不回退到手工 max+1**（回退 = 把洞重新打开）。
- **自述**：输出必须打印「基于主干 revision X 的 max 号 + 登记簿 max 号 →
  取到 Y」，取号依据可复核。
- 约定依赖诚实声明（写进脚本 docstring）：脚本消灭的是**脚本用户之间**的竞态；
  有人绕过脚本手工取号，残余窗口仍在。治本靠流程全员切换——本单落地后
  `AGENTS.md` 台账节加一句「预注册号一律 `claim_ledger_id.py claim` 取，
  禁止手工 max+1」（改 AGENTS.md 属流程变更，随 P0 同 PR，一行）。

## 4. 明确不做

1. **不动 crosswalk**。重号检查保持 error 档——它是最后防线，预占是第一防线，
   两层各司其职。
2. **不做跨机同步**。成立边界=单机；跨机场景升级方案 b，先论证再做。
3. **不改现有号**。存量号（含 `-07a` 超码后缀）全部保持原样。
4. **不做 release/回收子命令**（§3 第 3 条，回收与重号同病）。

---

## 5. 验收判据

1. **并发压测**：同时起 ≥8 个 `claim` 进程（shell `&` 即可），拿到的号
   **两两不同且连续**；登记簿行数 = 进程数。
2. 取号自述含「主干 revision / 台账 max / 登记簿 max / 取到的号」四项。
3. 主干台账已有 `-NN`、登记簿有 `-NN+1` 时，claim 给 `-NN+2`（两个来源都参与 max）。
4. 登记簿文件损坏（截断一行 JSON）时 claim 报错退出非 0，不发号。
5. 全量 pytest 不降（新增脚本带专项测试）。

## 6. 变异点（先红后绿，逐个精确击杀）

| # | 变异 | 预期 | 抓的是 |
|---|---|---|---|
| 1 | 去掉 flock | 并发压测出现同号，专项钉**红** | 原子性真来自锁，不是运气 |
| 2 | 取号只看台账不看登记簿 | 判据 3 钉**红** | 预占的号真的参与仲裁（否则预占无效） |
| 3 | 登记簿损坏时跳过坏行继续发号 | 判据 4 钉**红** | fail-closed 没被降级成 fail-open |

⚠ 变异前先 commit（本仓交接踩过两次的第 0 步）。
