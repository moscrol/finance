# 同花顺数据请求断线恢复

2026-09-30 的 nightly 同步因 TLS EOF 停止；19:30 在同一暂存库续跑时，两次均因 `http.client.RemoteDisconnected` 退出。`get_json` 只捕获 `URLError`，直接由 HTTP/套接字层抛出的临时断线不会使用既有重试。生产库因此正确地保留在 09-29。

## 选择与边界

采用客户端单次 GET 请求的有界重试，沿用 `retries`、指数退避、节流以及 429 的独立预算。比整批 856 个板块重跑粒度更小；不新增网络库或更改代理，也不放宽数据发布门。

新增覆盖：连接在响应前断开、响应体不完整、连接重置、套接字超时、TLS EOF。仅恢复完整成功响应；不拼接半份响应。持续故障耗尽原次数后仍抛 `HithinkAPIError`。业务错误、HTTP 429 及其预算语义保持原样。

HTTP 错误响应也进入同一个读取边界；已知 HTTP 429 仅凭状态和响应头使用原独立退避，不读取正文，避免正文断线将限流误分类为普通网络故障。

不改模型调用、模型选择、数据来源、金融计算、生产启动器或定时任务代码根。恢复试跑只写暂存库；全部数据校验通过、确认生产基线未变并留备份后，才可用现有原子换库函数发布。本分支合入 main 仍需用户确认。

## 验收

- 原实现面对直接断线的回归必红；修后开连接或读正文中的一次临时故障均能取得下一次完整响应。
- 持续故障恰好耗尽指定次数，最后一次不再等待，不包含凭据。
- 完整同花顺客户端、板块捕获和夜跑邻近测试通过，原 429 / 4001 行为通过。
- 使用固定候选提交续跑暂存库，保存失败与成功日志；同日门、跨日门、独立值审计均通过后，验证 8792 的实际数据日期与快照一致。
