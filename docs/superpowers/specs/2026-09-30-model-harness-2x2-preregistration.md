## 一句话

08-27 四臂对照里 ReAct 臂 0.857、产品臂 0.567，这 0.29 的差距一直被读成「我们的 harness 不如 ReAct」。
但两边**换了两样东西**：ReAct 臂是 Claude 驱动的控制台 ReAct，产品臂是 `glm-5.3` 跑的 continuous harness。
差距可能来自模型，也可能来自 harness，现有数据分不开。2×2 就是把两样东西各自单独换一次：

|  | 模型 G = `glm-5.3-flash`（生产同款） | 模型 C = Claude（08-27 同款） |
|---|---|---|
| **harness P = 产品 continuous（完整 8792）** | P×G（≈ 当前生产配置） | **P×C（新）** |
| **harness R = 薄 ReAct 控制台驱动器** | **R×G（新）** | R×C（≈ 08-27 react 臂） |

同一行比较 = 只换模型；同一列比较 = 只换 harness。两个方向的差各算一次，就知道差距主要在哪一边。

> **范围（第 3 次修订补）**：两臂的版本都已不是 08-27 那一版——模型 G 换成了 `glm-5.3-flash`，产品 harness
> 此后又合入了大量改动。所以本对照回答的是「**对现在的版本**，差距主要在模型还是 harness」，

## 5. 运行规则

- **重复**：每格每题 N = 3 次。20 题 × 4 格 × 3 = **240 次**。
- **顺序**：按轮跑，共 3 轮，排程由 `scripts/model_harness_2x2.py plan` 生成并存进收据，运行器照 `seq` 执行。
  每轮的题序用同一个种子 `20260930` 的随机数打乱；同一题的四格按拉丁方轮转先后，第几个跑 = `(题位 + 轮次) % 4`，让时段漂移平均摊到四格。
  每行带 provider 列（G → zhipu，C → anthropic），供运行器按 provider 串行。
- **限流间隔**：同一 provider 同时只跑 1 次；相邻两次启动至少间隔 90 秒（F4 冒烟时按实际 429 情况上调，记进修订记录）。
  G 格和 C 格是不同 provider，可以并行。
- **准入门（硬门）**：每次运行结束立刻执行
  `check_model_admission.py --expect-model <该格模型> <run 目录>`。
  exit 1（错配）或 exit 2（无证据）→ 该次**作废**、重排到队尾，**不计 0 分**。
  判定以 `analyze` **按产物重算**为准（第 3 次修订及 §10）：运行记录必须带 `artifacts` 路径列表；重算覆盖自报的 `admission_exit`，
  同时保留自报值、逐项结果及输入哈希；缺少原始产物则按无证据退出 2。重算**含子分支**：父产物引用的子事件
  缺失、损坏或环路 → 无证据（`--episode-store` 可重复指定分支 episode 所在目录）。
- **作废与计分的边界**：
  - **作废并重排**的只有 provider 侧故障，即 `stable_llm_fallback_reason` 为 `provider_rate_limited` / `provider_overloaded` / `provider_unavailable` 的运行。
    这类运行的失败原因里会带「限流：服务端要求 N 秒后再试」或 HTTP 5xx。
  - **照常计分**：其余失败，包括自家 deadline 烧完（`deadline_exhausted_local`）、答错、缺数、格式坏。这些正是要测的能力。
  - 同一格同一题最多重排 2 次；仍失败 → 该格**不完整**，涉及该格的效应一律不下结论。
  - 每格每题按 `seq` 取**前 N 次有效**；有效之后多跑的不取。
- **运行记录**（`analyze` 的输入，JSONL，一次运行一行）：`seq`（全局尝试序号，重排的运行拿新的更大的号）、`question`、`cell`（`PG` / `PC` / `RG` / `RC`）、`artifacts`（原始模型产物路径列表，相对运行 JSONL 所在目录解析）、`admission_exit`（历史自报值，仅留审计；analyze 自动重算，不能手填 0 放行）、`failure_class`（`stable_llm_fallback_reason`，没失败写 null）、`score`（有效运行必填）。

## 6. 指标与判定规则（冻结）

**单次得分**：machine-truth rate s ∈ [0, 1]（与 08-27 同口径）。**格均值**：先对 3 次取均值，再对 20 题取均值。

四个格均值记作 PG、PC、RG、RC（P/R = harness，G/C = 模型），效应这样算：

- 模型主效应 **ΔM** = ((PC − PG) + (RC − RG)) / 2
- harness 主效应 **ΔH** = ((RG − PG) + (RC − PC)) / 2
- 交互 **I** = (RC − PC) − (RG − PG)

**可判（callable）必须三条同时满足**：

1. **过方差门**：|Δ| ≥ 噪声底。这是 `docs/workflows/acceptance-workflow.md`「方差门」与 `intelligence/eval/variance_baseline.ab_decision` 的同一规则。
   - 噪声底取四格翻转率的**最大值**。
   - 每格翻转率 = 各题翻转率的均值；题翻转率 = count(标签 ≠ 众数) / 3。
   - 标签按单次得分分三档：满分（s = 1）、部分（0 < s < 1）、零分（s = 0）。众数并列时取字典序最小的标签（与 `variance_baseline.mode_of` 同一实现；翻转率不受并列取法影响）。
2. **过最小效应**：|Δ| ≥ 0.10。小于它，就算统计上可分，对「往哪投」也没有意义。
3. **过区间检验**：以**题**为单位有放回重抽，bootstrap 10,000 次（种子 `20260930`，抽样用 `int(random() * n)`，跨 Python 版本可复现），百分位法 95% 区间不含 0。

比较前所有数取 9 位小数，免得恰好 0.10 的效应被浮点误差算成 0.0999…。

**样本量粗估**：按 Arm A 校准实测的单次方差 0.1375（`intelligence/eval/ab_sample_design.py`）和 `projected_ci_half_width` 同一公式，20 题 × 3 次时主效应 95% 半宽约 0.094，刚好压在最小效应 0.10 之下；交互项约 0.19，只有大交互能判；次要分析（10 题）约 0.13，敏感性分析（17 题）约 0.10。这只是粗估：同题配对会让实际区间更窄，题间差异大会让它更宽。

**判定表**（按先后顺序取第一条命中的）：

| 读数 | 结论 | 对投入的含义 |
|---|---|---|
| ΔM 可判，ΔH 不可判 | 差距主要来自模型 | 暂停内容正确性线上的同类 harness 修补；优先解决模型准入与选型（难题路由到更强模型，或接受天花板） |
| ΔH 可判（R > P），ΔM 不可判 | 差距主要来自 harness | 逐题对照 R 与 P 的轨迹，找 ReAct 做对了什么（工具选择自由度、约束多少）；现有 harness 投入方向对，但要换打击点 |
| ΔH 可判（P > R），ΔM 不可判 | 产品 harness 优于薄 ReAct，模型差不可判 | harness 投入有正回报；08-27 的差距在当前配置下不来自 harness，也没被模型解释，先查题集与判分口径是否与 08-27 可比 |
| 两者都可判 | 两边都有 | 按 \|ΔM\| 与 \|ΔH\| 的比例分配投入；H1 / H2 按大小与方向裁决（ΔH 为负即 P 优于 R，H2 不成立） |
| 两者都不可判 | 差距在本样本量下不可复现 | 停止引用 08-27 的 0.29 差距；想要更细的结论，先扩题（新留出集），不要加轮次 |
| 另外：I 可判 | harness × 模型有交互 | 单独报告；如果是「P 帮 GLM、拖 Claude」，说明约束是按模型调的，换模型前要重审 |

**敏感性分析（必须报告，但不改变主判定）**：
