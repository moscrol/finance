# 金融 Agent 输入与底座验收规格

日期：2026-09-24。分支：`feat/architecture-audit-0924`。初始基线：`gitea/main@a54fed0d065f`。

## 1. 要回答的问题

用户要求「列一份要做的 spec，然后推进执行」。交付不是新的架构清单，而是对现有系统的三项可核查回答：每条输入线是否闭环、底座是否稳定、下一项优化是否值得做。

先执行只读基线检查、离线复现和审计工具修复。生产补数、换库、部署、恢复定时任务、写入个人记忆或批准方法规则，仍须按各所属工单的授权条件办理。本单不接管其他会话正在实施的修复。

## 2. 架构与权威来源

系统按闭环理解：输入 -> 分层资产 -> 检索与组织 -> 研究运行 -> 质量检查与交付 -> 反馈与回检 -> 经审查的沉淀。工具是受权限约束的操作接口；Skill 是按需装配的工作方法；记忆跨资产和反馈层存在，不是另一个不受审查的数据入口。

| 核查对象 | 权威来源 | 本单职责 |
|---|---|---|
| 能力是否存在 | `.agent-memory/10_knowledge/finance-agent-capability-graph.md` | 核对对应节点，不另造能力注册表 |
| 产品入口与两条引擎 | `docs/agent-product-door.md` | 分开记录 Workbench 与 CLI，禁止互相冒充验收 |
| 数据表和消费合同 | `market_feature_store/schema.sql`、consumption registry | 检查标准库、字段质量、消费范围 |
| 台账与唯一写入者 | `docs/learning/ledger-map.md` | 只读现有落点，新增的是审计收据，不是业务台账 |
| 修复归属及授权 | `2026-09-01-workorders-INDEX.md` | 引用已有工单，本单不抢号或重复施工 |
| 方法候选与审批 | perspective-distill、divergence-distill 技能 | 候选、批准、装配、有效性分别举证 |

生产健康接口、启动器、实际数据根和带版本的运行轨迹优先于工作树里的默认路径。部署版本、审计代码版本、数据截止日期各记一列。

## 3. 判定合同

每个断言只能为 `PASS / FAIL / UNKNOWN / BLOCKED`：通过、已证伪、证据不足、检查被前置条件阻断。旧工具的 `WARN` 保留原值，在报告中说明是哪种情况，不能自动升级为通过。

每条线至少记录：来源/用途、触发及预期频率、唯一写入者、标准落点、最新业务日期、采集时间、质量检查、实际消费者、失败告警、恢复入口、证据路径、代码/数据身份。未知字段显式标 `UNKNOWN`。

验收分五列：代码存在、已合入、生产装配、实际消费、金融质量。任何一列的绿都不替其他列背书。单次只读快照只证明采样时刻，不证明连续稳定。

| 层 | 必须证明 | 反例或故障对照 |
|---|---|---|
| 输入 | 该到的到了，正文/原件可追溯，业务日期正确 | 文件缺失、原件缺失、日期错误、重复输入 |
| 存储 | 主键/版本正确，关键字段有值，事实与观点分层 | 行在但值全空、撤回事实仍可见、历史日混入未来行情 |
| 检索 | 已提交源与索引一致，过滤合同下达至执行端 | 脏源、过期索引、截止时间未传递、过滤选项不受支持 |
| 研究运行 | 真入口生成轨迹，证据进入模型上下文 | 工具被声明但未调用、预算未下达、错误变成功 |
| 交付 | 关键断言逐条对证据，拒收不包装为成功 | 数值方向读反、空正文、跨公司混比、伪造代码 |
| 记忆 | 用户归属、审批与版本可追溯，可撤回 | 未批准候选影响回答、其他用户记忆泄漏、撤回后继续使用 |

## 4. 输入线验收范围

这是本次验收对象，不替代能力图谱。

| 输入线 | 内容定位 | 最低闭环证据 | 修复归属 |
|---|---|---|---|
| 每日复盘 | 市场事实 | 标准库日期、快照日期一致；local 计划必需字段有效；真回答引用同一截止 | #60/#61；历史补数走 duckdb-backfill |
| 晚间卖方 | 机构观点及有来源的事实 | 原贴 -> 提取/订正 -> 索引/图谱 -> 被引用；隔离条目不冒充语义已审 | 卖方 consumption / miracle 在途分支 |
| 晨汇 | 日前信息及线索 | 原件时间 -> briefing -> 检索/长河绑定 -> 真入口引用；历史问题不吃未来晨汇 | #87 及知识库 evidence-qc |
| Knevo | 研究方法候选 | 原件复算 -> 候选规则 -> 审批 -> 运行装配 -> 同题差分 | Knevo intake / absorption 在途分支 |
| SPT | 视角与方法 | 文章 -> 方法卡 -> 审批版本 -> 指定用户/视角装配 -> 可追溯应用 | Perspective Lab |
| 风远 | 视角与方法 | 同 SPT，独立检查而不是按文章数推断有效 | Perspective Lab |
| 公告/财报/PDF/IMA | 公司事实与报告上下文 | 原件标识、披露日、证据层级、实体写入门、可检索证据 | 既有 ingest / disclosure 入口 |
| 用户反馈与纠正 | 个人偏好、判断和回检 | 正确用户空间、唯一写者、纠正回灌、撤回/隔离 | ledger-map 与 userspace |
| 按需查询 | 当前任务的外部或本地证据 | 来源与时间、调用授权、成本/限流、失败显式化 | 工具注册表与执行合同 |

SPT、风远和 Knevo 是按输入事件更新的链路，不因为当天没有新文章就判过期。日更线按交易日/约定发布时间判断；没有频率合同的线标 UNKNOWN，不臆造时效指标。

### B. 实际消费与语义验收

先重放已有冻结轨迹，检查「拿到 -> 保存正确 -> 找得到 -> 进入上下文 -> 用对 -> 改善交付」在哪一步中断。新模型运行须先满足所属自然验收工单的前置与预算授权，不绕过 #76。

样题覆盖：最新复盘、卖方观点、历史晨汇、Knevo 方法、SPT、风远各一题；另有用户纠正与跨用户隔离两例。固定问题、代码、数据、模型、用户和视角版本；正常/缺数/撤回或未来信息对照明确预期。Workbench 走 `POST /api/conversations` 的 Episode 入口；CLI 对照只证明 CLI。

完成条件：每例保存请求、工具轨迹、证据、回答、逐条核对及缺陷；单例可证明可达，不证明方法有效或总体质量。前置不满足则标 BLOCKED 并指向 owner，不能删掉失败例。

### C. 稳定性验收

建议观测门槛：日更线连续 5 个交易日，事件更新线至少 3 次独立输入；采集、落库、检索、消费各有成功/失败分母及耗时。该门槛只表示初步运行稳定，不是统计上证明可靠。

在隔离环境演练：缺数据、索引不新鲜、工具超时、额度耗尽、重复请求、取消/重启。验收点为明确降级、无错误日期填充、无重复副作用、费用可对账、恢复路径可执行。生产部署需固定版本、四叶工程门禁、用户确认、回滚点与换版后复验。

完成条件：逐项结果可重放；重大故障清零；没有把未运行项当通过。跨日观察未满则继续标未完成。

### D. 优化对照

稳定性未达标前只修确定性故障。达标后冻结至少 12 道覆盖主要研究任务的问题，用同代码/数据/模型的基线和单变量候选配对比较，每臂每题至少两次；运行预算另批。

先检查质量底线：事实/截止/引用/权限无新增严重错误，再比较任务完成率、证据利用、p50/p95 耗时、全口径成本、维护负担。样本很小时只报观察值，不下总体优越结论。结论用「在这组任务和约束下更合适」，不声称全局最优。

## 6. 本轮执行保护

- 所有改动仅在本分支工作树，主工作区的他人改动不动。
- 生产只做本地只读 GET 和只读库/文件检查；不重启、不写用户目录、不重建索引、不恢复采集。
- 复盘会处于风控暂停，核查用 `--plan local`；审计命令的“建议恢复”文本不是执行许可。
- Python 检查使用主仓 `.venv-workbench/bin/python`。定向测试不称全量门禁，旧 SHA 的收据不移签。
- 不调用带通知副作用的 health 探针，不输出启动器的密钥。收据只保存本地接口的必要诊断数据，不收录私人对话正文。
- 文档发现项与修复项分开：某条业务线未验不意味着新建第二条实现。
