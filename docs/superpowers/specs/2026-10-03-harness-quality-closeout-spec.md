# Harness 质量闭环与工作区收口验收规格

日期：2026-10-03。此文件固定目标、范围和验收条件；任务板「金融工作区」父任务 **FINANCEWORKS-1** 保存执行状态、负责人、依赖和逐次证据。任何新会话先读父任务与最新评论，再认领一个子任务。

## 初衷与完成定义

让较弱模型更可靠地答对，让较强模型能在复杂问题上发挥更多能力。最终交付是有证据的回答质量改善，以及可核对的合入、部署、备份和工作树去向。

不能用测试数量、结构合规率、`completed`、少几个模板或更多自主动作替代内容正确性。代码已写、已验、已合、已部署、质量通过分别记账。原质检报告中的历史数字须重新核验，不能直接复制为现状。

总验收同时满足：

1. **较弱模型获益**：在同模型、同数据、同权限和同资源预算的旧版/候选版对照中，预先冻结的内容主指标改善，并通过预注册的最小效应和不确定性检验。
2. **较强模型获益**：同样的配对比较在事先冻结的复杂题集上证明提升；一般题不退化。只证明“不变差”或自主空间增加，仍不足以宣称“更强发挥”。模型分档有测量依据，不能只看型号名称。
3. **金融硬错误受控**：来源、对象、日期、单位、算术、财务口径及权限无新增严重错误；新闻、财务和传导链路都单列结果。整体均分不能掩盖某一类失败。
4. **真实入口成立**：最终验收经 Workbench 会话 API，保留 conversation/run、最终正文、来源和全部子调用证据。CLI、脚本模型和静态审查各自只证明相应范围。
5. **发布可回读**：固定 SHA 的本机等价门禁、GitHub 所需检查、规格/代码独立审查全部通过；部署后 health、readiness、静态资源、用户任务与回滚能力可核对；Gitea 备份回读成功。
6. **没有无人解释的遗留**：开放 PR、远程在途分支及工作树逐项有接替、保留或回收理由；活动树、生产树、数据根与回滚树可以保留。目标不是工作树数量为零。

## 已落实的部分与仍缺的证明

截至本轮起始快照，技能视图纠正及替代关系防回归、有界 429 重试、模型身份取证、正则路由冻结、平台锁自检和 CI 修正已有实现。它们仍须在工作包 1 中绑定实际部署版本，不重新包装成“内容质量已经通过”。Linux 的锁边界是拒绝不安全运行，不表述成 Linux 换库已获得同等能力。

记忆语义模块默认关闭；工具调用审计不等于工具面已简化；数据时效提示不等于换源完成；预测台账过期检查不等于积压已消除。旧独立评测中 news 0/8 可用、transmission 0/8 可用、financial 6 可用/2 部分；这些旧基线读数不能直接套给新候选，但必须有接替实验才能关闭对应缺口。

## 实验与裁决纪律

- 原 2×2 解决“差异来自模型还是 harness”的归因问题，使用原预注册的预算策略与判分规则；它不是候选上线验收。
- 双模型旧版/候选版配对实验单独预注册：同模型预算匹配，题目、顺序、模型配置、身份准入、主指标、阈值、样本量、成本上限和停止规则在首次调用前冻结。小规模冒烟只验链路，不能代签效果。
- 模型身份覆盖作者、核验、修复、子研究及失败重试。缺 usage 记未知；失败计入正确的分母，不补跑挑最好成绩。
- 全文判分先匿名化版本；独立盲评与执行者自审明确区分。关键错误逐题保留，格式评分不能覆盖事实错误。
- 对照无改善、不可判或证据不足时照实结案该实验，并回到模型/数据/工具/提示/架构的首错归因，不默认继续添加 harness 补丁。
- 已经失败且看过答案的题可以作为修复回归题，不再标为新留出题。

## 任务板与断点续跑规则

1. 每次开工读父任务、目标子任务及评论；用当前 version 认领，只保持一个由本会话执行的主工作包。
2. 开工评论写“本步服务哪条初衷、固定 revision、下一项能证伪的检查”。每轮只变一个主要因素。
3. 收工评论写“改了什么、证据、未通过项、下一步”，按实际状态放 in_progress / blocked / in_review；不因写完计划而关闭父任务。
4. 发生压缩、切会话或换 agent，从任务板和本规格继续；不靠聊天摘要猜任务完成。
5. 用户接受后才将待验收项置 done。总任务只有六条总验收均有证据时才可申请验收。
