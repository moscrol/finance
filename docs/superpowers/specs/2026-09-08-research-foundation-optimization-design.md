## 2. 总体设计与取舍

选择**在现有事实库、快照、标签目录、收据和运行时接缝上补合同**。保留现有产品门，避免把数据、评估或同步再做成平行系统。

| 方案 | 收益 | 代价与选择 |
|---|---|---|
| 补齐现有模块之间的契约 | 最大程度复用现有能力，能逐项验证 | 需要检查所有消费者；本提案采用 |
| 重建统一数据/记忆中台、全插件化重写 | 形式更统一 | 迁移成本高，不能自动解决前视和统计失真；本轮不采用 |
| 增加提示词、更多数据与更多回测次数 | 容易快速增加输出 | 无法保证历史真实性，增加探索次数还会增加偶然发现；不作为补强方案 |

| 边界 | 责任 | 契约 |
|---|---|---|
| 数据底座 | 事实内容版本、实体关系、快照、派生计算 | 返回当时可知的具体版本及字段可用性 |
| Runtime（运行时） | 执行、预算、取消、持久化、恢复、事件与成本 | 领域请求资源，底座授予并执行；领域不能绕过预算或恢复语义 |
| 领域 Harness（投研约束与流程层） | 方法、研究计划、上下文、证据、结论准入 | 不拥有通用执行循环，不用改预算替代研究取舍 |
| 评估与晋升 | 实验登记、最终统计结论、失效和升级 | 可以位于领域应用层，但评价器、留出集与晋升权限不受候选生成者修改 |

“能更换运行时”的验收是相同领域输入和脚本化模型下，领域决策不需要重写；不要求不同底座具有完全相同的取消、预算与恢复能力。能力差异由 OPT-08 明示。

## 3. 数据与时间合同

### OPT-01 内容版本与当时可知性 · P0

PIT（Point-in-Time，当时可知）必须绑定**具体内容版本**，而不只绑定交易日或实体名单。

设计要求：

- 每个事实版本保留内容 hash、有效时间、系统首次可靠取得该版本的时间、来源引用、替代关系与生成版本。发布时间若可靠，另存 `published_at`；不拿它冒充系统实际取得时间。
- 本产品历史决策回放默认回答“本系统在 C 时实际可知什么”。后补的旧公告即使发布时间很早，也不能回填为系统当时已持有；市场已公开信息的事后研究另带用途声明。
- 修订追加新内容版本。名单快照 `captured_at` 只能证明名单版本，不能给后补行情、资金值或新成员关系提供更早的可知时间。
- 复用已有冻结快照及分代机制；原始来源缺版本时允许明确降档，不从今天的内容反推旧值。hash 只负责身份校验，还须能解析回保留的内容。
- `point/state/range` 沿用统一 spec 的类型语义。单日 point 按日期等值匹配；state 使用半开有效区间；不要把 point 套入长度为零的半开区间而全部过滤掉。
- 当前严格等级明确为**日频 PIT**。同日盘后信息不能用于宣称当日开盘前可决策；若任务要求盘中或开盘前判断，须另给精确时刻证据，否则标为不可验证。

验收：

1. T 日原值与 T+7 修订并存，`slice(T,C=T)` 返回原值或可解释缺口；不能返回修订值且标 strict。T+7 查询能看到修订与原版本关系。
2. 改板块成员、别名或供应商代码后，历史查询保留当时成员宇宙；跨源数值不能仅凭同名直接联接。
3. 随机抽取冻结对象，hash 可验证且原内容可取回；删除可解析内容后，回放门失败，而非只看 hash 字符串通过。

落点：`river.py`、板块同步与分代写入、`intelligence/eval/pit_snapshot.py`。先阻断错误的 strict 宣称，再选择与现有写入合同兼容的内容版本存储方式。

### OPT-02 单点、区间、特征与回测共用时间边界 · P0

设计要求：

- 单点、区间、锚点、类比和回测都携带快照引用、cutoff、特征/标签版本及变换参数引用；每条派生对象保留成员引用和缺口策略。
- 训练窗口拟合标准化、分位数、聚类中心、特征筛选与距离权重；验证和留出窗口只应用冻结参数。全历史探索产物标记探索用途。
- 分清“截至区间末尾重建整段历史”和“沿历史逐日模拟决策”。前者可有共同 C；后者每个决策 T 用自己的 C(T)，不能让区间末尾知道的修订回流到较早的决策。
- 锚点研究的前瞻结果可在 outcome 窗结束后读；锚点当时的特征独立保留 C(T)。发现后来的赢家可用于结果分组，不能偷偷变成当时选样条件。
- 窗口缺字段、缺天、历史尾部未到期分别返回缺口、不可验证、pending；真实零值与缺失分开。

验收：

1. 冻结旧实验后，追加 C 以后的数据，旧切片、变换参数、特征、类比排名与输入 hash 均不变。
2. 窗口内一个必需值在 C 后才到达，单点、区间、签名、类比、回测都不能使用该版本。
3. T+5 的 outcome 不进入 T 的特征；按逐日模式回放与逐日单独执行结果一致。

落点：`river_window.py`、`river_query.py`、类比模块、methodology 的 labels/outcomes/runner；对应原 G-02c、G-08、G-11。

#### 3.1 占位清单（本轮唯一允许的未接入占位）

| 数据项 | 用户确认状态 | 接入时沿用的正门 | 当前消费规则 |
|---|---|---|---|
| L2 资金数据 | 待同步 | 现有 `scripts/moneyflow/` 管线、schema 中已有 L2 表；实施前核验具体 writer | 待同步窗口的资金计算返回 pending_sync；不能从成交额推算资金流 |
| 晚间卖方 | 待同步 | 第一落点为知识库 `wiki/raw/sellside/`，之后沿台账地图的观点提取与消费流程 | 不把未同步当“没有覆盖/舆论降温”，不生成伪造观点事件 |
| 晨汇 | 待同步 | 现有 IMA 原料获取与 morning-briefing；知识库 `wiki/raw/briefings/`、`wiki/briefings/` | 不把缺批次当“当日无事件”，不以其他日报冒充晨汇 |

三项都不安排本轮执行日期，不新增抓取器、不恢复已退役夜跑。只对待同步的目标窗口或批次标注状态；已有历史存量仍按实际质量可用。具体补齐起止日期未被用户指定，保持未排期，不能猜成全历史或某一天。

#### 3.2 接入时的状态合同（概念字段，尚非现有 API）

同步状态与分析可用性分开：

| 字段组 | 含义 |
|---|---|
| `source_id / target_window_or_batch / canonical_ref / writer_ref` | 数据源、目标范围及唯一写入入口；目标范围未排期可为空 |
| `sync_status / status_basis / status_recorded_at` | 本轮三项为 pending_sync / user_confirmed / 本轮确认时间 |
| `last_attempt_ref / last_error` | 有执行收据才填。未核实为空表示未知，不能解释为历史上从未尝试 |
| `available_through / required_fields / field_coverage` | 按来源、实体和窗口核验；未核实为空，不捏造最新日期 |
| `readiness / gap_reason / eligible_for_calculation` | 对当前请求的判定；依赖待同步字段时 unavailable / pending_sync / false |

只有实际尝试并失败的收据才允许将该次尝试标 failed。同步完成不直接等于 ready，还须校验字段、时间、单位、实体对应和来源版本。

分析消费门：任务声明必需实体、轨、字段、日期范围和覆盖要求；可选轨缺失只降低结论覆盖，不阻断无关计算。必需字段全空时，不论行数多少都不可计算。晚间卖方与晨汇引用同一原文时按来源身份去重，不能当两份独立证据。

验收：三项占位被读取时不发生外呼或写库；依赖项返回 pending_sync，不填零、不进统计分母、不记方法失败；只依赖盘面的规则可继续；真实同步失败与待同步在运维指标中分列；实际接入后通过字段质量检查才能变 ready。

持久化位置和 writer 实施时先登记到台账地图；本轮只在本节占位，不创建第二套同步状态账。

## 4. 方法检验与受控更新

### OPT-04 统一实验身份与晋升认证 · P0

把既有 lifecycle、队列和方法库入口接到同一个最终收据认证过程。这个过程可以是现有模块内的深函数，不要求再造服务。

一轮实验的固定身份：

```text
experiment_id + validation_cycle_id
rule_id + rule_version + rule_content_hash
label / feature / transform definitions and versions
fit_artifact_hash + fit_range + fit_cutoff (for learned transforms)
universe_policy + target_event + horizon + benchmark
split_protocol + dependency_handling + multiple_test_family
evaluator_version + model/prompt identity when outcome depends on a model
```

各窗口另有不可变 `input_manifest`：快照引用、cutoff 策略、实体宇宙快照、变换参数、样本与 outcome 引用。**三个窗口可以使用不同日期、不同 hash 的事实快照**；锁住的是实验语义及各自内容，不能要求发现、验证、留出使用同一个数据日期。标签或来源口径变动须有兼容声明，否则开启新轮次。只改标题或说明且计算语义未变时可单独更新元数据版本。

需要拟合的变换或抽取器只在发现集训练；拟合范围、截止时间与 `fit_artifact_hash` 纳入固定身份，后续窗口只应用冻结产物。首版采用固定参数；逐日自适应若后续引入，须先冻结更新协议，只读取当时已知历史并记录每日状态，不能用整段验证结果重拟合。

认证规则：

- 读取顶层最终结论，包括多重检验校正、时间与覆盖准入；内部原始统计结论仅供解释。
- 发现、验证、留出必须属于同一固定身份与预先声明的角色；不能从任意历史收据里事后挑三段成功窗口。
- 规则内容改变、标签语义改变、失效后重验都创建新验证轮次。旧失败与旧成功保留，但不跨轮拼接晋升。
- 晋升写入幂等且有唯一执行者；并发重复投递同一收据只发生一次状态转移。
- 旧收据缺认证字段时保留为历史观察或需重验，不自动给它补一个“通过”身份；现有方法不静默删除，标记待复核并保留原因。
- 数据修订影响旧样本时，原收据保留并标出受影响范围；新结果按预先声明的重算政策重新认证，不能任选修订前后较好的成绩。

验收：跨版本三成功、最终未通过但内部 supported、失效后一个新成功、事后挑窗、重复并发晋升五种夹具均不得误晋升；验证窗重拟合被拒绝，同一冻结拟合产物用于不同日期的合法快照可通过；同身份完整合法三阶段仍可晋升，避免修成“所有方法都过不了”。

落点：`methodology_backtest/lifecycle.py`、runner/store、`scripts/methodology_backtest.py queue`、经验卡与画像的实际消费门。对应 G-09/G-10/G-13/G-16。

### OPT-05 相关样本、留出隔离与全尝试记账 · P0

设计要求：

- 样本保留 entity、signal_date、事件族、outcome_start/end、stage 与来源身份；统计前不先展平成失去身份的布尔序列。
- 同时报原始样本数、交易日数、事件簇数、跨度和覆盖。每天数百板块增加横截面信息，但不自动等于数百个独立样本。
- 首个估计器采用预先声明的日期块重采样：每次整块携带该段全部实体，保留同日共振与窗口依赖；块长至少覆盖 outcome 的重叠范围，具体参数在发现期选择并冻结。重叠成员/同源事件按声明归组去重。有效块不足时输出 insufficient，不能退回原始二项检验宣布通过。
- Wilson 等独立样本区间可保留为描述性读数；没有独立性依据时不得作为晋升的唯一依据。区间方法、随机种子和依赖处理版本写入收据。
- 按日期切分；按 outcome_end 剔除跨入下个窗口的训练样本（purge，消除跨窗标签泄漏），必要的时间隔离长度在协议中固定。
- 留出集由评估执行者管理，候选生成者不可读取；一旦观察留出结果后调参，该窗口按已使用处理，下一轮需要新的未接触窗口。人工或其他入口已经看过的历史也要登记为已知；访问门不能证明人从未见过公开行情，最终确认优先使用预登记后的新时间段。
- 每次候选、调参、特征挑选、放弃与失败都进入同一实验族尝试账。登记发生在执行前，失败不消失；多重检验校正范围与重复查看策略必须显式声明，不能将无期限探索拆成多个有利小批次。提出次数、取得统计结果的检验次数和基础设施重试次数分列；同输入重试沿用 trial_id，不把日志行数当数学分母。
- 简单同期基准、无该规则的基准及主要阶段失效情况同列。N 达到旧显示门槛只表示允许报告，不等于具备统计力量。

验收：复制同日相关板块不会凭复制次数提升有效独立证据；同一天不被切到两侧；发现窗末尾 T+5 outcome 跨界被剔除，验证特征合法读取过去均线仍可通过；被读取过的留出集不得伪装成新留出；失败候选仍在尝试账；同族多次 run 与一次 scan 不能改变校正范围；固定种子重复统计结果一致。

统计依据：[Petersen 的金融面板相关性研究](https://www.nber.org/papers/w11280)、[Bailey 等的回测过拟合研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。具体估计器仍须用本项目样本验证，引用论文不等于统计门已通过。

### OPT-06 判断目标、情景树与反馈归因 · P1

一条方法先声明：预测/观察哪个事件、作用对象、期限、基准、失效条件与缺口策略。将三类结果分开评估：

| 目标 | 例子 | 不能代替什么 |
|---|---|---|
| 用户价值 | 更省时、能解释依据、能迁移到新案例 | 不能证明规则有效 |
| 判断质量 | 对预先声明事件的区分度、覆盖、拒答与误差 | 不能直接证明可执行交易收益 |
| 决策价值 | 在明确成本与约束下是否改善选择 | 若未来进入交易执行评估，再另立成本、仓位、组合风险合同 |

产品内分别保留 user_judgment、agent_judgment 与用户确认过的 observation_script。喜欢、跳过、同意只影响偏好或候选队列；不能成为行情判断正确的标签。未到期、待同步、不可解析也不算错误预测。

情景树沿用 G-15：条件由注册标签编译，明确节点观察日、到达日与后续回检日；子条件互斥并有 otherwise；由新到事实解析 realized_path。必须区分“某条件发生所以走了这条枝”和“这条枝对后续结果的判断成立”，不能用分枝必然匹配给方法打满分。

方法论评估同时保留支持证据、强反证与替代解释；框架作为候选假设接受检验，不以更像用户的语言作为正确性指标。保留探索用途，但它不能绕过 OPT-04/05 晋升。

验收：晚登记和 hindsight 排除；otherwise 与不可解析分列；世界走哪条枝不直接产生正确标签；回检使用独立到达的后续事实；确认/跳过不改变共享方法；同规则与预先选定的简单基准在同一窗口比较。

## 5. 研究输入与新特征探索

### OPT-07 可重建上下文与事实/假设分型 · P1

复用 G-14 的 context projection（把完整数据选择成模型实际看到的上下文）。持久化有序块、原对象引用、选择理由、预算、省略数量、缺口、时间限制和 projection_hash；只存 hash 而无法重建内容不算完成。

- 模型判断保存 model_id、prompt/config 版本、framework_version、projection_hash、工具定义版本与原始输出。重建模型输入不等于保证再次调用随机模型输出逐字一致；需要复现原答时读取冻结原答。
- 输入对象区分来源事实、确定性派生、模型抽取/叙述、待检验假设。模型散文继续不能直接进入事实标签和统计；将来若要结构化抽取进入计算，走 OPT-09 的验证与版本化入口。
- 判官核查事实与证据身份、时间、单位；对假设核查其被标注为假设及验证条件，不把尚待验证等同虚构事实。
- 事实有局部错误时优先修复绑定或对应事实，不让自由正文的句子形状决定整条推理是否删除。现有逐句修复与前瞻假设豁免保留，改变输出行为需冻结题集和消融对照。
- 主 agent 与子研究都保存各自实际输入；用户看到的投影也有身份，便于区分人和模型的判断依据。

验收：同版本同输入同预算得到同 hash；每个源 gap 都可见；预算截断按对象块进行；缺必要来源或投影无法进入可信判断台账；固定题集中无依据事实被拦，明确标记的可证伪假设仍能表达。

### OPT-08 运行时持久化、恢复与能力矩阵 · P0 失败语义，P1 完整恢复

设计取舍：可信研究默认 durable（关键事件可靠落盘）模式；进度通知的可用性与恢复真源分离。可选临时模式须在开始时显式选择并标注，运行中不能悄悄由 durable 变成“正常完成”。

1. **写入失败**：任何必需事件、状态检查点或结算记录写入失败，立即进入保存失败状态并禁止新派发；已有在途动作尽力取消并保留结果与不确定性。保留内存草稿并向调用方报告保存失败与不可恢复；禁止把该运行作为完整学习样本。进度 sink 失败不承担同样后果。
2. **完成语义**：领域内容完成与恢复记录完整分开；只有终态与必需事件保存成功才声明 durable completion。成本已发生但记录未全时保留不确定性，不能重置预算为零；存储恢复后按原意图核对并补结算，核对前不得恢复为 durable 模式或声明完成。
3. **恢复驱动**：将 ResumePlan 接到实际执行入口，处理未决模型尝试、工具意图、inbox、预算与取消。已确认结算按意图 ID 去重；未确认效果仅在效果侧支持幂等键（重复请求由执行方合并）或工具明确允许安全重放时重试，否则对账或停止。本地意图 ID 不能保证外部效果只发生一次；模型重试可能重复计费，须保留每次尝试。
4. **子研究**：父子关联、委派预算、每次输入、结果与终态均有独立可恢复引用；父任务终止后子任务不能继续使用已撤销额度。父恢复不得重复认领已完成子任务。
5. **取消与唤醒**：首个取消原因保留；取消继续向在途执行传播；inbox 重复投递去重，未确认消息重启后不丢；wakeup 要有真正驱动者而不只留日志。
6. **能力声明**：按产品入口、后端和部署 revision 声明预算、取消、持久化、子树恢复支持程度。拥有循环与租用 CLI 循环分开验收；不以一个后端的通过替全部路径背书。

验收：在意图前、意图后执行前、执行后结果保存前、终态保存前分别注入写盘失败与进程中断；恢复不丢未决消息、不增发预算、不重复已确认效果。用假工具验证未知结果策略，再在授权的隔离环境演练；不得对生产下单或破坏数据来测试。

落点：`runtime/agent_episode.py`、工具批次、`services/episode_store.py`、`episode_restore.py`、`episode_inbox.py`、`runtime/continuous_sub_research.py` 及实际产品入口。接续既有 runtime-base P2/P3/P4，不重开平行运行时。

### OPT-09 新特征与候选规则的受控研究入口 · P2

允许 Agent 提出超出当前标签组合的新特征定义、抽取器或计算代码，正式运行仍使用版本化注册目录。实验可在冻结的局部 `research.*` 特征目录中计算候选，普通问答无法调用，避免“必须先正式注册才能验证”的循环依赖。

候选包包含：要解释的现象、公式/代码、输入字段与单位、可知时间规则、缺口策略、适用范围、替代解释和验证协议。研究环境仅能读取授权的冻结发现集；权限、资源上限和评估器由宿主管理，候选不能改它们。

```text
候选包 → 隔离执行 → 时间泄漏/单位/确定性检查
      → 独立样例或人工标注集核验 → 版本化注册候选
      → OPT-04/05 方法验证 → 通过后供正式框架选择
```

需要拟合的候选特征遵守 OPT-04 的拟合身份与冻结规则。模型抽取器另保存模型、提示词、抽取版本和冻结结果，并针对准确性、跨时期漂移进行验证；验证通过也不能把后来抽取的结果写成系统过去已知。注册一个可计算特征与证明它具有预测价值是两道门。

验收：越权读取留出集/写主库/访问未授权网络被拒；不确定性产物声明冻结语义；单位或时间错误无法注册；未经方法验证的特征不会自动改变正式判断；可合法新增一个特征而无需改通用循环。

## 6. 文档、运维与产品闭环

### OPT-10 产品合同对齐与最小验证闭环 · P1

- 将 09-07 已确认的产品范围同步到统一 spec、词表、输出合同和相关测试。保留证据、概率来源、不荐股等边界；先识别哪些旧词语门已不适用，再局部修改，不按本提案自动删除所有输出门。
- 沿用个人/共享隔离。方法候选生成者不能改变留出访问权限、评估器或共享晋升规则；跨用户共享另走既有人工审阅与来源授权门。
- 先选一条输入已可用的方法、一种实体粒度、一个明确结果事件和一个期限。选择由用户现有方法与真实数据决定，本文不代填投资规则阈值。
- 完成一次「冻结规则与输入 → 历史验证 → 未来判断预登记 → 后续事实到达 → 回检 → 候选/失效状态」闭环。样本不足可完成工程验收，但不能把工程跑通声明为方法有效。
- 待同步的三项保持占位；仅依赖这些来源的扩展延期，盘面规则的最小闭环无需等待全部来源齐全。

验收：同一问题的 UI 与受支持入口使用一致产品范围；原判断不可静默修改；到期、缺数据、跳过、反证与规则失效各有可见状态；用户能从结论回到当时输入及最终收据。

### OPT-11 数据发布、恢复演练与部署证据 · P1

- 继续使用现有单一写入口、staging 与原子发布、冻结快照。读取失败时用明确的旧快照和新鲜度声明，不强行绕锁，也不把旧数据伪装为今日数据。
- 数据质量检查以任务必需字段、日期/实体覆盖、单位与版本为准；检查通过才发布可用快照。保存回滚锚和校验链，定期在隔离目录验证快照恢复与引用可解析。
- 运行时健康、数据就绪、研究正确性三种指标分开。健康端点返回 healthy 不等于六轨已同步，也不等于方法有效。
- 生产验收记录实际加载 revision、代码一致性、依赖版本、后端、数据 manifest 与执行到达的路径。仓库已合入、测试通过和服务已切换分别记录。
- 暂不增加数据库产品或分布式服务。未来出现明确的多进程写入需求时，再评估单写服务、快照读者或服务型存储；本轮的待同步与读取锁本身不构成换库理由。

验收：构造过期数据与正常服务并存，健康不替代数据门；恢复快照后旧实验输入一致；回滚后准确显示旧 revision；每项能力声明有该部署路径的执行证据，未执行的项标未验证。

## 7. 拆分、依赖与完成标准

| 阶段 | 范围 | 交付判据 | 可并行/延期 |
|---|---|---|---|
| A 先保护可信声明 | OPT-01/02、OPT-03 状态门、OPT-04/05、OPT-08 写失败语义 | 已知最小反例转为回归检查；错误输入或收据不能进入 strict/已验证/可恢复状态 | 数据、方法、runtime 三条线可分区并行；不在一张大 PR 混改 |
| B 跑通一个完整闭环 | OPT-06/07/10、OPT-08 恢复、OPT-11 | 一条方法从冻结输入到到期回检，支持重建、失效与恢复，保留基准和未接触窗口 | 依赖 A 对应合同；不等待三项占位源 |
| C 扩大研究上限 | OPT-09、更多实体/轨、完整情景树与类比 | 每个新增入口遵守同一时间、覆盖、评估与权限门 | 三项数据同步由后续明确任务启动，再沿 OPT-03 接入 |

原路线映射：OPT-01/02/03 补强 G-02a/G-02b/G-02c；OPT-04/05 补强 G-09/G-10/G-13/G-16；OPT-06/10 接 G-03/G-15 与个人闭环；OPT-07 接 G-14；OPT-08 接 runtime-base；OPT-09 接 G-16 的扩展；OPT-11 是跨路线发布证据。

整体验收需要同时成立：

1. 旧日期事实不会因未来修订或追加而悄悄变化；当时不可知的信息不能进入该次决策。
2. 每次可信计算均可重建数据、特征、参数、规则和评估协议；模型原答按冻结产物复现。
3. 三项占位如实可见，不产生同步故障误报，也不混入结果样本。
4. 不同方法版本、未通过最终门的收据、失效旧周期与相关样本复制不能伪造晋升。
5. 运行中断、写盘失败和重复投递有明确结算、恢复与样本准入结果。
6. 至少一个实际产品入口完成最小闭环；用户价值、方法有效性和工程正确性分开报告。
