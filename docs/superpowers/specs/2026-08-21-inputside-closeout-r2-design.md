## 总纲

R1 修的是**输出侧**（判官删除权、契约可满足性、回填映射）。本批修**输入侧**：
证据从库到模型的供给链有五个形状（I 调用层暗资产、II 无取证义务、III 瘦管道、
IV 词频绑架、V 索引挤占），加上**预算结构**（79% run deadline_exhausted、67%
主稿归零全靠修复窗）和 W1 的一个显式残余。

原理（为什么输入侧值得一批）：输出侧修得再好，判官只能在**送进来的证据**里
做裁决。R-11/-12 实测：KB 沉淀对发酵/复盘题形贡献为零（通道不通），即使调用
也只送 800 字符词频段。这是 RAG 系统的经典分层——调用决策（planner）、
检索质量（retriever）、送达预算（context builder）三层各自能把上限打穿，
修任何单层都救不了另两层。五形状按这三层分组，验收也按层分开预注册，
避免「送达变大但仍是词频段」这类混杂归因（R-12 预测③）。

## V1 · KB 通道计划引导（调用层，形状 I）

**台账行**：`R-20260821-13`（实施 PR 立案时逐字抄本单验收判据）

**背景**：`resolve_evidence_plan`（`intelligence/services/evidence_capabilities.py:339`）
对发酵/复盘题形只列盘面+新闻 requirement；`kb_search`/`evidence_search` 在
contract 里授权但不进计划 → 模型顺计划零调用（R-11 实测 5/5 案例；全局近 5 日
94 run 仅 26% 调 KB，集中在个股深挖/估值题形）。钙钛矿 chain_mapping 死格
真因=通道不通非库无。

**目标行为**：题形→KB 通道的映射进 evidence_plan。至少覆盖：题材发酵、
题材产业链、复盘（板块归因段）。执行方须先枚举现有题形清单并给出
「哪些题形该含 KB、判据是什么」的小节，经验收方确认后再写映射。

**前置（本单第一步，不得跳过）**：量 KB 检索耗时分布（p50/p95，向量+BM25 分开），
写进验证文档。W4 已证成稿轮预算常态紧张（残值 median 13s），通道打通必须带
预算账：若 p95 会把成稿轮压穿，映射须带预算门槛（与 retrieval-tier plan 分档对齐）。

**验收判据**：
- TDD：发酵题形夹具 → `resolve_evidence_plan` 输出含 KB requirement，先红后绿。
- 重放：R-11 验证文档 §5 的 5 案例，钙钛矿题形 plan 含 KB requirement。
- 变异：删掉题形→KB 映射 → 夹具红。
- live（部署后）：同题形探针 trace 出现 `kb_search`/`evidence_search` 调用；
  KB 有证据题材（如钙钛矿）的 chain_mapping 格有据可写（R-11 预测①逐字）。

**禁区**：不得无条件全题形加 KB（预算账）；不得动 W2 的 satisfiability 逻辑
（缺证降级已由 -08 管，本单只管「有证不取」）；不得绕过 evidence_plan 直接在
prompt 里硬塞「请调 kb_search」。

## V2 · 缺口声明取证义务（调用层，形状 II）

**台账行**：`R-20260821-14`

**背景**：「缺公告级证据」类负面断言在零 KB 查证下做出（减肥药 run 实证——
本次真缺撞对；KB 覆盖好的题材同一行为=假缺）。

**目标行为**：缺口声明二分——「库无」（本轮有 KB 查证记录且未命中）vs
「未查证」（本轮零 KB 调用）。零查证时公开稿文案不得写成断言性「库无/暂无」。

**验收判据**：
- TDD：合成 trace（零 kb 调用 + 缺口声明）→ 文案带「未查证」限定；
  有查证未命中 → 允许「库无」。先红后绿。
- 变异：二分判据删掉（全部当库无）→ 红。
- live：零查证的断言性缺口声明归零（R-11 预测②逐字）。

**依赖**：与 V1 串行同单或紧后（同 evidence_plan/文案邻域）。V2 可先行——
即使通道未打通，文案侧降级为「未查证」已是诚实增益；V1 落地后「未查证」
占比应下降，此消长本身是 V1 的旁证读数。

## V3 · kb_search 送达粗管道（送达层，形状 III）

**台账行**：`R-20260821-15`

**背景**：agent loop 唯一 KB 文本入口 `_kb_search`（`intelligence/services/agent_research.py`）
硬编码 `hits[:5]` + `excerpt[:160]`（送达 800 字符）；同栈 `llm_evidence` 粗管道
（`kb_rag.py` `_matched_llm_evidence`，8000 字符预算）已被 evidence_search/主链
消费而 kb_search 未接。长电案 6 命中送达半个 URL。

**目标行为**：`_kb_search` 送达接 `llm_evidence` 通道，预算与 evidence_search
同规格或按剩余预算分档（对齐 retrieval-tier plan）；`hits[:5]`/`[:160]` 双硬编码
改为可配置且默认值经预算账论证。

**验收判据**：
- TDD：同 query 送达字符数断言（夹具对比新旧规格，先红后绿）。
- 重放：长电案 6 命中重放，送达含正文级信息（不再是半个 URL / 纯路径行）。
- 变异：管道退回 160 截断 → 红。
- live：与 V7 的送达计数读数联动（送达字符数数量级提升；答案 KB 引用密度上升，
  R-12 预测①逐字）。

**禁区（预注册的混杂）**：与 V5 分开验收——R-12 预测③：只修 III 不修 IV，
送达变大但仍是词频段。V3 的验收只看「送达量与结构」，不得拿「答案质量没提升」
否决 V3，也不得拿 V3 的送达量提升冒充 V5 的选段质量改善。

## V4 · 索引卫生（索引层，形状 V）

**台账行**：`R-20260821-16`

**背景**：液冷案 top-5 被 4 个 theme-radar 验收工件页（v5-v7）挤满——测试产物
在知识索引里；另有同族近重复页无折叠。

**目标行为**：① 工件页（验收/测试产物，按路径或 frontmatter 可机械识别）不进
知识索引；② 同族近重复页检索时折叠（同 slug 多版本只出最新）。

**验收判据**：
- 重放：液冷 query 重放，top-5 无工件页。
- 索引审计：工件页在索引条目中为 0（给出审计命令）。
- 变异：排除规则删掉 → 重放红。
- TDD：索引构建入口对工件路径的排除钉，先红后绿。

**独立可并行，成本最低，建议早做**（它直接改善 V3/V5 的验收环境——
挤占消失后送达窗里才有真页可测）。

## V5 · 选段质量（送达层，形状 IV）——后置

**台账行**：`R-20260821-17`（实施时立案）

**背景**：excerpt = query 词最密 chunk = 来源清单/wikilink 堆/路径行
（长电案 6 命中 4 条零信息）。

**分期**：先做低成本版——选段时排除结构噪声段（来源清单、链接堆、frontmatter、
表格行密集段），优先正文段；语义 rerank 版（embedding 相似度选段）另评估，
不在本单。

**验收判据**：长电案重放，4 条零信息 excerpt 变正文段；结构噪声段命中率读数
下降（V7 供数）。TDD：合成页（正文+来源清单）选段落正文，先红后绿。

**后置条件**：等 V3 落地后测残余——粗管道送达变大后，词频绑架的伤害面
可能已缩小，届时按读数决定本单优先级。

## V6 · deadline 预算对照实验（预算结构，R-10 下游）

**台账行**：`R-20260821-18`（实验单，立预测行：三候选谁优是可证伪命题）

**背景**：R-10 已证结构性成立——近 8 日 410 run 中 deadline_exhausted 79%、
carried=0 占全部 run 67% 且全走 repair_reentry；成稿轮残值 median 13s。
修法三候选在案：① 成稿轮 reserve（R-20260816-09 的 60s 讨论）；② carried
门槛（低于阈值不进修复窗直接续写）；③ 修复窗正名二段生成。

**本单产出是实验报告，不是代码改动**。受 `R-20260816-07`（无实测不得抬 T）
约束：实验期不得改生产默认参数，用探针用户 + 影子配置分臂。

**实验设计要求**：
- 分臂：对照（现状）+ 至少候选①；时段交替或用户分流，避免时段混杂
  （R-10 已证无时段聚集，交替即可）。
- 指标（全部已有埋点或 V7 补齐）：model_finish 率、carried>0 率、
  修复窗依赖率、答案长度、judge_status 分布。
- 样本量：每臂 n≥50（基线 79%，检出 15pp 变化的最小可用量）。
- 判据预注册：候选臂 model_finish 率较对照 +15pp 以上且答案长度不降 →
  该候选进实施立项；否则记「未达标」并留读数。

**禁区**：不得在实验结论前改生产 timeout/预算参数；不得只跑 n<50 就下结论。
