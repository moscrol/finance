# 视角确定性信号合同：隔离候选

## 授权与范围

用户在三题待确认页之后指示「你按照最优方案推进」。本轮将其记录为委托 agent 选择审计候选方案，采纳原三题的验收立场，不再要求用户逐项做实现选择；不是用户亲自逐题签署、作者立场认证、批准生产画像或部署。

保留上一轮 `proposal.json` 原字节及 `pending_human_review` 历史标签，通过本文记录后续委托决策，不回填/伪造旧 `user_approval`。原题 SHA256：`6f627694b119109156d3cbdf52fe32382cdd52ec50ee2f3cbcee6e06d456e933`。

本分支采用的标准：

1. 指数稳定、但容量离散与减量博弈：偏风险，不推导普遍性机会。
2. 容量板块分歧后修复，逻辑、逆势表现、主动性同时成立：列入机会观察，后续承接仍需验证，不是追涨指令。
3. 仅凭盘面完成财务审计/造假认定：明确弃权；已核实经营事实仍可作背景。这是使用边界，不伪装作者引文。

原文已在学习语料中，本轮只测保真，不测未见题泛化或真实模型理解。机会合同由 agent 复核来源后设计，尚无独立金融语义审查。

## 选择

原 `_hit_terms` 是字符串片段命中，不是语义理解。它不能自动推导改写题与原规则相同，也会把否定句里的信号当命中。保持未配置规则的既有行为，为被明确选择的规则添加可选 `profile.signal_match_rules`。

- `field`：只允许 `opportunity_preferences` / `risk_triggers`。
- `value_sha256`：绑定该字段中唯一、逐字一致的既有值；值漂移、缺失、重复或合同结构非法时抛错，不退回旧匹配。
- `all_of`：至少两组短语，组内任一、组间全部成立；不自动生成同义词。句内匹配，不跨句拼条件。
- `none_of`：任一反证短语出现即拒绝触发。
- 只用 `facts`，不用问题中的设想补齐事实；假设、传闻、疑问、引语等可识别标记拒绝触发。与候选短语同分句的否定/减弱等信号优先否决，后面出现正向词也不能抵消。
- 绑定规则完全替代旧匹配，不能靠整句原规则或局部词绕过条件。其他规则不变，诚实边界仍优先弃权，`none` 仍不等于 `abstain`。
- 保存前校验绑定；沿用画像列表棘轮防止整表回写静默删合同。字段不进入 LLM patch 白名单，不新增自动审批入口。

这是受控事实摘要的确定性合同，不是通用中文解析器。双重否定、跨句指代、时间先后、多主体同句、隐含条件及未知措辞没有语义保证；保守拒绝会带来漏触发。同句并不证明同一主体，调用者仍需核对事实归属。已配置字段不改变 Workbench 的画像提示内容，也不让该确定性评分成为模型质量判官。

## 被否方案

| 方案 | 决定与理由 |
|---|---|
| 把原题改成画像原句或期望改为 none | 否：消掉问题而非验证能力 |
| 全局扩大二字/分词命中 | 否：不保留前提，否定和弱相关文本也可能触发 |
| 新增模型语义评分 | 本轮不做：需要独立评价、费用和真实入口前置，不能冒充离线检查 |
| 默认给所有画像启用合同 | 否：既有规则没有逐条审查，不改变未配置部分 |
| 立即写入正式画像与考卷 | 否：委托推进不等于扩大原本只读的生产边界 |

## 实现与检查

`perspective_signals` 只负责验证/匹配；`evaluate_role` 让考卷与确定性合议复用同一判定；`_save_profile` 校验合同及删除棘轮。模型请求链不改。

`preview_perspective_exam --match-candidate` 额外核对候选与原题/画像的内容哈希、approved patch 的身份/字段/值/原文引用，深拷贝后加入合同和原拟议边界；原画像、边界单独模拟、合同+边界模拟分栏。不输出私人值、原文或命中原因全文。所有输入结束时复验，正式卷新建/改动也拒绝。

候选为 `docs/verification/2026-09-25-spt-signal-contract/candidate.json`，实现与候选先提交冻结，再跑真实输入。测试覆盖每个必要条件、否定/反向/假设/引用/疑问、跨句拼接、问题污染、旧规则绕过、绑定漂移、源票据变化、原画像不变和考卷边界优先。

即使候选三题通过，预演仍是 `BLOCKED/exit 2`，不能授予正式验收或生产写入资格。整体架构阶段 B、连续稳定性和模型质量仍分别待验。
