# 薄 ReAct 在既有预算内交付答案

父任务 `FINANCEWORKS-5`；预测 `R-20261004-01`（原子领取）。用户已要求按质量收尾规格逐步推进。本次是 F1–F4 准备中的一个独立修复，执行前固定以下边界。

## 问题与目标

R17 原始 `live/RG/thin-result.json` 与 `live/RC/thin-result.json` 都在执行四个工具后继续向模型暴露菜单，第二轮工具意图触发 `tool_budget_exhausted`，最终为空。当前 `ee8f3c48c` 的 `intelligence/eval/thin_react.py` 仍有该行为。目标是让模型知道可用资源，并在既有资源内交付自己撰写的答案；资料不足仍须明确说出。

## 方案取舍

- 采用：每轮公开剩余工具次数、模型轮数和墙钟时间；工具额度为零或进入最后模型轮时，给空工具菜单并说明只能依据已有证据回答、说明缺口。
- 增加工具帽或额外写作轮会改变资源预算，不能用于本修复。
- 自动拼接工具结果成答案会替模型作答，破坏薄循环对照的含义，不能采用。

## 行为合同

1. 每个模型请求末尾带一条独立的资源状态消息。`model_turns_remaining` 包括当前轮；工具剩余次数按已派发次数扣除；秒数来自同一绝对截止。
2. 工具用尽或最后一轮时 `tools=[]`；否则使用原工具列表。最后一轮从已有 `max_turns` 中使用，不增添轮次。
3. 模型仍可任意时刻直接回答。菜单关闭后的越界工具意图继续被现有硬门拒绝；单批超额仍整体拒绝，不截取一部分执行。
4. 保留所有身份准入、工具授权、原生尝试计数、截止检查及首次失败。失败不得写 `completed`，也不生成替代答案。
5. 资源状态及菜单关闭原因随该轮事件留证；`allowed_tools` 继续表示整次实验初始白名单，而非每轮实际菜单。
6. 不改 P、题目/真值/金融语义/工具 schema、默认预算或 2×2 §5–§6。正式实验必须重新冻结 R 的代码/提示哈希，新行为不回写旧 R17/R19 结果。

## 验证与可宣称范围

先在旧实现用遵循菜单的脚本模型复现“工具已用尽、仍获菜单、空答”，再原样复验。补最后一轮、仍有余量、越界工具、错模型和截止边界，运行 thin ReAct 与身份准入相关测试。脚本模型不是质量收益证据；F4 仍须四格真实入口和完整身份/评分，240 次仍受原启动门约束。
