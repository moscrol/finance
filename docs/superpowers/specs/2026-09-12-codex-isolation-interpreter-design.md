# Codex 沙箱探针解释器修复

用户已授权继续质检后的独立清障。原迁移候选 `b2d40776` 冻结不动；本修复从 `gitea/main=6382c13b` 独立准备，不推送、不开 PR、不合并、不切生产。

## 已复现的问题

全量 pytest 把 `.venv-workbench/bin` 放到 PATH 首位，单跑未这样设置。探针以 `shutil.which("python3")` 选沙箱子解释器，前者命中位于仓根的虚拟环境入口。现有沙箱拒绝启动该入口，返回码 71，四项均变成 unexpected_error。原二进制版本 0.153.4；同一候选仅变 PATH，单测 0.45 秒通过 / 0.65 秒失败。证据位于用户运行时目录 `reviews/gate-matrix-b2d40776-qc-ma8n0z52/`。

## 选择与边界

采用当前宿主 `sys.executable` 经 `Path.resolve()` 解开软链后的真实可执行文件。探针只依赖标准库，不需要虚拟环境包。这样选择不受 PATH 影响，也不额外放行整个仓根。该机器真实解释器位于现有只读允许的 Homebrew 目录。

比较过：继续解析 PATH 再解软链仍会随调用者换 Python；硬编码 Homebrew 的 python3 会随全局版本切换；扩大沙箱允许目录则改变了被测边界。以上均不采用。若宿主真实解释器本就不在沙箱允许范围内，继续 fail closed（不能证明就拒绝），不自动扩大权限。

四项安全断言、Codex 路径、超时和网络禁用选项保持现行合同。收据添加带默认值的解释器、返回码和标准输出/错误字段，旧构造调用继续可用；输出截断到 4096 字符供失败定位。proven 仍要求子进程 exit 0 且四项全部 denied。

## 验证与交付

先把真实安装测试参数化为继承 PATH / 虚拟环境前置，观察旧实现的后者失败；补非零退出不得变 proven 与错误输出保留的测试。修复后两种 PATH 及整文件通过，再在迁移与其他清障集成后的最终候选上跑完整门禁。watchdog 未定论，不把它与沙箱合并归因。
