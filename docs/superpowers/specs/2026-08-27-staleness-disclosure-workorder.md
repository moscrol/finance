## 0. 一句话

**站立日可见，落后不可见。** 系统打印「隐式最新交易日：2026-08-25」，
但从不计算「今天距它几个交易日」，也没有任何词面说「未更新」。

根因不是漏了一句话，也**不是**某个 `min()` 写错了——现有那几处 `min()` 对它们各自的
消费者都是对的（PIT 保证）。根因是：**全系统只有「从数据自身派生」这一个日期参照系，
没有第二个以外部日历为参照的信号**，于是「整体停更」这件事在结构上无处可测。

修法因此是**加法**（新增一个日历参照的信号），不是改法（改既有钳制会打穿 PIT，见 §4.0）。

## 2. 根因：只有一个参照系，而它派生自被测物

`intelligence/api/app.py:205-209`：

```python
if snapshot_date and db_date:
    # 快照超前 DuckDB 一天时，用快照日当 floor 会让每条结构化查询 stale。
    # 两边都有日期时取较早的那天——那是供给方真能端上来的上限。
    return min(snapshot_date, db_date)
```

**那条注释是对的——对它要解决的问题而言。** 作为「供给上限」，`min()` 完全正确：
不能承诺端不出来的数据。

问题**不是这个值算错了**，而是**全系统只有这一个日期参照系**，
它对「能端出什么」是权威，对「是否停更」却**结构上无法回答**：

| 职责 | `min()` 是否正确 | 理由 |
|---|---|---|
| 供给上限（能端出什么） | ✅ 正确，**保留** | 不能承诺端不出的数据 |
| 停更检测（是否落后于日历） | ⚠️ **它答不了** | 基准派生自被测物，整体漂移时基准同步漂移；**这不是它的 bug，是缺一个外部参照的第二信号** |

**可迁移的失败形状**：**当检测器的参照系由被检测对象派生时，被测对象整体漂移不会被检出，
而且读数依然自洽。** 这和 08-05 那次「断言粒度比被保护物粗一档」同族，换了个轴——
那次是粒度，这次是**参照系**。两者共同点：**门失效时不报错，报绿。**

### 2.1 这不是假想：`R-20260826-01` 就是这个形状

台账原文根因链：

> `market_snapshot/latest.json` 停 08-24 → `_runtime_market_reference_date`=`min(snapshot, db)`
> 钳到 08-24 → 修复前同题 run 全部 as_of=08-24、**08-25 在 episode 出现 0 次**

两天，**零告警**，靠双臂对照才发现。当时的处置是**补数据**（`sync_market_snapshot.py`）
**加一条流程判据**（daily-full 完成判据须含 market_snapshot 产物）——
**`min()` 这个结构本身没动。**

⚠ **不要把这条读成「预言兑现」**（本单初稿这么写过，是过度连线，已订正）：
那行台账确实预登记过失败形状「postfix run 仍站 08-24（= min() 之外还有第二处钳制）」，
但该行 outcome 是 **`confirmed`**——**那个条件失败从未发生**。
`episode_tools.py:212` 是同形状的另一处 `min()`，**不是**那句预登记所指的东西。
两者的共同点是形状，不是因果。

## 4. P0 · 交付层停更披露

### 4.0 ⛔ 先划红线：**不要改 `_structured_freshness_floor`**

本单初稿把 `episode_tools.py:212` 写成 P0 目标，**那是错的，且会打穿 PIT**。实测它有三个消费者，
全部承重：

| 调用点 | 用途 | 动了会怎样 |
|---|---|---|
| `:327` `_structured_as_of` | 盘面**查询上界** | cutoff=07-21 却取出 08-13 的行（docstring 点名的 C7） |
| `:773` | market reference date | 盘面锚点漂 |
| `:1205` | `_task_authorizes_historical_window` / `_requests_earlier_window` | **历史窗口授权判定**改变 |

它对这三个消费者**都是对的**。它不是一个「装错了参照系的检测器」，
而是一个**被多方消费的 PIT 原语**——错的是「除了它之外没有第二个、以日历为参照的信号」。

**所以 P0 是加法，不是改法。**

### 4.1 做什么

**改动面**：**新增**一个独立的停更信号 + 一个独立的渲染字段（**都不是**既有的
`calendar_disclosure`，也**不复用** `_structured_freshness_floor` 的返回值）。

**量纲必须是交易日，不是自然日。** 周六问「今天市场怎么样」站在周五数据上是**正确**的，
不得披露落后。按自然日算会**每个周末和假期各误报一次**——一个每周固定误报两次的
新鲜度告警，一周内就会被训练成忽略，比不做更糟（「降 severity 把决定权交给下游」的同族）。

**判定放单一事实源**，与休市走同一层（task frame / 服务层），**不要放渲染层**——
渲染层判定就是造第二个事实源。

**文案**：落后 ≥1 个交易日时，形如
`今日（{today}）数据未更新，以下为 {standing_date} 数据（落后 {n} 个交易日）。`
