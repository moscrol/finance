# 回答质量：数据与修订保真

用户已要求接续提高真实回答质量，承接上一轮三处已确认缺口。本轮不把工程通过、卡数或篇幅作为内容收益。

## 范围与设计

1. **数据状态**：`ask_blocks._mainline_context_block_for_llm` 保留涨停计数的未知/真实零/正值。`NULL` 渲染为明确缺失，零仍为零；不借其它表猜补、不改查询窗口或来源。已知为零才可以形成零值事实。
2. **补查修订**：`ContinuousTurnAdapter._resume_for_backfill` 去除句数与质量的等价关系，沿既有结构核验、语义核验、公开交付以及持久化失败路径处理候选。较长稿仍须满足证据和原任务，不新增预算/轮次，不自动给未知断言补依据，不让保存失败成为成功。
3. **检索立场**：`evidence_search` 的支持/线索/反方检索桶标签与每张证据一起送达，不能只依附可能被截断的总观察尾部。立场表示检索方向，不认证独立反证或来源硬度；日期、正文原件身份和现有证据资格保留。使用既有卡片投影，不另造第二套证据台账。

不修金融术语关键词、不代写作者结论、不强制章节，不扩大工具权限、截止或数据写入范围。来源升级和错误全市场排名仍需真实内容核验；这三处修复不能自证已经消除那些错误。时间长河完整接入与自然记忆收益属于下一独立验证，不能在本轮报完成。

## 替代方案与取舍

- 推荐上述三个生产接缝：有真实失败证据，可离线撤保护验证，保持当前循环。
- 仅增加写作提醒：成本小，但无法恢复已经失真的缺值或丢失的标签，也无法让被丢弃的修订交付，因此不用。
- 扩观察字符、追加判官、扩大预算：可能帮个例，但不保身份/语义，并增加成本，因此本轮不用。

## 验收

每处先运行能在旧代码报错的最小确定性回归，再修、再跑邻近真实链路；须包含未知与零的对照、较长有效/无依据/保存失败的对照、长观察末尾反方卡的送达对照。复用冻结首次失败原件，不改题或挑稿。

独立 Spec 后做代码质量复核，全部通过后再执行准确提交的既有完整门禁及 GitHub PR 检查。产品上线须遵守会话既有合并/部署授权与仓库保护规则。真实模型验收固定原问与数据身份、记录真实模型/输入/调用账，保留第一次结果；只签实际样本的变化，不推总体胜率，不以减少篇幅作为改善。
