## 0. 一句话

第一刀收口时的瓶颈是**顶部横盘（承接盘反复）与底部横盘（缩量右底 / 共建主线）在六个指数视角上分不开**——创始人第六段说这两段「和成交占比前三板块主流板块是一体两面的，还有市场的赚钱效应也是相关的」。第二刀先把板块侧能在**市场级**聚合出来的量拿到平台八段上量区分度，有区分度的进八段证据；再往下才是板块级的角色标签与赚钱效应聚类。

## 3. 第三步（已落）：板块级赚钱效应——特征向量与并排聚类

创始人第六、七、十段：「赚钱效应其实就是市场的聚类分析，得有特征值才能分析」「特征聚类应该可以组合，就是要联立分析，不一定要直接锁死答案」。落法：

- 特征表 `history_sector_features(trade_date, sector_ts_code, …)`：`pct_chg`、`amount` 与占比、`diff_ratio`、`limit_up_count / limit_up_ratio / market_share / fd_amount`、`rps_3/5/10`、`dual_red_strict`、`new_high_count`（板块内 1 年以上新高数，经 `fact_stock_high_daily.plate / whitelist_sectors_json` 映射，覆盖待核）。
- 「赚钱效应板块集合」几套并排、都进收据、不锁死：(i) 涨停家数前 10；(ii) 严格双红集合；(iii) 5 日涨幅前 10；(iv) 各特征名次均值前 10；(v) 确定性 k-means 的「最热簇」。差分本身是读数。
- (v) 的落法（`sector_roles.kmeans_hot_cluster`）：每日在板块横截面上取五个特征——`pct_chg`、成交额占比、`limit_up_count`、5 日复合涨幅、`diff_ratio`——各自做当日 z 分；k = 3；初始中心取按综合分（z 分之和）排序后的 1/6、3/6、5/6 分位点；最多 20 轮，同距离归较小簇号；「最热簇」= 综合分均值最高的簇。没有随机数，同一输入永远同一输出（测试锁死：输入行序打乱结果不变；不足 k 行则 NULL，不当作 0）。真库上 `money_effect.kmeans_hot` 集合中位 17–29 个板块（比前四套大），落在前三申万之外的比例八段都在 0.44–0.57，候选规则四态 **not_distinguishable**（下方 0.478 vs 上方 0.443，前 / 后半段 0.38 / 0.57 不一致）——按第三步的初衷这本身是读数：把「热」放宽到一簇，赚钱效应就不再偏向量板块之外了。
- 与市场级 regime（`feat/money-effect-regime-rules` 的四轴，未合 main）联立：先只并排出表，不合并。

### 5.3 第五步结论

题材层能拿到的增量是「承接」这一维（平台自己的命名对象），把承接盘反复从共建主线里再拨出 4 天、把主升判对抬了 4 天；集合更替率 / 集中度 / 价板块家数在八段上没有可用的区分度。承接盘反复 → 左底向下 25 天完全没动，把这 25 天逐日摊开看：全部在周均线下方，其中 10 天是 `cross_below_kind = first`（2025-02-28、06-13、07-31、08-27、09-03、09-18、2026-01-30、05-21、05-27 等），其余是紧跟其后的 1–3 天——即高位横盘里**短促的首次下穿**（最长一段 2025-09-18 → 09-23 共 4 天），平台照旧叫承接盘反复，我们按创始人第五段「左底向下是第一次从周均线下穿」立刻判成 左底向下。差别不在数据而在定义：高位之后一次几天就收回的下穿算不算左底向下、要不要「持续」（创始人第六段给过「持续 = 三天」的尺子，但那是说偏离度走向）——要创始人拍板（骨架 §1.5）。

## 6. 验收

1. 两次全新重建 labels / succession 哈希一致（§1.3 已过；第五步做了三次，见验收记录 §7）。
2. `calibrate-stages` 两次输出逐字相同；参数文件 `stage_bands_derived_from` 现记 `labels_canonical_hash / labels_source_fingerprint / labels_source_max_trade_date`，钉住区间是从哪一次标签构建读出来的——源库在回填，分位数会跟着动。
3. 板块侧各列的缺口按表分别记（`fact_stock_high_daily` 当日缺 → `new_high_1y_count_null`，涨停热度表当日缺 → `limit_*_null`，承接四列窗口不齐 → `limit_premium_*_null`），不出 0。
4. 采纳任何新视角进 `BAND_VIEWS` 前，收据里必须有 `agreement_train / agreement_validate` 两段读数，且验证期不明显变差。
5. 门禁：pytest、ruff、层级 / 路径 / 未读字段 / 数据集注册 / 工具可达。
6. SQL 里的浮点聚合必须与求和顺序无关：`AVG(DOUBLE)` 在并行哈希聚合下顺序随机，第五步两次重建里 `limit_premium_pct` 有两天在 6 位小数的进位边界上翻了（0.6590625 → 0.659062 / 0.659063），连带 succession 的 context JSON 也变。改成 `SUM(CAST(… AS DECIMAL(18,6))) / COUNT(*)`（整数精确求和）后三次重建一致；`price_mean` 同法预防。
