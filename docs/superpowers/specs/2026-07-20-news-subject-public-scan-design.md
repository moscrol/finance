# 新闻主体解析与公共路径扫描修复设计

## 生产证据

新闻冲击 E2E `run_20260720_025842_751960` 暴露两项问题：

- `PublicLeakScanner` 把 `http://...` 中的 `p:/` 当成 Windows 盘符路径，造成
  `public_scan_failed`；产物中没有 `/Users/`、`/home/` 或真实盘符路径。
- `understand_query()` 把“光模块相关消息对产业链和核心公司的影响”解析成主题
  “产业链和核心”，导致闭环检索偏到军工等无关资料。

## 设计

路径扫描只修 Windows 盘符边界：盘符前不得是字母或数字。这样
`https://example.com` 不命中，`C:/Users/name/file` 与
`/Users/name/file` 仍命中；不对 URL 做整体豁免。

新闻主体解析采用显式主题优先：

1. 先匹配句首的“近期/最新 + `<主题>` + 相关消息/新闻/公告/事件”；
2. 命中后以 `<主题>` 为 news-impact subject；
3. 未命中时继续使用既有“事件对 `<目标>` 的影响”规则；
4. 公司锚定逻辑保持不变。

## 验收

- 失败测试证明旧扫描器误报 HTTP URL、旧解析器返回“产业链和核心”；
- 修复后 URL 不报路径泄漏，Unix/Windows 本地路径仍被拦截；
- 目标问题解析为 `news_impact + 光模块`，既有英伟达 GPU、关税、公司公告用例不回归；
- 相关与全量测试通过；
- 重新部署后同一新闻问题通过公共扫描，检索主题为光模块且不引用军工等无关召回；
- 每轮后 RAG worker 保持 ready。
