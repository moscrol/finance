# 自主研究视角反馈：隔离候选

## 目标与范围

来自 K3 明日十只观察候选的逐轮对照：较早的查询选择决定了后续候选视野，末尾核验无法检查从未考虑的方向。用户明确否定用固定股票池或查询清单替代自主研究。

本片复用 PLAN 与连续 Episode 的 research_progress：模型提出视角，工具提供新信息，再由模型修订研究方向。不是预设领域视角分类器，不新增工具、子 Agent、权限或预算。默认关闭 `WORKBENCH_ADAPTIVE_RESEARCH`，仅显式 `on/1/true` 开启候选；生产是否部署看 `/api/health`，仓内实现不等于生产更新。

## 协议

`ResearchPlan.perspectives` 可选，最多 8 项。省略时旧 JSON 投影不增加字段。每项：

| 字段 | 含义 |
| --- | --- |
| perspective_id | 模型自定的稳定标识，最多 64 字符 |
| question | 本视角要回答的问题，最多 300 字符 |
| status | open / supported / contested / blocked / not_relevant，均是模型声明 |
| supporting_evidence | 已见证据 E 序号，最多 8 个 |
| contradicting_evidence | 已见反证 E 序号，最多 8 个 |
| assessment | 当前判断、缺口或不适用理由，最多 300 字符 |
| next_check | 哪种新信息可能改变判断，最多 300 字符 |

supported 至少声明支持引用；contested 至少声明反证；blocked/not_relevant 必须说明理由。**这些结构约束不证明引用正确或判断成立。** 修订沿用现有任务身份与 revision 规则，不得悄悄移除旧视角，可明确标记不相关。8 项是上下文上限，不是覆盖评分或建议凑数目标；探索超过上限的压缩策略本片未实现。

第二轮 live 已输出六视角 PLAN，但 Markdown JSON 代码框被旧解析器拒收；第三轮模型修正引用数组长度后，又因尾部一句「继续取证」被拒收。兼容规则改为用 JSONDecoder 读取首个完整对象（裸 JSON 或 JSON 代码框），可有普通尾部说明；拒绝前置文字、第二个 JSON 值、尾部结构化内容/代码块，不放宽对象字段与权限。这项协议兼容修复同时适用于 off/on；证据数组上限也明确写进动态指令。旧失败样本不改判。

领域层复用既有 E 序号映射检查引用是否在提交时存在。未知引用仅记录诊断，不成为完成准入；后续工具恰好生成同号证据不能追认旧声明。只有新的 PLAN 可以重新引用已有证据。

## 反馈接线

- 动态输入说明自主研究协议；静态系统提示词不变。
- PLAN-only 与 PLAN + tool_calls 两条已有路径均把计划登记到进展账。与工具同轮修订不新增模型往返；纯计划轮仍受原上限约束。
- 第一轮 live 中 K3 两臂均未提交 PLAN。修订后，仅 deep/max 在首批取证后、没有视角计划且研究预算未关闭时，送一次 `adaptive_research_checkpoint` 输入，该次请求不提供工具菜单，明确请求自主 PLAN。它消耗原时间预算及原纯计划轮额度，不扩大总额度；quick/standard、已有视角、已关闭预算均跳过。失败不循环复核，下一轮恢复原研究。它是一次有界研究检查点，不保证模型遵从或视角质量。
- 检查点按既有研究档位触发，不根据题面硬编码复杂度。原留出题的 max 简单事实臂为解释空视角而生成非法字段，实测多次协议拒收。2026-09-21 修订复核输入：已有证据足够的单一事实直接 FINAL_JSON，不必 PLAN；空视角理由仅写在既有 task_summary/open_gaps。不新增分类器，不保证所有简单题零开销。
- 公司比较臂两次修订先后因改名 answer_elements、遗漏 branch_goals 被既有校验拒收。复核改为接收当前已接受的 PLAN，和常规进展反馈共用 `plan_revision_constraints`：最小 revision、原输出项、原分支目标与原视角标识。约束直接派生，不是第二份状态；不删校验、不替模型补计划，也不替模型确定研究方向。
- 每批原始观察后的 `runtime_budget.research_progress.adaptive_research` 带最新模型声明、登记时批次、之后的批次数、未知引用和未决视角标识。
- 该对象经既有 `tool_budget_state.model_content` 持久化，模型可见内容与日志派生内容同源。
- 新证据计数只表示资料增量，不表示视野完整。反馈要求检查遗漏、矛盾和最可能改变结论的信息，然后自主决定是否补查。
- 强制收口仍按原预算执行，不能为填写视角增加轮次。普通直接结束仍由既有 FINAL_JSON / 证据绑定 / 语义核验接收，本片不新增自报式完成闸。

## 取舍与未做

| 方案 | 决定与理由 |
| --- | --- |
| 固定池、固定必须查的表 | 否。把本题分叉固化为未来所有题的研究路径，会违背用户目标 |
| 每批另调一个反思模型 | 否。先用现有下一轮模型请求完成判断，避免重复上下文与预算开销 |
| 每批要求 PLAN-only | 否。与工具同轮提交仍为常规路径。第一轮反证后只对无计划的深度研究加一次有界检查点，接受一次往返代价，须再测收益 |
| 按自报 covered 通过收口 | 否。模型声明不等于证据核验，结构校验不能证明语义覆盖 |
| 强制所有问题写计划 | 否。简单事实题不需要多视角清单 |
| 复用引擎 B 的 ResearchState 作为 A 的新真本 | 否。本轮 A 使用现有 PLAN/进展账，不跨引擎双写状态 |
| 公开缺口和名单一致性 | 本片提供生成纪律，不宣称完成独立校验或修复整个公开投影链 |

## 验证与迭代规则

机制测试覆盖旧协议/开关兼容、边界解析、丢视角、反证保存、先编引用后补证据、同轮修订、纯计划提交、无计划不能被解释为完整、强制收口与事件派生一致性。检查点另验：至多一次、错误 PLAN 不反复触发、已有计划跳过、预算耗尽不重开。

`intelligence/eval/fixtures/adaptive-perspectives.questions.json` 保留开发题与四道原留出题标签。四道原留出题已于 2026-09-20/21 在 `ced8203c` 执行同版本双臂，之后仅可作为回归题，不再算未见样本。`scripts/inspect_adaptive_research.py` 对已完成双臂提取逐轮记录；可显式指定 episode store 归档私有事件流，再生成 SHA-256 清单，不改原 run。该脚本只报活动指标，不自动颁发语义质量分。

真实对照用 `scripts/compare_adaptive_research.py`：同代码、同问题、同模型、同旁车设置，默认 off/on 两臂使用真实 Workbench 会话入口。`--arms on` 仅作单臂机制检查，不构成对照；inspection 对此不填写双臂相同条件结论。隔离用户目录，不覆写旧原件，保存原答与 run 工件；只接受对应 run_id/message_id 的正式完成答案，等待 delivery_pending 清除。凭证只从环境变量读取、临时 BYOK，最终清除并关闭临时服务。

诊断指标：是否提交/修订视角、是否因观察增加或放弃方向、是否发现反证、未知是否被误写成负面、重要缺口是否进入公开答案、工具/模型调用与耗时。计划更长或资料更多不算质量提升。live 数据不冻结、n=1、作者自审，均必须明确披露；不能作为合并或上线许可。

本轮按私有 trace 复现协议失效，再以冻结观察前缀只替换 checkpoint 输入，分别回检修订约束与单一事实交付。这是有界协议实验，不是新版本完整研究重跑或质量证明。原本地风险双臂均调用了联网取数路径，且公开缺口仍有丢失；这些问题未被本片修复，继续阻断上线。后续需另取未见题及重复样本，验实际取证改向、反证约束、材料授权与公开答案。合并与更新 8792 仍需用户确认及既有合入门禁。
