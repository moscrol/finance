# P1b 第二片：根请求锚点与目标解释版本

基线 `fde21a6c1`（第一片代码 pin `c18d6f0fe`）。仅当前独立分支离线开发；不推送、合并、部署或真实模型请求。R17/R19及正式240保持封存。

## 本片边界

先拆开“原请求”“当前目标解释”“自拟研究步骤”三件事，不直接热改 TaskFrame / ResearchTaskContract。根请求在 ResearchRunContext 创建时从初始可信合同固定，保留完整原问题、原 TaskFrame 指纹、全部输出身份及材料边界；后续 repair 执行投影不重算根。内容引用不等于用户/会话认证，也不证明解释正确。旧合同、授权与恢复快照仍精确匹配，不迁移或重签；无解释且根未分离时保持 v1 原形，其余 v2 单独带原根与可选接受态解释。

唯一提案门仍为 PLAN，增加可选 `interpretation`：`request_ref`、`base_revision`、`goal`、`reason`。解释版本与 PLAN revision 分开计数；未提交解释的计划修订不增解释版本。只允许修订目标解释，**不开放题型/主体/时间窗及输出/grounding重装配**；它们依赖后续合同/恢复投影切片，当前未知键拒绝。旧 PLAN 不强制新增字段，无 PLAN 仍可直接答/取证。

## 接纳与消费者

- 单 owner 在 PLAN 接纳点检查根请求引用与最新解释版本，保留已接受解释；过期、越权、坏格式不得派发同包工具。目标解释变更须理由。
- 根请求、义务、工具权限、材料读取上限、信息截止、取消、根预算都不从提案取得。接受解释不调用 factory，不新建预算，不改旧证据条目或覆盖账。
- 接受后的当前解释通过原消息事件送入下一次模型输入；工具请求事件关联其解释版本，不能只有日志字段而模型不可见。终局恢复也须能拿到当前解释而非只读初始目标。
- SDK 必须在 provider 返回与本地工具执行之间接纳 PLAN；已以真实 SDK + 离线模型检验 hook 次序。不能只在 runner 最终返回后解析，工具那时已经执行了。SDK timeout 后同 session repair 保留已接纳解释，但不是新增磁盘恢复执行器。
- 解释提案与工具同包拒绝；repair/deadline flush 关闭新 PLAN 接纳及其同包工具。授权型升档仍由原 governor/ledger 裁决，不由解释提案自行授予。
- 纯 PLAN 续轮使用原总截止/轮次额度，不追加私有无限重试。SDK 若未在本片安全实现，应明确拒收、不宣称支持；完整 HTTP 与语义结构重装配未完成也如实列欠账。

## 验收

先红后绿：根原文精确保留；解释独立递增/继承；跨根与 stale 拒绝；未知授权字段拒绝；混合包先裁决再工具；提示实际可见；同对象预算/截止/合同/证据；保存失败/取消/截止不派发；无 PLAN 与旧 PLAN 控制；旧授权实物不变。相关套件及撤保护反证必须记录原失败与还原检查，数字不移签到后续 SHA。

这是第二片，不是完整 P1b。自然语言目标可能理解错误，根引用只提供可追溯对象；保留义务不是证明全文覆盖。题型/主体/时间窗、旧默认槽退出、完整合同/恢复投影重装配、前端/E2E/独审/真实金融质量继续待办。离线 HTTP 专项已贯通脚本模型修订、真实会话入口、工具和落盘，仅证明接线，不证明自然请求理解质量。新测试/收据归本片，第一片数字不继承。
