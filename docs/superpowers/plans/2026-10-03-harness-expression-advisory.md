# P1b 第三片：跟踪 / 排序方法不再另立完成门

## 目标与范围

用户目标：让弱模型有可用的方法支架，让强模型能选择更好的研究和表达方式；优化不以新增补丁或测试数量为收益。

本片只处理候选树的 Episode 路径：词面命中的跟踪 / 排序模板不得在任务合同之外新增必需输出、触发修复或压低完成状态。沿用前两片的输出来源、冻结根请求、goal 解释、预算及证据边界。不宣称最新主线缺失能力，不搬并行补丁。

## 单一权责

- **任务合同**拥有交付义务；结构核验检查真实绑定及缺项，语义核验检查正文及证据。用户已明确进入合同的要求即使恰好叫 `track_ttl` / `ranking_matrix`，也不能按名字删除或豁免。
- **方法建议**提供跟踪变化、同维度比较、寻找改判证据的思路。Episode 不强制标题、固定表头、默认有效期、四态措辞或机械排序结果；无真实基线不能编造旧结论。
- **模板诊断**只说明旧解析器识别到什么。收据以版本 / advisory 权限和 `missing_template_elements` 区分，旧 `missing_outputs` 键保留为空用于兼容读取，不再冒充任务缺项。可解析模板仍供后续登记使用；未识别不证明语义未交付。
- **真实矛盾及证据缺口**仍处理：期限自相矛盾、伪造引用、被核验删除的断言、用户必需输出缺失，继续走原检查与有界修复。无错误的自由表达不花补写预算。

## 实现方向

删除适配器结构 / 语义 / 公开 / 异常恢复出口的模板缺项合并链，删除由合成槽名决定修复预算类别和附加补写指令的分支。陌生绑定统一走原 unknown-output 拒绝；合同内同名绑定仍合法。保留材料交付的 input-only rewrite，不扩大授权或预算。删除模板链暴露真实核验修订对伪缺项的依赖：纯核验诊断可申请既有 tool-closed delivery grant，无须伪造必需输出；预算层接纳此申请仍受原根余量 / 单轮帽 / 档位限制。补证已包含作者修订，消耗本 Episode 的一次纯交付机会，不能再回落到工具开放的进度授予。

阶段化 `review_feedback` 与事实拒绝策略信号分开传入领域分类：前者可说明被撤销的错误材料缺失声明，不能因此撤销既有 input-only rewrite；完整性拒绝仍不能变成缺项申请。已退休 `expression_slot_binding` 从活动拒绝码表移除，历史事件按原 payload 读取，不重签或重分类。

跟踪与排序的 Episode 提示改为简短可选建议；机械再排序只展示沿用旧箭头假设的参考推演，不要求照抄。旧 CLI ask 的强模板 / 补全段本片不迁移；共享解析与持久化仍保留，不能把本片说成两条引擎全部退出词面约束。

## 成对验证（离线）

1. 真 Episode + 脚本模型 + 适配器：自然段、列表、不同标题、旧标准模板均可交付；不新增修复 / 模型调用 / 工具动作，正文和合同身份保留。
2. 正文经过语义投影后，不重新追加模板义务；真实删除诊断仍进入 repair，并复核新稿。
3. 用户明确要求与旧模板同名的输出：缺绑定仍缺项，提供合法绑定可完成；伪造证据仍拒绝。
4. 无预算与可信旧稿恢复出口不能补造模板缺口；历史任务不叠前向模板、不登记的边界保留。
5. 提示与诊断检查：方法可见而非必填，解析收据不能驱动完成判定。

先红后绿；撤保护恢复旧式强门必须触发行为反例。新代码另定 pin 后跑完整 Python 门禁，不移签 e859 的旧收据。真实弱 / 强模型的质量改善尚待另获授权的对照验证。
