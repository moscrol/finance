# 05 · 把口语、材料和盘感变成研究任务

这活为什么干：用户不必先会写专业提示词，系统能从“这条线不对劲”或一份材料里读出研究对象、矛盾和下一步。保留用户意图 > 主动补足语境 > 少问无效问题。

## 我替领导拍的板

- 第一刀：口语与已有可读材料（粘贴文本/URL/CSV/已有PDF解析结果）。图片/OCR或原始PDF若没有现成能力，明确列第二刀，不先造文档平台。
- 普通缺省先带假设推进；只对会改变对象、日期或核心目标的歧义发一次精简提问。
- 研究模式可随发现修订计划，但不得静默改写用户真正的问题。

## 界限

只改 task_frame.py、query_understanding.py、user_task.py、episode_factory.py的输入上下文装配及其测试；附件存储/上传若需改API，给09接口合同并串行接入。不修改判官准入和runtime预算。已有 fix/task-frame-missing-material-clarify 要先看差量。

## 现状与任务 0

已有不可变TaskFrame、题型/证据策略、缺材料识别和澄清机制；不是新增另一个路由器。核验Workbench真实接受哪些输入，逐项记录“可上传/可解析/能进入模型/支持追问”，没有实测不写全支持。

冻结12个自然问题，包括：模糊盘感、两家公司代称、日期追问、带原文、不给原文、数据表、同词不同题型；最好从历史真实问法抽取。

## 任务

1. 提取对象、时间范围、要解决的判断、用户已有假设、需要的成果；展示一个简短可编辑的理解，研究可同步推进。
2. 盘感翻译为竞争解释与能区分它们的观测变量，例如“龙头不涨是不是退潮”必须区分龙头变化、板块宽度、成交与阶段，不能只改写原话。
3. 已提供的材料自动进入研究上下文，引用材料本身的表头/段落/时间；对“这篇”和后续代词保持同一材料身份。
4. 把用户的方法描述转为“条件→预期→适用环境→反例”的候选框架，调用07已有验证接口；首次提取不宣称已验证方法。
5. 反向验证：只改日期/对象/材料内容，计划应相应变化；保持原题不变只换措辞，目标应一致；材料缺失不得凭标题编原文。

## 完成条件

- 12题中至少10题无需用户改写提示词即可进入正确任务；存在关键歧义的题能一次聚焦澄清，后续沿原任务继续。
- 4组连续追问与至少2种当前支持的材料从默认入口验证，材料内容确被使用；新增第二刀需求另列，不能拿未支持输入冒称完成。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/05.md，换会话先读；需范围外改动记 blocked/05.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/05.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
