## 判官：用户的直觉有代码依据，但要分清损失位置

本轮确定性对照实测两项：

1. 必需输出都已完成，仅多绑定一个扩展输出，整体会变成partial并失去部分发布资格。核心答案还没到语义判官就变成gap。
2. 同一来源家族的新页补齐了一个缺口、支持一个输出，仍被计为零新证据并拒绝继续修复；只把来源家族换掉就放行。

第二项也在当次生产快照的代码中确认，但尚未统计自然对话的发生频率。完整命令、输入与输出见 [判官证据](evidence-judge.md)。

建议按“保留有效部分→针对缺口补搜/计算→局部修正”升级。内容进展和来源独立性分别计算：同源新公告可能有大量新事实，新网站转载旧新闻却可能没有增量。

还有两项待真实验收的接缝：纯语义问题目前可降为issue后直接发布，没有普遍启动补研究；web_fetch提示词按工具名把官方网页也粗归为二手材料。后者由02把发布主体/文档类型传进证据，判官按材料实际内容使用。

不重做：句级修复、部分答案放行、窄范围数值回查、按页索引新鲜度均已有。V11判官引导回检索仍是设计，且旧文的公开标注描述已落后当前代码，应先更新接缝合同。

## Wiki / RAG：优先让知识参与推理与计算

Wiki提供实体、机制、关系、历史与方法；RAG（检索增强生成）负责为当前问题选择适当的原文；计算工具验证数值推导。三者一起回答“这个变化会传导到哪里、谁的差异最大、如何验证”。

本地知识库已有关键词与向量混合检索、章节前缀、邻块读取、一跳关系、agentic多查询模式。建议增量：

- **由片段走回原文**：定向读章节、表头、单位、相邻条件，追到来源全文；解决“找到了却没读到答案”。
- **由实体走到机制**：从需求、成本、客户和产能关系展开研究分支，再检索各条路径的原文；关系图不能直接充当财务兑现。
- **由单点走到横向综合**：实体深读、关系展开、题材综合三种范围按问题选择；比较题给每个对象相同维度。
- **由资料走到方法**：分清思考框架、环境参数和当时判断，框架交给07运行历史检验，结果进入09下一次研究。
- **由存量走到变化**：相关资料更新后局部刷新研究包和计算；老材料的历史价值不因年份旧而消失。

选型建议：先接通已有组件，再比较上下文补充和重排是否有收益，暂不换整套图数据库。Anthropic介绍的上下文检索是在片段前增加能定位该片段的信息；本仓已有标题/章节前缀，真正要实验的是公司、期间、表格上下文是否还丢失。[官方方法](https://www.anthropic.com/engineering/contextual-retrieval)

Microsoft GraphRAG区分围绕实体的局部查询、跨资料的全局查询和逐步展开查询；可借查询范围的分工，先消费已有relations与synthesis，不必重跑一套全库实体抽取。[官方查询概览](https://microsoft.github.io/graphrag/query/overview/)

完整飞轮应当是：

```mermaid
flowchart LR
  A[新数据或用户问题] --> B[识别值得研究的变化]
  B --> C[Wiki原文与关系查询]
  C --> D[取数计算与竞争解释]
  D --> E[排序 情景 验证条件]
  E --> F[真实后续结果]
  F --> G[修正适用条件与下一次查询]
  G --> B
  C --> H[具体数据缺口]
  H --> I[已有采集与入库链补齐]
  I --> D
```

07先把第一条固定方法真正接到日常；08让有价值的问题推动补齐；09让回检结果改变下次研究的查询、工具顺序、案例选择。学习先改善研究策略，不需要等到统计显著才允许使用一个待验证假设；正式宣称方法有效沿现有统计合同。

## 验收与路线取舍

三个可选方向：先换更大模型，容易试但现有材料损失仍在；重写Agent框架，成本高且会重复已有部件；先释放现有能力并补深读/计算/持续研究，能用同题差分逐项判断收益。本次推荐第三个，再用00分离“模型本身不足”和“系统没让它发挥”。

验收以正确且有用的任务成果、计算可用、研究新发现、连续推进为主；时间和费用一并展示。源码存在、相关测试通过、默认入口可达、真实验收、生产已生效逐项报告。历史回放、固定材料对照、真实前向各有各的结论，不能互相替代。
