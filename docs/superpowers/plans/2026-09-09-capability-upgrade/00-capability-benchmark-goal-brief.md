# 00 · 用真实工作衡量能力增长

这活为什么干：让每次升级能回答“用户现在多完成了什么”，并建立和 Knevo 比较的共同尺度。你负责评测，不替建设者改实现。正确完成任务 > 研究增量 > 速度与费用。

## 我替领导拍的板

- 默认（建议）：第一版 30 道真实工作题，20 道可见开发题、10 道由独立验收者保留的换题验收；数值不是已有基线。
- 比较模型能力、系统能力和产品体验分别计分；融资额、工具数量与测试数量不计能力分。
- 没有当前 Knevo 访问或同题数据时，先比较本项目升级前后；旧对比只作失败样本，不宣称赢了竞品。

## 界限

只改 intelligence/eval/ 下本任务新增评测集与结果汇总、docs/verification/ 下本任务文件；运行和产品实现只读。测试题与评分规则在建设者运行前冻结，隐藏题由独立验收者保存，执行者不自行出题再宣布全胜。活跃 agent 的测试服务与工作树不使用。

## 现状与任务 0

读 docs/learning/knevo-distill/ab-ledger.md、E-005-comparison.md、E-006-runtime-retrieval-memory-lifecycle.md、E-008-methodology-source-and-tool-selection-probes.md（后者可能仅主检出有未提交稿，应保留状态说明）。既有对比包含对方自述与有限黑盒实测，不能直接当今天的基线。

先验证 Workbench 测试入口及现有评测脚本；记录代码 revision、模型、数据截止日、工具权限、耗时、费用。给出一个实际可跑的批测命令，不捏造原本不存在的 CLI。

## 任务

1. 题型覆盖盘感翻译、材料理解、财务计算、跨公司比较、产业传导、历史类比、情景更新、反例推翻、跨日续研、方法验证。每题预先定义用户可检查的成果及必需数据；不得拿缺数据的题强逼确定答案。
2. 双层比较：同模型/同数据/同预算比较机制；各自正常产品配置比较用户体验。不能把前者结果冒称完整产品结论。
3. 主表记录任务是否完成、正确且有用的研究点、计算正确性、排序及改变排序的条件、继续一问是否推进。附录记录错误、过度拒答、无效工具调用、时间和费用。
4. 采用匿名配对人工评审，独立模型只辅助；至少20%样本由第二评审复核。胜/平/负、失败题全文、随机重复样本都保留。未来才知道的预测，当前只评推演和条件设计。
5. 反向验证：放入一个文风很好但算错/未完成任务的答案，证明不会因流畅度获胜；恢复后运行正式结果汇总。

## 完成条件

- 30题清单、数据前提和评分规则冻结；升级前基线实际跑通，失败也有记录；每个建设任务能复用同一套比较。
- 输出本项目前后差分；只有存在同题真实竞品样本的范围才报告竞品胜负，样本量与预算条件一并列出。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/00.md，换会话先读；需范围外改动记 blocked/00.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/00.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
