## 2. 设计（沿仓内表达层惯例，零新数据源）

新模块 `intelligence/services/ranking_contract.py`：

1. `parse_ranking_intent`：排序词面（排序/优先级/谁更/哪家最/最受益/补涨顺序…）× 多对象信号（「A、B、C」/「这三家」/「哪家」）双门；排除涨幅排行/成交额前 N 等快事实。`parse_scenario_update_intent`：如果/若 … 排序怎么变/再排序。
2. 契约文本（legacy 与 episode 两版，结构同、证据记号不同）：主判断 → 公司矩阵（固定表头）→ 财务传导 → 竞争解释（≥2 + 区分变量）→ 改判条件表（固定表头，方向用 ↑/↓）→ 历史类比（机制相似 + 不适用）→ 下一步（补关键缺口 / 比较替代解释 / 检验条件）→ 再排序题加新旧对照表。
3. `parse_ranking_artifact`：从答案解析矩阵、改判条件、竞争解释、下一步 → `RankingArtifact`（JSON 原生 payload）。
4. `apply_scenario`：机械再排序——基线序 = 优先级列；命中改判条件行时 ↑ 上移一位、↓ 下移一位（↑↑ 两位），稳定排序；未覆盖变量 → 「排序不变，需补敏感性」。这是 Q6 与反向验证的判据来源。
5. 缺件 → `ranking_*` 合成 id 并入 `missing_outputs`（同 track），`expression_slot_binding` 与修复说明一起认这些 id；收据 `ranking_contract` 写进 episode dump。
6. 改判条件登记 `checkpoints.jsonl`（source=`ranking_flip_condition`，category=改判条件，stocks=受影响公司），`foresight` 渲染开放条目 → 07 回检对象、09 续研输入。
