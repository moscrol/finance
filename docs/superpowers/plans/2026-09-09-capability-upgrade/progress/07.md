## 我替领导拍的板（实现层）

1. **立场是派生的，不存第二份状态**：`flywheel.derive_standing` 只读 protocol / history / capture / recheck
   收据算出「历史演练读数 + 待验对象 + 每次回检分类 + 下次选择」；与 `methodology_backtest.lifecycle`
   同一哲学。106MB 历史原件不在消费路径上读：CLI 每次写完收据刷新一份**按输入指纹命名**的立场摘要
   `standing/<fingerprint>.json`（指纹 = 全部收据文件名的 SHA-256），消费方按目录列表算指纹取摘要，
   指纹不符就报「摘要过期」而不是读大文件。摘要是缓存不是真源，可随时重算。
2. **回检分类六选一 + 环境标记**：`supported` / `method_error` / `data_insufficient` / `environment_change`
   / `no_signal` / `stage_not_applicable`，另有 `execution_deviation` 标记（回检早于到期、信号日漏登记）。
   环境变化 = D+1..D+5 任一日 `market_stage` 离开协议适用集合；这类日子不算方法错也不算支持。
3. **选择梯子（确定性、可解释、非统计结论）**：against = 历史演练两差值为负(0/1) + 前向 method_error 次数；
   for = 历史演练两差值为正(0/1) + 前向 supported 次数。against≥2 且 for=0 → `exclude`；against>for →
   `downgrade`；for>against 且样本≥3 → `adopt`（仅作观察透镜）；其余 `candidate`。当前阶段不在适用集合
   → 直接 `exclude`（环境不适用）。任何档都写明「不出胜率、不构成买卖建议」；统计门仍归 OPT-04/05。
4. **观察登记只在有信号且阶段适用的 D0**：无信号的 capture 保留为「今日无信号」事实，不登记 checkpoint。
   到期回检 supported→hit、method_error→miss；data_insufficient / environment_change →unverifiable
   （带降级披露，不进分母）。`object_type=method_observation` 单列，不进用户判断的命中率。
5. **自然语言 → 方法**只做关键词匹配（双红 + 连续/持续/三日），匹不上的方法文本存 `candidates/<sha>.json`
   （content-addressed，同一 store 纪律），不做通用编译。
6. **`daily` 编排命令**：主库水位 > 旁路水位则重建 labels + outcomes；到点 capture；到期 recheck；刷新摘要。
   只交付命令与文档，不装 launchd（沿原任务授权）。
