# 04 · 范围外改动与阻塞记录

范围合同（`../../04-calculation-artifacts-goal-brief.md`「界限」）列的白名单：计算接线、`market_financials.py` / financial_data 适配、`research_tool_registry.py` 与 `episode_tools.py` 的计算条目、`intelligence/api/artifacts.py` 本类产物适配、对应测试、带本单编号的文档路径。下面每条都是白名单之外、但不改就交不出「可下载产物」的最小改动，逐条说明为什么与改了多少。

## 1. `intelligence/runtime/conversation_orchestrator.py`（+1 import、+2 调用点、+1 方法）

- **为什么**：连续研究的 run 产物只在这里写（answer.md / continuous-episode.json / report.json / followups.json）。「已有 run/artifact 身份复用，不添加平行文件服务」意味着计算产物也必须从这里落盘，别处没有 run_id + RunStore 同时在手的位置。
- **改了什么**：`continuous-episode.json` 落盘之后各加一行 `self._publish_calculation_artifacts(...)`（完成分支与失败分支各一处——失败分支也发，是任务 5「保住其他完成项」）；新增 `_publish_calculation_artifacts`，渲染失败只记 `calculation_artifacts_failed:<exc>` 降级、不动主路径。
- **没改什么**：不改 adapter、不改 `ContinuousTurnResult`、不改 `AgentOutcome`。计算记录走既有 `ToolRunResult.telemetry → tool_result 事件 → private_artifact.events` 数据通路，runtime / harness / batch 三层零改动。

## 2. `intelligence/services/ask_blocks.py`（新增两个函数，原函数行为不变）

- `_financials_block_for_llm` 只回文本块，挂不了结构化观察值。抽出 `_resolve_financials_target` 与新增 `_financials_bundle_for_llm`（块 + 行 + 取数结果同源）；原函数改为调用新的解析器，输出逐字节不变。
- 两个既有测试（`test_episode_tools.py` 里 monkeypatch `_financials_block_for_llm` 的）改为 patch `_financials_bundle_for_llm`：注入接缝随实现移动，断言不变。

## 3. `intelligence/tests/test_capability_amplification_p0.py`（一处断言放宽）

## 5. 验收实例的环境偏离（不是代码改动）

- 机器 16 GB 内存、交换区 28 GB 已用 28 GB（09-09 14:58 实测），生产 8792 的 BGE 常驻 worker 约 4.3 GB。本单的 8794 实例以 `RAG_WORKER_ENABLED=0` + `KB_RAG_PYTHON=/nonexistent/...` 启动：kb_search / evidence_search 立刻失败返回、不加载模型，避免第二个 worker 把生产挤进交换。财务题不依赖知识库，判官对「检索器不可用」按缺口处理；这一点在报告里如实标注，不是「生产同构」。
- 其余环境变量（模型出口 cockpit 57244、判官、工具授权、超时）与生产 launcher 逐字相同；`FORESIGHT_USERS_DIR` / `FORESIGHT_EPISODE_STORE` 指向 `~/.finance-runtime/calc-04/`，不写生产用户目录。

## 6. 尚未做 / 明确不做

- `financial_data` 仍是 `query_scope=episode`：同一轮第二次调用被拒。多公司靠 `subjects` 一次传，「看完第一家再补第二家」做不到；改批次执行器（`episode_tool_batch.py`）不在本单范围。
- UI 无表格阅读器：CSV 投影为 `download`，`.html` 走 legacy_html 沙箱 iframe。原生表格 / 图表视图归 09。
- 跨轮沿用（`inputs_from_calc`）的默认加载器在**当前用户**的 runs 目录里按编号找；多用户部署下 user 与请求 user 可能不一致（生产单用户钉死，不受影响）。要按 run 绑定加载器需从 `app.py → GLMAgentRuntime → ContinuousAgentEpisode` 三层传参，留待需要时再做。
