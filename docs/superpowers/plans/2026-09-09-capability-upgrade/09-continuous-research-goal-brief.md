# 09 · 把聊天变成能跨天推进的研究项目

这活为什么干：同一个题材研究到第二天，系统知道已解决什么、还缺什么、新信息改变了哪里。持续推进与结果变化 > 聊天摘要更长 > 每次重写完整报告。

## 我替领导拍的板

- 优先给已有 workbench-research-journey 负责人接续，runtime-base负责人处理运行恢复，不再造会话/记忆系统。
- 自主跟踪只针对用户已表达关注的研究对象；先在隔离环境验证触发，不在本规划任务中安装监控。
- “猜你想问”按下一步最能解决的问题生成；点击后继承研究状态并真执行。

## 界限

按 /Users/a77/fwp-wt-workbench-research-journey 的现有修改确定UI/API白名单；只改其研究项目展示、已有run store续研接线、followups.py与记忆消费路径的窄接口及测试。runtime持久化沿既有runtime-base合同；07拥有固定协议结果写入，08拥有补数事件；历史案例、反例及其方法状态的保存/检索由历史发现S4原负责人提供。本单只消费上述对象，不双写台账或另造案例库。

## 现状与任务 0

已有用户记忆、followup label/full_prompt、选角器、跨题材剧本及runtime续跑机制。逐项确认当前真正默认可达的能力，未见handoff先读该分支git log和代码，不把旧分支名当已完成产品。

冻结3个研究项目，各有首问、追问、新材料、隔日更新、结果回检；用真实默认入口测试，不复用CLI伪造Workbench会话id。

## 任务

1. 一个研究项目保留用户问题、当前判断、解释分歧、未解问题、已读资料、计算产物和后续触发点；只用现有对象构建视图，不把整段聊天再抄一份。
2. 首次先给可用成果，继续完成深层任务；刷新/恢复后从已完成节点继续。新材料只重跑受影响计算/结论，并解释变化。
3. 下一问卡片至少区分“补关键缺口/比较替代解释/检验条件”；点击继承对象与时间，不能变成三个同义改写问题。
4. 回检结果在下一次研究中改变先验与问题排序，提供一句“上次哪个判断让我这次这样查”；共享研究事实和个人偏好分清。
5. 反向验证：进程中断、用户换题、工具回调重复、新证据推翻旧结论、两个用户同题；状态不串、不丢有效产物。

## 完成条件

- 3个项目各完成至少3轮真实连续研究，至少1轮跨服务恢复，用户不需要重贴背景；新材料和回检结果都产生可见研究差量。
- 三张下一问卡中至少两张实测点击后推进不同未解问题；07/08结果接入后能自动或在用户继续时恢复相关研究，不能仅有静态面板。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/09.md，换会话先读；需范围外改动记 blocked/09.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/09.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
