# 03 · Wiki 成为可联立的产业研究地图

这活为什么干：让库里的公司、概念、机制、报告互相帮助解题，回答一段变化传导到谁、在哪里中断。因果可解释与覆盖完整 > 漂亮大图 > 多建页面。

## 我替领导拍的板

- 先做现有图谱的查询与组合，不新建图数据库；主题综合视图是可再生成的派生材料。
- 三种读取：具体实体深读、关系路径展开、整个题材的横向综合。GraphRAG的local/global思想可参考，已有图谱优先。
- 先选3个资料足够的题材，避开历史发现负责的行情模式挖掘。

## 界限

知识库仓只改 scripts/query_relations.py 的新增查询入口及其下层只读查询模块、skills/lib/rag/ 的综合视图选择/检索模块和测试；新增派生视图置于该仓既有派生索引位置，任务0查实。wiki实体事实和relations大JSON只读，不借研究地图批量改正文。金融侧只提供graph_lookup适配合同，由06唯一接入；知识库包验收通过即可交06集成，不等待06结束才交付。

## 现状与任务 0

本项目已有 graph_lookup、relations、wikilinks一跳、多跳检索、synthesis资料；不是从零做知识图谱。通过索引和query_relations核对概念/公司/证据/题材时间线的真实字段，禁止全量cat relations。

对3个题材各冻结“供需变化→传导环节→公司差异→当前验证点”的问题，标出已有与缺少的边；资料不足的题材换成有材料的对照，但保留缺口记录。

## 任务

1. 输出题材研究包：产业环节、关键变量、公司暴露、支持/限制条件、最近变化、尚缺的信息，每个部分可展开到现有原页。
2. 从需求事件向下追收入/成本/资本开支，从公司向上追共同需求；多路径能并列，关联关系不直接当成已兑现收入。
3. 提供跨公司比较所需的相同维度、报告期和单位，区分已知值/可计算值/未知值；“未找到”不输出0。06/10在金融侧联立04计算结果；知识库不反向依赖金融runtime，也不实现第二套财务计算器。
4. 综合视图随相关源变化重建受影响题材，再次问同题能看见差量；陈旧摘要自动回到原页查证。外部市场实时数据经现有工具挂载，不静态抄死在Wiki。
5. 反向验证：删掉一条关键边/换掉来源日期后，报告对应传导应变化，不能只是缓存原答案；无关页改动不重建全库。

## 完成条件

- 3题材各至少2个真实问题、合计至少6题，在知识库查询包中拿到有来源正文支持的跨实体传导与差异；至少3题较基线多覆盖一个预先定义的关键子问题。此时交付状态为“知识库实现已验、待06集成”，默认Workbench最终验收归06。
- 相关页变更→局部刷新→下次回答变化的完整链路可复跑；没有第二份手工维护的公司事实库。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/03.md，换会话先读；需范围外改动记 blocked/03.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/03.md。本单先通过知识库查询包验收，最终由06经过 Workbench 的真实对话入口完成集成验收；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
