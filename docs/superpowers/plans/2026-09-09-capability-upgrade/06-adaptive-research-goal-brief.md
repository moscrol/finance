# 06 · 让 Agent 根据发现决定下一步研究

这活为什么干：面对复杂问题，系统会补查、试算、比较不同解释，发现方向走不通时换路。完成关键子问题 > 有价值的新增发现 > 固定流程完整。

## 我替领导拍的板

- 优先改既有连续Episode与ResearchPlan；不换Agent框架、不再包一个万能门面。
- 探索允许提出未验证假设并尝试验证，回答时说明它是推断；不因所有结论尚未确定就停止研究。
- 并行只用于相互独立的研究子问题，第一刀最多3支；简单事实题直接取数即可。

## 界限

只改 research_plan.py、research_task_planner.py、generic_research_owner.py、runtime中现有计划/工具调度与停止策略及其测试；本单唯一拥有agent_research.py的graph_lookup适配及对应episode_tools/registry条目，负责03最终Workbench集成验收，在02/04共享接线提交后顺序集成。01拥有continuous_turn_adapter的判官修复区，本单使用其接口；不复制领域准入规则。先核已有run_subagent与runtime-base工作单，运行时恢复由09接续既有工程。

## 现状与任务 0

已有自选工具循环、研究计划与多种planner；存在并不代表当前任务授权到最底层。读取 docs/agent-product-door.md 并确认真实调用链与默认开关。冻结8个复杂问题和4个简单事实题，比较模型真正可见和实际调用的工具。

## 任务

1. 研究状态保存问题、竞争解释、已完成子问题、当前缺口、下一项最有区分力的动作。按预期能解决多少关键问题选工具，而非固定按工具列表跑一圈。
2. 能把02深读、03关系包、04计算串成多步工作；同源的新材料有增量就继续，重复搜索无收获则改查询或换工具。
3. 在真正独立的问题上并行比较，如需求真伪/财务弹性/历史环境；汇总共享结论与分歧，后续只针对分歧补查。不要三个agent回答同一个泛问题再拼文。
4. 研究预算按任务轻重分配，工具可用但实际没授予的情况可见；先用读数定位限制，再调整造成真实失败的局部配置。给用户先呈现已有进展，继续处理剩余部分。
5. 反向验证：一个分支失败、一个工具空结果、材料互相冲突、预算将尽、用户改方向；已有成果不能被整体覆盖成失败模板。

## 完成条件

- 8个复杂题较基线至少多完成2题的预定义关键成果；4个简单题不出现无价值的多Agent调度。
- 真模型事件记录证明确实根据中间结果换过查询/工具或结束无效分支，保留完整成功失败与费用比较，不能只展示PLAN文字。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/06.md，换会话先读；需范围外改动记 blocked/06.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/06.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
