## B2 · `sync_akshare_sw_l1_daily` 对历史窗会把「当前实时快照」写到窗口末日（writer 缺 historical 模式）

- 位置：`market_feature_store/sync/sync_akshare_sw_l1_daily.py` 第 283–299 行：`realtime = _fetch_realtime()` 后无条件
  `records[(end, name)] = 今日实时值`，`end` 是 `_target_dates` 给的窗口末日——为日更设计，历史回补时 `end` 不是今天，
  于是历史日被今天的值覆写，且 realtime 成交额单位（百万→已 /100 转亿）与 hist 不同源。
- 本单处置：属于 daily-full 维护者的 writer，不在本单白名单内，**没有改它**。`data-requests fill` 在隔离库上跑历史窗时
  用 `mock.patch.object(mod, "_fetch_realtime", return_value={})` 关掉实时步（`--no-historical-workaround` 可复现原行为），
  覆盖检查把 `source LIKE '%realtime%'` 落在早于今天的行判为 `invalid`（日期错），不算补齐。
- 建议 writer 维护者：加 `historical: bool` 或按 `end < date.today()` 自动跳过 realtime；顺带处理 `_target_dates` 依赖
  `fact_market_daily` 已有行的问题（历史窗需先由 index-daily 建行）。
- 证据：见 `docs/verification/2026-09-09-data-requests-08.md`「反向验证」一节（排练库上先复现 invalid，再用 workaround 补齐）。
