# 01 · 判官保住有效答案，并指导补研究

这活为什么干：用户已经问到、有材料支持的内容，应当尽量交付；有缺口时系统知道补什么。正确的有用内容保留 > 把缺口补上 > 表达格式。

## 我替领导拍的板

- 默认从两条已复现缺陷和一个补搜接缝做第一刀，不关闭全部判官。
- “信息新增”按解决了什么问题衡量；同一个官方来源的新页面也可能有重大增量。
- 局部标注与补搜预算先用现有配置，只在真实失败证明不够时改变预算分配。

## 界限

只改 intelligence/services/episode_verifier.py、episode_issues.py、episode_semantic_verifier.py、repair_coordinator.py、episode_progress.py 与 intelligence/runtime/continuous_turn_adapter.py 的准入/修复接缝及其测试；不改检索排序、工具权限、数据写入、评测评分。若同文件已有 agent 改动，按函数边界对接已有负责人。

## 现状与任务 0

源码基线 f90af450 的轻量实测发现：①必需输出均完成时，多绑定一个已有证据支持的 extra_analysis，可能 completed→partial 且部分发布失败；②同来源家族新页关闭1个缺口、支持1个输出，仍 new_evidence=0，修复被拒。原始复现见本组 evidence-judge.md。

已有 V8/W5/partial-release、句级修复、回退保护，不重建。V11设计在 docs/superpowers/specs/2026-08-22-v11-judge-guided-retrieval-design.md；不能把设计当已接默认路径。复验派发时最新主干是否已修，再决定剩余差量。

## 任务

1. 将判官失误与检索前丢弃分开记录；对被挡答案回放“候选结果→模型可见→草稿→发布”，标出首个损失点。至少选12个真实失败/边界题，不只跑两个人造例子。
2. 已完成必需输出不因无害扩展研究整体丢失。扩展内容验证后进入扩展区；不合格部分可剥离，既有事实和计算保留。修复后的事实数、用户问题覆盖率都要比较。
3. 修复进展按新增有效证据身份、缺口关闭、输出支持变化判定；家族多样性另记。只换标点/重复同页不应被算进展；同源新页确实解题应允许继续。
4. 把可解决缺口翻译为下一步动作：缺原文就取页、缺季度就取数、缺推导就计算。接续V11，局部补搜→局部改写→发布已完成部分；不强制把每道简单题升级成长研究。
5. 反向验证：独立删除关键支持或替入矛盾数字，证明会要求修复；同时保留其他正确部分。验证判官不可用时不会把“没审到”伪装成“查证通过”。

## 完成条件

- 两个确定性反例均修复；12题冻结样本中可答问题被整体挡回的次数至少减半，有用正确内容保留率不下降，未达目标如实列题。
- Workbench真实对话覆盖扩展分析、同源新证据、局部缺口、无法补齐四类；逐题展示升级前后答案，错误事实数不得增加。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/01.md，换会话先读；需范围外改动记 blocked/01.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/01.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
