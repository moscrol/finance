# 08 · 让研究缺口驱动补数据，补完后继续回答

这活为什么干：重要问题缺一个字段、时间段或公告时，系统能形成补数任务，补完后恢复研究。能解决的研究问题增加 > 数据行数增加 > 覆盖率报表变绿。

## 我替领导拍的板

- 先做3类可由既有来源补齐的具体缺口；不启动全市场无限回填，不采购新源。
- 缺口按“会改变多少正在研究的结论/用户关注程度/是否可补”排序；优先补会影响判断的。
- 已知L2、晚间卖方、晨汇占位不自动改成同步失败；既有用户决定仍按09-08规格处理。

## 界限

只改现有research/KB ingest queue编排、增量完成事件与恢复研究接线及测试；来源状态/字段可用性由OPT-03原负责人定义，本单消费，不重建状态门。生产事实写入仍由daily-full维护者执行。先读 docs/learning/ledger-map.md 和 docs/knowledge-backfill-rules.md，定位唯一写入者，不另建队列/台账。OPT-11及已有数据洞工作由原负责人接续。

## 现状与任务 0

已有daily-full、research-queue、kb-ingest-queue和回填流程。先核 /Users/a77/fwp-wt-data-holes、fwp-wt-broad-index、fwp-wt-fill-gate 的最新状态及现有工作单，找三个未被接手的具体断点。分析只读canonical事实表，不手工SQL直写生产。

## 任务

1. 回答中的缺口生成结构化请求：需要的对象/指标/时间、受影响子问题、已有来源尝试、完成后续做什么；合并重复缺口并保留消费者列表。
2. 从已有合法来源自动取回/解析可补部分，先在隔离staging验证日期、值和单位；需要人工条件的请求显示真正缺什么，避免每天盲重试。
3. 原维护链完成写入或索引更新后，发出包含数据/索引版本、已满足依赖及影响范围的完成结果；07/09据此重算受影响结论并恢复研究，而不是让用户重新问整题。
4. 优先级由实际问题与新增结果反馈更新：长期无人使用的数据降优先；能解开多个问题的字段升优先。
5. 反向验证：有行但关键值全空、日期错误、部分回填、来源失败、重复完成信号；只恢复满足条件的消费者，重放不产生重复副作用。

## 完成条件

- 3个真实缺口在隔离链完成“问题→请求→补齐→恢复研究”，每个都新增一个原本答不了的子问题；证据是前后回答差量，不仅是行数。
- 至少一个请求被两个研究任务复用，完成信号可重放且只更新一次；生产回填未执行则明确只完成隔离验收，不能写已修生产数据。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/08.md，换会话先读；需范围外改动记 blocked/08.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/08.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
