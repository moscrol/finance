# 02 · 检索找到材料后，继续读到能解题

这活为什么干：用户问的是答案，系统应从命中页继续找到关键原文、表格和关联条件。可用材料进入答案 > 单次召回分数 > 省一次工具调用。

## 我替领导拍的板

- 第一刀优先“检索→定向开页→补上下文→缺口驱动再搜”；不更换向量数据库或全库重嵌。
- RAG（检索增强生成）已有关键词与向量混合、多跳、反方检索；此单提升其实际解题率。
- 老资料可以回答历史与稳定知识；索引是否对应当前文件、事实适用哪天是两个问题。默认自动检查/恢复，不把所有stale直接当当前事实使用。

## 界限

金融侧只改 kb_rag.py、agent_research.py 中KB检索/取页及web_fetch的只读函数与来源metadata、closed_loop_retrieval.py、hop_retrieval.py、kb_slot_rerank.py、episode_tools.py的本工具接线及对应测试。知识库侧只对照现有 skills/lib/rag/，若必须更改页读取接口，提供独立窄补丁并与03按顺序集成。research_tool_registry.py的本任务工具条目与来源描述只在04尚未开工时修改；04从本单集成后基线开始。

## 现状与任务 0

读 knowledge-base-private/skills/lib/rag/README.md。现有切块已有标题/标签/章节前缀、邻块读取、一跳关系；rerank（二次重排）曾在本地干净索引的历史评测下降，不全局强开。page_freshness已修过“一页变全库失效”，先核生产版本是否吃到。

核对现有 kb_search、evidence_lookup 是否已经能定向取得任意所需段落，若能就接通调用而不添加同功能新工具。冻结20题及正确原文位置，记录候选召回、进入上下文、最终使用三段损耗。

## 任务

1. 深读工具输入候选页/章节/所缺信息，返回命中原文、必要相邻段和表头单位；支持从结构页追到来源全文。重用原始chunk，补充上下文不覆盖原文。
2. 查询按任务选择材料：概念/方法/历史/当前事实分别选时间与文档范围；跨实体比较必须保留各对象材料，反方与约束条件有空间，避免同一篇占满上下文。
3. 新鲜度失败可重读相应原页或重查有效快照；更新恢复走现有索引服务，不要求用户先学git。无法恢复时仍给可用部分与具体缺口。明确旧年报适用的报告期；web_fetch材料按真实发布主体和文档类型分类，不能仅因取页工具名就把官方原文归为二手。
4. 缺信息再查的查询词来自已读材料和缺口；停止条件是已有信息足够回答或再查无增量，不固定所有题都窄/宽/反跑满。
5. 反向验证：答案藏在章节末端、表头在相邻块、别名与股票代码混用、无关页变更、目标页改变、历史资料与最新资料冲突、官方原文与转载同文不同发布者，各留独立用例。

## 完成条件

- 20题中关键原文进入模型上下文且被正确用于回答的成功数较基线增加至少4题；若基线已≥18题，则剩余失败至少修好1题且不退步。
- 默认Workbench可自动完成深读与补搜，呈现完整失败表与耗时/费用；不能只提高离线命中率或用增加巨大上下文达标。

## 全局与执行约定

本组目标是提高真实研究任务的完成度：读懂问题、找到材料、完成计算、形成判断、延续研究。编号与依赖见同目录 INDEX.md。该文件是本任务的范围合同，仓库 AGENTS.md 仍适用。

每张单从派发时最新 gitea/main 的独立工作树开始；涉及已有分支先读其交接并比较差量，不重复实现。进度写本组目录 progress/02.md，换会话先读；需范围外改动记 blocked/02.md，继续范围内工作。只提交本单白名单实现文件、对应测试和带本单编号的文档路径，不合 main、不切生产。本文数值均为建议验收目标，当前未测的基线必须在任务 0 采样，不能写成既有成绩。

先核验真实命令与测试入口，冻结输入、判卷点和基线，再实现；新验收脚本的实际命令及返回码写入 progress/02.md。最终必须经过 Workbench 的真实对话入口；纯函数、假模型测试可定位问题，不能替代真实用户验收。模型与数据访问按现有配置，不购买服务、不新增外部消息发送。测试按仓规使用主树 .venv-workbench 解释器。

不得以删测试、放宽题目、隐藏失败、固定答案或只展示成功样本达标。相同实验三轮无改善时交差分与阻塞原因，停止该方案继续独立子项；这算有结论的探索，不能标能力已完成。每张单最终报告“已实现 / 已进默认入口 / 真实验收 / 生产生效”四项。
