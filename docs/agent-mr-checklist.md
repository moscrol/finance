## 二、逐条对照

| 子项 | 现状 | 缺口 / 下一步 |
|------|------|------|
| 行情数据落库 | ✅ DuckDB `market_feature_store`，28 表、个股日线 182 万条 | — |
| 各模态时间戳 | 🟡 盘面数据按交易日存；研报/纪要有来源页但**「可得时间 vs 发布时间」未强制区分** | 来源页 frontmatter 增加 `publish_time` 与 `available_time` 两个字段并强校验 |
| 股票池规则 | 🟡 有自选股 / 强势股库，但**池的纳入/剔除规则未文档化** | 写明每个池的构建规则与更新频率 |

**研究员阶段结论**：数据「量」够，但「时间戳治理 + 池规则 + 幸存者」这三块是 PIT（point-in-time）地基，必须补。这是文章最强调、也是你升级操盘手前绝不能含糊的一块。

### MR-2 时间一致划分 / walk-forward / 防泄露 —— 🟡 待加固
| 子项 | 现状 | 缺口 / 下一步 |
|------|------|------|
| 题材发酵回溯按时间轴对齐 | ✅ `theme-fermentation-tracer` 把消息面×盘面按日期对齐 | — |

**研究员阶段结论**：现在主要做「解读/复盘」，泄露风险中等；但「题材怎么发酵」这类回溯**最容易把后视信息当成事前判断**——要在回溯报告里显式标注每个结论用的是哪天可得的信息。

| 子项 | 现状 |
|------|------|
| 输出形态 | 当前输出是**带出处的分析/建议**，不输出可交易动作（符合研究员定位） |

## 三、研究员阶段的「地基加固清单」（按优先级）

> 只列研究员阶段就该做、且能直接为将来操盘手铺路的事。操盘手专属的 MR-3/MR-4 暂缓。

1. **【MR-1】时间戳治理**：来源页强制区分「发布时间 / 可得时间」，盘面与文本统一 PIT 口径。← 最高优先，承重墙。
2. **【MR-5】记忆/回填时间禁运检查**：禁止把晚于可得时间的信息回填到更早日期。
3. **【MR-2】PIT 截断**：分析/回溯脚本加「只用决策时点及以前信息」开关，回溯报告标注每个结论的信息可得日。
4. **【MR-6】复现三件套**：数据快照标签 + 模型/prompt 版本记录 + 关键日志追加式防改写。
5. **【MR-1】池规则 + 幸存者**：文档化股票池构建规则，标注历史回溯是否含退市标的。
6. **【MR-7】权限矩阵**：给每个模块写明「可读范围 / 可写目标」。
7. **【MR-3 预留】结构化建议 schema**：把「自然语言观点」逐步转成「建议字段（标的/方向/时点/理由/证据ID）」，零成本为升级铺路。

## 四、一句话定位

> 你的 agent 现在是**有纪律的研究员**：证据分层、硬事实门控、留痕、采访门控、完成闸门——这些恰好是文章最看重的「市场工程纪律」雏形。
> 距离操盘手的差距集中在**执行层（MR-3/4）**和**复现性深度（MR-6 的版本化/不可变日志）**。
> 按上面 7 步把地基夯实，等「只读研究员」这层被验证得足够可靠，再逐级往「假设生成 → 研究执行 → 组合建议 → 受约束执行」推进——这正是文章建议的稳健路径，也是你说的「地基稳了才做操盘手」。
