## F1 · P1：弱排版信号直接冻结，会把用户的真实禁令“确定地判错”

**位置：设计稿 43–54、63–72 行，尤其 48 行。**

规则把任意 `缩进 ≥2 空格行` 冻结为材料，失败分支为 `—`；冻结后不再参与指令识别。`no_constraint_confirmed` 的新增条件只能挡住“未分类”，挡不住“错误地分类为保护范围”。

最小反例（用于设计推演，不是 v7 运行结果）：

```text
请分析这个案例：
  请只依据本条消息给定材料，不读取任何材料外数据。

甲公司总收入20，相关业务收入2。

1. 相关业务占比多少？
2. 这个比例能说明什么？
```

按表逐步执行：第二行被缩进规则保护 → 指令扫描看不见唯一禁令 → 剩余材料/题组都能分配角色 → 没有未闭合、没有相邻疑禁令 → 允许 `no_constraint_confirmed → real×full`。这不满足本稿“真禁令不丢”的安全目标。

**修订要求：** 区分强边界（显式引用/围栏且边界完整）与弱材料候选（仅缩进/长度等启发式）。弱候选内若有可能是用户自己的约束，不能仅因排版就视为已确认材料；需可验证的材料归属依据，否则 `boundary_uncertain`。明确构造重叠时强边界优先，不允许通过扫强保护块内部命令解决弱候选误吞——那会重开材料注入问题。长文的“阈值/短问句”也应绑定明确常量/谓词，而不是交实现者临场定义。

**补验收：** 上述两空格禁令变体必须澄清或 material_only，不能 full；对照样本把同一句放进明确引用材料则不得升级为用户指令。两者要同时成立。

## F2 · P1：候选必须是“完整状态解释”，不能把疑似片段的局部交集当最终授权

**位置：设计稿 87–94 行；合成关系另见 67–72、104–106、143–154 行；风险断言见 201 行。**

v7 固定候选 `{按材料→allow(full), 按指令→allow(该约束值)}`，D4 又直接消费这个交集为最终能力集合。它未定义与同消息已确认限制、续轮继承限制、多处疑似约束的合成顺序。

最小反例：

```text
请只依据给定材料回答。

「甲公司总收入20，相关业务收入2。」
不要联网。

1. 相关业务占比多少？
2. 这个比例能说明什么？
```

- 第一行已确认 `material_only`。
- 明确材料块后紧接“不要联网”，按 D1 相邻规则是 `boundary_uncertain`。
- 对疑似片段单独按 D2 求交：`allow(full) ∩ allow(local_only) = allow(local_only)`，会重新允许本地材料外数据。
- 完整解释的两个候选其实都必须保留第一行：`∅ ∩ full = ∅`、`∅ ∩ local_only = ∅`；最终仍为 material_only。

续轮同样存在：继承 `B_base=material_only` 时，“片段按材料”应当是**不改变基底**，不是重置 full。“按指令”也不能把含糊的“不要联网”当作明确取消原来的仅材料限制。

**修订要求：** 先解析可信基底、已确认约束及真正显式的覆盖，再为每种歧义解释求完整允许集；最后求这些完整集合的交。每片段仍可保持二元检测，不需要引入任意候选生成器。无明确放宽时可表达为：

```text
P_known = 已确认/继承约束施加后的允许集
片段按材料候选 = P_known
片段按约束候选 = P_known ∩ allow(约束)
P_final = 所有完整候选允许集的交
```

明确取消旧限制可以扩大 `P_known`，但含糊片段不能充当这种授权。多处约束还需确定合成与冲突规则。D1 应明确“不确定优先于有约束确认”，而确认无新增约束只能表示 no-op，不能越过 D7 抹掉续轮状态。

同理，`state_unavailable` 若无法证明完整候选，走已经认可的澄清出口即可，不必为本阶段硬补猜测模型。风险节的“交集数学保证只可能偏窄”应加前提：**真实解释未被候选生成遗漏，且候选保留已有授权边界**。交集只保证不超过它收到的候选集合。

**补验收：** 同消息 material_only + 疑似 local_only、继承 material_only + 疑似 local_only、多个疑似片段、单纯“继续”无新限制、明确放宽的正向对照。前两者不得重新放行本地读取。
