## 决策对比

| 方案 | 评价 | 决定 |
|---|---|---|
| 独立候选账＋原准入不变 | 内容存在、可公开、核验通过、任务完成可以分别判断 | 采用 |
| 直接接受格式错误/历史缺口 | 会把保稿误当完成，可能掩盖证据身份错 | 否决 |
| 只撤短稿提示 | 有助表达，但不能修拒收后的覆盖及恢复失忆 | 仅作一部分 |
| 先换SDK/模型或扩大预算 | 共享harness政策仍会随执行壳迁移，同时改变变量难归因 | 暂不做 |
| 模糊diff压缩旧稿 | 容易删限定语或把新证据套到旧E号 | 否决；精确追加 |
| 统一把全部证据无限塞回去 | 有无关内容成本，且不改变provider上下文容量 | 否决；完整必要卡＋紧凑无关兜底 |
| 给SDK/恢复另建隐藏重试池 | 绕过根预算，延迟和费用失控 | 否决；沿原额度与RepairGoal |
| 从任意持久model_turn猜稿恢复 | 可能把工具请求/外任务/未认证信封当研究成果 | 本片不做跨进程恢复；需另立明确状态合同 |
