# Harness release scope snapshot — 2026-10-02

## 背景与发现顺序

本轮目标是把近期优化收口到用户给定的四条原则：改善信息/证据/状态反馈，保留模型的任务与工具决策，把预算、权限、证据身份留作硬契约，并用未参与调试的题目和强弱模型检验迁移收益。

先审了本地 19 个补丁和新分支 `feat/tool-usage-differential-p0-0929`。审查发现工程性改进（身份、授权、预算、协议、错误反馈）可迁移；第 20 号按弱/强模型分档的硬语义策略、按坏例扩张的金融路由，以及数字字段候选没有足够的留出证据。工具差分分支的离线回放虽一致，但原始 manifest/元数据覆盖不完整，公共 cohort 还带用户目录标识，不适合直接发布。

随后在集成树按顺序合入 PR8、PR10、PR11–14、PR15，冲突保留双方的运行契约和收据语义。PR14 的 evidence_read 保持默认关闭、显式能力授权；复现时发现分支回灌会把已展示正文再计为新阅读量，应修记账而不是把补读变成强制流程。

最后检查生产数据：服务代码仍是干净 detached 版本，10/1 快照把可用的 9/30 内容错标为最新。用交易日表核对后，在隔离目录生成正确历史快照，并以原子顺序修复派生小 JSON；receipt 证明 DB 未变、readiness=200。此动作只修数据状态，不能代替代码发布。

## 方案取舍

| 方案 | 评价 | 结果 |
|---|---|---|
| 继续堆金融词/公司名硬路由 | 已知坏例可能变好，模型解释权和迁移性变差 | 否 |
| 20 号弱模型硬路由、强模型放松 | gate 可被空强侧/已知题通过，不能证明目标 | 否 |
| 保留协议、证据身份、预算、错误反馈改进 | 约束可审计且不规定市场推理路径 | 选 |
| evidence_read 固定逐句核验 | 会把可选工具变成重流程，且已见覆盖记账 bug | 否；修覆盖后仍让模型选择 |
| 休市日继续请求 AkShare | 会把旧内容伪装成当天新数据 | 否；实现交易日三态保护 |
| 直接把快照修复当部署 | 派生数据和代码版本混淆 | 否；单列运维收据 |
