## 决策与被否方案

| 方案 | 评价 | 结果 |
|---|---|---|
| 把实际渲染字段纳入既有精简要求 | 换载体不应丢掉约束，但完整义务优先 | 已做，仅提示，不加接收门槛 |
| 降max_tokens、硬截断或限制claim数量 | 可能让JSON或子问不完整，改变交付合同 | 不做 |
| 相同绑定按ID引用，测试逆变换 | 减少重复输入且可逐字段核对 | 已做，原审计对象保留 |
| 模糊相似合并、跨句共享锚点 | 抹掉输入归属或来源差异 | 不做；不一致仍发送原副本 |
| 加预算、加重试、去掉非事实复核 | 会把新合同假装成原验收 | 不做 |
| 假钟驱动逻辑计时，保留真实慢流测试 | 剥离机器调度，不放宽预算不变量 | 已做，仅两项测试 |
| 单次完整报告即宣布修复 | 报告未通过，原入口仍未交稿 | 不采纳 |
