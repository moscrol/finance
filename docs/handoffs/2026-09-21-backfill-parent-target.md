# 302132 父命令目标参数拒收

## 背景与发现

承接 `2026-09-21-backfill-main-ready.md`。前向四文件候选 `400d02dd` 通过旧代码全量，但继续作者复核发现：CLI parser 接受 `--db`，父路径却始终由 `MARKET_FEATURE_STORE_DB` 解析目标。操作者显式给副本路径，不等于父流程真会使用副本。这是目标绑定风险，旧全量通过不能排除未覆盖的输入边界。

代码 `49f32259ea5aab495ae928e63e73c453cd31fae4` 只在 `args.db is not None and not args.child` 时早返回2，早于parquet检查、收据探针与父编排；内部child显式目标合同不变。没有读写真实生产库。

## 方案与理由

- 采用拒收父路径的显式 `--db`，保留既有环境目标合同；不扩大受控写入接口。
- 否决静默忽略参数：操作者意图和真实目标不同是危险状态，不应被help小字掩盖。
- 本轮不新增父编排数据库路径参数或另开直写入口；那会扩大共享发布层改动，需要另行合同与覆盖。
- 只改302132入口，不宣称所有修复命令的目标参数都已审过。
