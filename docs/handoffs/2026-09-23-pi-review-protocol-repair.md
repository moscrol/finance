# 2026-09-23 PR #868 审查工具协议修复

## 背景

用户要求修复，不是重启审查。1830 批 GLM 准入同一响应同时提出 read/write，写入参数在读结果返回前已生成，错误副本无法被 create-only 工具覆盖。随后发现正式阶段 CLI 名单没有 `deliver_stage`。旧批次维持 `BLOCKED_GATEWAY_TOOL_ROUNDTRIP`，失败证据不可修改。

## 发现与决定

1. 核对 pi SDK：注册工具不等于进入 CLI 允许集合。新增配置化阶段名单和真实 session_start 菜单检查，不再仅直接调用工具函数测试。
2. 读取官方事件合同，使用 message_end 在执行工具前检查整批调用；成功 tool_result 才推进下一轮菜单。记录本轮发出时的状态，不能靠同批工具顺序执行满足依赖。
3. 用真实 pi CLI 接脚本化本地假服务，既覆盖 SDK 过滤和事件顺序，又不读取 Keychain、不消耗真实模型额度。
4. 控制器反例揭露请求计数钩子顺序问题：SDK 对未注册的同批工具报错后可能尝试下一轮，先记账再拒绝会多算。把状态机放在记账前，保留拒绝原因；外发数与假服务接收数重新一致。
5. 提交代码为 `324a76f9a`，再于干净树复验。未提交版本的通过收据只属开发读数，不能移签固定提交。

| 方案 | 决定与理由 |

| 真模型验证接线 | 本轮不选；确定性本地假服务足以覆盖 CLI 合同，真实服务端兼容性留给另行授权的准入。 |
