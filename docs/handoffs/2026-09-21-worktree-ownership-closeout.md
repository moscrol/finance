## 背景

用户要求检查未收口工作，先核是否已有 agent 推进，再接手无人推进的有效增量。主检出处于 detached HEAD 且有大量他人改动；目录数、cherry+数与实际任务数不是同一个分母。本轮使用独立协调树 `ops/worktree-ownership-closeout-0921`，基准 `728f3271`，没有修改主检出或原脏树。

完整历史采样和逐线依据在 `docs/verification/2026-09-21-worktree-ownership/`。它是有时间边界的证据，不替代下次重新运行看板。

## 按发现顺序

1. 交叉检查注册表、handoff、PR、部署账本、进程 cwd 与近期会话，观察到财务前提/行情、研究保稿、自适应修订、求证、同花顺研究数据及旧补丁收尾六条近期推进线。没有接管这些现场；相关旧枝也不直接宣称已吸收。
2. 旧看板把失效目录跳过、查询失败当零值，并允许文档脏树进入可拆候选。修复后采样可见 18 条异常。继续审查发现 porcelain 前导空格被 strip 破坏、子目录会借父仓事实，以及长扫描的 main 基准可能漂移，均补进原工具及测试。
3. 核实部分旧线已有接替实现：技术日报/监管查询、旧看板、G-04、judge 校准及指令/钩子。保留具体提交指针，不再整枝重放。`git cherry` 不识别语义重写或部分吸收，因此正号只是调查线索。
4. 复盘会 `c06a66f3` 的三个核心源码在 main 仍等于其父版本，不能称已吸收。但旧补丁会冲突当前指令与 nightly 配置，且批量熔断传播仍需离线审核。保留远端分支，未解除停抓、未访问服务。

## 方案取舍

| 问题 | 采用 | 被否方案与原因 |
|---|---|---|
| 活跃归属 | 多源交叉核验，标明只是近期采样 | 进程存在即有人推进，会把遗留预览当作者 |
| 失效记录 | 未知单列，保留元数据 | 查询失败按零/干净，会制造错误清理建议 |
| 旧补丁 | 查接替源码和提交，按功能线登记 | cherry+全合，会重放已改写的旧逻辑 |
| 回填接管 | 当前main独立候选与新收据 | 原枝旧绿直接签新组合，不证明兼容 |
| 清理 | 原件全留，后续逐树另验授权 | 按干净数量批量删，忽略Git外数据及reflog |
| 通用沉淀 | 修原工具、补既有知识笔记 | 再建平行看板或覆盖harness脏BUILD.md，增加漂移/争用 |

## 结论的边界

本轮完成的是归属盘点、看板安全修复、回填前向整合与必要保全，不是所有旧功能的业务验收。活跃任务未重复实施；五条未决登记保留。所有新增 PR 均需继续验收，未自动合 main，也未部署、生产回填、改定时任务或删树。
