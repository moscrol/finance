## P1-1：Git status 执行失败被解释成干净树，完整门禁误放行

定位：`scripts/reconcile_hithink_gate.py:61-62,122-129`，尤其 125-126。

`git()` 没有 `check=True`，调用方只读 stdout 不核 returncode。`git status --porcelain` 因索引损坏/不可读等原因退出非零时，stdout 可为空，当前逻辑把它当作 clean 并继续跑修复。

真实复现：

```text
actual_status = ?? review-only-dirty-marker.txt
git status rc = 128
stdout = ""
stderr = fatal: .../corrupt-index: index file smaller than expected
gate verdict = PASS; gate exit = 0; checks = 22; tree_clean = true
```

证据：`git-index-results.json` + `git-index-replay.json`。这是检查器执行失败后的误放行，不是声称原 affe282d 收据伪造。

**最小修法**：Git helper 对非零 rc 抛出包含 argv/rc/有界 stderr 的异常，或显式记录失败后终止；HEAD 与 common-dir 同样核 rc。检查工具未成功运行时，不得解释其空输出。
**回归要求**：真实损坏临时索引 + 脏树应在克隆/CLI 前结构化 FAIL、exit 1；正常干净树通过、普通脏树拒绝、短 SHA 拒绝。

## P1-2：报告兜底依赖同一个失败目录，承诺的结构化 FAIL 仍会缺失

定位：`scripts/reconcile_hithink_gate.py:90-99,117-118,358-360`，尤其 94-96。

令 `--output-base` 指向一个已存在普通文件：`OUT_BASE.mkdir()` 抛 FileExistsError；顶层捕获后 `finalize(1)` 仍选择这个 OUT_BASE 写文件，再抛 NotADirectoryError。`print(report)` 在 write_text 后面，最终 stdout 空、只有 traceback、没有结构化报告。目录无写权限、磁盘耗尽或 RUN 在报错前消失等同类故障也会击中同一依赖。

真实复现 exit 1，因此**没有误报 PASS**；问题是十二轮明确要求的失败证据合同没有兑现。证据：`probe-results.json` 的 output_base_collision，完整 stderr 在仓外 `probes/output-collision.stderr`。

**最小修法**：报告先序列化；主路径失败后使用独立的仓外临时目录（不回退 cwd），两者都写失败仍尽力输出 JSON 到 stderr/stdout 并 exit 1。无法承诺所有存储设备失败时还一定有磁盘文件，合同应明确最终降级介质。
**回归要求**：输出路径冲突、mkdir 权限错误、mkdtemp 错误、主报告写失败四类至少覆盖；再补 JSON 损坏/CLI 超时的异常收据测试。只测短 SHA 和普通 dirty tree 不能代表这些路径。
