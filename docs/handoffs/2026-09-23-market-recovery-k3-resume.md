3. 有界重开 explore 01b，提示先交 F2 探针再扩读。7 次请求都收到 HTTP 200、11 次工具完成，但仍持续扩读/思考，未执行任何模型 write 工具，也没有通过 bash 写出探针。600 秒会话上限触发，最后一轮流被终止，exit 143。提示中的增量交付没有实际兑现。

## 方案与取舍

| 方案 | 评价 | 结果 |
|---|---|---|
| 把一次 45 秒最小请求超时解释为 K3 不可用 | 混淆载荷形状、等待窗口与模型可用性 | 否；用户纠偏，真实工具往返已反证 |
| 带工具的流式请求，并观察真实 Pi 工具链 | 能分别记录首包、工具回传、网关状态与完成情况 | 采用；13 次请求、11 次 200、2 次 504 |
| Pi exit 0 或 HTTP 200 即视作独审完成 | 前者可藏模型错误，后者可只有未完成的流 | 否；必须核对终稿、探针、执行与阳性对照 |
| 有界重开并要求先交探针 | 可保留进展，但仅靠提示没有保证执行 | 已试一次；本轮没有交付，记会话超时 |
| 无限重试或换模型绕过阻塞 | 超出本轮审查约束，也不解决交付节奏 | 否；停止新请求并保留可复核阻塞 |

「工具回传后必失败」也不成立：真实 Pi 会话已经完成多轮工具往返。没有足够样本判定具体载荷触发了 504，不能由一次对比推断因果或稳定性。
