## 按发现顺序

1. readiness曾把快照/总览日期不等放入critical，Episode工具又因旧日丢弃证据。先拆开诊断和可用性：真实日期差异仍报false/advisory，不伪造一致；取数上界只用information_cutoff。
2. finance_query允许截至cutoff的真实最新可用切片，但模型自选旧窗口不能自证授权。探全表最新日时移除请求time_range；用户严格历史范围、未来过滤、真实主体退出判定保留。整表落后不编造主体退出。
3. 复查发现旧ask、D4及总览仍按“同日主线”隐去事实。改各表独立取最新可用日；稀疏schema只限制对应部分；缺涨停数/板块数保留“-”，真实0仍为0；判读规则保留observation且不当事实证据。
4. 快照对账实际由check_market_snapshot_contract及测试消费。日期差异改WARN，不把原质量合格快照打成不可用；partial仍不ready，未知日期/读库失败仍是对账FAIL，不外推成所有分析不能做。
5. 首版日期fallback仍会把正文中的回顾日或预计交付日当来源日。确定性renderer现在给各事实追加“；数据日期：…”，混合块使用该标记。单provider显式source_date优先；明示未知/畸形标记保持None，不被fallback或正文日期补齐。
6. 预取转文本曾丢PrefetchItem.source_date。逐item逐事实保留原日期，标题/限定语不盖事实日期。上游聚合as-of与底层行情日不同的语义未擅改；总览专题测试隔离预取，预取来源日另有专项测试。
7. 06de3dfc完整全量只剩local_only测试的一条旧期待：“旧一天的主线必须空”。c57ec654只修测试为交付7/23事实、日期准确、无gap且io_effect=local_read；外部socket/subprocess尝试仍为零，缺库/空库/指定7/24日查询为空等保护保留。没有为测试绿放宽运行逻辑。

## 方案比较

| 问题 | 被否方案 | 采用与理由 |
|---|---|---|
| 日期不齐 | 继续阻断或诊断强置true | 诊断保真，分析保留已有证据，两种职责独立 |
| 取数上界 | 总览日作为所有表上界 | cutoff硬上界，各数据集可有不同最新日 |
| 旧窗口 | 任意旧窗口都获准 | 真实全表max证明最新可用；严格历史合同不变 |
| 来源日期 | 最大正文日期/统一总览日 | 元数据显式传递；事件日不是来源日 |
| 来源未知 | 用参照日补齐 | 明示未知不猜，防止伪造时效性 |
| 缺字段 | NULL补0/整个块丢弃 | 局部缺项保留未知，其他真实事实照常交付 |
| 对账WARN | 顺带把partial升级ready | 只撤日期相等要求，质量合同独立保留 |
| 只改表达 | 改prompt但不改取数 | 取数、证据、旧入口、协议/共用基线一起修 |

日期可不同不意味着可直接相除或比较。收益率、估值、财务比例仍需核期间、单位和口径；本枝没有重写计算引擎。也未删除全仓所有stale状态或其他快照质量要求。
