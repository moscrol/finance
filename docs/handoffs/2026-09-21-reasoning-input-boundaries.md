3. 再将旧快照上限编成 material_only。V2 不再重查，却暴露投影层把无检索需求当成
   non_research；进入 Engine B 材料兜底，没有生成合法复核答案。
4. 同时审过默认基线：它把盘面证据排为全局最强、所有题先定阶段，与本任务冲突。
   已限定 CR-01/02/03、SPT-A10 的适用主张；真实行情仍有过强归因，不能据此宣称改善。

## 方案比较

| 选择 | 被否方案 | 理由 |
|---|---|---|
| 来源解析与合同编译共用材料限制判据 | 在两个模块各补一套词表 | 两处漂移会出现识别了材料却没收窄权限；引用必须先被掩码。 |
| 分开只用旧快照与本地可重查 | local_only 就算遵守用户边界 | 本地重新查询同样可能替换数据；V1 已真实发生。 |
| 保留硬来源门，记录材料交付失败 | 将所有直接回答统一改为 user_premise | 会把源头缺失隐藏成通过，绕开现有 E2 逐句来源责任。 |
| 旧答案只供引用/撤回，新编号须有原件 | 把旧 E1 和助手正文放进本轮证据 | 会把待审断言自证为事实；身份、日期和范围尚未核验。 |
| 限定原规则作用域，保留身份/开关/知识门控 | 再加宏观或流动性固定模板；删除所有基线 | 目标是按主张选择证据，不是换一种强制视角，也不是丢失已有领域方法。 |
| 不把 non_research 改成假检索需求来绕分流 | 强制 needs_retrieval=true | 研究交付与取新证据是两件事；还需同时解决材料资格和快照身份。 |

解析、复核和基线修复独立于 `FINANCE_RESEARCH_REASONING`，后续配对必须用同一版本比较。
