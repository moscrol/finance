## 按发现顺序

1. 原比较器 summary 检查只看 `total/passed/failures`，不看矛盾分类统计/通过率；
   failure 的值也未严格验证。更根本的是 summary 丢掉通过题号，另一套同题数全通过结果
   可生成完全相同的摘要。统计补齐无法恢复身份，不能以当前题集去猜。
2. 先写拒收回归，得到实际 7 RED；去掉 summary 推断分支，仅接显式 `cases`。
   保留严格布尔值、非空/一致题号、重复键检查，以及回退 FAIL/否则 INCONCLUSIVE 合同。
3. 为旧答卷迁移新增 `score --cases-json`，保持 `--json` 人类汇总接口。
   初稿三文件 75P 后继续查上游：提前返回导致陌生题号被丢弃，重复题号/JSON 键也会覆盖。
   新增 8 RED，修复后 87P；没有把一次绿当成输入合同已全闭合。
4. 增补合法两题四臂 256 种布尔组合及缺 cases/failure 形状回归，最终定向 91P。
   用已有变异运行器在固定 `f1e90ae3a` 拆七处保护：7/7 真实抓红，还原 91P。
5. E2E 单独用真实会话 HTTP 入口的离线后端探针追踪继承、owner 合同和门禁前草稿。
   第一轮探索消除两项旧名，随后另起目录仅消除 `direct_answer` 重复项，排除混杂。
   已确认主体/owner 未丢，重复旧名没有 claim 候选是当前失败的直接原因。
6. 诊断脚本始终返回原 missing 判决，旁路 complete 不进入产品。
   草稿虽有风险/验证栏目，但结构门认领的 direct_assessment 只是公司研究范围摘要；
   因此没有直接映射旧名、加公司名或松断言来洗绿。
7. 分开提交比较器 `f1e90ae3a` 与诊断 `a68f48bfb`；后者干净树重跑十一文件 **561P**，
   收据按完整 SHA 验真，全仓 Ruff、两个提交 hooks 通过，模型新请求 0。

## 决策与被否方案

| 选项 | 评价 | 结果 |
|---|---|---|
| 修补 summary 的统计一致性 | 能堵 F1，堵不住通过题身份丢失的 F2 | 否 |
| 显式逐题结果，summary 统一拒收 | 以更小边界同时堵两类缺陷；需原答卷迁移 | 采用 |
| 用当前题集补通过题，或把旧 summary 自动升级 | 同题数不等于同题集，无法补回已丢身份 | 否 |
| 强制比较器题号属于当前内置题集 | 把通用比较器锁死在具体题库上，仍不认证题面 | 否 |
| 新增 `--cases-json`，原 `--json` 保留 | 机器配对与汇总展示分开；错误输入先拒绝再输出 | 采用 |
| 因格式改变重跑真实模型 | 增成本且换实验输入，不是确定性迁移 | 否 |
| 直接改 `direct_answer` 映射或删除 E2E 断言 | 可让结构绿，却不足以证明真实追问得到回答 | 否，本轮只定位 |
| 公司名特判/拼到缺口提示 | 只迎合一条断言，不解决输出身份或内容完成度 | 否 |
| 把基座同样失败当作合入豁免 | 只能缩小归因，不能抵消验收红灯 | 否 |
| 诊断探针旁路重算，不改变返回值 | 能定位单因素机制，并保留原失败现场 | 采用 |
