## 按发现顺序

### 1. 先复现，再挑刺

从空旁路库第三次重建 `build-labels` / `build-sector-roles`，canonical_hash
与收据**逐字节相同**（`16a27afb…` / `ba1b17e4…`）。确定性这块是真的。
全量 pytest 8340 passed、ruff 全仓通过、dataset 注册审计 34+16=50、
`rg 'sk-fuyao'` 为 0。这一步没做完不该开始找问题——否则挑出来的每条都要
被「你是不是环境没配对」挡回来。

### 2. 收据里两条同类读数，只解释了一条

`build-labels` 的 gap 账本同时写着：

```
"auction_zt_pct_median:auction_zt_pct_median_null": 257
"dragon_count:dragon_count_null": 166
```

收据把 257 挑出来解释了「这不是切主弄丢的」（属实，旧 zt 面板本来就从
2026-01 才有），却没提 166。而 166 恰恰**是**切主弄丢的：旧龙虎表在日历
416 天里覆盖 405 天，同花顺只回溯一年、覆盖 242 天。

这条是本轮最重要的发现，且它不需要任何额外工具——**数字就在对方自己的
产物里**。复核时先在被检对象的输出里找「同类读数被区别对待」。

### 3. 两个标签是换定义，收据只报了吻合那天

| | 收据报的 09-07 | 其它日子 |
|---|---|---|
| `tf.new_high_1y_count` | 21（旧 22，几乎一样） | 09-01 44 vs 62、09-02 22 vs 38 |
| `tf.sector_up_ratio_pct` | 83.08（旧 85.61） | 09-01 71.16 vs 58.81 |

09-07 是这批里两边最吻合的一天。不是造假，是**只做了一天的点检**——但读者
会把它当成「切主前后一致」的证据。

### 4. 除权日那条，差点得出反结论

初判：新口径用裸 `close/LAG(close)`，除权日会把送转算成暴跌（实测除权日
平均绝对差 0.51pp、最大 −36.76pp，非除权日 0.0024pp）。于是写公式修正，
拿旧表当标尺一验——**偏差反而变大了**（中位 0.72pp）。

差一点就据此判定「公式或字段单位错了」。实际是：**旧表自己在 8,390 个除权
日里只有 946 行是复权值**，其余 7,444 行同样是裸价跌幅（`300897.SZ`
2026-05-27 十送四，旧表写 −30.13%）。把标尺按「旧表这行到底复没复权」分层
之后，公式在那 946 行上与旧表中位绝对差 **0.0037pp**，946 行里只 9 行 >0.5pp。

**标尺有杂质时先把标尺分层**——这条比那个公式本身值钱。
