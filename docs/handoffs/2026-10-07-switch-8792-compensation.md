# 8792 切换脚本补偿与证据边界 · 2026-10-07

PR #62 的首次脚本只保护启动前检查与正常卸载等待。本会话接手后，在隔离夹具中确认 macOS 未找到服务的返回码、端口探测错误以及链接/账本/启动失败的补偿行为；未操作生产服务。

先补齐失败路径，独立 Standards 复查又指出回滚也需要等待异步卸载、相对运行链接须按链接父目录解析、账本恢复失败不能报成功。进一步复查发现，Git 读取索引失败时标准输出为空，原判据把“无法检查”误认为“干净”。新旧快照均须成功读取 Git 状态后才允许停服。

| 决定 | 被否方案 | 理由 |
|---|---|---|
| 切换与回滚共用卸载、端口检查和启动重试 | 回滚直接 bootstrap | bootout 异步，失败路径同样可能有残留进程 |
| lsof 返回1且无错误诊断才判空端口 | 任意非零都当端口空闲 | 查询失败不证明端口已释放 |
| 停服后各失败路径统一恢复旧链接、账本和服务 | 只恢复链接或重复手工补偿 | 运行版本与账本可能不一致，重复逻辑容易漏路径 |
| 账本失败仍尝试恢复服务，但回滚退出7 | 服务启动后直接报回滚成功 | 可用性恢复不能掩盖无法归属版本的账本错误 |
| 新旧快照的 Git 状态读取失败在停服前退出2 | 只检查 stdout 是否为空 | 损坏索引实测 exit128、stdout为空 |
| 操作说明仅保留一条切换命令 | 脚本之后继续执行旧手工四步 | 会发生二次切换或重复写账本 |
