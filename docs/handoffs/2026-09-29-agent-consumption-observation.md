# DuckDB → Agent：数据消费审计与人工观察验证

**2026-09-29｜隔离验证版，未发布**

> 结论：目前不能说 DuckDB 中的相关数据已经全部被 Agent 可靠消费。通用语义查询能执行，不等于字段有意义、日期符合任务、单位一致或推断成立。本轮已落地补充审计器和原工作台的「观察验证」页；数据质量修复、专用消费者全路径验证与正式部署尚未完成。

## 1. 一眼看清现状

| 检查层 | 实测结果 | 能说明什么 |
|---|---:|---|
| 真实 DuckDB catalog | 72 个表/视图 | 不再只看 schema.sql 声明 |
| fact / feature 对象 | 56 个 | 26 通用语义登记 + 16 明确豁免 + 14 未归属 |
| 未归属对象 | 14 个，其中 10 个非空 | 通用登记覆盖存在缺口；不等于已排除专用、动态消费路径 |
| FinanceQuery 执行探针 | 26 / 26 成功 | SQL 与已登记字段能执行，包含有意为空的数据集 |
| Episode 工具探针 | 15 success / 10 stale / 1 empty | 按本次“最新事实”任务的日期要求返回或拒绝证据 |
| 未授权负向探针 | 正确拒绝 finance_query | 当前能力边界没有被绕过 |
| 最新日的有用性 | 仍存在全空指标、丢失标记和单位陷阱 | 不能把 success 当作质量合格 |

**口径说明：**56 是物理表/视图对象数，不是 56 项独立业务能力。26 个语义对象包含 24 表、2 视图。另 16 个基础/维表对象不应机械地各自变成 Agent 工具。

本轮查询以库内最新交易日 **2026-09-24** 为基准，任务日期为 09-29；这不代表市场数据已更新到今天。Episode 每集探针最多取 3 条，属于工具级读通检查，不是全历史数值验真，更没有调用模型验证最终回答。

## 2. 最重要的四个发现

### A. 旧登记审计会漏掉库中新出现的表

现有审计按 schema 声明检查 40 张表，仍可报告 `ok=true`；物理库中另外 14 个 fact 对象却不在通用语义登记或明确豁免中。

新增 `scripts/audit_agent_data_consumption.py` 从真实 catalog 出发，复用现有登记，不另起一套 registry。它以只读方式检查：

- 实际表和视图、总行数与登记归属；
- 优先采用已登记语义时钟，其他对象仅提供物理日期概况；
- 最新切片各字段非空数量、登记列是否存在；
- 暴露指标全空、有意为空等情况。

可复跑命令（Mac 项目根目录）：

```bash
.venv-workbench/bin/python scripts/audit_agent_data_consumption.py \
  --db db/market_feature_store.duckdb \
  --output .tmp/arena-consumption-0929/consumption-audit.json
```

本次审计返回 **exit 1 / requires_attention=true** 是正确发现缺口，不是脚本崩溃。脚本已上传、执行并有测试，**尚未加入 CI**；它也没有自动登记、补数或修复数据库。

### B. “日期新”仍可能只有名单，没有分析指标

09-24 的 `fact_mainline_sector_daily` 有 **69 行**，但已暴露的 8 个数值指标全空，包括成交额、相对量、涨停数、最高板、净流入、强度、强度变化和涨幅。Episode 仍可返回 `success`、`gaps=[]`。

因此必须增加**按来源和任务所需字段判定的质量门槛**：不能只凭最新日期和行数，就把“最新板块名单”当作“有量价证据的主线判断”。同时，不能把所有 NULL 都一律视为故障或填零。

### C. 同名 `turnover`，含义并不相同

主表 `fact_stock_daily.turnover` 对外表示换手率；09-24 的 **5,555 行全部为空**。

原生 `fact_stock_daily_hithink.turnover` 虽然有值，但同日、同码对账发现：

- 原生表当日 5,557 行，5,557 个唯一股票代码，`adjusted=none`；
- 主表 5,555 个代码全部一对一匹配；
- **5,555 / 5,555** 的原生 `turnover / 1e8` 与主表 `amount` 一致到主表的四位小数精度；最大差异约 `0.00005` 亿。

这批值是**成交金额口径，不能拿来填换手率**。例如原生记录的 `turnover` 达数十亿元量级，不是百分比。仍需补齐原写入链和接口单位契约，不能仅凭同名字段非空就自动提升为权威数据源。

### D. 新高源名单存在，但成分表的标记没有跟上

按同日、同股票代码关联：09-24 新高表中的 **389 只股票**，在板块成分表有 **3,443 条 `high_status IS NULL` 的关联记录**。

因此这批空标记不能直接解释为“非新高”。后续需要核对新高周期、成分映射与富化规则，再修复消费语义；本轮没有回填或把空值批量改成新高。

## 3. 工具可达性不等于完整可用性

### 已经走通的范围

逐个执行了 26 个登记数据集的 FinanceQuery 和对应 Episode 读工具路径，保留 SQL 指纹、实际日期、证据数量及 payload 哈希。能力未授权时得到：

`UnknownResearchTool: 能力未授权：finance_query（工具 finance_query）`

### 本次被旧日期拦截的 10 个数据集

`auction_stock_daily`、`regulation_pool_daily`、`regulation_event_daily`、`historical_mapping`、`dragon_summary_daily`、`dragon_seat_daily`、`dragon_tiger_daily`、`global_index_daily`、`global_stock_daily`、`event_daily`。

这些探针实际服务日期为 09-02，未满足本次 09-24 的最新日要求，返回零条证据。该结论针对本次任务和查询，并不表示历史研究也不能使用它们。物理日期最大值也不一定等于工具本次服务日期，例如事件表物理最大日期是 09-03。

`stock_technical_snapshot` 属于有意为空，不用其他日频数据悄悄替代。

### 仍不能宣称打通的范围

- 14 个未归属对象的专用、动态消费者尚未逐条实跑；字面搜索没有命中不等于没有路径。
- 部分 L2 数据已有专用服务使用，最新数据也到 09-24，但豁免说明仍写着旧日期；专用 Agent 任务链尚未完成验证。
- 语义 SQL 与 Episode 的成功返回不能证明最终 LLM 推理正确；本轮没有模型调用。
- 查询哈希和数据库来源追溯，不等于每条判断都有原始公告、产业材料或分钟行情证据。

## 4. 原 Dashboard 已新增「观察验证」

入口：**原工作台 → 长河 → 观察验证**。当前 Arena 只读预览默认打开此页；Mac 8798 尚未发布这些改动。

不是另一套报价看板，而是在原日报、板块六轨、连板及时间联动基础上增加：

**同日事实 → 可被推翻的假设 → 逐条核对 → 预先写反证 → 指定复查日期 → 冻结记录 → 追加复查。**

### SPT：量能与结构

1. 市场是否提供量能条件？区分一次放量和持续放量。
2. 主线在扩散还是缩容？联合行业占比、板块宽度与前排联动观察。
3. 支撑/压力、缩量回踩与后续续量的条件是什么？
4. 哪些现象会推翻当前解释？

### 风远：根、干、果与双锚

1. **根**：产业逻辑靠哪些订单、价格或供给证据兑现？
2. **干**：对资金结构的判断有没有相应证据，而非仅有价格结果？
3. **果**：人工明确方向锚、高度锚，再核对板块联动。
4. 区分基本面证伪与流动性挤压，写明框架失效条件。

模板依据已有判读基线和画像整理，不代表作者当前观点，也不是已校准策略。画像材料量为 SPT 50、风远 24，置信度均为 medium，其中包括重建/记忆材料，不能宣传为全部核验过的原始资料。

### 重要约束直接出现在页面上

- 日线不能代替 30/60 分钟结构证据；分钟证据不足就选“缺数据”。
- L2 净额不等于持有人身份。
- 全市场最高板不自动成为所选板块的高度锚。
- 研报覆盖不等于公开消息热度；没有利多证据就不贴“利多不涨”标签。
- 所有条件默认**未评估**，没有自动判定成立，也没有伪造评分。
- 历史日期缺归档时明确显示缺失，不偷换成其他日期的数据。

### 怎样实际使用

1. 选择观察数据日和 SPT/风远模板；先看同日事实，必要时跳到日报、六轨或连板。
2. 填写具体对象与假设。逐项选择支持、反对或缺数据，并补证据备注。
3. 写下什么出现才算确认、什么出现就撤回，以及晚于观察数据日的复查日期。
4. 冻结原条件。以后只能在页面流程中追加复查，不覆盖原假设。
5. 导出 JSON，或生成一段要求 Agent 主动查反证的核查提示词；页面不会自动提交给模型。

记录保存框架版本和条件快照、实际录入时间、观察数据日、归档状态/路径/SHA256、所见事实和连板摘要。比如 09-24 的归档可能在 09-27 生成，09-29 才录入观察：**这不是“09-24 当时就知道”的证明**。

当前使用浏览器存储，按日期/对象/模板隔离草稿。记录类型为 `human_observation_not_backtest`，`strict_point_in_time=false`。浏览器记录不防篡改，不跨设备同步，也没进入服务器或 Agent 正式台账。存储不可用时明确报警，只保留当前页内存并提示立即导出。
