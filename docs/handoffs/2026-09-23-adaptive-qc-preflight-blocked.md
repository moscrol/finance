## 选择与理由

| 选择 | 被否方案 | 理由 |
|---|---|---|
| 降低一次生成的工作量，逐探针落盘 | 直接延长旧会话或单发帽 | 避免一次长生成吞掉整个交付，预算边界不变，原失败仍可追溯 |
| 先验证read/write真实往返 | 只拿小载荷200证明整个审查器可用 | 代理、工具与写盘都在审查链上，必须按载荷形状验 |
| 本地502与上游状态分开记 | 照抄runner的BLOCKED_PROVIDER_HTTP_502作根因 | shim在无上游响应时也能生成502；原账本status=null才是观察边界 |
| 第二次连续失败后停候选 | 再换effort、账号、模型或提高上限连续试 | #75规定有限尝试，且当前连准入资格都没有，不是产品缺陷证据 |
| 端口在授权白名单内重选 | 放开所有回环以避EADDRINUSE | 端口资源竞争不应变成生产或网关访问权限扩大 |

本次没有证据说明medium/8192/逐文件提示确实改善了独审，它们未到pi真实往返；不能从一次小载荷失败唯一归因形状、账号、服务或负载。
