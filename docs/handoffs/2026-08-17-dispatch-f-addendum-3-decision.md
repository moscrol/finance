## 1. 但在 5a–5d 之外，有个更前面的问题

**回头读 §9.4 的原句式：**

> 「A′ **不能让** 带 citations 的记录率相对 A **下降超过** 5 个百分点」

这是**非劣性护栏**（不许变差），**不是主检验**（要证明变好）。主检验是下一条：

> 「A′ 在 P95 延迟、修复成功率、恢复能力或维护成本中**至少有一项达到明确改善**，吸收才算兑现」

**护栏不需要「能分辨 5pp」的统计功效，只需要能排除大幅回退。**
把护栏当主检验来配样本量，是 2026-08-17 之前的读法错误——**我的锅，不是你的。**

## 2. 用你自己那把尺子看，这是层次错配

按 spec §2 的两分层与 §14 的反推口令：**这次吸收改的全是通用底座**
（工具流水线、EpisodeScope、生命周期、Durable Event/Projection、ResearchProfile）。

**拿领域层指标去检验通用层改动，本身就是错配。**
「带 citations 的记录率」是领域产物的性质，那批接缝**没有理由**去动它——
所以它测不出差异，一半是因为指标退化，另一半是因为**它本来就不该被期待有差异**。

| 指标块 | 层 | 角色 |
|---|---|---|
| 领域质量 | 领域 | **护栏**：只排除大幅回退 |
| **Runtime 质量**（tool 失败率 / 首轮超时率 / repair 恢复率 / P50·P95 / cancel·resume·restart / Trace 对账） | **通用** | **主检验：收益在这里** |
| 工程成本 | — | 辅助 |

**后果：围绕「带 citations 率」算过的所有样本量——#69 的 450「刚够」、
追加①的 772、你这次的 845——都是在给护栏配主检验的功效，方向错了。**
845 这个数没有错，是它要回答的那个问题问错了。

## 3. 下一步（唯一一件）

**给 Runtime 质量块单独算功效。** 那组指标的方差结构与领域指标完全不同：

- P50/P95 延迟是**连续量**，不是二值退化指标；
- repair 恢复率、cancel/resume/restart 成功率**基率高**，不像带 citations 率那样多数格恒 0；
- tool 失败率、Trace 对账完整率同理。

**很可能所需 n 远小于 450，也可能 450 就够——但没人算过。**

要做的：

1. 从 #68 那 45 条（及任何可用历史产物）**离线**提取 Runtime 质量各指标，
   给出每项的基率与方差；
2. 按 5pp（或该指标合适的效应量，**由你提议、用户拍**）推 `required_nr`；
3. 出一页「主检验功效」，明确哪几项在 450/臂 内可判、哪几项不可判。

**离线能做多少做多少，不够再谈跑。** 仍不开 900。

## 4. 五个选项的处置

| 选项 | 裁定 | 理由 |
|---|---|---|
| **5a** 改名 | **采纳，已落 spec** | 名实不符会发假绿。已改成「发布面带 citations 的记录率」 |
| 5b 闸前 unsupported claim count | 不采纳 | 需先落盘闸前 claims，等价于 5d 的一半，且仍是护栏侧 |
| 5c 闸前通过率 | 不采纳 | 零改产物是优点，但仍是护栏侧指标，不解决层次错配 |
| **5d** 落盘闸前 `source_ids` | **采纳，但并行做、不阻塞开窗** | 恢复字面含义有独立价值；**但恢复后它仍是护栏不是主检验** |

领域护栏侧同时降级为：**报分层后的点估计与区间，遇到 >5pp 回退才停**；
**不因为「分不出 5pp」而扩样本**——护栏分不出小差异是可以接受的。
