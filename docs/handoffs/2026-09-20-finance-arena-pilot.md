# FinArena 邀请试运行：实现与边界

## 背景

用户要搭建金融 Agent 评测平台，允许用户参与，重视体验与真实胜率。前序讨论已明确：用户偏好、研究事实质量、选股排序、组合收益和执行可靠性不能互相冒充。平台要能调用参赛方，不仅是粘贴答案。

主工作树为 detached HEAD 且有大量他人未提交改动，因此从当时的 `gitea/main@728f3271` 新建 `/Users/a77/fwp-wt-finance-arena`，分支 `feat/finance-arena`。本轮没有改主工作树，没有调用生产金融工具或改生产库。

## 决策

| 方案 | 判断 | 结果 |
|---|---|---|
| 在现有 8792 Workbench 上直接加公众投票 | 会把公众流量、会话与私人投研数据置于同一服务边界 | 否；独立 FastAPI 和 React 入口 |
| 一开始引入 PostgreSQL、队列、容器集群 | 对本机邀请试用增加部署依赖，当前无并发需求证据 | 暂缓；独立 SQLite 事务账本，公网阶段重新评估 |
| 贴答案即进入完整 Agent 榜 | 无法证明答案来自平台发起的一次真实运行 | 否；真实运行原件绑定内容指纹，人工 demo 永不进榜 |
| 开场填充模拟胜率或收益曲线 | 会把 UI 示例当作实际能力与实绩 | 否；正式对战、正式票和策略成绩初始为空 |
| 游客票全部正式计数 | 清 Cookie 可无限换身份 | 否；游客可体验，正式票需运营签发的一次性邀请，但不是强身份认证 |
| 用投票胜率宣布最佳 Agent | 题目/对手/评审分布未校正，小样本波动很大 | 否；描述统计、样本标记、分开平局与双差，无实力排序 |
| 在本轮手写交易收益模拟器 | T+1、涨跌停、不可成交与成本口径尚未验证 | 暂缓；仅事前登记，不声称策略实绩 |

## 实施顺序

1. 建立独立的数据模型、SQLite 事务写入者、会话与邀请、匿名分配、幂等投票和正式统计。
2. 建立运营异步双 Agent 调用：arena-v1 与 OpenAI 模型对照，运行预占、限时、失败留档、无自动重试挑答案，输出待审核再发布。
3. 建立用户页面：对比、材料、理由、投后揭晓、题目提交、历史、举报、统计与策略前向页面。
4. 后端最初 28 项通过。浏览器首跑 6/8：装饰字母进入可访问名称，导致 `A 更好` 变为 `A A 更好`；给装饰字母加 aria-hidden 后通过。
5. 用户题目补齐运行/审核/发布/撤销状态，并允许从“我的评测”进入自己的已发布题目。相同问题与材料/截止指纹的重复运行不增加题目覆盖数。
6. Arena 素材移入独立 `arena-public`，避免原 Workbench 构建顺带复制。测试数据只在独立临时 SQLite 中。
7. 提交门禁误报 SQLite `row_factory` 没有读取者；读取者实际在标准库。按现有 `ALLOWED` 标准库属性例外添加这一项，没有跳过钩子或放宽基线。
8. 代码提交 `c8390b98`。本地服务已用最终代码重启，127.0.0.1:8816；截至检查正式榜仍为空。

## 接手边界

- 本轮没有配置授权外部参赛者、没有调用真实付费模型。网络协议测试使用 httpx 模拟传输，端到端测试使用临时夹具。
- 现有金融 Agent 的 Workbench 会话接口不是 arena-v1；仍需独立适配与授权，不能直接填 URL 假定兼容。
- 题目须经运营批准才调用；无队列后台 worker、跨进程取消、预算计费结算或崩溃自动恢复。杀进程可能留下 running，必须保留并核查，不能静默重跑。
- 远程 Agent 的工具/数据权限、截止遵守、版本真实性未隔离验证。没有完整专家事实评分、模型判官、置信区间、BT 排名或串票检测。
- 策略是运营事前登记；仅核对来源运行和身份，不自动核实策略字段与原答案一致，更无成交与收益结算。
- 会话 30 天、绑定浏览器、无账户恢复；不是已完成公网安全审计的服务。不得直接开放生产 Workbench。
- 未运行全仓 Python、既有 Workbench E2E 和完整 registry 合入检查；未推送、未建 PR、未合 main。

操作与协议唯一说明见 `docs/finance-arena.md`。两个重复执行的诊断动作已留为可运行浏览器测试与 smoke 脚本；本轮复用的是既有事务/预占/去重模式，没有新增通用 harness 机制，不扩展另一份通用工具清单。
