## 决策与被否方案

| 决策 | 被否方案 | 理由 / 条件 |
|---|---|---|
| 质量疑点保留为批注，judge状态照实 | 关数字/引用/语义门；把rejected改passed | 内容交付与认证是两个合同；用户能读不等于已核验 |
| 先有安全正文，再加附注 | 把批注、来源注、占位符当作“非空”证明 | 派生说明不能反过来证明原始正文存在；必须测真实调用顺序 |
| 脱敏幂等、保护相邻正文 | 整行粗删或只清第一次 | 多出口重复清洗很常见；安全残片不能撑稿，也不能连坐正常分析 |
| 精确追加两稿、核E身份与语义元数据 | 模糊diff、同hash就直接覆盖、旧E号变新卡 | 会把限定语删掉或让证据错配；不可靠时拒强拼并保当前可信任务稿 |
| 材料题精确题段嵌套并重验 | 全文尾部乱拼或补段不计字数 | 题段归属/材料范围/历史义务也是身份与完整性边界 |
| 只承接已准入且刚返回的finish | 任意模型文本都能在超时兜底发布 | 原协议的安全、证据完整性仍须承重；不能靠保留洗白forged hash |
| 同预算有界修复，不增影子调用 | 无限再问、给新补充自动complete | 用户要保留分析，不是授权额外成本或伪造修复成功 |
| 真会话一次提交、失败也封存 | 重采样到成功再报结果 | 避免选择偏差；N=1仅证本次轨迹，不能推可靠性或收益能力 |
| 整体验收未过，下一刀固定准入前反例 | 14项局部绿就上线；删历史比较完成度门 | 真问题是正文生命期，不是历史结果突然齐了；准入判据不能被牺牲 |
| 私有量具归档，不升级新产品入口 | 把固定日期/端口/用户脚本泛化成通用框架 | 本轮一题；工具含特定路径/快照与live锁，需语义判定，复用产品probe与扫描器更稳 |

## 下一刀的输入与验收边界

从封存 `continuous-episode.json` 取 `turn-6` / `turn-7` / `finalization_recovery`，先做确定性红测：上游候选有安全同任务分析、格式或普通完成度未过，后续失败或另写稿也不静默覆盖；完整性/授权/任务身份违规仍拒收。

需要设计的不是“把admit_finish改成接受所有内容”，而是**候选正文的保存/公开资格**与**可执行finish、绑定、完成度资格**分开：

- 对合法JSON但 `history_missing_comparison` 的draft，可保留待核验分析，历史状态仍partial；完整性错误不可借此旁路。
- 对正文+协议混合输出，严格定义正文提取，剥私有协议与密钥，拒绝工具调用和歧义；不要用大括号切片猜JSON。
- 两稿合并后重新核对引用/题段/字数/未履行义务，不能从不可信bindings生成引用表；模型error或foreign task不授权复用。
- 继续复用根deadline、调用账与SDK共享RepairGoal；预算耗尽不能靠追加保留再发模型调用。
- 保留本次 `not_passed` 为历史，不覆盖原件。新代码用新revision、新收据、新有界验收，不再次提交本协议原题挑好答案。

尚未全审：`FinanceResearchHarness.admit_finish()`各格式/内容/完整性分类，SDK `sdk_invalid_finish`出口、`_carry_repair_finish()`、旧helper/eval动态可达性；恢复1200字/12卡/360字符生成限制未撤。旧合成链真实模型、真实浏览器研究交付、外部独立QC、完整金融质量验收未做。原七类金融问题及manual mappingproxy故障另线。
