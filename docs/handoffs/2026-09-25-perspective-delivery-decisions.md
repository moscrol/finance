## 方案对照

| 方案 | 评价 | 决定 |
|---|---|---|
| 只断言 context 存在 | 可保留上游证据，但不能检出 adapter/serializer 漏传 | 保留，并扩到首次provider回调 |
| 真实调用模型 | 可检验实际响应，仍需独立质量标准；当前数据、预算、发布前置未闭合 | 本轮不做 |
| 伪模型返回成功答案 | 易把合成结果当completed消费证据，还会走判官/写回 | 否；专用BaseException立即停止 |
| 改runtime新增审计模式 | 扩大生产行为面，已有构造器可注入 | 否；只扩scripts与测试 |
| 导出完整请求到报告 | 便于人工读，但带出私人原文/画像 | 否；仅在内存比较，落计数/哈希 |
| 从SPT画像反推考卷金标 | 同源自证，且不具备用户审批 | 否；交owner/用户冻结 |
| 旧真实run或当前请求绿签质量 | 两者都缺独立质量证据 | 否；四层分报 |

四层为历史票据、当前装配、请求送达、实际采用/质量。考卷是旁证，不自动跨层。
