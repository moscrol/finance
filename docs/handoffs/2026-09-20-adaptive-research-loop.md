## 按发现顺序

1. 已有 PLAN、同轮 PLAN+工具以及研究进展账，缺的是模型自定视角、支持/反证和后续判断的回传。本片复用已有合同，不引入第二份 ResearchState 或新工具。
2. 增加可选 perspectives 与每批反馈。首次离线回归发现 loop 直接调用领域证据映射违反已有架构门禁，移回领域层，未放宽门禁。
3. 第一组真实双臂 `pair/`：两臂都无 PLAN。候选的三批反馈确实到达，但模型直接取证/收口。提示词存在不等于机制被采用。
4. 加一次有界检查点：仅 deep/max、首批取证后仍无视角且预算未关闭时，一次请求不提供工具菜单，要求自主 PLAN；仍消耗原预算和原纯计划轮额度。已有视角、快速档与已收口跳过，不反复强制。
5. 第二组 `pair-v2/`：K3 写出六视角，但 JSON 代码框被旧解析器拒收；随后模型放弃计划。补上完整代码框兼容。
6. 第三组 `pair-v3/`：首份计划引用数组超八项被拒收；模型修正后，在 JSON 尾部加一句继续取证，再次被拒收。字段上限补入模型指令；解析器用 JSONDecoder 接收单个开头对象/代码框及普通尾部说明，仍拒绝前置文字、第二个结构化值、尾部代码块和越权字段。
7. 最后只做候选机制检查 `smoke-v4/`，不是第四组双臂。K3 五个自选视角被接收，下一批反馈携带 revision=1、零未知引用和三个未决视角。实际随后查核心龙头、核心趋势股、板块周期、消息面。没有 revision=2，因此尚无「观察后改变/放弃视角」的 live 实证。
8. 两份原始失败 PLAN 在最终解析器只读重放均接收（v2 sequence=16 六视角；v3 sequence=25 五视角）。这是协议修复证据，不改原 live 的失败结论。

## 决策与替代方案

| 方案 | 评价 | 结果 |
| --- | --- | --- |
| 固定池/固定必查表 | 针对本题补名单会压掉模型自定研究视野 | 拒绝 |
| 只加可选提示 | 第一组反馈可见、PLAN 仍为零 | 不足，增加一次有界检查点 |
| 每批另调反思模型或强制纯计划 | 放大上下文与往返开销，难区分真调整与填写表格 | 不做；同轮修订仍是常规路径 |
| 对任何格式差异一律拒收 | 两次已产出的计划因无歧义包装被丢弃 | 分开包装兼容与严格对象校验 |
| 放宽权限/预算以填完计划 | 自报完整不授完成，预算必须先于副作用 | 不做；既有收口规则保留 |
| 引用在后续出现后追认旧计划 | 会让先编引用得到事后合法化 | 诊断冻结在提交时，新 revision 才能重新引用 |
| 另建引擎 B 的状态真本 | 引擎 A 已有 PLAN/进展账 | 不双写、不做跨引擎重构 |
| 默认开启后收集反馈 | 单题样本不足且已见公开边界缺口 | 默认关闭，不部署 |
