## ② 429 有界退避

**没有**照报告字面「把 429 加进可重试列表」：`TRANSIENT_MODEL_ERROR_MARKERS` 的重试是**不等待立即重试**，
且 episode 修复轮共用同一份标记——直接加进去就是 09-09 那次「0.6 秒连撞三次 429」的原样复现；
网关 `model_cooldown` 4939 秒时还会白烧配额。

- `llm_refine.http_failure_text()`：429 时读 `Retry-After` 头（秒数），读不到再读 body 的 `reset_seconds`，
  追加成 `LLM 调用 HTTP 429（retry_after=Ns）`。前缀不变，`stable_llm_fallback_reason` 照旧判 `provider_rate_limited`。
- `llm_refine.rate_limit_retry_delay()`（单一真本源）：有提示照提示等、只向后抖 0–25%；无提示 0.5/1/2 秒指数退避；
  最多 3 次；单次 > 30 秒或等完剩不下 5 秒给重试本身 → 不等，直接交出原因。
- agent 循环（`GLMModelClient._complete_provider_chain`）：仅当已是链上最后一家 provider 时等（生产常态：单 provider + 账号池网关）；
  后面还有 provider 就换一家。等待分片 0.2 秒、可取消；trace 记 `rate_limit_wait_s`。
- 合成路径（`synthesize_messages`）：429 在本段剩余时间内等一次再试，次数仍受 `_RETRY_MAX_ATTEMPTS=2` 约束；其余 HTTP 错误维持直接降级。

## ③ 模型准入闸

- `ModelTurn.requested_model`：适配器写上本回合请求的生效模型（写手覆盖 → 构造参数 → provider 默认，与实际发出的 `model_override` 同序）。
- `agent_runtime.served_model_mismatch(requested, served)`：只把路由前缀（`zhipu/`）、思考强度后缀（`:low`）、日期快照（`-2024-08-06`）当同一模型；
  `glm-5.3` vs `glm-5.3-flash` 判不一致。任一侧缺席返回 `None`（判不了 ≠ 通过）。
- `model_turn` 事件新增 `requested_model`，不一致时再加 `served_model_mismatch: true`；适配器同时打 WARNING 日志。旧事件形状在缺请求信息时不变。
- `scripts/check_served_model.py <实验目录> [--expect glm-5.3] [--strict]`：逐 episode 汇总，退出码 0 一致 / 1 不一致 / 2 判不了（--strict）/ 3 无 model_turn。
  旧事件没有 `requested_model` 时用 `--expect` 指定。**实验收据先过这道闸再读 A/B。**
