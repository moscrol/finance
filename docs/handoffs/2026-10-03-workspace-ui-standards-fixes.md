## 按发现顺序修复

1. K 线的板块净值跳过未知日后继续累乘，三日 `+10%、缺、+10%` 输出 `[1.1, null, 1.21]`。现在缺行或涨幅 NULL 都令该日及后续累计净值保持未知，输出 `[1.1, null, null]`；后续真实单日涨幅和有效涨幅覆盖率仍保留。说明文字明确累计缺口，不改变原 `range_aggregate` 的非严格标量估计。
2. 时间轴先按名称收集整个区间的所有代码，再按日合计成分；显式 S1 会吃进同名 S2。现在先从 canonical `fact_sector_daily` 视图选定每日代码，再按 `(日期, 代码)` 联结热度和成分聚合。代码请求只匹配自身，缺日仅接受现有 `resolve_entity` 合同中已登记的历史别名；名称请求保留跨日有效换码，同日候选按代码稳定选择一条。`codes_seen` 保留候选，盘面的 `sector_code` 暴露每日实际选择。S1/S2 同名且同一股票各资金 2 的反例，现在 S1 资金为 2、成分数为 1。
3. 观察记录使用挂载时旧 state 覆盖最新 localStorage，导致另一页已保存记录或复查丢失。保留原 `foresight.observation-workbench.v1` 格式，草稿、冻结、复查统一走同名 Web Lock。锁内重新读取→按记录 ID 合并→写回，同一记录优先保留已存的原始条件和证据，只合并追加复查；storage 事件同步记录展示。组件等待锁回调完成才报告保存成功。锁 API 缺失、请求被拒或存储写入失败时不降级为无锁写入，保留内存记录与导出入口，并明确未保存。
4. 显式归档日期被放在 `overview &&` 内，行情接口 503 或一直等待时归档根本不请求。现在归档按所选日期独立挂载；行情失败仍显示原错误，板块映射为空，日期不回退。原“市场失败时不挂载归档”的 mock 子组件断言随修正后的合同更新，真实子组件回归另证请求与可读内容。

## 方案取舍

| 方案 | 评价 | 结果 |
|---|---|---|
| 未知日后恢复原净值 | 等同将未知收益当零 | 否决，累计未知向后传播 |
| 全区间同名代码集合每天求和 | 供应商覆盖会重叠，盘面与成分口径不一致 | 否决，各轨共用每日代码 |
| 固定一个区间代码 | 会切掉名称请求的合法历史换码 | 否决，按日选择并保留代码信息 |
| 每次保存只重读 localStorage，或只监听 storage 事件 | 修好顺序覆盖，仍有跨页读改写竞争 | 否决，全部写入口共用 Web Lock |
| IndexedDB 迁移 | 本次只需串行化原格式写入，无需另建存储体系 | 未采用 |
| 无锁时继续写入 | 无法兑现不覆盖已存记录的承诺 | 否决，内存保留并提示导出 |
| 行情成功才挂载归档 | 独立归档被行情故障拖断 | 否决，按日期独立加载 |

Web Locks 是同一浏览器 storage bucket 内的合作锁，默认独占；回调完成后释放，写入没有逃出回调生命周期。它只约束使用同名锁的参与者，不声称能阻止旧版标签页、第三方脚本或开发者工具直接写 localStorage，也不提供跨设备同步。依据：[W3C Web Locks](https://www.w3.org/TR/web-locks/)。无锁环境的记录只能在当前页面内存保留，离开前必须导出。
