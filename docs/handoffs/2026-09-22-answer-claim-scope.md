# 2026-09-22 · 把「口径越界」从人工判断变成确定性判据

## 为什么做这件事

K3 写手 / 无判官上线卡在两项验收，其一是**内容质量**（另见 `2026-09-22-k3-acceptance-readonly.md`）。09-21 两次真实首跑的接线是成立的（K3、终稿判官 0 调用），但答案里有四条**结论比证据宽**的表述。既然目标就是不要 LLM 判官，那这四条就必须有**不依赖模型的判据**，否则每次上线都只能靠人逐句读，读一次签一次，不可复跑也不可回归。

本轮产出的是判据本身，**不是内容质量通过**。

## 做了什么

`intelligence/services/answer_claim_scope.py`（新）逐句检四类形状，命中给原句、理由与改写方向：

| 规则 | 触发条件 | 豁免 |
|---|---|---|
| `latest_trading_day_unverified` | 断言某日是「最近/最新交易日」 | 取过交易日历；或写明库内/截至某日/快照口径；或本就是否定句 |
| `scope_claim_exceeds_comparison` | 全称范围词（所有/全部+板块/行业/可比公司…） | 实际比较数 ≥ 已知全集；或句内自带「已比较 N 个」这类限定 |
| `fund_flow_claim_without_flow_evidence` | 断言资金/主力净流入流出 | 本次取过资金流；或句内明写未取资金流、不据此判断 |
| `unit_gap_claim_contradicts_input` | 声称输入未注明「单位」而题面已给数量单位 | 只说币种未知；题面确实没给单位 |

`scripts/check_answer_claims.py`（新）把一次冻结 run（`run.json` + `continuous-episode.json` + `answer.md`）读成证据上下文——证据日期、是否取过日历、是否取过资金流、板块比较了几个——再跑规则，命中退出 1。**下次真实验收可以直接跑它出结论，不必重新讲道理。**

## 关键点：检出器自己被真实语料抓出三个缺陷

这是本轮最有价值的部分。写完规则先拿两次首跑和仓内已归档答案压，**三次都是语料赢**：

1. **误报**：材料题的「材料没有给出**单位投资额**对应产能…」「…折旧摊销、**单位成本**…」被判成单位缺口。`单位X` 是指标名，不是「缺单位」。→ 要求「单位」后不再接汉字（允许接「的」或标点）。
2. **漏报**：真正的缺陷句「材料未注明公告日期、是否审计、合并或分部口径及**币种单位**」距动词 20 字，短窗口接不住。→ 窗口放到 30 字，靠上面的收尾条件压误报。
3. **误报**：仓内 golden 快照的「以下使用截至 2026-07-08 的历史盘面快照…**不能视为最新交易日复盘**」被判违规——这句说的正是本规则想要的写法。→ 加否定句与快照口径豁免。

**教训可迁移**：检测器不拿真实语料压，就只是把作者的想象写成了正则。这三条都不是「多写几个关键词」能提前想到的，全是语料撞出来的。三条都留了回归测试，用的就是原句。

## 决策与被否方案

| 选择 | 不采用 | 理由 |
|---|---|---|
| 新建独立 lint 模块 | 塞进 `output_review` | 那条路要的是 AskResult 结构化产物，且主要服务 `ask.py`；本轮四条规则要的是 Episode 证据上下文，硬塞会把两种输入搅在一起 |
| 离线 CLI 判据 | 直接改实时作答链 | 改线上要部署授权，而当前生产还在回滚版；先把判据钉住，接入单独议 |
| 缺上下文时沉默 | 缺上下文就报警 | 范围/单位两条没有分母就无法证伪，宁可漏报也不制造噪音（日期/资金流两条纯文本可判，照常报） |
| 拿真实首跑+仓内答案调参 | 只用自己写的样例 | 自造样例只能验证作者想到的形状，三个真缺陷全是真实语料抓出来的 |
| 保留误报修复的原句做回归 | 只写抽象用例 | 原句才是下次改正则时真正的护栏 |
