## 背景：修的是什么

`urlopen(..., timeout=T)` 的 T 是 **socket 空闲上限**——两次收到数据之间最多等多久，对端吐任意一个字节即重置；
它不是 **absolute deadline**（整次请求最多运行多久）。原实现把获批秒数当后者用，于是持续滴流的对端能把一次调用无限延长。
13 个探针场景里 7 个越窗，最狠的 `judge_late_report`：批 0.8 秒、2.94 秒才回包，却记 `status=success` 被采纳，
剩余预算还按"对方守约"记账——超时语义一错，判官可用性与预算归因一起不可信。

## 决策与被否方案

| 决策 | 否掉的选项 | 理由 |
|---|---|---|
| 接管在途改动 | 另起炉灶重写 | 实现读下来是对的，重写只会丢掉已有考量，且与生产者工作冲突 |
| 探针改走真实传输层 | 保留探针自建 opener | 探针自己绕过被测对象，它的绿证明不了产品行为 |
| 变异验证四条 | 只看"测试全绿" | 全绿可能是测试没绑住保护；M2/M4 起初正是如此 |
| 测试放宽到远大于 spawn 开销 | 加重试 / 加 `flaky` 标记 | 重试把"机器忙"和"实现错"一起吞掉；根因是断言选错了量 |
| 断言"worker 未活过截止" | 断言返回码必须是 124 | 过度指定机制：慢 spawn 下另一条同样正确的停止路径先触发 |
| 改 8 个测试文件的桩签名 | 让生产代码改用关键字传 timeout 去迁就旧桩 | 契约由传输层定义，迁就测试等于把契约倒挂 |
| `daemon` 加进门禁 ALLOWED | 删掉 timer / 硬造一个读取点 | 读取点在 stdlib（`Thread.start()` 读它）；与既有 `sock` 条目同类，已按同样格式注明理由 |
| 提交后再跑完整门禁 | 用提交前那次的绿当验收收据 | 收据要绑得住 SHA；提交前跑的说不清对应哪份字节 |

## 已知代价（必须传下去）

**每次 HTTP 调用多一个子进程启动**：空闲约 0.15 秒（`fast` 场景 0.024 → 0.166 秒），高负载实测可 >0.35 秒，
且**算在调用预算里**——截止时钟在 spawn 之前就起跑。生产窗口是几十秒，占比 1–3% 可接受；
但**亚秒级窗口（如判官只批 0.8 秒）现在会比以前更早失败**。这是用延迟换"截止可信"，是自觉的取舍，不是 bug。
若将来嫌贵，方向是常驻 worker 复用进程，**不是**把 spawn 排除在预算之外（那等于又把绝对截止让掉）。

## 可迁移知识点

- **"超时"至少有两种**：socket 空闲超时（两次数据之间）与绝对截止（整次请求）。只说"超时 30 秒"是没说清的，
  流式接口上二者差着无穷大。
- **测试替身不会自动跟着契约走**。改了被 mock 对象的签名，全仓的假实现都是潜在的红；它们不受类型检查保护。
- **变异验证是"测试有没有在守"的唯一硬证据**：绿只说明没踩雷，杀掉变异才说明有人看门。
- **时间断言要选对被测的量**：断言"某条具体路径触发"会把环境噪声算进来；断言"有没有越过界"才稳。
