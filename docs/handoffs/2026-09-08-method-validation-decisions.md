# 第一条方法实验：实施决策留痕

背景：用户已将基础强化 spec 交给另一任务，随后授权本会话推进第一条方法验证闭环。基线 `f90af450` 已有标签、收益、规则编译与统计四态；现有统计回答的是“绝对上涨成功率”，本轮问题是持续性是否比当天双红增加信息。于是保留旧管线，新增研究应用和协议。

| 选择 | 未采用方案 | 原因 |
|---|---|---|
| 先固定双红候选的三组研究 | 通用任意knowhow DSL、修改原seed的成功定义 | 用户已接受从这条候选推进；把新比较问题塞回旧二项成功率会混淆含义 |
| 同日板块等权、再日期等权，完整基准才比较 | 平铺板块日算“独立N”；缺成员时自动缩基准 | 市场共振和缺数据会制造看似更多的样本、偷偷改变比较对象 |
| 冻结观察，结果另读另存 | 回检时重跑最新标签 | 标签重算不应改写当时到底选了谁 |
| 归档校验和当前计算兼容门分开 | 所有读取都绑定当前LABEL_VERSION | 模拟升级后旧报告曾打不开；物理文件保留而无法读取，不满足失败可回溯 |
| 持锁后及写前读取实际时钟，非阻塞锁 | 在可能等待的锁之前只读一次now | 质量审查用23:59:59→次日00:00:01重现了补登记；修后拒绝且不落观察 |
| 实际收盘与构建时刻门 | 只相信旁路calendar和source_max已过五日 | 规格审查把未来日期写进测试库，D0当天曾得到paired；修后拒绝，不产生提前结算 |

首轮协议在收益比较前登记。当前源码默认只支持这一候选，未来其他knowhow须增加明确版本实现，不能把任意JSON解释成规则。程序没有改变生产只读工具注册表、运行时或数据采集链。

先用真实旁路核版本与水位：v3、416个日历日、水位09-07、标签09-08重建。历史运行因此明确是重建研究，不能追认过去日期的前瞻。首跑和最终代码复跑数值一致；最终仅2个共同完整日期，保留负的描述性差值，不降低数据门制造更多样本，也不据两天宣布规则失效。

验证、原件、测试收据及实际数字见 [交付说明](../verification/2026-09-08-method-validation-loop.md)；操作见 [工作流](../workflows/method-validation-loop.md)。严格PIT、源日历完整性和统计认证仍由基础强化任务处理，两个任务衔接时应传完整协议和板块日记录。

后续应做：核查18个信号日为何只剩2个完整比较日，从前向起点09-10开始真实提前登记。不要做：把两个软件复跑算两次独立实验、把新版本成功覆盖旧版失败、把未发生的前向样本算成已验证结果、自动修改个人画像或参数。
