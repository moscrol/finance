## 背景

上片已让原句、审查阶段和理由回原Episode，也抓到并修复“丰富诊断改变预算分类，误挡材料零工具修订”的退化。但还有两个明确空白：SDK会截取20项/每项500字符且没有复用领域重写提示；数字条件的具体诊断直到原补证轮用完才送达，此时进度或预算门可能不准再修，留下“但上涨家数仍待改善。”这样的删前件残句。

目标是在原授权内更完整、更早地提供信息，不加研究回合、不直接替模型改写、不把私有gaps拼到正文。

## 决策与被否方案

| 方案 | 评价 | 结果 |
| --- | --- | --- |
| 复用领域 `repair_goal_message` | 所有运行后端应消费共同消息合同，避免修复文案只在单后端生效 | 采用；本片仅改SDK |
| 在SDK再维护一套金融重写提示 | 两份规则会漂，私有裁剪会切坏结构诊断和原句 | 否决 |
| 解析领域提示JSON后合并快照 | harness合同是字符串，也允许纯文本；解析会暗中收窄合同 | 否决；改用外层 `REPAIR_CONTEXT` 保留原样消息 |
| SDK缺历史时重开工具研究 | 已有快照不是完整provider会话，不应借修订扩研究链 | 否决，沿原拒收规则 |
| 原数字补证已获准后添加具体诊断 | 在原有机会尚未消耗时给模型原句，不改变动作许可 | 采用 |
| 等删句后再无条件追加一轮 | 绕过无进展/耗尽门，诊断本身不能创造行动额度 | 否决 |
| 补证前诊断冒标preflight判决 | 此时只是取证请求，尚未作删除判决 | 否决，显式 `before_backfill` |
| 自动恢复拒句或替模型补转折/gaps | 会重新引入无支持断言或把私有说明当事实 | 否决，仍由模型在原会话里修订 |

去掉隐蔽截短会使部分输入更长；没有实测token费用、速度或上下文窗口极限。未来若压缩，要在共同接口保留完整语义单元并显式说明遗漏，不重新偷偷截半条JSON。
