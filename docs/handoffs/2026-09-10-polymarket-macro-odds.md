## 背景

不读这段会误判后面每个决定：**Polymarket 的价格不是事实，是市场定价。** 它是搭在 Polygon
链上的去中心化预测市场，某个结果的份额价格（0~1）即市场对该结果的隐含概率。所以这张表
天然是「别人怎么赌」，不是「会发生什么」——`intelligence/services/finance_query.py` 的
`_UNREGISTERED_TABLES` 里把它标成 `candidate` 而非注册可读，就是因为「agent 该怎么引用
（当独立信号还是仅供人工参考）」这个问题**本轮没有答案，也不该由实现者单方面拍**。

接入动机是三类事件与 A 股有传导：宏观（Fed/FOMC 利率路径）、地缘（Geopolitics/Military
Strikes/China，影响风险偏好与油价）、加密（Crypto/Bitcoin，部分 A 股概念股联动）。刻意
不接 Elections 大类——各国地方选举居多，噪音压倒信号。

本轮接手时前一个 session 已完成：schema 建表、sync 模块、CLI 子命令、`_UNREGISTERED_TABLES`
声明、6 个测试。**接手的直接触发点**是用户指出一处测试自身的错误（见下「发现 0」）。

## 按发现顺序

### 发现 0：那个失败的测试是测试写错了，不是代码错

用户判断：`test_fetch_returns_partial_and_flags_truncated_when_upstream_stalls` 的假数据第一页
只放 1 个事件，而 `fetch_relevant_markets` 有「短页 = 最后一页」的正常提前退出
（`if len(events) < page_size: break`），所以压根走不到第二页，也就测不到「第二页中断」。
处方：`page_size=1` 让第一页变成「满页」，分页才会继续。**这个判断是对的**，我核过代码路径，
并按此保留。可迁移教训：测分页/重试逻辑时，假数据必须让被测的翻页条件真的成立。

### 发现 1：门禁与审计本来就是绿的

`ruff check .` 全绿；`market_feature_store.cli registry-check` 通过；
`scripts/audit_dataset_registration.py` 通过（51 张表 = 34 注册 + 17 豁免，新表走豁免声明）。
所以本轮不需要补注册——**新表没进 consumption_registry 是有意的**（只落库、不接夜跑）。

### 发现 2：实跑挖出真问题——上游 `closed=false` 不可信，30% 的行是已结算的旧市场

用 `MARKET_FEATURE_STORE_DB` 指临时库做端到端实跑（**全程没碰生产库**），得 1106 行。
值层面初查很干净：probability 无 NULL 无越界、每个 market 概率和精确 = 1.00、end_date 解析正常。

但抽样「成交量最高」时看到 `Netanyahu out by March 31? → Yes = 0.0`，而当天是 9-10。量化后：

| 交叉 | 行数 |
|---|---|
| 未过期 × 概率正常 | 708 |
| 未过期 × 概率退化 0/1 | 68 |
| **已过期 × 概率退化 0/1** | **324** |
| 已过期 × 概率正常 | 4 |
| end_date 为 NULL | 2 |

即 328/1106（30%）的行 `end_date < trade_date`，涉及 164 个 market，其中 324 行概率已退化成
0 或 1——**就是已经开奖、只差上游改状态的旧市场**。

危害不在「多几行」，而在**它们历史累计成交量很大，按 `order=volume` 排序直接占据头部**：
今天按成交量取 top N，会拿到一堆三月份就有答案的旧问题，而它们长得跟前瞻概率一模一样
（都是 0~1 的数）。agent 一引用就是**把结算价当预期读**。这正是 AGENTS.md 警告的形状的变体：
覆盖率审计只抓行数，抓不到「行在、值是旧答案」的语义陈旧（比「值全 NULL」更隐蔽，因为值非空且合法）。

### 发现 3：病症不是「挂死」是吞吐坍塌，且重试立刻就能成

修完过期过滤重跑，第一次就在**第一页**耗尽 45s 预算返回 0 行。原文件头的诊断是「单发正常、
同进程连发第二页才挂」，与此矛盾。同进程连探 8 次（每次 8s 预算）：

```
成 / 挂 / 成 / 成 / 挂 / 挂 / 成 / 成      → 坍塌率 ~37%，且挂完紧接的重试立刻成功（3.3~7.7s）
```

再测响应体本身：

| 状态 | 大小 | 耗时 | 吞吐 |
|---|---|---|---|
| 健康 | 9.85 MB | 4.2s / 8.1s | 1.2~2.4 MB/s |
| 病态 | 读到 0.59~0.66MB 就超时 | >30s 放弃 | **0.02 MB/s** |

结论：连接不断、字节一直涓流，只是**慢 100 倍**。所以 `urlopen(timeout=)` 这个 socket 超时
**永远不触发**（每次 recv 都刷新计时），必须自己按总时长掐——这一点原实现是对的。
但「一挂就放弃」是错的：默认只拉 1 页，等于**夜跑约 1/3 的夜晚整天 0 行**。

### 发现 4：服务端按 tag 过滤这条路探过，不走

想减小 9.85MB 包体以降低坍塌暴露面：

| 方案 | 实测 | 结果 |
|---|---|---|
| `tag=geopolitics` | 包体 9.85MB，与不传完全一致；样本里出现 ATP/Aliens | **参数被静默忽略** |
| `tag_slug=geopolitics` | 生效，20/20 事件确实带 Geopolitics 标签 | 有效但不采用 |

不采用的理由：包体大小由「每个 event 内嵌多少 market 元数据」决定（**~100KB/event**），
过滤只减少事件条数、不让单个 event 变小。按 14 个白名单 tag 各发一次请求，总字节更多、
且每次请求独立承担 ~37% 坍塌率，整体可靠性反而更差。故维持「一次大请求 + 客户端白名单过滤」。

## 决策表

| 决策 | 选了 | 否了 | 为什么 |
|---|---|---|---|
| 过期市场 | 入库前剔除（`_is_expired`，`end_dt < today` 才丢） | ① 信上游 `closed` 字段 ② 保留并加 `is_expired` 列让下游过滤 | ① 实测 30% 行是过期的，字段不可信；② 这些行占 volume 排序头部、外观与前瞻概率无异，指望每个下游都记得过滤 = 把坑留给别人 |
| 同日到期 / 无 endDate | 保留 | 一并丢 | 同日仍在交易；endDate 缺失（实测 2 行）属无法判定，不能当过期 |
| 过期判定基准 | `date.today()`，不跟随 `--trade-date` | 用 trade_date | 接口只有「当前」快照、无历史参数，`--trade-date` 只是标注日 |
| 坍塌 | 重试 3 × 15s，总天花板仍 45s | ① 不重试 ② 加长单次预算 | ① 夜跑 1/3 夜晚落 0 行，而重试仅 ~4s；② 病态 0.02MB/s 下读完 9.85MB 要 ~500s，加长不解决 |
| 包体 | 一次大请求 + 客户端过滤 | 服务端 `tag_slug` 逐 tag 拉 | 见发现 4：总字节更多且坍塌暴露面 ×14 |
| 三次全挂 | 返回已抓部分 + `truncated=True`，CLI 印「部分快照」 | 抛异常让夜跑失败 | 诚实降级优于全无；但**要求调用方照实标注**，不得当全量用 |

## 验证与收据

- `pytest tests/test_sync_polymarket_macro_odds.py` → **9 passed**（原 6 + 过期剔除 + 边界 + 重试恢复）。
- 全量 `pytest -q` → **9070 passed / 77 skipped / 1 xfailed / 0 failed**，361.87s。
  收据 `~/.finance-runtime/test-receipts/20260910T*-3ed44703.json`。
- `ruff check .` 全绿；`registry-check`、`audit_dataset_registration.py` 通过。
- 真实端到端 8 次（临时库，**未写生产库**）：修复后稳定 778 行 / 53 事件 / 389 市场、4~6s。
  值层面：过期残留 **0**、每 market 概率和精确 = 1.00、probability 无越界无 NULL、
  volume 头部全为前瞻问题（FOMC 9/16 三结果 不变 37.5% / 加息25bp 62.5% / 降息25bp 0.35%，自洽）。
- 重试有效性：加之前 3 次里挂 1 次；加之后 5 次里 4 次成功（其中 1 次是「挂 1 次 → 重试成功」，
  1 次三连挂耗满 45s 返回 0 行并标 truncated）。

**不成立的结论**：坍塌率「~37%」来自 n=8 的单次探测、且是同一时段同一出口 IP，不能当稳定
SLA 读；「3 次重试够用」同理只有 n=5 的支持。要定夜跑告警阈值必须另做多时段观测。
