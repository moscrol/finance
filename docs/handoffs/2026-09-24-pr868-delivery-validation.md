## 发现与动作

1. 读取 Pi 扩展 API 与真实 CLI 回归，确认工具执行抛错会把错误反馈给模型，而成功返回 `terminate: true` 会终止阶段。原 `deliver_stage` 只核 probe_files 非空，实际路径到 `run_stage.py` 退出后才检查，因此错误没有修正窗口。
2. `pi_review_protocol.mjs::validateExploreProbes` 在交付接受前核非空数组、绝对路径、普通文件、真实路径归属当前轴的 work/probes，拒绝软链接越界和探针根重定向；与原退出检查对齐，目录内至少有一个直接位于根下的普通 `.py` 文件。验证只观察，绝不修写审查者路径。
3. 生成器将验证放进实际交付工具。失败时不写 submission/REPORT，不标 delivered；保留原始请求及拒收结果。还有阶段预算时返回工具错误，由模型自己纠正；最终保留请求、请求硬上限或 deadline 已到时直接拒绝。原阶段结束后的身份、文件与输入指纹校验仍保留。
4. 两个审查轴均测试普通修正，以及第 16 次失败、第 17 次最终请求修正。关掉即时验证的临时变异输入会退回旧行为：一请求后退出，最后结构校验失败；原始错误路径仍原样可追溯。
5. 首轮路径夹具误把 `/private/var` 删前缀当无效路径，但 macOS `/var` 是有效别名。改用明确缺少工作区根的路径，不改变产品规则。开发失败收据保留。
6. 提交后冻结复验遇到另一个 #813 审查进程占用 19899，产生 4P/53S，未采信为通过。测试夹具改为先绑定操作系统分配的独占 loopback 端口，再只替换临时测试输入中的路由及一致性检查；正式生成物仍锁定原 19899，未停止或访问其他审查服务。

## 方案取舍

| 方案 | 结果与理由 |
| --- | --- |
| 宿主替审查者补 `/Users` | 否。会改写独立交付，并掩盖实际输入错误。 |
| 只保留退出后校验 | 否。虽能拒绝错误，但已终止的模型无法使用剩余预算修正。 |
| 即时拒收 + 原退出校验 | 采用。修正机会在预算内，交付后文件变化仍会被拒。 |
| 每次错路径另赠请求或重开封存批 | 否。内容修正消耗原阶段预算，最终请求没有追加额度。 |
| 调停占用 19899 的另一会话 | 否。隔离测试端口即可，不干预别人的进程或授权。 |
| 新造独立审查框架 | 否。扩展现有协议与测试足够。 |
