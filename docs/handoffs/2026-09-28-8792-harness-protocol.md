## 发现与决定

1. 首次提示和纠错提示要求六字段，旧解析器却仅收五或七字段。固定合法回复在旧实现调用两次后报 `unparsable_response`；TaskFrame 检索下限仍在，不能将此例写成零检索。
2. 冻结回归另证实：先对齐、后校验的顺序让无效回复污染目标、假设、歧义，并提前触发澄清；成功重试的补充未被采用。旧实现四例为 3 failed / 1 passed。
3. `14a6059ee` 新增纯 `controller_protocol`，共用字段与类型定义、首次/纠错形状说明；先通过协议与路由校验再补充任务，只向 TaskFrame 传三个模型可补充字段。旧五/七字段精确兼容，`required_outputs` 仍由任务合同拥有。门页同步于 `d98eb1978`。
4. 固定基线的研究接线复验 63 项通过：精确板块/日期/成员、注册与实际模型菜单、阶段逐层传递、工具局部错误保留证据与同 Episode 补查。没有证据支持重写这些已有机制。

| 方案 | 取舍 |
|---|---|
| 只给 parser 增加六字段 | 否：首次提示、纠错提示与解析合同仍可独立漂移。 |
| 接受任意字典或取消校验 | 否：无效回复仍可能污染任务与路由。 |
| 新增引擎、增加重试或放宽判官 | 否：本次反例不需要，且会混入新变量。 |
| 单一协议 + 接收后补充 | 采用：修复格式与状态更新边界，保留原策略、预算及检索义务。 |
