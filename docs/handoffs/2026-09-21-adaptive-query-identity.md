## 按发现顺序

1. 代码地图返回 empty，未据此声称架构不存在；沿产品门、原始事件及实际源码核对。
2. 原 `_semantic_tool_status_registry` 按 capability/status/result_count/source_trade_date 去重。
   旧本地风险 on 样本的监管、行情、核心股三次查询均为 finance_query/empty/0/None，因而被合并。
   provider detail 有数据集文本，但从诊断散文反解不适合作为身份合同。
3. 原始父会话事件已含 call_id、arguments 和结算，改为直接使用该真本。
   先补 8 个复现，旧实现实跑全红；不是收集错误或空测试选择。
4. 新投影按本轮唯一 call_id 配对；请求须早于结算且工具一致。
   缺编号、重复请求/结果、错工具、晚到请求、未结算均保留记录但不猜查询范围。
5. 对 finance_query 沿用 `FinanceQuerySpec.from_arguments` 的结构解析，传原请求参数，
   包括数据集、筛选值、窗口、排序等。结构解析不是数据覆盖、参数业务有效性或权限认证。
   其他工具目前仅投递调用状态，不传自由文本参数；子研究/预取没有父事件对应时只有 trace。
6. `execution_status=returned/error/unresolved/unverified_result` 与 provider 的 status 分开。
   delivered_evidence_count=0 仅表示没有交付证据，不是源表行数或无风险结论；不造 E 卡。
   provider trace 保留请求/服务日期与窗口，不再粗去重，不按工具名或顺序与调用行拼接。
7. 查到通用 JSON 空值压缩还会删查询条件中的 null/空字符串，给 requested_query 保留原表达式。
   测试覆盖 null、空字符串、false、0、空数组和开放起点，不把展示压缩套在数据语义上。
8. 原检查器增加显式 `--project-current-judge-status`，四题八臂在新目录离线重建。
   输出 origin 明确是当前代码重建，不是历史实际判官请求，也不是新模型复验。
9. 旧空行情查询使用裸代码 300308，而后续按名称得到的行情行是 300308.SZ。
   编译探针确认监管查询仍绑定 `stock_ts_code = '300308'`，不自动补后缀；
   finance_query 和监管入库源码自旧实验 ced8203c 未变。没有读取主库或执行查询，
   不能确认旧监管表真实代码分布、该股是否在表内或查询覆盖完整。

## 决策与被否方案

| 方案 | 评价 | 结果 |
|---|---|---|
| 从已有事件按唯一调用身份配对 | 请求与结算已有真本，乱序返回也可正确关联 | 采用；异常配对保守缺省 |
| 给 ProviderTrace 再加一份查询真本 | 需要多个生产者同步写入，旧数据仍缺字段 | 本片不采用 |
| 解析 detail/observation 或按工具名、结果顺序猜配 | 同工具异查询/并发/错误路径会错配，诊断格式不稳定 | 否决 |
| 仅扩大粗状态去重键 | trace 缺调用与数据集身份，仍不足以还原查询 | 否决；保留独立过程记录，不相加计数 |
| 把空查询包装成事实 E 卡 | 把“未见结果”升级为“事实不存在”，污染证据链 | 否决 |
| 在判官输入里补认股票代码、补查询或扩大窗口 | 请求事实被改写，会掩盖原始口径错误 | 否决；原样保留并承认覆盖未核验 |
| 复用 inspector，在封存包外输出 | 保留失败样本与旧哈希，避免第二套审查脚本 | 采用 |
| 把本片工程通过当成质量/上线通过 | 无新自然模型记录，正文保真仍失败 | 否决，继续阻断 |
