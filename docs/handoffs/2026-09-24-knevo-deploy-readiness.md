## 决策与被否方案

| 选择 | 被否方案 | 理由 |
|---|---|---|
| 合入当时主干后按版本分别取证 | 用旧定向收据签新组合 | 基底、代码和运行输入不是同一个身份 |
| 私有尝试历史与最终裁决分离 | 只保最后一次，或把历史 pass 沿用 | 前者抹证据，后者误授权新稿 |
| 保留原题/八问/来源/预算/判官 | 减题、补引用、改 kind、加重试、关判官 | 会改变被验的交付合同，不能修复原问题 |
| 模型/字段顺序实验只作诊断 | 单次合法 JSON 或报告返回就上线 | 语法、来源绑定、金融语义与稳定性是不同证据 |
| 完整绿与早先 8 红共同保存 | 只留下最好的一轮 | 同版本不一致尚未归因，不具备可删掉的失败 |
| 本地候选不推送 | 以工程绿替代用户授权 | 未获推送合并结果或生产切换授权，且语义仍失败 |

## 工具沉淀与后续

已将审查历史的机械留证/脱敏能力放进现有 runtime 与 `knevo_regression`，没有新建第二个产品入口。仓外模型探针绑定冻结私有请求，只做有限诊断，未包装成生产开关或通用验收工具；原因是接线可机检，金融蕴含和小样本稳定性仍需独立核验。

跨任务原则写入共享记忆 `contract-vs-delivery-mismatch` 的“最终状态不是尝试历史”。`harness-reference/BUILD.md` 有他人在途改动且本地领先远程，未越界改动；本轮不另造通用组件清单。首次全仓应带完整失败详情的教训写入项目 lessons。

2. 保留并定位 8 项保活测试的整仓不一致。最新完整绿收据成立，但不能据此宣称不稳定性已修复。
