# 切换中断补偿补查 · 2026-10-07

本轮第二轴 Spec 复核指出：命令返回码失败虽有补偿，INT/TERM中断会绕过正常调用栈，停服后可能直接退出。这项是独立发现，不能用此前69项夹具或Standards批准覆盖。

在停服命令发出前登记切换在途状态，注册INT/TERM/HUP处理；捕获后沿既有补偿流程恢复旧链接、旧SHA账本和服务。补偿过程有同样的卸载等待与启动重试上限，忽略重复信号，避免恢复重入或半途再次中断。恢复成功返回原信号退出码130/143/129；恢复不完整返回7并保留失败标记。新版本启动并完成记账后清除在途状态。

否了只改文档缩小承诺：TERM发生在启动重试或等待卸载阶段是正常可遇到的操作边界，保留中断补偿比要求操作人记住手工恢复可靠。否了恢复中立即响应第二次同类信号：会再次留下半恢复状态。SIGKILL、断电和宿主故障无法捕获，规程明确这个物理边界，不能宣称任意中断都可自动恢复。

隔离夹具在首次bootout成功后的等待段发送INT、TERM、HUP，验证各自退出码、一次恢复、旧SHA账本及旧服务启动；另验证中断后的回滚账本失败返回7。四项通过，收据 `~/.finance-runtime/test-receipts/20261007T021425Z-2f7a24d3-828d21f1525d.json` 为dirty定向迭代读数。没有操作生产服务。本实现的最终回归、变异及当前head CI需另核，旧脚本blob批准不移签。
