## 结论：不只是三个写手错误

共同结构性问题是：**把低维统计摘要及启发式分类，当作含义充分的历史比较证据交给写手；源端对象的身份、定义、集合范围在文字化时没有完整保留。** 之后用完整传输保证这份文本原样送达，但传输验证不会修正源端读数的适用范围，也不会补回此前已丢的含义。

分清四类责任：

1. **方法适用性缺口**：突出度在小候选集下受数学上限约束，不能直接套同一判断阈值。
2. **领域概念混合**：距离贡献小不等于趋势方向一致，签名相同不等于逐日路径相同。
3. **对象到材料的含义损失**：候选筛选策略、百分位定义及窗口身份没有稳定地作为计算对象的一部分送达。
4. **写手越界仍成立**：已给日期与逐维数值，GLM 仍误判重叠、把走平说成反向、把展示子集扩成全部。上游问题不能替这些错误免责。

这是确定性程序行为与原件的归因，不声称知道 GLM 内部为何选择某句话，也未证明一种新表示就能让模型稳定改好。

## 按发现顺序的证据

### 1. 先排除工具传输遗漏

重新调用原两库的 `history_payload()`，与第二轮送给 GLM 的 `expected-tool.json` 对象完全一致，库前后哈希不变。旧两轮封存清单分别 58 / 85 项再次全部核验。既有观察器已证明第二次真实请求携带同一完整工具文本。

因此当前问题不宜继续归为 pi 把表截短、拿了不同库或换了模型。这个排除只适用于已封存两例；没有为真库、其他入口或多轮担保。

### 2. 突出度的小样本结构性偏差

源码：`intelligence/services/river_lens.py::landscape`、`Landscape.reading`。

现公式：`s = (Q05 - d1) / (Q50 - Q05)`；Q05/Q50 分别是升序候选距离的第 5 / 50 百分位，采用线性插值，不是第 5 / 50 名。代码用 `s >= 1` 读成「排名相对突出」，`s < 0.2` 读成「候选排名不突出」。

设距离 `d1 <= d2 <= ... <= dn`，当 `3 <= n <= 20`，令 `a=0.05*(n-1)`：

- `Q05 = d1 + a*(d2-d1)`；
- `Q50 >= d2`；
- 若分母为正，则 `s <= a/(1-a)`（舍入前）。

所以 n=6 时上限为 1/3，n=7 时上限为 3/7；**这两种规模下永远达不到代码的 1.0 判断阈值**。原真实两例正好分别只有 6 / 7 个 river 候选。

纯函数反例：最近距离为 0，其余全为 1、100 或 1,000,000，n=6 的 s 均为 0.333，n=7 均为 0.429。n=2 时 `[0,100]` 得 s=0.111，源端直接输出「候选排名不突出」。同样保留一个零距离最近者和远离的其余候选，改变集合大小就可跨过分类阈值。

**判定**：公式数值没有算错，但它不是与候选数无关的突出程度认证。量纲不变性不能代替小样本适用性。不能只向模型解释 p5，也不能为两例调低阈值即宣称修好。此证据同样不证明原两例最近者事实上突出；只是撤销当前类别作为可靠依据的资格。

### 3. 「对齐」混合了距离大小与方向

源码：`river_lens.py::DimDelta.contribution/verdict`。贡献是 `abs(均值差) + 0.5*abs(首尾段差之差)`，不超过 0.5 就标「对齐」。箭头在 `lens_block()` 另按首尾段差的 ±0.3 判断。

反例：均值都为 0，当前首尾段差 −0.31、候选 +0.31；贡献仅 0.31，标「对齐」，同时箭头为 ↓ / ↑。这不违反距离算式，却直接否定函数旁「不能把反向走势报成对齐」注释的普遍性。已有反向测试只测 ±4 的大幅情况，不能支撑该泛化。

原 changed-gap 材料中偏离度 −0.51 / +0.06、贡献 0.40 也标「对齐」。按现箭头口径，这是下降 / 近零，不是下降 / 上升。不能把「距离贡献小」「方向相同」「变化很小」压成一个 verdict；也不能倒过来因方向不同而偷偷改距离公式。

### 4. 签名从一开始就不是路径

源码：`market_regime_analogs.py::window_signature`。每维仅保留全窗 z 均值与末三分之一均值减首三分之一均值。

把 `[0,0,0,0,0,0]` 与 `[0,0,10,-10,0,0]` 在同一拟合范围标准化，两窗签名完全相同，距离为 0；中间过程却不同。**均值与首尾段差无法恢复中途波动、先后次序或完整形态。** 首尾段差接近零也只证明该摘要接近零，不证明窗口逐日走平。

这是摘要表示的能力边界，不是反对使用签名筛选。筛选相近环境可以用它；要回答路径、转折、持续性，须沿既有历史查询/路径追踪读取对应证据，不能让语言模型从摘要还原不存在的信息。本轮未新增路径工具，也未发送新材料。

### 5. 对象到模型材料的含义损失可以定位

源码：`market_history_context.py::HistoryBlock/market_history_blocks`、`river_lens.py::build_lens/LensResult.to_dict/lens_block`、`market_regime_analogs.py::_find_regime_analogs/regime_block_for_llm`。

| 环节 | 可核对事实 | 后果与边界 |
|---|---|---|
| 百分位 | `Landscape.to_dict()` 有 `standout_definition`；实际文本只送 p1/p5/中位/p90 与「身位」解读，未送公式或「百分位」定义 | 不是 pi 丢字段，而是调用 renderer 时未投影。仅改用现成 JSON 也不够，需先处理方法适用性 |
| D10 选择 | 候选先按距离排序，再贪心选互不重叠的历史窗 | 文本不带该选择策略，也不带筛选前/后数量；模型把展示数当候选池大小 |
| 两套候选 | normal：D10 可比7→展示1；river可比7→展示3。changed-gap：D10可比6→展示2；river可比6→展示3 | 不同特征/选择策略是允许的，不能按序号合并；「分开计算」也不等于统计独立 |
| 重叠 | 两例river展示三窗均只有3对中的2对重叠；changed-gap两D10窗无重叠 | 「存在重叠」「两两均重叠」「后续观察窗重叠」「统计独立」是四个不同命题。日期其实已在原材料中，模型仍有读错 |
| 候选身份 | `build_lens()` 接 `(label,start,end)`，结果只存 `(label,signature,decomposition)` | 同标签、不同日期而签名相同的两个候选可得到完全相同字典和文本。本次 loader 把日期拼进 label，故不是说实跑日期消失；是通用结果类型依赖展示名代管身份 |
| 展示子集 | D10 只展示5个原始均值，比较使用的活动维/首尾段差更多 | 不能用五行的相近推出「全部主要差异仅偏离度」 |
| 来源 | river `feature_sources` 列配置中的全部特征来源，包括未提供路径的判断文件和退出维 | 配置来源、实际读取、有值、参与比较要分开；源码有来源表不等于本次确已读该来源 |

两个同名双红计数还暴露了更上游的定义差异：D10 先 `WHERE` 筛合格行再 `GROUP BY`，无合格行的日没有分组，得到 None；river 在实际有源行的日分组后 `COUNT FILTER`，得到 0。原两例分别有 24 / 22 天一边 None、一边 0。D10 的非空值于是全为1并常量退出，river则保留0/1变化。**共享双红谓词不等于共享日覆盖与缺值合同。** 0可以是「本次已观测源行内的合格数」，却不自动证明完整题材宇宙为0；本轮不据此批量补零或强行让两视图一致。

### 6. 顺带发现的潜在缺日收益问题，不能冒充原题根因

`market_regime_analogs.py::_forward_facts` 对后续5日 `[1%,None,1%,1%,None]` 仍连乘3个非空值，得到3.0301%，`_fwd_text` 称「后续5交易日累计终点收益3.03%」。在缺日时，覆盖阈值通过不等于拿到了完整期限的累计收益。

此为已复现的生产者合同缺口，但**原两组合成数据的指数日涨跌字段完整，没有触发它**。要单列修复与回归，不把它拿来解释本次 p5/重叠错误，也不顺手改变本轮历史样本数值。

## 选型与后续顺序

本轮决定只做到可复现归因与修复方向，不把诊断仓促变成又一批条件分支。

| 方案 | 评价 | 本轮决定 |
|---|---|---|
| 继续追加「p5不是名次」「不要说重叠」等提醒 | 不能修有限样本偏差、丢失的对象身份、路径摘要歧义；继续让写手补做确定性计算 | 否决作为主修法 |
| 换写手、降温、多抽几次或加通用判官 | 尚未修上游，无法分开责任；重抽不能证明正确性 | 本轮不做，GLM身份保持 |
| 直接传 `LensResult.to_dict()` | 比纯文本多一些字段，但候选日期已丢，逐维字典也未保留候选首尾段原值；方法问题仍在 | 不把换JSON语法等同于修复 |

建议实施顺序：

1. 在现有 `MarketRegimeArtifact` / `LensResult` 及共享接缝恢复一份可核对的计算结果：窗口身份与日期、指标定义/单位/缺值口径、拟合范围、候选生成与选择范围、当前/候选原值和首尾段摘要、逐对区间关系、实际来源状态。人读文本与工具结构均从它生成，不另造研究引擎或新台账。

3. 先让上述反例成为长期性质测试（验证数学与领域含义，不是验证某句免责声明存在）：候选规模/平移缩放、反向与近零、同签名不同路径、同名不同窗、候选/展示集合、逐对重叠、None与观测0。还要检查真实模型入口收到的结构与文本含义一致、缺关键范围时不输出强结论。
4. 离线合同固定后才恢复原两例各一次GLM首发；保留旧稿，不重抽绿。两例已参与开发，只能回归，不能签未见场景的泛化。仍只限获准的合成数据；额外真实数据或独立质量验证另定范围。
