## 方案比较

| 方案 | 评价 | 结果 |
|---|---|---|
| 调大 50ms 容差或重复跑到绿 | 仍依赖系统调度，没有固定输入；放松判据 | 否决 |
| 修改生产时钟或两条 loop | 本次证据指向测试输入不同，不足以改生产行为 | 否决 |
| 仅冻结 deadline 模块的测试时钟，精确比较预算 | 等输入测等行为；不污染线程池或其他测试的时钟 | 采用 |
| PR 继续指旧候选根 | 安装时得到不完整修复，文件接线一致也是假成功 | 否决 |
| 立即指向一个合并预览根 | 绕过“合后 main 干净检出”部署约束；不能预知实际合后 SHA | 否决 |
| 代码先验收，部署绑定另交付 | 生产根保持不变；实际升级仍需真实 main、独立绑定验收及安装授权 | 采用 |

## 部署后续

本 PR 不切换生产根，仅合入它不会让夜跑自动用到新版。合入后需要从真实 main 准备干净不可变运行根，单独提交和验收根绑定（sync 两个键、finalize 同步根、S7 缺省及 wiring 常量），让安装源同样来自已合入的干净 main。之后执行 nightly-only dry-run 并重新申请安装授权。

旧 Plan B 停用，不从 QC 预览树或共享脏主树安装。生产请求时序、跨进程次数、每日数据恢复仍待真实部署后验收；本地单测不得替代这些结论。#61 同批部署需基于最终联合 main 重新固定身份。

## 可复用结论

逻辑等价测试应控制时间输入，而不是用更大的误差掩盖不相等的输入。局部替换模块引用能避免全局假时钟干扰线程和超时设施；这个模式适用于重试、额度、缓存到期等测试。沿用仓内 monkeypatch 和收据工具，没有新增生产抽象或测试框架。
