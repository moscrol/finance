## 决策与被否方案

| 问题 | 采用方案 | 被否方案与理由 |
|---|---|---|
| local 夜跑桥接 | 在一个 stock-daily 结果中承接多来源尝试，dump 前置，registry 顺序同步 | 只在另一个编排器增加步骤不能证明真实夜跑可达；把主源与桥各留一个独立最终状态，会让恢复结果与重试归属更难对账 |
| 失败之后何时重试 | 必需行情在下游前原位重试，仍失败即停 | 派生之后末尾重试不能证明派生消费了恢复后的输入 |
| 目标日残留行 | 失败状态与残留行均保留，不自动覆盖 | 删除部分结果后自动补齐，需要另行裁决部分 flush 和恢复范围合同 |
| 覆盖率依据 | 身份表与当日真实 bar 集合交叉核对 | 成分行数不能证明行情存在，更不能把缺 bar 当非涨停 |
| 过期计划 | 执行事务内重新检查目标状态与默认不覆盖政策 | 只在 build 阶段拒绝已有数据，挡不住随后写入；原子事务本身不代表计划仍有效 |
| 整体收据 | 最终状态与每次来源尝试分别记录 | 兜底成功不应抹掉源失败；源失败也不应覆盖最终已恢复的结果 |
| 两项沙箱红灯 | 同提交、同解释器、不同代码目录的对照；后续预览放 /Users | “主线也失败”不足以归因；不得删除测试、放宽权限或把局部复验移签为全仓通过 |
