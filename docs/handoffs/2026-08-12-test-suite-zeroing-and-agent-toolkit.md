## 一、测试套件 15 failed → 0

### 最要紧的发现：测试在往用户的云同步大脑目录里写

`FORESIGHT_USERS_DIR` / `FORESIGHT_USER` / `SUBCONSCIOUS_VAULT` 是用户为「两台机器共享
一个大脑」设的**真实**环境变量，而 `userspace.users_dir()` / `resolve_user_id()` 是
**运行时**读 env 的（这是对的，跨机同步就靠它）。于是不显式指定用户的测试直接落到真人目录：

- 断言 `len(buf)==1`，实际读到 **913 条**真实会话缓冲
- 断言 judgments 文件不存在，实际为 True
- **更糟的是写**：实测测试创建了 `tester/` 与 `alice/` 两个用户目录，真人目录 mtime 被改动，
  而那是云同步 vault ——垃圾会同步到另一台机器

**这不只是「测试挂了」，是测试在污染生产数据。而失败本身是唯一的警报。**

### 三类根因

| 类 | 数量 | 根因 | 修法 |
|---|---|---|---|
| 环境泄漏 | 11 | 见上 | conftest **模块级** pop + autouse 夹具兜底 |
| 金标漂移 | 2 | `monkeypatch` 的 `latest_run` 早已不被 `cmd_board` 调用（重构成扫目录），**mock 成了空操作**，测试读真实 runs 目录，记录从 1 份长到 20 份就红 | 走公开接口显式传 `run`；把钉死整行表头的断言改成断言「三轴各自独立成列」这个真不变量 |
| 依赖缺席 | 1 | 要用知识库仓的 RAG 虚拟环境真建索引，该环境不在本仓 | `skipif` + 明确理由，写死家目录换成 `Path.home()` 派生 |

另修一条时钟敏感偶发：`pytest.approx` 默认是**相对**容差 `rel=1e-6`，对 30.0 即 ±3e-5，
而该值来自活 deadline，真实流逝的几十微秒会被减掉（实测差 4.9e-5）——**单独跑 5/5 失败、
全量跑反而过**。改绝对容差 `abs=0.05` 后 10/10 通过，人为压满 CPU 也通过。

### 修法的关键修正：夹具时机比副作用晚

第一版只加 autouse 夹具，**实测不够**：`pytest --collect-only` 一个用例都不执行，
真人目录 mtime 照样变。因为副作用发生在**模块导入期**——
`from intelligence.api.app import ...` 光是导入就初始化了用户态存储。

> **可迁移：副作用发生在哪个阶段，探针就得架在哪个阶段。**
> 定位过程：逐用例探针一无所获 → 换 `--collect-only` 复现 → 证明是导入期 →
> 按收集单元归因到具体文件 → 单独 `python -c "import ..."` 确认。

### 验证

- 全量 4513 用例 → **4508 passed / 5 skipped / 0 failed**（原 15 failed）
- 收据干净：`dirty: False`、`worktree_dirty_total: 0`、`failed_ids: []`
- **仅收集**与**全量执行**两种尺度下，真人目录 mtime 与条目数均零变化
- 零回归对照：合并前在 main 上跑同一批 = 15 failed，失败集合逐条一致

## 三、「工具包三件套」原则（用户确立）

> **搭建 agent 的能力要沉淀成三件套：正确的设计、正确的搭建、正确的审计。
> 检索源只提供方法论（形状），工具包提供可执行的组件与判据。
> 任何写出来且可复用的组件与工具，必须落进对应那一件，不留在一次性脚本里。**

为什么分三件：三者**失败方式完全不同**——设计错了骨架，后面每步都在补救；
搭建没编目，同一个坑踩 N 遍；审计没有可判定观测量，就拿噪声当信号或长期红着不看。
**本轮那 15 条常年失败掩护了 11 条真实数据污染，就是第三种失败的实例。**

### 落地

| 位置 | 内容 |
|---|---|
| `~/harness-reference/KIT.md` | 三件套总纲 + 现状盘点 + 缺口 + 五条沉淀纪律（新建） |
| `~/harness-reference/BUILD.md` | **搭建工具包**：七个可迁移模式 + 16 个零件（新建） |
| `CLAUDE.md` / `AGENTS.md` | 原则 + 七个模式名 + 三件现状表 |
| `agent-memory` 项目笔记 | 一行索引 |

### 搭建侧的七个可迁移模式（每个由 2+ 零件独立验证）

1. **棘轮式门禁** —— 存量免检、新增拦截。判据是「有没有新增」不是「是不是合理」。
   baseline 从源码**生成**不手抄（手抄会与源码分叉，且分叉时门禁照旧发绿）；
   比对「文件+具体字面量」不比个数。
2. **圈小而稳的一侧** —— 圈底座（15 个、稳定）不圈积木（200 个、会长）。
   新成员默认受保护，没人需要「记得登记」。反向做法实测更贵：改 40 条 import 而非 30 条。
3. **事实投递 > 提醒** —— 在唯一保证被看到的时刻，打出**与错误信念直接矛盾**的那条事实。
   「宿主 python3 会得到偏高的失败数（实测 71 vs 14）」比「请使用正确的解释器」有效得多。
4. **预算 + 声明式截断** —— 砍了什么必须说出来。**限定语必须排在被限定内容之前**
   （放后面会被正文挤出预算，「限定语没了、正文还在」比两者都不注入更坏）。
   尾部预留先生成再量长度，不写死常量。
5. **结论携带成立条件** —— 不追求「让 agent 互相信任」（做不到也不该做），
   而是把验证成本降到几秒。`dirty=true` 的读数跨 agent 一律不可采信。
6. **单一真本源且生成** —— 两处清单必漂（本仓当天就在依赖清单上栽过）。
   算依赖要遍历整棵 AST，不能只扫顶层 import。
7. **认不出来就 fail closed** —— 否则「写错」和「正确」在门禁眼里长得一样。

## 四、本轮踩的坑（都属「量具骗人」族）

- **空对空的差分永远通过**：比对失败集合时变量未词分割，pytest `no tests ran`，
  两侧都是空文件，`diff` 报「完全一致」，差点当成零回归。→ **A/B 差分必须先断言两侧非空**。
- **zsh 不做无引号变量的词分割**（bash 会）。同一个坑犯了两次：第二次是打备份包，
  `for d in $TESTDIRS` 只迭代一次，产出 29 字节空包。没造成损失是运气——删除逻辑用同一个
  错误模式，判假所以一个目录都没删。
- **`touch` 不产生 git 改动**：用它验证「改了代码门禁会不会重新报警」，得到假的「门禁被修哑」结论。
- **「0 未推送」不等于已同步**：`harness-reference` 没有 remote，`origin/main..main`
  静默返回空。见下方缺口。
