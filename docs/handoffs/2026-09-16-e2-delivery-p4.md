## 背景与发现顺序

1. Knevo 旧题就绪性核查发现两个确定性问题：第三题包原有8问却解析出6问；acceptance 同一 case 的 followup 每次新建会话。这只证明管线有缺陷，不证明模型必然漏答/失忆。旧样本已揭盲，只用于诊断，不算独立胜负。
2. 解析修复 `5ebd6e61`：第7问以“有两个后续案例”开头、请求在续行，弱材料识别提前吞掉整段及第8问。完整题体参与候选判定，保留外层材料认领/强保护/编号连续性。三份题面夹具只含问题，不含外部原答。
3. 采集修复 `2e81b2ae`：case 内复用会话、case 间隔离；按 POST 返回的本轮 run/message 身份等待消息自己的非空终稿，不拿迟到旧答代替，不把 run claim 当消息已写完。创建/提交/轮询共享 deadline；失败即停止 followup。CLI 0仍可表示“失败证据成功落盘”，不等于题目通过。
4. P4 初始反例修正了测试 API/类型用法后，得到真实行为红灯14F/7P；此前 root budget/task event/judge seam 等夹具构造错误不当产品缺陷证据。
5. 逐题状态接入 finish、结构验证、语义放行、适配器与预算：发现 legal_gap 会被旧 ranking/track 模板重新开缺口、工具关闭会把漏题降 optional、零证据不能补交缺项说明，分别在原接缝修正。
6. 加固发现：原题义务可被合同 replace/from_dict 删除或降 optional；T3“更新备忘录”未触发 memo；Markdown 题内编号列表偷题号。逐一加入反例；混用 `## q1` 和同级 `2.` 的错误测试夹具改成同层 `1.`/`2.`，不是放宽生产规则。
7. 后续6个反例证明：语义拒绝可被普通降疑/元陈述豁免洗白；回退稿/最后脱敏仍保留旧状态。缺口拒绝先于普通豁免处理，按原文坐标回到原题；公开投影共用重验函数，适配器在修复决策前及最终呈现后复验。拒绝状态不可因回退恢复旧稿而消失；删句不重编号。
8. 全出口重验最初把判官 outage 的暂扣稿误判漏答，离线适配器反例2F/56P。改为 unavailable 只保留既有义务与 pending_rejudge，不为审查不可用发补写轮；普通 full 文本逐字不变及全 answered 的既有语义完成语义另以2个红灯修复。

## 决策与被否方案

| 选择 | 被否方案 | 理由/边界 |
|---|---|---|
| answered 沿用 `fulfilled`，新增 `legal_gap` | 全局重命名/复用旧 `gap` | 保留既有消费者，W2 preplaced_gap 与普通缺证据不混同 |
| legal_gap=题内公开具体输入缺项+无法判断后果，绑定原题号 | 仅 binding 私下填 gap、泛泛“材料不足” | 结构交代可机械验证；真实性/相关性仍交实际判官 |
| 含 gap 只能 partial，全 gap 加说明 | 用 evidence_boundary 充当一道已答题、全 gap completed | 问题分母只能是原题；不能把未回答升级成回答 |
| 缺项也实际送判，拒绝重开原题 | fabricated passed/not_applicable、元陈述全豁免 | “没提供”本身可能是错误断言；全 gap 不免检 |
| memo 同一 `answer_qN` 槽、仅明确请求触发 | 固定 q8/额外 memo 槽 | T2无 memo，T3 q8≤200字；另一个题包≤180字方法卡不是本题 |
| 正文非空白字符含标点/Markdown保守计数 | 引文/代码块不计数、自动截断 | 引用不能藏超长；标题/原题复述/占位语/引用空壳不算回答 |
| 公开转换后重验，旧拒绝只可由新补写重判解除 | 仅首稿核验、rollback重新获批 | 用户看到的是最终投影，不是旧 bindings；普通 full 不改 |
| outage 与漏交付分开 | 把暂扣稿当 writer 漏答反复补写 | 保留 unavailable/pending_rejudge，不烧无意义轮次 |
| input_only_rewrite 由领域明确授权，预算层给零工具有界窗 | 假增 evidence_count、无工具就降 optional | 问题义务不消失，不伪造事实覆盖；cycle/deadline/root账本仍约束 |
| 原题合同替代旧题型模板 | 叠加 ranking/track 旧槽 | 不替用户增造矩阵/TTL等未请求交付 |

`material_delivery.py` 是 D5 的确定性交付检查，不是 D6 的事实锚点验证。判官接收原题和 typed 的历史用户材料审核缺失声明；这些 review context 不自动注册成事实证据，助手旧答不充当历史材料。普通 full 不获得 legal_gap 豁免。
