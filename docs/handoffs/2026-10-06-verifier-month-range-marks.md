# 数值门「待核」误报：月份 / 日期与有据区间（T1-turnover）

## 背景

数值门是 `intelligence/services/episode_semantic_verifier.py` 里的 `_novel_numeric_condition_tokens`：在条件句里抽数，证据里找不到出处的数在公开稿句内挂「（待核：「X」未在证据中找到出处）」（2026-09-28 起标注，不再删句）。同一个函数还驱动三件事：回滚模式下的整句删除、W5 补证前的 `numeric_condition_unsupported`、记忆借数的删除判定。所以「少点名一个数」同时意味着少删一句、少触发一次补证。

2026-10-06 8792（`76d1586cac04`）生产探针 T1-turnover，问「2026-07-22 华工科技最近一周的换手率怎么样，有没有放量」（`run_20261006_123340_714206`，存证 `~/.finance-runtime/model-first-harness-1006/deploy-76d1586cac04/probe-after/T1-turnover/`），公开稿点名了：

| 句 | 点名 | 性质 |
|---|---|---|
| 13 | 「6 月」「一月」 | 月份，时间点 |
| 15 | 「1.2」「0.9」「0.75~1.07」 | 前两个是模型自拟判据；区间是派生比值的舍入 |
| 16 | 「44%」 | 模型自算（105.47/73.37−1），证据里没有 |
| 18 | 「6%」 | 自拟阈值 |

用户要求：月份 / 日期与两端有据的区间不点名，自拟判据照旧点名，修法最小，不放宽对真自拟阈值的审查。此前 10-06 的 harness PR 已豁免用户题面里的数（`_question_quantities`）。

## 按发现顺序

1. **重放先行，不靠读代码推**。用 `scripts/judge_loss_point_replay.py::_rebuild_outcome`（默认保留观察值）重建 contract + outcome，结构核验后以 `ASK_SEMANTIC_JUDGE=off` 跑语义核验（生产当时 `judge_mode=deterministic`）。在生产快照树 `~/.finance-runtime/finance-workspace-76d1586cac04` 与当时的 origin/main 上，公开稿都与 `answer.md` 逐字节相同——定位从这里开始。
2. **「6 月」**：`_MONTH_TOKEN_RE` 要求「月」紧贴数字，GLM 在数字与汉字之间加空格；抽数正则 `_ARABIC_QUANTITY_RE` 却允许单位前有空白，于是「6 月」成了带单位「月」的数量。同句「7 月」没被点名纯属巧合：派生计算的观察值 6.9984 落在 7 的 ±0.5 内。
3. **「一月」**：来自「较前一月放大」，`_CHINESE_QUANTITY_RE` 认得汉字数词，月份掩码不认。
4. **「0.75~1.07」**：派生计算卡里就有 `amt_ratio_recent_over_base=0.7511`、`to_ratio_recent_over_base=1.0747`（结果摘要原文 + 结构化观察值）。但 `_rounded_quantity_matches` 只让两值候选对两值证据，区间从不逐端核。无单位的数只能靠观察值（无单位证据数的舍入比对被维度守卫挡掉），所以这条路非观察值不可。
5. **同族扫描**：日期 `_DATE_TOKEN_RE` 同样不容空白，只修月份会把「6 月 30 日」掩成剩「30 日」，一并修。
6. **全存档普查（第一版，两端完全对称）**：39 句解除、0 句新增，但按支撑来源逐端追查后发现，「后续2-3个交易日」「1-2个交易日」「2-3 周」「2-3 日」这类模型自拟的观察窗口，两端全靠无单位观察值 ±0.5 凑上（「2周」被 1.8845 撑、「2个」被 −1.86 在「缩量」负向语境下翻号撑）。这违反「不放宽自拟阈值」，于是加了整数端点规则。
7. **普查（定版）**：25 句解除、0 句新增；解除的区间两端都是证据原文或同单位数值。
8. 调试一条测试时撞上一个**既有假阴性**：`_DATE_TOKEN_RE` 的 `(?:0[1-9]|1[0-2])[-/.](?:0[1-9]|[12]\d|3[01])` 会把「10.15」「11.25」这类两位小数当 MM.DD 删掉，「若股价跌破 11.25 元则止损」整句不审（「9.25 元」照审）。未改，见后续。
9. 期间 origin/main 前进到 `ea217633c`（上游改了 `derived_calculation*.py`），rebase 后在新生产快照 `d5d7c5f6017e` 上重放：存档原样复现、裁剪夹具与整份存档逐项相同，上游改动不影响这次重放。

## 决策与被否方案

| 方案 | 评价 | 结果 |
|---|---|---|
| 月份掩码容空白（含年份前缀），认汉字一月到十二月 | 与既有设计一致：阿拉伯「1月」到「12月」本就按时间点掩，「N 月以上 / 以下」是时长照审 | 采用 |
| 汉字分支带数词后顾、不认「两」 | 「二十月」的尾巴不是十月；「两月」不是月份名，是时长 | 采用，各有守卫测试 |
| 只补「6 月」这一个字面 | 下一次换个写法照旧误报 | 不采用 |
| 中文年月日容空白 | 不改则「6 月 30 日」剩「30 日」；与抽数正则单位前的 `\s*` 对齐 | 采用 |
| 区间两端各按区间单位过一遍原判据 | 区间就是两个数并排写；每端仍受百分比整数规则、限定金额 3 位有效数字、负向语境约束 | 采用 |
| 按算术推导认区间（87.13/116.01、7.52/7.00） | 会放过 44% 这类模型自算、证据里没有的数；何况比值本身就在证据里 | 不采用 |
| 两端与单个数完全对称（整数端点也借观察值 ±0.5） | 普查实测放过自拟观察窗口；区间此前从不吃这个容差，对称等于新开口子 | 不采用 |
| 整数端点不借无单位观察值的舍入 | 同仓先例：整数百分比只认整数字段、粗金额只认恰好相等；小数端点容差 ±0.005 撞不上 | 采用；整数端点仍可靠证据原文或同单位值 |
| 顺手收紧单个数的观察值容差 | 会在全存档新增点名（T1 的「8%」即是），属另一个决定 | 不在本 PR |
| 夹具用存证裁剪件（12 张已绑定卡 + 记忆缺口卡逐字照抄，丢 events / traces） | 手写证据会带上检查器的词表；整份存档 2MB 太大 | 采用；裁剪前后重放逐项相同 |

## 后续

- **单个数的观察值 ±0.5 容差**：T1「维持 8% 以上」借 7.5212 过关。收紧要先普查新增点名，再定规则（可参照本 PR 的整数端点规则或百分比整数规则）。
- **日期掩码吞两位小数**：10.01–12.31 的两位小数被当 MM.DD 删，自拟阈值整句漏审。修法要能区分「10.15%」「11.25 元」与真日期「10.15」，先普查。
- en dash「7–10 月」两个正则都不认区间。
- 普查脚本已是第三次从 reviews 目录手抄（09-25、09-29、本次），值得收进 `scripts/review_probes/` 并写明它防的坑（门禁临时目录、按稿去重、保留观察值）。

## 不要做

- 不要把整数端点规则「统一」成与单个数对称：那正是被普查否掉的版本。
- 不要按算术推导放行区间或单个数：44% 这类模型自算的数会一起被放过。
