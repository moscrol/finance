## 背景与结论

用户要求继续推进 Harness 优化，并核对并行 agent 的在途工作；不是继续给已见金融题加规则。总方向沿 `acc743c84:docs/superpowers/specs/2026-10-02-model-owned-harness-spec.md`：模型主导语义，代码守来源/权限/资源。

P1a 已允许有版本、有理由地撤回模型自拟计划，并让可选身份贯穿补写/失败投影；但上游装配仍可能把建议变成用户义务。本片只解决**输出来源随对象及消费者保真**，不宣称在线题意修订已完成。

## 按发现顺序

1. 先只读核对 P1a、并行设计、旧输出身份候选及 R13–R19；未拼成联合树，未用发布候选的全仓绿替本分支签字。
2. 从输出义务对象入手，新增来源与别名来源并集；抽出共享 `RequiredOutput`，旧导入保留 re-export。启发式、程序、模型计划、方法、用户及运行时来源可区分，来源不等于授权或语义正确性。
3. 迁移可信 TaskFrame/factory 和真正消费者。研究程序按本次 `FactSlot.required`，不再按全球槽名名单；同名/别名合流保必需性 OR。旧无元数据保持 legacy 原义，拒绝全体默认槽一律降可选。
4. 兼容测试从未修改的 P1a 树导出旧 frame/授权快照，而非新代码自己序列化再恢复。新增来源进入新 hash/授权比对；旧授权不迁移、不重签。
5. 真实脚本循环测试发现测试任务 ID 共用活根预算、工具 trace 为空两处夹具问题；分别用独立任务 ID 和真实 ProviderTrace 修正，不绕过根预算/来源验证。legacy 提示载荷新增字段破坏精确回归，改为默认省略字段。
6. 首个固定实现相关29文件1436P/1S、11变异通过；随后全仓18819P/8F。材料题是拒绝发生得更早；其余7例为真正回归：controller 历史继承重建 ID 集，却留下旧来源元数据。未修改 P1a 的三历史文件170P，排除“原有红例”。
7. 新增历史来源两例先红，再修 controller：ID 与元数据同步迁移，用户义务（包括合并来源中用户见证）始终保留；只过滤不再采用的建议，保原 local_only。材料恢复测试同时覆盖 legacy/新来源。提交 c18 后重新全仓及全部变异，才签本片工程结论。

## 非显然决定与被否方案

| 决策点 | 备选及评价 | 选择 / 理由 |
|---|---|---|
| 按谁判断必需性 | 槽名 advisory 名单容易把同名用户要求降级；新增槽还要登记 | 来源随对象、必需性独立记录；程序新增项沿 `FactSlot.required` |
| 旧默认槽迁移 | 一律可选会在根请求覆盖锚点缺失时制造空答假完成；一律 user_request 把猜测伪装授权 | legacy 保旧必需性，明确迁移尚未完成；后续有请求锚点再退出旧权力 |
| 别名合流 | 后写覆盖会丢硬要求；只保主来源会丢审计见证；拼两份执行槽导致重复完成判定 | 必需性 OR + 来源并集；目标槽的证据/grounding 配置继续负责执行资格 |
| 来源可信性 | 允许 Controller/PLAN 自报 user_request 相当于自己授予义务身份；把来源标签当语义证明仍是黑箱 | 仅可信装配器填写；模型提案不改来源，用户来源也不能自证解释正确 |

## 下一片建议：根请求与解释版本接缝

开始前仍须定小片计划，不把本节当真实实验或发布授权。

1. 复用既有 PLAN 作为提案入口，先钉根请求的稳定身份/原件与用户义务对应；原请求不可被解释覆盖。明确旧 `task_frame_hash`、任务合同和恢复身份的兼容边界。
2. 允许解释 revision 改题型/主体/时间窗前，先验证 stale 提案不改变状态、不派工具；同包修订与工具按单一 owner 顺序裁决；成功修订才进入下一次真实提示。
3. 保用户义务、材料读取上限、根预算/绝对截止/取消；已有证据原件不删，适用性在新解释下重新判断。不要复制新预算池或把旧证据 ID 当新范围支持证明。
4. 先明确连续 Episode 与 SDK 的接纳点和失败反馈，再实施；SDK 初始来源已贯通不等于 PLAN 已支持。完整 HTTP 新链应有专项测试，不以底层脚本循环代替。
5. 每迁移一段写清谁失去旧裁决权，避免旧题型默认/词面门和新解释两套永久并行。真实金融效果另经授权预注册最小对照，既有失败不翻案。
