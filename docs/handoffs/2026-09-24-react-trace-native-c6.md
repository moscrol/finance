## 方案取舍

| 选择 | 被否方案 | 理由 |
|---|---|---|
| 新头重取收据 | 六模块字节相同就移签旧四叶 | 组合中的主干变化仍可能影响行为 |
| fixed argv/真实exit/阶段交付/产物检查点 | 只靠提示和总请求帽 | 包装返回值、合法JSON和有效覆盖相互独立 |
| 显式厂商序列化与出站校验 | 相信本地thinking off标签 | 兼容SDK可能未送该字段，模型本身也不支持off |
| 更正量具后独立重现C6 | 知道探针索引错便把全部红归夹具 | 量具错误与产品错误可以共存 |
| 扩定义两侧共享正则 | 只修删除侧或放宽数字门 | 同一标题在删除/幸存必须同义，数字真实性仍独立约束 |
| 停后副本修stage schema | 原地修改封存工具或扩大终审PASS条件 | 要保留执行时的真实合同，缺覆盖不能洗成通过 |
| 明确停止未准入等待 | 放宽无他人pytest门或留下后台自动开跑 | 资源门不应因目标着急而漂移，停批后仍可能突然启动重任务 |
