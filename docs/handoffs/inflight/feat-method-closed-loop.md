## 这个分支做什么
走 OPT-10「用一条现有方法跑完真实跨日闭环」时抓到的两个真缺陷，修在源头：

1. **合取式标签丢了三值逻辑**（`labels.py`，`LABEL_VERSION` v4→v5）：`dual_red_strict` /
   `diff_ratio_turn_up` 把「任一输入缺失」一律传播成 NULL，丢掉 `FALSE AND unknown = FALSE`
   那半边——已确定为假的行被记成「不知道」。改成「先判确定为假、再判不可知」；`turn_up` 把
   **结构前提**（无相邻前一交易日 / 前一日 gap）与合取项分层。判 1 的条件一字未动，不是放宽口径。
2. **收据同日三段互相覆盖**（`receipts.py`）：文件名只到日期粒度，同日跑完三段只剩最后一份，
   `_stage_ladder` 永远凑不齐三级。现改为**任何一次运行都不被覆盖**。

## 复核历程：六轮、二十余条
每轮都用复核留下的反例脚本复现 → 修在源头 → 变异确认。逐条明细在各轮 REVIEW 报告里，
本文只留**还会再犯的教训**：

- **「唯一性」「先后」「兜底」是三件独立的事**，指望一个字段兼顾就会反复漏（连错四轮）。
- **原子占名 / 完整发布 / 不可覆盖 / 崩溃恢复是四个独立承诺**；测试必须在承诺交接点
  **终止进程**（`os._exit`）才测得到，`except BaseException` 清理对真实终止无效。
- **发布用 `os.link` 不用 `os.replace`**：后者覆盖已有目标，破掉「失败证据不可覆盖」。
- **坏文件交给人**：分不清残留与真证据时报清楚，不自动覆盖也不自动删除。
- **登记 ≠ 切换，标记 ≠ 停用**：`register` 不改绑定要靠 `activate`；`supersede` 必须让
  `list_studies` 真的不再枚举，并在**产生副作用之前**拒绝 `daily`/`capture`。
- **业务退出码不能与崩溃码撞车**：Python 未捕获异常退 1、argparse 退 2。用 1 表达
  「从未配置」，一次崩溃就被读成「没配过」而静默回退旧协议。故 `unset` 用 **4**。
- **「查不出能力」≠「没有这个能力」**：`CLI --help | grep -q` 取的是 grep 的码，help 自己
  崩了也只是「没命中」。必须先确认 help 退出 0 再判断。
- **证据损坏会伪装成证据不存在**：坏收据被静默跳过 → `report --refuted` 打印「没有任何规则
  被证伪」。读不出就要出声并把汇总标为不完整。

**更正一条曾写进注释和测试的错误原理**：旧 CLI 的 `active --help` / `activate --help`
并**不**返回 0，实跑均为 `invalid choice` → **exit 2**（本树复现）。顶层 `--help` 探针仍是
对的选择（不依赖这条微妙规则），但不能拿那个理由背书。
