## 决策与被否方案

| 选择 | 被否方案 | 理由 |
| --- | --- | --- |
| 固定现有 PR HEAD | 为 main 纯文档增量再次前向 | 运行时代码未变，避免无意义地更换受测身份 |
| 分离已完成与未完成步骤 | 重新跑 #910 74 项 | 当前 SHA、树、解释器、依赖与目标仍一致，收据重新校验通过 |
| 共享 30 分钟等待额度 | 无限后台或忽略外部 pytest | 观察不是资源预约；有限等待保留边界，不抢占他人 |
| 归档只写协调分支 | 在两张受测 PR 上提交新文档 | 文档提交也会改变 HEAD，导致下次精确版本检查重新失配 |
| 记录未执行 | 用静态绿或旧全仓补齐结果 | 没有本次执行就没有本次收据 |

单次资源观察不能保证接下来有独占窗口，这一点已在 `gate_resources.observe` 的 scope 中声明。要让长门禁可靠推进，需要执行方共同安排测试窗口；本轮没有改共享调度器、其他会话或资源规则。
