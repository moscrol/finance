## 发现顺序与证据

### P2-1：schema 是浅层外壳，缺证据/失败终态仍发绿，嵌套缺失仍裸异常

位置：`scripts/verify_302132_backfill_acceptance.py:138-216`，以及 `403-412`。

本轮把原交付父收据复制到隔离目录，修改嵌入子报告时同步写出对应的独立子报告，避免只触发深比较不一致。数据库完全未变。

| 单因素变异 | 实测 |
|---|---|
| 两轮子报告删除 `parallel_source_md5` | PASS 25/25，rc=0 |
| 两轮子报告 `ok=false` | PASS 25/25，rc=0 |
| 两轮父子 revision 和 `--expected-revision` 均设 `not-a-git-revision` | PASS 25/25，rc=0；实际没有声称的 40hex 格式校验 |
| `expected_window_counts={}` | PASS 25/25，rc=0；只验 dict 类型，没有非空/键值/与实况一致性 |
| `pinned_technical_0911` 删除 `ma26` | rc=1，`KeyError: 'ma26'`，**无输出 JSON** |

这不是单纯文案缺漏：显式失败的子报告被签成成功；缺嵌套字段仍破坏“结构化 FAIL rc=2”的接口。外层 `isinstance(..., dict/list)` 不能代表内部结构已经合法。

要求：为父收据、spec、子报告递归定义所需字段及约束；严格验证日期、revision/hash 格式、数值有限性、非空集合及其成员类型，显式验证子报告成功终态。所有后续访问必须建立在验证成功的结构上；读取/计算异常归入有名的 FAIL 检查并保留结构化诊断。不要只针对 `ma26` 再补一个 `.get()`。逐字段删除/错误类型参数化回归，独立子报告同步变异。

### P2-2：parquet 三向绑定只覆盖 apply，verify 可使用另一输入仍全绿

位置：`scripts/verify_302132_backfill_acceptance.py:199-204,258-271`。

复现：只改 verify 父 spec 与其子报告的 `parquet_sha256` 为 64 个零，并同步改独立子报告；apply、实际 parquet、两份数据库都不动。结果 **PASS 25/25，rc=0**。

原因：`_schema` 只证明每轮自己的父=子；唯一实际文件哈希校验从 `receipts['apply']` 取值，没有把 verify 接到同一冻结输入，也没有对齐两轮 spec。于是不同输入的 verify 也能被当成 apply 的幂等复验。

要求：对每一轮分别验证 `spec.parquet_sha256 == child.parquet_sha256 == actual_parquet_sha256`；同时核对 apply/verify 的完整授权 spec（若存在允许差异，明确白名单），不能只要求两个 version 都带同一前缀。增加“只改 verify 输入”和“只改 verify 授权 spec”的反例。

### P1-1：外部 oracle 从结果库读取源表，输出与源同坏可自证通过

位置：`scripts/verify_302132_backfill_acceptance.py:327-337,356-375`。

本轮最后单独做真实数据变异：在自有完整演练副本中，把 `302132.SZ / 2026-07-02` 的 `open` **58.0 → 59.0**，分别修改：

- `fact_stock_daily`（待验回填输出）；
- `fact_stock_daily_hithink`（本来不在授权写范围内的输入表）。

基线（run9 换前备份）、parquet、原父子收据全部不变；仅为副本入口复制收据并重定位子报告路径。结果 **PASS 25/25，rc=0**。再次通过 `--expect-fixed` 包装重放，包装器正确返回 2，证明反例门禁本身能报红。

原因：`FROM fact_stock_daily_hithink` 没有 `prod.` 限定，实际读取待验 clone 自己的源；该源表不在双向不变比较中，收据里的 `parallel_source_md5` 也未重算比对。两个公式独立，但输入仍由被测结果提供，因此能一起错、一起过。

影响：保护范围之外的源表变化与错误回填价格可以同时逃过最后一道独立验收。这里**没有证明当前写入器会自然产生这种破坏**，证明的是验收无法拒绝已经损坏的产物；不能据此给生产输出安全签字。

要求：oracle 的并跑数据从不可变基线读；对结果中的并跑源表增加禁止变更比较（至少本轮依赖切片，若合同承诺整表不动则整表），并将重算源指纹与两轮子收据绑定。不要只比较“两份 JSON 中 md5 相等”。加入上述主表+源表共同变异，必须结构化 FAIL rc=2。
