# 云端投研优化资料公开交付（2026-10-07）

## 背景与授权

用户要让云端模型直接读取历史 SPT 蒸馏、用户框架和投研协作约定，继续优化而非重新访谈。最初考虑私有记忆仓；核查发现该仓历史还含无关私人运行材料，直接转公开会扩大披露范围，之后转私有也不能收回已复制内容。用户随后明确允许独立公开资料仓或直接放到公开 `moscrol/finance`，并要求不放在 `agent-memory`。

本轮选择后者：只发布筛选的静态研究快照，保留原记忆仓私有。授权没有包含生产画像写回、数据库更新、模型研究运行、合并或部署。

## 按发现顺序

1. 核实 `finance` 已公开，主工作树有其他任务改动。从 GitHub `origin/main` 的 `582b9d55cd1f6e6f69469eb996f144203b3c7d20` 新开隔离树和 `docs/cloud-research-context` 分支，未移动主树。
2. 原计划的私有导出没有提交或推送，移出记忆仓工作树；该工作树恢复干净。没有拷贝记忆仓的 Git 历史。
3. 从真实用户空间读取三份画像、文章索引、历史 patch 和纠偏；逐条筛选 59 条投研相关纠偏，连同关联的 4 条归档事件导出。不是把完整纠偏台账当成当前系统指令。
4. 公开版只含 74 条文章元数据（SPT 50、风远 24），361 条 patch 去掉逐字引文，保留关联 ID、内容指纹与原状态。风远 24 条中 6 条明确为再生材料，不冒充作者原文。私人路径、生产用户标识替换为占位符。
5. 阅读入口专门对照后续版本：板块 RPS 已剔除；流动性链不是固定模板；减法不等于减少有用视角；历史用途边界不混成当前授权；旧 SPT 词面候选已因 12 项挑战中 8 项失败被拒收。
6. 实现提交 `3f6aba6c6bedb767513cb8329abe0c3bc6cb1e63` 推送到公开分支，创建 [PR #71](https://github.com/moscrol/finance/pull/71)。无认证回读 README、manifest 及全部 10 个载荷，字节与指纹一致；无需合并即可读取。

## 方案对比

| 方案 | 评价 | 结果 |
|---|---|---|
| 把完整 agent-memory 转公开 | 会公开无关历史，不只本轮资料；可见性切换无法收回已复制内容 | 放弃，保持私有 |
| 另建无历史公开资料仓 | 能隔离披露，但增加仓库与代码关联维护 | 可行但未采用 |
| finance 内独立资料目录和分支 | 用户已授权公开目标；方法、代码、既有验收资料能同仓关联 | 采用，不自动合并 |
| 全量上传文章、引文、私人考题 | 公开阅读不需要全文再分发；来源许可和个人材料范围不同 | 排除全文，保留索引和指纹 |
| 只上传最新画像，不留历史纠偏 | 会丢掉撤销／归档关系及后续适用范围限定 | 保留筛选纠偏、生命周期事件和阅读说明 |
| 自动把历史 approved patch 回填画像 | 可能恢复主动剥离的数字、抹掉人工修订 | 不回填、不重新裁定 |
| 自动定时同步用户目录 | 容易扩大后续公开范围，且把 Git 快照误作运行真本源 | 不实现；每次刷新重新审阅白名单 |
