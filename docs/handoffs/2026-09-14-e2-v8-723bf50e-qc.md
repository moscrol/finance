## F1 · P1：推断出来的“引导块终点”不足以授予强保护，仍可吞掉块尾真禁令

**位置：设计稿 51–58 行；联动 68–69、82–89 行。**

v8 把引导块列入强保护，结束条件却仍是“空行后首个符合顶层指令/题组句法的行；或文末”。这种结束位置不是显式闭合标记，不能证明之前的所有内容都属于引用材料。失败分支只覆盖“无明确终点且有疑似禁令”；后面恰好有题组时，会被视为已有终点。

最小设计反例（禁令与前行无空行，题组前有空行）：

```text
材料如下：
甲公司总收入20，相关业务收入2。
请只依据上述材料回答，不读取任何材料外数据。

1. 相关业务占比多少？
2. 这个比例能说明什么？
```

按强保护表的一条直接执行路径：
1. “材料如下”开启引导块。
2. 禁令之前没有空行，未触发结束；第一题之前有空行，块在第一题处结束。
3. 已找到结束位置，未进入“无明确终点”失败分支。
4. 强保护冻结后不再扫描内部指令，第三行禁令不可见；弱候选复核也不管强保护块。
5. 指令区无约束，所有文本已分配角色，遂有 `no_constraint_confirmed→real×full` 的放行路径。

若实现者想用相邻规则阻断第三行，他就必须先把第三行从推断的强保护范围里拿出来；正文没有规定这个范围收缩/冲突优先序。**相邻规则与强保护表可导出不同结果，不能靠实现者自行选安全读法证明已闭环。**

修订建议（不必重做解析器）：
- 只有明确建立材料引用身份、且有可靠闭合边界的范围，才能享受内部指令不扫描的强保护。
- 仅凭引导词＋后续空行/题号/文末推断出来的范围，先作候选；非独立强保护的内部若有疑似约束且无法证明材料归属，就 boundary_uncertain。
- 明确强保护内层范围的优先级，不能为了修此例而把真实围栏/引号里的同句升级。

补验收：上述“有题组终点但块尾有真禁令”不得 full；对照将同一句放入明确闭合的材料引用，不能升级为用户指令。A17 当前只锁缩进，A13 的“无终点”不能替代这例。

## F2 · P2：A-only 歧义也可进入交集出口，但 capability 集合没有 A 轴信息

**位置：设计稿 60–63、88–89、102、125–140 行。**

弱候选检测明确包含“假设……”，所以不确定的前提声明也会触发 boundary_uncertain；该状态无条件提供“澄清或按 §3.2 权限交集继续”两个出口。可是 allow 只定义了 B 轴三种数据范围，A=fictional 的映射明确写 B 不变。

设计反例：

```text
请分析这个案例：
  假设甲公司明年订单翻倍成立。

1. 这会怎样影响收入确认？
2. 哪些环节仍不能确定？
```

若缩进行的材料归属无法证明，两个候选完整语义不同：
- 按材料：它只是待核验陈述，不据此改变 A；
- 按用户前提：A=fictional，且须生成对应 premise_mark，不能证伪该前提。

两种解释的 B 轴权限都可能为同一 P；求交仍为 P。该计算既没有 `allow(fictional)` 定义，也无法决定 A、premise_marks、前提域声明与裁判行为。把“最终 IO 权限有了”当成“完整状态歧义已解决”，会留下猜 A/漏标记的实现空间。

最小修订：**交集继续只用于可完整确定 A/marks、仅 B 有歧义的情形；A/marks 仍有歧义则走已有预取前澄清出口。** 若作者要支持 A 歧义不停机，需另定语义合成规则，但不是本阶段必需。补一个 A-only boundary_uncertain 断言即可。

这是歧义出口的适用域缺失，不是重开明确的 `fictional×full` 正向 A8，也不要求改变 B 轴消息级设计。
