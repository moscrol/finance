# 历史发现研究设计：决策记录

## 背景

用户明确纠正产品优先级：允许事后从已走强的个股或板块中发现特征，单次发现产生假设，再回查多段历史的相似与失败案例，检验并修正规律。先锁定双红规则做前向积累不能代替这条研究能力。

正文见 [历史发现 spec](../superpowers/specs/2026-09-09-historical-discovery-research-design.md)，提交 `51f236d9`。本文记录设计成立的背景，不是产品已经实现的报告。

## 核对与选择

1. 从 `gitea/main@f90af450` 新开干净文档工作树；原主目录的他人改动未动。两位子 agent 分别核对历史入口与方法验证基础，第三位审查 spec。
2. 确认 Workbench 已有连续 Episode、发酵时间轴和类比预取；尚未确认模型主动调用 River 计算的路径。选择沿现有入口接通领域研究，不重建 loop，不宣称现有历史能力全部缺失。
3. 区分整段走势相似与触发时点相似：前者服务发现，后者才用于检验后续结果。否决在发现前冻结完整规则，也否决用其他赢家榜单充当验证全集。
4. 历史检验可以使用发现案例之前的年份；已暴露与调参使用过的样本不能伪装留出。正式统计、保护集和晋升依赖基础 OPT-04/05，新增算子依赖 OPT-09，避免平行系统。
5. 审查发现终局验收可能被当作首版前置；补切片适用表，S1+S2 先交付研究用途的自主复盘与同类/反例比较。严格认证和新增恢复未完成时限制相应承诺。
6. 源码复核纠正模块归属：题材类比在 `market_analogs`，环境类比在 `market_regime_analogs`，个股在 `stock_analogs`。RunStore 同名覆盖的事实也写入 spec，要求新研究原件经唯一 writer 增加不可覆盖合同。

## 验证边界

本轮只核对源码与文档：本地链接、文档结构、验收编号与 Git whitespace 检查通过，提交钩子通过。未跑农业真实研究，未核验该波的数据覆盖，未运行新增产品验收或全量测试，未改数据或部署。所有新增接口/字段是目标合同。

## 接续

实施从 S0 定位真实窗口与 Workbench 基线开始；再做 S1/S2。L2、晚间卖方、晨汇按用户确认待同步，已有历史存量按具体窗口核验；不恢复采集或安装日程。与基础补强及固定方法应用分工见 spec §10。
