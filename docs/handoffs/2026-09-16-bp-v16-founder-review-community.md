# BP v1.6：同步创始人测评与社区后续合作

## 背景

用户先选定自己贴出的 v4.0 口播，要求推进 PPT，明确不喜欢磁盘 v5.0 的模板式重排。已交付桌面路演 v4.3，保留十二页顺序，补必要信息与收尾。随后用户问“BP 不用更新吗”，因此本轮同步阅读材料，而不是继续保留相互矛盾的 v1.5。

本工作树 `docs/bp-v1.3-roadshow-align` 开工为干净树；主检出有其他未提交内容未触碰。读取已有母本、生成脚本、PDF 脚本、申请表答案与测试后，沿既有母本生成流程修改。

## 决定

| 方案 | 判断 | 结果 |
|---|---|---|
| 沿用 BP v1.5 不动 | 仍要求社区招首批用户，与创始人自行邀请资深测评矛盾 | 不采用 |
| 将十二页口播直接变成 BP | 独立阅读所需事实、预算和验证边界会丢失 | 不采用 |
| 保留八页阅读结构，同步事实与决策口径 | 两份材料用途不同，关键陈述一致 | 采用 |
| 随叙事扩产品套餐或重算价格 | 用户未授权，且没有新成本验证 | 不采用；原参数和草稿保留 |
| 把设计写成已上线 | 本轮只做材料，没有重验产品运行状态 | 不采用 |

## 变化

- 摘要与用户体验：认知、时间和市场复杂度不匹配；从依赖博主到依赖 AI 未必解决核验。
- 底座：模型理解问题，数据库与计算工具做联立核算，数据和口径仍要核验。
- 协同进化：补提取前置、用户纠正分化遗漏的设计场景；三项分别验证，不承诺越用越准。
- 首轮：创始人自行邀请资深投资者，测真实研究任务。资深认可不等于普通用户持续使用和订阅需求。
- 后续：与社区探索产品商业化、体验和传播；一人交付交流为主，算力 API 额度为补充。
- 九十天：测评修复、独立试用、社区与订阅探索，均为建议计划。移除旧 100 人候补名单增长承诺及未确认的 Alpha 活跃率扩招阈值，保留预登记判据和可靠交付要求。
- 申请表答案同步 v1.6；历史 Marp 只更新路演指针，不重新制作。现有签名 DOCX 不改。
