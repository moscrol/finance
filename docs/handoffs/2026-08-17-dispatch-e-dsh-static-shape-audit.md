## 0. 一句话

不跑 dsh，只拿它已经画好的插槽当尺子，把我们每个组件量一遍，产出三分类。
**这是 Arm B 降级的对价**——不做它就等于净减了一项能力（spec §9.1.2）。

## 1. 判据（反推口令）

> 明天若必须做成 dsh 插件，它挂哪条**已经写在架构图上的**接缝？

| 判定 | 含义 | 记什么 |
|---|---|---|
| 挂得上、不用改 loop 图 | 形状能在 dsh 上跑 | 记接缝名；无动作 |
| 只能塞进某个 tool 的 `execute` | dsh 只宿主流水线 | 记为可接受 |
| 找不到接缝、或必须改 agent-loop | **焊死了 或 它就是领域真源** | **两者必须分开判** |

最后一档是全轨最容易出错的地方：**「焊死了」是待拆的债，「领域真源」是正常状态。**
把后者写成整改项，就会去「修」一个本来就该那样的东西。

## 2. 两条纪律（写死，防止把尺子读成整改单）

1. **「能挂上」≠ 生产改去跑 dsh。** DuckDB、截止日、绑定仍在本仓。本轨只检验边界像不像插件。
2. **「挂不上」≠ 我们没拆好。** dsh 本来就不判「这数对不对」（spec §5.2）——
   语义核验与 Evidence Ledger 挂不上是**正确结果**，不得据此立整改项。

## 4. 方法

1. 用解析器数组件，**不要用固定行号**（CLAUDE.md 已记过一次翻车：沿用固定行号数错工具数）。
2. 每条给**证据等级**：`[实测]`（读过代码/跑过）/ `[推断]`。**推断不得写成结论。**
3. 判「焊死」时必须指出焊点在哪个文件哪个函数，否则只能记 `[推断]`。
4. 负面断言（「我们没有 X」）走三步纪律：全树 grep 同义词 + 读能力图谱
   （`agent-memory/10_knowledge/finance-agent-capability-graph.md`）+ 读项目笔记看板。

## 5. 完成定义

- 全组件三分类清单，每条带证据等级与文件定位。
- 「焊死」那一档单列，附拆焊建议；**与「领域真源」那一档明确分开**。
- 清单自述对哪个 revision、哪个 dsh pin 成立（§9.5 末条：dsh pin 变更须重跑）。
- 回写 spec §9.5 的产出物指针。

## 6. 为什么不派出去

按 ai-agent-book ch10 的总判据「协作过程有没有引入单个 Agent 在生成时无法获得的新信息」：
本轨是**对着同一批代码和同两份 spec 再想一遍**，没有新信息——正是书里说的
「同模型对着同一段文本再想一遍，通常不该开子 Agent」。

且本会话已经把两份 spec、层级门禁、工具注册表、episode 批次预算、
`degraded_fallback` / `episode_semantic_verifier` 都读过了，**交接成本高于执行成本**
（ch4 实验 4-3：交接质量不够时，开子 Agent 比自己干更差）。

**所以这一轨自己做。**
