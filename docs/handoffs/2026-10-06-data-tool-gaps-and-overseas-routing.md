### 2. #56：三处工具合同修复（已上线 `76d1586cac04`）

- **复制旧值逐行标注**：同主键上一行收盘与涨跌幅完全相同、会话日却不同的行，标「疑似复制旧值，不可当作该日行情」；
  聚合结果给窗口级提示。
- **`turnover_est`**：成交量(手)×收盘÷流通市值(亿)÷1e4，流通市值取板块成分快照按日去重。对账东财 / 同花顺 / iFinD / 新浪原值：
  7–8 月 99% 误差 <2%，各月 95% 以上 <10%；2026-01、2026-04 起覆盖过半。原值缺时，缺值提示里点名 `turnover_est`。
- **下线 `sector_daily.strength`**：生产 D9 曾按这个全空列取「最强 50 个板块」，排序实为随机；拒绝时的重试提示会把模型引到有数的 `mainline_sector_daily`。

| 决策 | 选了 | 否了 | 为什么 |
|---|---|---|---|
| 复制行怎么处置 | 标注、不删 | 查询层直接过滤掉 | 删了模型连「这天有问题」都看不见，会当成缺数去别处乱找；标注让它自己决定换源（旁路实测它确实去查了网页） |
| 收盘不变且涨跌幅为 0 的重复 | 不标 | 一并标 | 收盘不变时真实涨跌幅本来就是 0，停牌 / 平盘与复制分不开；涨跌幅非 0 而收盘不变才自相矛盾（实库 13 行属前者） |
| 推算换手率放哪 | 单列 `turnover_est` | COALESCE 进 `turnover` | 混进原值列后逐行分不出来源，违背「降级报告带身份、不伪造证据」 |
| 何时 join 板块表 | 只在要 `turnover_est` 时 | 所有 `stock_daily` 查询都 join | 其余查询零额外开销；缺板块表的库也不报错 |
| 推算值写不写库 | 查询时算 | 回填进 `fact_stock_daily` | 写库是回填，要走 duckdb-backfill 与采访；查询时算可随时撤 |
| 原值缺时 | 只提示可改取推算列 | 自动换源 | 缺值文案的「不自动换源」是既有合同，换不换由模型定 |
| `strength` | 下线 | 留着、空值照报 | 留着会被拿去排序（D9 实例）；下线后只多一轮调用，重试提示把它引到有数的表 |

## 不成立的结论

- 盲评 n=10，一题之差跨阈值：只能说「接近持平」，不能说「已超过」或「仍落后」。
