# 2026-10-03：P1b 第三片方法建议化交接

## 背景和本次落点

用户要的是减少重复裁决：弱模型有方法可借用，强模型能选择研究路线和表达；不是靠增加模板、重试或测试数量制造优化感。前两片分别保留输出来源、冻结根请求并独立版本化 goal 解释。第三片发现另一份隐形合同：跟踪 / 排序解析器按标题、表头、期限等词面再次生成“必需输出”，即使任务合同已满足，也会追加补写或降为 partial。

本片只撤 **Episode 路径中这份额外完成权**，不撤任务合同、证据核验、材料权限、历史意图或预算边界；旧 CLI `ask_synthesis` 与共享解析 / 登记暂不迁移。方法仍以可选建议进入模型输入，是否更利于真实弱 / 强模型尚未试验。

固定身份：生产逻辑 `ae03b189a4bdb6af87def3e4b32b89e09dc8afa9`；最终代码 / 测试 **`631ea887618b0044a79fd1e0c3621e99b70c4505`**；Memory 候选 **`6643bb3a57d8145bb458247d4783b2b754c1a4ff`**。文档提交身份单独放第三片 `closeout.json`，不把代码收据改挂到文档 tip。

## 按发现顺序

1. **先明确唯一完成权责。** 任务合同规定“必须交什么”，方法建议只解释“可以怎么研究”。在 `UBIQUITOUS_LANGUAGE.md`、门页及第三片计划中明确边界，再移除适配器结构、语义、公开和异常恢复出口的模板缺项合并及补全段。
2. **名字不能代表来源或权限。** 删除按 `track_*` / `ranking_*` 名称授予修复的分支，以及 `expression_slot_binding` 特殊 FORMAT 拒绝；同名用户要求必须保留，合同外未知绑定仍按完整性错误拒绝。退休码退出活动表，历史事件不重分类或重签。
3. **提示与收据同步降为建议。** Episode 跟踪 / 排序提示改为“方法建议（可选）”；机械再排序标“参考”，不冻结未覆盖变量。v2收据单列 `missing_template_elements`，兼容空 `missing_outputs` 不证明任务完成。
4. **撤掉伪缺项后，暴露真实修订依赖它启动的问题。** 有证据、有正文且确有核验反馈时，允许无真实缺项的关闭工具文字修订。`review_feedback` 传可行动诊断，`rejected_claims` 仍是事实拒绝策略信号；材料诊断不能误撤已获准的 input-only rewrite。
5. **候选分类与资源准入必须分开。** delivery 机会用尽仍保持 delivery 候选，不能掉入 progress / cold restart 再拿工具；补证轮已含作者修订，就消费本 Episode 的一次 delivery 机会。工具次数耗尽不等于文字时间没有余量，但根预算、provider 单笔帽、档位轮次和去重不变。
6. **扩成对反例并修复过期探针。** 用自然段、自选标题与旧模板对照；保留同名用户要求、事实拒绝、材料权限、历史和存储失败反例。旧探针不能 patch 已删除函数，改为撤掉实际公开 scope / 阶段反馈接口，再在新 pin 重跑。
7. **首次提交及全仓揭示的是两类测试问题。** runtime catalog hook先拒绝过期目录，生成后提交。`ae03b189a` 全仓6F：两项积分时钟在改动前 `7c90d8526` 也能复现；四项材料 prompt 仍期待强模板标题。前者给测试注入 `_Clock()`，后者对齐可选方法合同；不改计费、不恢复强模板。两文件修正形成 `631ea8876`，重新全仓、变异和收据检查。
8. **收尾只处理文档和候选记忆。** 复核 pin 原件，Memory 基线与候选 lint逐条比较；新增符号虽然被图谱标成 `MERGED`，只表示默认树有同名符号，不据此写“已合入”。共享 Memory 与并行分支保持不动。

## 决策 / 被否方案 / 理由

| 问题 | 采用方案 | 被否方案与理由 |
|---|---|---|
| 模板重复裁决 | 从 Episode 各出口删除模板增缺项 / 补写链 | 只改提示不改消费者，仍有隐形完成门；全面删核验会同时丢掉真实事实边界 |
| 方法支架 | 保留可选思路，作者自选表达 | 全删提示会丢弱模型的研究参考；保留强制标题继续让形式冒充完成 |
| 同名输出 | 按合同身份和来源履约 | 按 `track_ttl` / `ranking_matrix` 名字统一豁免或授权，会误删用户义务 / 放大许可 |
| 收据兼容 | v2建议性权限，模板诊断独立字段，旧缺项键留空 | 原地保留旧缺项语义会回流成第二份合同；直接删键扩大兼容破坏面 |
| 真实核验修订 | 直接以证据、正文和诊断申请关闭工具的文字轮 | 伪造缺项启动修复会重新立模板门；无条件重试会扩大调用与预算 |
| 材料权限 | 可行动诊断与事实拒绝分开 | 把所有反馈都并入拒绝，会错误撤销既有材料重写许可；反向用诊断授新权同样不成立 |
| 被拒delivery | 类别不变、资源准入拒绝 | 重新归类为progress / cold restart会绕过一次机会，打开工具 |
| 补证后的修订 | 补证作者轮消费同一delivery机会 | 再买纯文字轮使同一问题多拿机会，违背既定预算边界 |
| 迁移范围 | 只迁Episode，解析 / 登记与旧CLI另片 | 一次删除共享链会牵涉登记授权与旧入口，无法用本片证据签全部路径 |
| 首轮红灯 | 先旧版复现时钟，修测试fixture；提示预期跟随已确认合同 | 不因测试名称像计费回归就改生产；不为旧文案预期退回强模板 |
| 证据身份 | 代码pin、文档tip、Memory pin分列，新根归档 | 把脏树 / 首轮 / 旧片绿数移签会失去可追溯性；不覆盖旧closeout |
