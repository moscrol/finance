# 机制表示研究试验

预注册：`R-20260916-04`。用户 2026-09-16 在讨论“理解是结构压缩”后授权推进。
本轮交付一个旁路诊断试验，不改生产提示词、画像、工具菜单或自动方法晋升。

## 要验证什么

在相同材料、相同研究任务和相同模型预算下，把事实组织成“变量传导、竞争解释、区分变量、适用边界”，是否比逐条整理更有助于保留关键反证和选择下一条证据？

压缩率、文笔、概念名字、篇幅短都不是成功标准。长期目标是能被新证据修订的研究框架，不是更像理论的摘要。

## 当前范围

`intelligence/eval/fixtures/mechanism-pilot-v1.json` 是作者制作、答案已公开的合成诊断题包，不是封存留出集，不代表真实市场分布，也未经过独立专家评审。案例只涉及需求与利润传导、提前备货、替代供给、事前预期、利润与现金、市场共振等竞争解释。

两组的材料逐字一致，公共任务与 JSON 输出字段相同，只改变组织方式。基准组没有被禁止推理或找反证，实验组也没有额外材料、答案键或工具。按题交替执行先后顺序，单次请求无对话历史。

这测的是**提示词组织方式下的合成证据选择**，不是已经发明新概念，不是完整 agent 行为，也不是现有 Workbench 的效果基线。选项提供了研究方向，因此不测开放式发现新问题的能力。

## 执行

在含本分支代码的工作树根运行。新树可使用主树 `.venv-workbench/bin/python` 的绝对路径，不要求重装环境。

```bash
python -m intelligence.eval.mechanism_pilot prepare --directory "$HOME/.finance-runtime/mechanism-pilot/R-20260916-04"
python -m intelligence.eval.mechanism_pilot run --directory "$HOME/.finance-runtime/mechanism-pilot/R-20260916-04"
python -m intelligence.eval.mechanism_pilot report --directory "$HOME/.finance-runtime/mechanism-pilot/R-20260916-04"
```

`prepare` 不需要凭据：冻结原材料、答案键、两组完整提示词、调用顺序、预算和量具代码指纹。完整材料保留，不用摘要覆盖原件；模型输入只从问题/事实/选项三个字段投影，不包含答案键。

`run` 使用已有 `llm_refine.detect_provider / synthesize_messages` 适配器，从当前进程已配置的 provider 取凭据。不读取生产用户记忆，不修改服务配置，不自动读取 Keychain。无凭据时 exit 2、`no_configured_model`、0 次调用；不是失败模型答卷。凭据由既有运行环境配置，不写进命令参数或试验文件。

首次执行冻结 provider 名称、请求模型、端点摘要和思考配置；续跑不得变更。同组预算相同，具体数值以 `protocol.json` 为准：包括实际传给适配器的输出 token 上限与超时，每格最多一次 HTTP 尝试。字符上限是返回后的结构检验，不冒充供应商 token 限制。当前适配器不返回 served model，此字段留 null，不能证明供应商内部没有换模型；token 实际用量没有测量，不用字符数替代成本。

每格先原子占用 `attempts`，再调用模型，最后写 `responses`。重跑只执行尚未占用的格；已经失败、输出坏 JSON、或占用后尚无答卷的格都不自动重抽。若进程崩溃，占用格保留为 `attempted_without_response`。这牺牲自动恢复率，换取不因多次抽样挑到“最好的一次”。更换提示词、模型配置或代码须另开试验目录并登记新尝试，旧尝试不删除。

不可覆盖发布与内容摘要复用 `research_validation.Repository.publish` / `contracts.digest`。这里只复用存储原语，**不把诊断计数写成概率实验或方法验证收据**。哈希证明内容绑定，不是防有权限者重算哈希的签名或安全沙箱。

## 如何读数

`report` 只读冻结协议与答卷，重算指标，不调用模型，不依赖当前题包文件。

- 主指标：下一条核查问题是否命中预写答案键，按题成对比较。
- 保护指标：反证编号集合是否与答案键完全一致，最多两条；全选、重复编号、未知编号不合格。
- 每组同时报告计划格数、完成格数、失败/未跑/待答状态；失败不能从计划分母消失。
- 只有两组都完成的题给成对胜/平/负，完整配对数必须同时展示，不能拿幸存配对外推全集。
- `organization / reason / change_condition` 保存供人工核查，**字段非空不证明解释正确、因果成立或条件可操作**。机械得分只能证明选择题命中。
- `pending` = 尚有未跑或待答格；`incomplete` = 均已有终态但含失败或不合格；完整才为 `descriptive_only`。所有状态都禁止自动晋升、金融决策与效果认证。

## 阶段判据

1. **量具校验（本轮）**：证明同材料、答案键不进模型输入、预算真传到底层、失败留分母、重跑不重抽、协议与答卷不可覆盖。合成题全对只是量具通路，不是方法有效。
2. **合成模型诊断**：冻结后跑一批，原样保留全部结果。若两组都满分，说明存在天花板效应，不能声称有效；若实验组反证表现更差，先查是否过度压缩，不通过反复改提示词重跑同题选赢家。所有结果都只是设计线索。
3. **真实材料独立评审**：由未参与提示词设计者挑选新材料并确认反证和区分变量。事先冻结来源、可知时点、研究期限、材料预算、评价标准与退出条件；仍先测研究过程，不借后验上涨反推机制正确。这里才建立 Workbench 原入口的真实对照，而非将直接模型调用冒充产品收据。
4. **真实前向观察**：另行预注册假设与预期，记录候选框架及失败历史。收益/概率问题符合合同才接 `research_validation.freeze_study/register_forecasts/settle_outcomes`；当前该模块 forward 只接受人工/确定性概率，不能把 LLM 结果硬塞成确定性来源。历史比较走 `historical_research`，其 research_only 边界不变。

到第 3 阶段以前，不接入生产长期记忆，不改用户框架母本，不建立“自动创造概念”模块，不宣称压缩已经提高研究或投资能力。
