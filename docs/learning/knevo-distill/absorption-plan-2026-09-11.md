### R4/R5 的收窄（2026-09-11 复核笔记，`~/agent-memory/00_inbox/2026-09-11-knevo-new-corpus-absorption-review.md`）

两条都**按原样执行会造重复件**，所以改定义而不是改状态：

- **R4 不做摘要引擎**。市场总览已有阶段/风险/验证点，排序输出已有主判断/竞争解释/
  改判条件/下一步，再加一个「三要素压缩头」只是重叠。初版四条丢弃规则里的「非主线」
  和「只留一条主矛盾」**已撤**——非主线正是新线索与反证的藏身处。留下的唯一判据是
  「保留的信息要能回答：它改变哪项判断，或帮助裁决哪个未解问题」。
  真正的增量落在**材料侧而不是文案侧**：`evidence_window.select_agent_evidence`
  原来只按相关性/硬度/新鲜度/独立性排序，**不认识反证**，十二篇同一笔订单的转述稿
  可以把唯一一条弱源反证挤出窗口。现在同事件合并成一位（出处在证据链末尾列出）+
  反证保底置顶，两条子句各有反向对照测试（关掉就红）。
- **R5 不采纳「六项满足四项」投票阈值**。那六项里价格响应/资金/拥挤度共享同一批
  成交数据，独立计票等于把一个信号数三遍。改成两问分答：产业证据变化（兑现路径是否
  变强）与定价状态（已经反映多少、哪些判断不了），允许「逻辑增强 + 已拥挤」同时成立。
  另有两处口径修正：①原清单「sellside-coverage-cross 只有覆盖密度单维」**与实际不符**，
  该 skill 已在查库内已知信息、覆盖密度、盘面背离与观点冲突四问；
  ②`event_pricing.reaction.CONSENSUS_GAP` 至今是 `"not_wired"`，**没有事前预期源**——
  所以契约要求无预期源时逐字声明「只报告价格状态」，不许拿上涨本身当共识证据。
- **接线优先于契约**（R1a 的教训）：定价状态问句（「液冷还能追吗」）一个中期词都不带，
  原来拿不到拥挤度分位，契约层再写一百遍「要写拥挤度」也只能得到编的数。所以先放宽
  D6 门控（`is_pricing_state_query` 并入 `midterm_intent_for`），R1a 的负例
  （「今天信创板块怎么样」「今天哪些板块涨了」「过去 10 个交易日涨停家数逐日变化」）
  逐条有测试钉着仍然关闭。
- **本轮不上修复硬门**：两个契约的缺件只进收据（`judgment_delta` / `pricing_split`
  两个 receipt 键，`continuous_turn_adapter` 产出），**不并进 `missing_outputs`**——
  那会触发修复轮、改预算行为。先用同题对照实验量出效果，再决定要不要接
  `track_contract.is_contract_rewrite_only` 那条表达槽路径。

- question-bank 的「回灌落地仍欠」暂**不改**：正门形态未定之前改它会锁死错的那个。

### 台架自身踩的两个坑（比结果更值得记）

1. **首轮漏传 `thinking:{"type":"disabled"}`**（生产 `llm_refine` 是传的）。契约让
   prompt 变长 → 推理 token 吃光 `max_tokens` → **所有加契约的臂 `content` 长度为 0**，
   读数反向，差点得出「契约让结果变差」。终态指标为零往往是「中间态被截断」，不是
   「模型无视指令」；台架必须复制生产的运行条件，`finish_reason` 要进记录。
2. **反证检测词用了「资本开支」这类通用词**，模型凭自身先验就能写出来，造成假阳
   （J3-A0 反证不在窗口内却判命中）。换成证据独有的数字（15% / 2028 / 12%）后消失。

一次性台架在 `/tmp/knevo_ab.py`，按 CLAUDE.md「实验性代码默认不提交」不入库；

## 正门那一次（2026-09-11，三跑才问对问题）

同一句「英维克涨这么多了还能追吗」，三次运行，每次只有一个条件变。**前两次的结论都是
错的，错在不同层**，记全是因为这三步各自会再犯：

| # | 条件 | 结果 | 当时的（错）结论 |
|---|---|---|---|
| 1 | `cli ask`（默认） | 无 LLM，模板渲染，两段标题 0 | 「正门看不到，可能被题材渲染器盖住」 |
| 2 | `cli ask --compose` | `LLMDeadlineExceeded` 降级模板 | —（暴露出 1 是入口选错） |
| 3 | `--compose --llm-timeout 600` | 合成成功，两段标题仍 0 | 见下，这次才是真读数 |

1. **入口选错**：`cmd_ask` 传 `compose=args.compose`，而 `--compose` 是 `store_true`、
   **默认 False**；契约注入点 `ask_synthesis.py:872` 在 `ask.py:4129` 的 `if options.compose:`
   里面。那一跑一次模型都没调，契约不可能出现。生产入口全是开的：
   `api/app.py:1455` 请求模型 `compose: bool = True`、`conversation_orchestrator.py:2859`
   `compose=True`、CLI 的 `chat` / `agent` 硬编码 True——**只有 `cli ask` 默认关，我恰好
   测了唯一关着的那个**。
2. **预算不够**：`--llm-timeout` 默认 60 秒，还要在 brief/composer/judge 之间分，
   合成抛 `LLMDeadlineExceeded`（`llm_refine.py:1772`），正文回落模板。表头那句
   「LLM 合成超过共享截止时间」是**我们自己的 deadline 走完**，不是网关慢。
3. **真读数**：`compose=True, synthesize=False`（抄 `conversation_orchestrator.py:2859`
   的条件，只造 prompt 不调合成模型）dump `prepared_synthesis_messages`——

   ```
   question_type = 'stock_deep_dive'      # 不在 _EXCLUDED_QUESTION_TYPES 内
   该 question_type 下契约字数 = 782
   prompt 内含 产业证据变化/定价状态/无事前预期来源/禁止投票式判定/相对分位 = 全 True
   prompt 总字数 = 27958                   # 契约占 2.8%
   ```

   契约**在 prompt 里**。但答案两段标题都没出现，`missing_pricing_split_elements`
   判 `('industrial_evidence_section','pricing_state_section')`，`violations` 为空。
   读正文会发现它**实质上分了两段**，只是用了自己的小标题。

**可迁移的那一条：契约在 prompt 里的占比是它能不能变成结构的自变量。** 台架里契约占几分之
一、模型 100% 照做；正门里占 2.8%、模型按实质答对但不照格式。所以「台架验过」只能声明
上界。下次量表达契约，先记 `len(contract)/len(prompt)`，再谈遵从率。这跟
`harness-prompt-is-part-of-the-measurement-condition` 是同一个坑的两面：那次是台架
prompt 让指标偏好，这次是台架 prompt 让遵从率偏高。
