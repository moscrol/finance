# Q11：三库矛盾仲裁规则（Knevo 回贴摘要）

问题：finance_memory_query 检索到共享记忆库和我自己的记忆矛盾时（比如风远说透支、我自己复盘说还在共识期），按什么优先级仲裁？skill 里有规定吗？

## 三层处理规则（skill 原文要义）
1. **不自动判决，先摆出来**：按来源标注区分 user-finmemory（个人观点/复盘）与 finmemory（共享认知），检索结果分层（核心 thesis/事实/推理模式/反方失效条件/噪音）——矛盾必须可见，禁止合并成"市场有分歧"。
2. **双方都只是 prior**：任何含结论/概率/时间窗的记忆命中只能标"已有判断/历史基线"，必须用图谱/provider/web 补证——**模型曾写入的综合 insight 不得原样当当前事实**（防记忆自我强化回路）。
3. **仅有的两条硬规则**：
   - 「共享框架优先级**不低于**用户记忆，不要只靠用户记忆+新闻碎片下结论」（防个人偏见，注意措辞是"不低于"非"高于"）。
   - review-check 场景：「记忆 vs provider 冲突以 provider 为准」——**仅限事实层**（毛利率数字类），不适用判断层矛盾。

## 判断层矛盾的实操流程（它给的例子）
双方标源 → provider 查当下数据（资金/换手/估值分位/板块分化）→ web 补催化/利空 → 输出"你认为 X、共享框架认为 Y、当前数据更支持 Z（理由）+ 监控信号"。禁止 personal 自动判对、也禁止共享库自动推翻用户 thesis。

## 架构解读
- P3 探针文档面已答：**判断层无硬仲裁，事实层 provider 至上**。这个设计的本质是"记忆是 prior、数据是 likelihood"的贝叶斯姿态——先验冲突不内部裁决，引第三方证据更新。
- 残留验证点（低优先，可选实测）：文档说的是应然，实际回答中它是否真做到"双源分标不合并"——AB-001 里它引用风远框架时**没有**同时报告用户库是否有矛盾观点，可作为一条行为观察继续留意，不必单独花积分。

## 与本地对照 / 回灌
- 我们同构物：证据分层（L1/L2/L3）+ 45 天复核，但**记忆/结论的"prior 化"规则缺失**——workbench 检索到旧 synthesis 结论时是直接引用的，没有"标为历史基线并强制用当前盘面数据核验"的门。
- 回灌候选（高价值）：①ask 管线中 W 检索命中的旧结论强制打"历史基线"标签并触发 D* 盘面块核验（=它的第二层规则）；②冲突呈现契约："A 源认为 X / B 源认为 Y / 当前数据支持 Z"三段式，禁止和稀泥合并；③事实层冲突以数据源为准的硬规则写进 qa 闸门。
