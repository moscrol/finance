## 1. D1 v4：顶层三分区（先拆指令/材料/题组，再谈识别）

现 splitter 的失败不只是吞编号题：T2 的开场禁令（「请只依据上面的虚构行业材料……」）
和 T3 的续轮声明（「继续上一轮的虚构案例……其余条件不变」）也被并进材料正文——
于是约束检测器即使在「材料块外」找，也找不到已被吞掉的指令。

v4 把拆分改为**有序三遍**（全部确定性）：

1. **指令区提取**：面向助手的行为指令句——约束/禁令（只依据/不要联网/假设……）、
   交付要求（逐题回答/字数限制/格式）、续轮声明（继续/接着/其余条件不变）。
   判据：祈使/限定句式 + 指向「回答方式」而非「回答内容」。指令区**不是材料**
   （不进证据内容），是 D2 约束检测的**唯一**输入。
2. **题组区提取**：材料块之外、以 `^\s*\d+[.、)）]` 开头的段落，序号连续成组
   （允许空行分隔，v3 规则不变）；question_id = 用户原编号。
3. **材料区**：剩余正文（含被引用的研报/虚构案例正文）。材料里的「假设/不联网」
   字样因不在指令区，天然不会被当命令（v3「只在用户指令区识别」由此落地）。

无指令区/无题组时行为与现状完全一致（回归锁 A5/A6 覆盖）。

## 2. D4 v4：冻结点原子三元组 + 非工具先验同约束

QC 复现：只删 allowed_capabilities、保留 mandatory 取证项 → 合同构造报错。
根因是「授权」「取证计划」「输出槽」三者在冻结处必须**互相一致**，不能只改一角。

v4 规定冻结点（episode_factory 合同定型处）对 data_scope≠full 的任务**原子生成**：

- **授权**：material_only → 移除 finance_query/evidence_search（含 :256 重加与
  :639-644 回补后的最终集合）；local_only → 仅摘实时拉取类；
- **取证计划**：同步重建——material_only → requirements 为空、mandatory_capabilities
  为空（与授权同空，不再出现「授权空但 mandatory 在」的构造冲突）；边界/声明槽按
  D3 v3 的前提域声明处理，不进 mandatory；
- **输出槽**：按 question_id 生成（D5 v3），与授权/取证计划在同一次冻结写入合同；
- **非工具先验**：最终模型输入里的非工具内容——opening_prefetch 消息、prime/知识
  前缀、会话摘要——同样受 data_scope 约束：material_only 时不注入外部事实型先验
  （预取短路见 v3；prime/知识前缀中的市场事实段同禁），同题链上下文（上一轮材料
  与原答）作为用户前提保留。
- dispatch 兜底不变（v3 A9）：模型主动请求被禁工具 → 执行层拒绝 + trace 留痕。

## 3. D6 v4：条件化纯度 + 材料锚点

- **纯度校验以 data_scope 为条件**：
  - material_only → 市场事实句必须绑定材料锚点或前提域声明；绑外部 provider 即拒；
  - local_only → 实时/外部 provider 绑定即拒，本地 fact 表绑定合法；
  - full（含 A8 的 fictional×full）→ 不做纯度校验（虚构前提仍可自由结合真实检索，
    与 A8 不再冲突）。
- **材料锚点**：前提域事实句的绑定必须携带具体锚点（material_id + 片段引用/哈希），
  不是一句「结论仅在材料内成立」的类别标签。basis=user_premise 只说明**类别**；
  锚点才证明**绑定**。无锚点的市场事实句在 material_only 下仍被拒——声明句不替
  任意事实背书。

## 4. 验收断言（v4 增量修订；A1–A10 其余沿用 v3）

- A2 增补：T2 开场禁令、T3 续轮声明被拆入**指令区**（不进材料、不进题组）；
  约束检测只读指令区。
- A3 改：material_only 下市场事实句 100% 带材料锚点或前提域声明绑定；
  full 下不校验（A8 正向用例保持）。
- A9 增补：material_only 的合同中授权、取证计划、输出槽三者一致（构造不报错）；
  最终模型输入无外部事实型先验（预取/prime 前缀的市场事实段缺席）。
- A11（新）：指令区误报回归——材料正文引用「假设……」的研报题，约束不触发、
  行为与现状一致。
