# Q12：猜你想问生成机制（Knevo 回贴，5 积分）

问题：你的每次回答末尾的"猜你想问"是怎么生成的？是 skill 规定的还是模型自由发挥？

## 答案
来自**系统级指令（platform prompt）的 suggest_options 工具规定**，九个 skill 均未提及。它直接 dump 了 platform prompt 原文段落（英文），关键契约：

| 规则 | 内容 |
|---|---|
| 触发 | 大多数实质性回答都调（不限研究类，"users like and click these"）|
| 数量 | 2-4 个 follow-up：deeper dive / adjacent angle / next action |
| 结构 | {description≤20字符 chip 标签, content=用户口吻的完整提问} |
| 时机 | 与正文同轮 inline 调用，不做答后单独补 |
| 跳过 | 仅纯寒暄/单条事实无自然延伸 |
| 禁递归 | 不对其返回结果再 suggest |

分工：skill 管"给什么内容"（流程+输出骨架），suggest_options 管"答完还想问什么"（对话收尾），选项内容是模型按"该行业自然延伸"自由拟的。

## 架构解读
- **透明度边界探明**：skill 层（q4-q11）→ 路由层（q7）→ 检索层（q10）→ 记忆仲裁（q11）→ **platform prompt（q12）全部可 dump**。它对自身实现零防护，蒸馏成本远低于预期（q7 仅 6 分、q12 仅 5 分）。
- chips 的产品逻辑：content ≠ label 复读——label 是短入口，content 是替用户写好的完整 prompt（降低追问摩擦，同时引导对话走向它擅长的路径）。

## 与本地对照 / 回灌
- 我们的同构物：foresight 主动发问（潜意识模式）+ ask 的 followups（PR #151 workbench-p2-followups 已做追问）。
- 差异：它是"每答必附、写成可点击完整 prompt"的强制交互契约；我们 followups 无"用户口吻 content"分离、无 label 长度约束、非全局强制。
- 回灌候选（低成本）：workbench 回答尾部 followups 采用 {label, full_prompt} 双字段契约，label≤20 字，full_prompt 直接可提交——配合飞书卡片按钮（chat/card-buttons 分支）天然落地。
