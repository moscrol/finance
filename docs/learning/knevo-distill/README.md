# Knevo 方法论蒸馏笔记（基于 71 页使用分享，2026/6/30）

## 一、他做得好的核心机制（按章节）

### 定位（P1）
- 「认知复利系统」：不替代判断，而是把高手的权重排序、风险嗅觉、肌肉记忆**显性化**。
- 分工明确：用户给方向感和取舍，系统补变量、反问、推演和证据链。

### 二章：七个基础动作（日内闭环）
1. **今日复盘 = 作战地图**：不是行情摘要，而是压缩成「主矛盾 + 情绪扰动 + 裁判变量」，落到次日情景、板块落点、交易纪律。
2. **盘中监控 = 先定义信号再量化**：时间窗 + 2-4 个信号 + 偏多/偏空阈值 + 买/等/减/不动。例：「盯 PCB 封单是否松动、科创50 能否站稳 1770、量是否萎缩」。
3. **盘感翻译**：把"我不舒服/我共振"拆成可验证语言（隐含框架、变量排序、触发条件、动作分层）。
4. **猜你想问 = 问题资产**：8 种可复用 prompt 骨架——情景推演、盘中信号清单、新闻映射产业链、横向对比排序、仓位框架、时间轴与领先指标、历史类比带边界、复盘回放。
5. **记忆库入库纪律**：只收「已验证的框架/偏好/错因/验证口径」；未验证的判断先进决策追踪，命中/未命中后再回流成记忆。三分法：进记忆 / 进决策 / 暂不沉淀。
6. **决策追踪 = lifelong learning loop**：判断写入 → 市场验证 → fork 回当时上下文 → 用户归因（命中：哪条假设可复用；未命中：漏了什么指标/排序哪里失真）→ 系统反思回写记忆 → 统计胜率。
7. **事实审查**：传闻/小作文先钉真伪，再拆传导范围、可交易与不可交易部分。

### 三章：进阶提问（L1 钉事实 → L2 推演 → L3 读结构 → L4 校准框架）
- **情景推演**：不预测单一答案，事件 → 乐观/中性/悲观 → 传导对象 → 持仓动作 → 证伪信号。
- **推板块推票 = 追求排序**：确定性、弹性、兑现时间、是否已定价、下一个验证信号——并要求系统说明**排序何时会变**。
- **行为模拟**：问「谁有权改变变量、他的激励是什么、转向后传导到哪」而不是继续问行业数据。
- **资金推演**：博弈阶段问玩家属性和心理，比基本面更有增量。
- **认知压力测试**：行情高热时把自己框架放进压力环境——早期预警/加速信号/拐点确认三层，把「还能不能追」改写成「拐点如何确认、动作如何分层」。
- **价值迁移**：重大催化拆短期情绪 / 中期业绩路径 / 长期角色与利润池迁移。
- **记忆召回**：用旧框架解释当前体感（风险保护 vs 叙事切换 vs 框架需修正）。

### 四章：反馈双线成长
- 共振 → 追深（证据、反例、证伪信号）→ 凝练成框架 → 入库。
- 相悖 → 给证据纠错 → 系统回看记忆、归因、更新框架（不是只改结论）。
- 看起来对但未验证 → 写入决策，等市场回答后回放假设链。

### 案例：国产算力共振闭环（6/11→6/18）
盘感 → 系统结构化 → 连续多日校准（不追 PCB、推存储/国产算力）→ 6/17 晚间用新事件代入框架追预期差 → 6/18 兑现。关键不是结论对，而是把盘感、新闻、相对强弱、追问校准到**同一条判断链**上。

## 二、与我们双盲/台账系统的对照

| Knevo 机制 | 我们已有 | 差距 |
|---|---|---|
| 决策追踪 + 命中/未命中 + 胜率 | 双盲答卷 + T+1/T+3 recheck + verdict | ✅ 结构相近，我们更严格（冻结+双盲）；缺**胜率统计面板**和**错因归因回流** |
| 作战地图式复盘 | 台账 §1 底稿 + §2 核心判断 | 我们偏数据表，缺「主矛盾/裁判变量/次日情景」的压缩叙事 |
| 阈值化验证条件 | §3 验证阈值（t1/t3/targets） | ✅ 已有，甚至更结构化 |
| 记忆库入库纪律（验证后才入库） | §8 用户批注区（手工） | 缺「批注 → 经验库 → 下次预测自动引用」的回流管道 |
| 猜你想问 / 追问链 | 无 | 双盲 agent 是一次性答卷，没有多轮校准 |
| 认知压力测试 / 行为模拟 / 资金推演 | 无 | 可作为答卷新增章节或独立技能 |
| 错因归因（未命中后 fork 回上下文反思） | verdict 只判命中 | 缺系统性错因分类与反思回写 |

## 三、可蒸馏落地的候选项（按性价比排序）

1. **命中率统计页**：从历年 verdict/recheck 聚合 codex vs claude 的方向命中率、标的跑赢基准率、假设命中率，渲染进看板。
2. **错因归因回流**：verdict 未命中时自动 fork 当日答卷上下文生成「反思 JSON」（漏了什么指标/排序失真在哪），沉淀进一个 lessons.md / 经验库，次日答卷 prompt 自动附带最近 N 条 lessons。
3. **答卷增加「压力测试」章节**：每份答卷强制回答「本判断的早期预警/加速信号/拐点确认各是什么」，对应 Knevo 的认知压力测试。
4. **批注回流管道**：§8 批注非空时，nightly 链提取批注生成「硬规则候选」，人工确认后进入答卷 prompt 的规则区。
5. **问题资产库**：把 Knevo 附录的 8 种 prompt 骨架和优质问题改写成我们的技能文件（skills/），复盘时可复用。

## 四、建议向 Knevo 提的蒸馏问题（用户可代问）

1. 「把你判断一个板块是'情绪脉冲/资金切换/主线扩散'的完整判据清单列出来，包括每个判据的数据口径和阈值。」
2. 「你做方向排序时用哪些维度打分？确定性/弹性/兑现时间/拥挤度各怎么量化？排序何时会变？」
3. 「决策未命中后你的错因归因分几类？每类的识别特征和修正动作是什么？」
4. 「认知压力测试的信号分层（早期预警/加速/拐点确认）在 A 股用哪些具体指标？」
5. 「你判断'高覆盖方向是共识兑现还是主线再确认'的硬条件是什么？」

—— 这些答案可以直接翻译成我们双盲答卷的 prompt 规则和 verdict 判据。

## 五、2026-08-02 运行态实测增量

本轮三组只读实验的完整记录见：

- `E-006-runtime-retrieval-memory-lifecycle.md`：finmemory 检索矩阵、fundacore 正确查询通路、推荐到长期记忆的生命周期、UI/持久化不同步边界。
- 共享 Agent 可直接吸收的运行时契约：`/Users/a77/agent-memory/10_knowledge/finance-agent-knevo-derived-knowledge-runtime-contract.md`。

本轮新增校正：

1. `fundacore` 不能通过 `finance_memory_query` 查询，正确链路是 `finance_entity_resolve → finance_graph_context`。
2. 图谱有实体不代表有边、事实或证据；返回必须保留 `entities / edges / facts / evidence / gaps`。
3. `finmemory` 召回存在跨 query 重叠、泛化词噪声和时间词偏移；不能把一次 top-N 召回当作事实裁决。
4. pending recommendation 不等于长期 memory；`hitCount` 不等于预测胜率，memory confidence 不等于校准概率。
5. 异步/UI Agent 的验收必须同时检查 payload 持久化、工具事件、助手输出和会话索引，不能只看 HTTP 200。

后续本地回灌优先级：

- P0：统一知识卡 schema，分离 graph/shared memory/user memory/provider。
- P0：图谱空边/空事实门控，禁止模型补关系。
- P1：检索 provenance、跨 query 支持度和预测验证 ledger 分离。
- P1：推荐状态机与长期 memory 写权限隔离。
