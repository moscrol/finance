# Q10：finance-mode 检索硬触发规则原文（Knevo 回贴）

问题：finance-mode 的检索硬触发具体规则原文是什么？记忆/行情/新闻三路各调什么工具、什么顺序、什么条件跳过？

## 触发条件表（原文）
| 命中条件 | 必须调用 |
|---|---|
| 具体标的（公司/代码/ETF/指数/板块/行业）| finance_memory_query + finance_quote(days=0)；个股概览首选 finance_instrument 一次拿全（基础档+现价+日K+新闻+龙虎榜）|
| 「最近/现在/今天/最新/近期」+行情/消息/事件/公告/异动 | finance_news(days=N) |
| 公司/产业链/上下游/竞对/客户/供应商 | finance_entity_resolve + finance_graph_context |
| 财报/营收/利润/现金流/估值/PE/PB | finance_statement 或 finance_quote(provider=ifind, days=30) |
| 用户给出观点/持仓/看多看空/目标价/止损线 | finance_memory_query 历史基线 + provider 核验当前状态 |

## 执行规则（原文）
1. **并行发起**：记忆+行情+新闻同轮齐发，禁止串行。
2. **必须实际调用**："想到要查"不算；**空结果也是信息，要如实披露**，不得主观判断"可能没覆盖"就跳过。
3. **快答 = 检索后短答**，不等于跳过检索。
4. 空结果改写重试：中英切换/简称↔全称/公司名↔代码，总共最多 3 次。

## 唯一豁免（三条）
①纯寒暄/确认 ②纯流程/格式澄清 ③与标的当前状态无关的纯概念/静态属性（"什么是 PE"）。拿不准时默认检索。

## 架构解读与本地对照
- P2 兜底裸测探针可取消：兜底不是裸 LLM 已白盒确认——所有实质问题强制过"记忆+行情+新闻(+图谱)"四路并行，质量下限由检索前置保证，出口 verifier 只管上限。
- 亮点设计：①**触发条件写成词面+语义混合表**（比纯触发词鲁棒，比纯 LLM 判断可审计）；②**"用户给出观点"也是触发条件**——用户表态即拉历史基线核验，这是我们 record-correction 的前置对偶（它先核验再回应，我们事后纠偏落档）；③空结果改写重试的次数上限（防检索循环）。
- 与我们对照：workbench prime/ask 的块路由（W/M/V/D*）同构，但我们缺：①"用户表态→自动拉历史基线"触发；②改写重试策略（我们检索空就报缺，不做 query rewriting）；③finance_instrument 式"一次拿全"聚合工具（我们个股要串多个块）。
- 回灌候选：ask 管线加 query rewriting 重试（空结果时简称/代码/别名改写 ≤2 次）；把"用户观点触发历史基线核验"挂进 foresight/对话层。
