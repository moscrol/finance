# Q8：finance-industry-track skill 自述（Knevo 原文回贴摘要）

问题：介绍 finance-industry-track 的最佳用法和提问模板

## 设计要点
1. **track vs report 的边界规则**：有上期基线/固定周期/只要新信号/跟踪自己 thesis → track；首次系统看行业 → report。"深度报告建立框架，行业跟踪维护框架"。
2. **delta-only 契约**：只保留有信息量的变化，无变化项直接跳过，"上期结论还在就写无变化，不水字数"——反凑字数的显式输出纪律。
3. **输出骨架**：本期要点 / 数据速览 / 个股异动 / **观点更新（对照上期：支持/削弱/无变化/信息不足四态）** / 下期关注（指标+时间节点+触发条件）/ 一句话结论。
4. **自衔接循环**：第 5 段"下期关注+触发条件"是下一轮跟踪的输入——报告之间形成链。
5. **基线缺失的降级路径**：无上期基线时用 finance_memory_query 拉历史记忆观点替代，但明示"用户口述基线质量最高"。
6. **观点有效期分级**：track 结论 30 天复查，深度报告 90 天——输出带 TTL（存活期）标注。

## 与本地对照
- 同构：我们 daily-ops 晚间流程/卖方交叉就是 delta 型跟踪（以库内已有为锚只写增量）；concept-delta 分支同理。
- 我们缺：①**观点四态对照**（支持/削弱/无变化/信息不足）——我们的 synthesis 更新没有对上期结论的显式判定字段；②**观点 TTL**——我们证据有 45 天复核标记，但"判断/结论"本身没有有效期字段；③**下期关注→下轮输入**的显式衔接（我们 foresight checkpoint 是同构物但只覆盖可证伪点，不覆盖"下期观察清单"）。
- 回灌候选：给 wiki/synthesis 页加 frontmatter 字段 `prior_verdict_check: 支持/削弱/无变化/信息不足` + `valid_until`；晚间流程收尾产出"下期关注清单"并在次日流程开头强制读取。
