# Q13：内部流程与拒答/降级纪律（Knevo，24 积分）

问题：你回答一个盘面问题时的内部流程是什么：先检索什么、后检索什么、如何决定引用记忆库还是现算？什么情况下你会拒绝回答或降级回答？拒答和降级各自的触发条件、以及降级后必须保留哪些信息？

# 盘面问题回答的内部流程

这个问题问的是我自身的工作机制，正好可以从刚加载的 `finance-mode` 技能中完整回答。

---

## 一、检索硬触发：开口前的铁门槛

金融模式有一条最高优先级规则——**先检索、后开口**。只要用户消息满足以下任一条件，回答前必须先调对应工具，即使用户没让我"查一下"、即使我自认为知道答案：

| 触发条件 | 必须调用的工具 |
|---|---|
| 出现具体标的（公司/代码/ETF/指数/板块/行业） | `finance_memory_query`（历史观点）+ `finance_quote`（现价），个股深度优先用 `finance_instrument` 融合拿 |
| 涉及"最近/今天/最新/异动" + 行情/消息/事件 | `finance_news`（带 `days`） |
| 涉及公司/产业链/上下游/竞对/客户/供应商 | `finance_entity_resolve` + `finance_graph_context` |
| 涉及财报/营收/利润/现金流/估值/PE/PB | `finance_statement` 或 `finance_instrument`（profile.extra.fundamentals） |
| 用户给出观点/持仓/多空/目标价/止损线 | `finance_memory_query` 取历史基线 + provider 核验当前状态 |

**唯一豁免**（可不检索直接答）：纯寒暄、纯流程/格式澄清、与标的当前状态无关的纯概念问题（"什么是 PE""茅台的股票代码"）。拿不准时默认检索。

---

## 二、检索顺序：并行优先、先宽后窄

### 第一轮（并行发出，不串行）

```
finance_memory_query（窄+宽双发）  ← 同时发出 ┐
finance_quote / finance_instrument ← 同时发出 ├ 同一轮
finance_news（如涉近期）           ← 同时发出 │
finance_entity_resolve + graph    ← 同时发出 ┘
```

**关键词构造规则**（第一轮就要宽召回，不等空了再改）：

1. **窄+宽双发**：查"宁德时代"的同时查"动力电池 储能 锂价 产能周期"
2. **多形态扩展**：中文名 ↔ 英文名 ↔ 简称 ↔ 代码 ↔ 核心产品 ↔ 概念标签
3. **复合问题拆解**："X 会不会因为 Y 涨"拆成 X 本身、Y 事件、X↔Y 关系三组
4. **时间维度**：近期事件用 `days=3~7`，趋势用 `days=30`
5. **反方词主动加**：除正向逻辑词外，加"减产 库存 杀估值 竞争加剧"

### 第二层：空结果改写重试

若 `finance_memory_query` / `finance_graph_context` 返回空或只命中实体无邻居/事实，则串行改写：
- 中英切换 → 简称↔全称 → 公司名↔代码（美股中文名→ticker、港股→5位代码）→ 代码带/不带后缀
- **上限**：首次 + 最多 2 次改写 = 总共 3 次；仍空则停，披露为 gap

### 第三层：补证与兜底

- 记忆/图谱提供了历史基线后，**价格/涨跌/公告/政策等易变项**必须再用 provider 核验
- Provider 覆盖不足或材料不足以判断时 → `web_search` / `web_fetch` 补全
- 有实体就查图谱：记忆命中中出现公司/产品/产业链/竞对时，必须再走 `finance_graph_context`

## 三、记忆库 vs 现算的决策逻辑

这条来自技能中的「检索原则」：

| 数据类型 | 优先走哪 | 原因 |
|---|---|---|
| 稳定 3 个月以上的行业框架、产业链、公司事实、历史观点、推理模式 | **记忆/图谱** | 不易变，记忆库是高效缓存 |
| 价格、涨跌、突发事件、公告、政策变动、地缘事件、最新财报 | **金融 provider 现算** | 记忆只提供历史基线，易变项必须实时核验 |
| Provider 覆盖不足或需要公开网页原文 | **web search/fetch** | 无类型广域召回，用于补漏 |

**关键纪律**：记忆的角色是"历史认知与研究线索"，不是当前事实源。即使某条记忆包含完整结论/概率/操作建议，也必须标为"已有判断/历史基线"，再用图谱 + provider + web 补证验证。

---

## 四、拒答的触发条件

拒答 = **完全不做、不输出结论**。触发条件：

| 条件 | 说明 |
|---|---|
| 实盘交易请求 | "不进行实盘交易、券商登录、资金划转或订单提交"——直接拒 |
| "必涨/必跌/保证收益"类要求 | 拒绝包装成确定性收益承诺 |
| 超出金融投研边界且无法关联 | 极少触发，大部分问题至少可以给方法论框架 |

---

## 五、降级的触发条件

降级 = **仍然回答，但降低确定性、标注缺口、更换数据源**。触发条件比拒答多得多：

| 降级触发 | 降级后必须做什么 |
|---|---|
| Provider 返回 `missing_config`（缺配置） | 说明该数据源不可用的原因（脱敏），给出 fallback 路径 |
| Provider 返回 `degraded`（链路异常/限流/权限） | 说明降级原因，转向公开 web / 用户文件 / workspace |
| Provider 返回 `NO_DATA_FOR_QUERY` | 表述为"该标的/字段当前没有返回数据"，不编造 |
| 记忆/图谱空结果改写 3 次仍空 | **停止重试，把缺口作为 gap 披露**，不无限重试、不编造 |
| 只有二手来源、无一手披露 | 明确标出"二手来源"或"公开资料推断"，不伪装成一手 |
| 关键事实无法完成当前核验 | 写明"基于历史记忆的预案，未完成当前验证" |
| 事件概率无法可靠量化 | 说明数据不足以量化，给情景树 + 定性判断，不做精确数字 |
| 第一个 provider 不可用 | 按工具返回的 fallback 线索继续尝试其他 provider / web / 用户文件，不直接放弃 |
| 仅命中单条记忆 | 标为"已有判断/历史基线"，不能当自动答案用 |

---

## 六、降级后必须保留的信息

降级不是删减信息，而是**换源 + 加标注**。降级后回答中必须保留以下内容：

1. **尝试过什么**：明确列出调用了哪些 provider / 记忆 / 图谱 / web 搜索，各自的返回状态
2. **缺口具体是什么**：哪个字段/数据源不可用、原因（脱敏表述）、对判断的影响
3. **使用了什么 fallback**：降级路径（如"datasvc 不可用，以下数据来自 web_search → 来源 X，发布日 Y"）
4. **来源标注不降级**：即使降级，来源标注规则照常执行——渠道 + 底层来源 + 时间
5. **事实/推断/假设的区分**：降级后推断成分更多，但必须把三者分得更清楚
6. **待补证清单**：报告类回答里明确写下一步需要补什么数据
7. **已有判断与当前验证的分离**：记忆命中的结论必须与实时核验结果分开写，不能混在一起

---

简而言之：**检索是硬前置**（并行→宽召回→空结果改写→provider 现算→web 兜底），**拒答只针对实盘和收益承诺**，**降级是常态机制但必须保留溯源、缺口和 fallback 路径**。降级后回答的可信度降低了，但透明度必须提高。

## 架构解读与本地对照

**与 q10 的边界**：检索硬触发表这次是重复（[[q10-检索硬触发规则]] 已 dump 过原文），本题的增量全在**拒答/降级侧**——q10 只说了"必须先检索"，没说"检索不到时怎么办"。

**它的拒答面窄到极致**：只有实盘操作类（下单、划转、券商登录）和确定性收益承诺两类会真正拒答。除此之外全部走降级。这条对我们的意义是反向的：我们 acceptance 里 C1（未来日期无数据）、C2（非交易日）、A8/A9 这类题，一直卡在"零证据到底算拒答还是算降级"没定分类。knevo 的答案给了一个可抄的划分线 —— **无数据不是拒答理由，只是降低确定性 + 标注缺口的理由**；拒答只留给"做不了的动作"和"不能给的保证"，而不是"查不到的事实"。

**降级后必须保留的 7 项**（这是本题最可回灌的部分）：尝试过什么（含各源返回状态）／缺口具体是什么及其对判断的影响／用了什么 fallback 路径／来源标注不降级／事实-推断-假设三者分得更清／待补证清单／历史基线与当前验证分离写。它有一句话点得很准：**降级后可信度降低了，但透明度必须提高**。我们 resolver 的 unverifiable 分支目前基本只做到"标注缺口"这一项，其余 6 项没有强制字段。

**空结果重试上限**：首次 + 最多 2 次改写 = 3 次，然后停手把 gap 披露出来。我们的检索层没有这个显式上限。

**可回灌候选**：把这 7 项做成 resolver 降级输出的必填结构（缺一项即视为降级不合格），配合 acceptance 的 A8/A9/C1/C2 打分口径。
