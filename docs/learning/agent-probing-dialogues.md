# Agent 探针对话与进化型验证假设

> 目标：通过特定的验证假设和对话方式，逼 agent 暴露知识库的真实作用和自身能力边界，
> 把暴露出的信号导回现有进化回路（verdict 台账 / failure_mode 归因 / 经验卡）。
> 与三流问句模板（`forecast-question-templates.md`）互补：三流测「预测准不准」，
> 本篇测「知不知道自己为什么准/不准」。

## 一、进化型验证假设（原则：预测必须落在 agent 有信息优势的地方，否则测的是运气不是能力）

### 1. 知识库时间差假设（最有价值）
「库内 X 公司已有 L3 证据（订单/送样/中标），但卖方覆盖 <2 篇 → 预测 T+5 内覆盖密度上升或首次异动。」

- **验证的是**：知识库是否领先市场。hit = 库有 alpha；miss = 证据分层有问题（把软推演当硬证据了）。
- **裁定**：stream=卖方，horizon=T+5；miss 归因优先查 evidence_layer 标注是否虚高。

### 2. 反向排除假设
不只预测「谁会涨」，也预测「这个热门题材我判断是纯情绪、T+3 内无 L3 证据跟上 → 衰竭」。

- **验证的是**：排除的命中率比正向更能暴露认知质量——正向预测有市场 beta 兜底，排除没有。
- **裁定**：判衰竭但 T+3 出现 L3 证据且板块新高 → miss，failure_mode=「证据搜集滞后」或「情绪判断过早」。

### 3. 传导链假设
theme-radar 产业链图谱说 A 涨会传导到 B（上游/设备/材料层）→ 预测 B 的滞后启动窗口。

- **验证的是**：概念图谱的边是否真实有效。miss 直接指向该清理哪些废边（graph_only 关系不等于市场传导）。
- **裁定**：miss 归因写明是「边不存在」（图谱废边）还是「边存在但节奏错」（窗口估计错）。

### 4. 自我校准假设
每条预测标信心档（高/中/低），跨期统计「高信心命中率是否显著高于低信心」。

- **验证的是**：校准度。不校准 = 它不知道自己不知道什么——能力边界最直接的量化。
- **落地**：答卷 hypotheses/thresholds 附 confidence 字段，aggregate 按信心档分桶看命中率。

### 5. 反事实复盘假设
miss 之后追加一条「如果当时看到 Y 数据，我会改判吗」→ 下次同类场景验证该修正规则。

- **验证的是**：failure_mode 从静态标签升级为可测的修正规则；同类错误第二次再犯 = 修正规则无效。

## 二、探针对话（日常使用，不需要专门仪式）

| 探针 | 问法 | 暴露什么 |
|---|---|---|
| 先证据后结论 | 「回答前先列出你要用库内哪几条证据、各是什么层级（L1-L4），没有的显式写缺口」 | 缺口清单 = 知识库边界地图 |
| 同题双问 | 同一问题分别问「只用库内证据答」和「自由发挥答」，对比差异 | 差异大处：要么库缺数据，要么它在编 |
| 追问证伪 | 任何结论后固定追「什么信号会推翻这个判断？给具体数值」 | 答不出数值 = 结论不可裁定 = 超出能力边界 |
| 让它出题考自己 | 「基于当前库，你最没把握的三个判断是什么？」 | 它主动暴露的不确定区比外部猜的更准 |
| 老题重问 | 隔 1-2 周重问同一问题，看结论是否随新证据更新 | 不更新 = 库在增长但认知没接上（检索/编排层问题，用 RAG telemetry 定位是哪层） |

## 三、落地决策：统一 ask 路由 + probe 标签（不封独立模块）

**决策（2026-07-03）**：探针问答不封装独立模块，统一走 ask CLI 路由，只加轻量探针标记。

- **理由**：
  1. 探针的价值在于测**日常同一条链路**（检索→编排→回答）；独立模块是另一套代码路径，测出的边界不是日常问答的边界，校准数据失真。
  2. 沉淀层已齐、缺的只是打标：retrieval_audit 台账（检索质量）、interactions.jsonl（反馈）、
     experience_cards（教训）、verdict 台账（裁定）。独立模块会重复造这几层。
  3. 已有先例可复用：「潜意识模式」skill 的"会话级开关 + 退出时回读沉淀"模式。
- **做法（最小改动）**：
  - `ask --probe <探针类型>` 或 dispatcher 触发词（如「探针：同题双问」）——路由不变，
    只在 retrieval_audit / 回答 meta 里多打一个 `probe_type` 标签。
  - 会话结束回读（与潜意识模式回读合并）：库缺口→ingest 待办、可裁定假设→verdict 草稿
    （带 stream/horizon）、复现教训→经验卡。
  - aggregate 按 `probe_type` 分桶：「同题双问差异率」「证伪追问可裁定率」随时间收敛与否 = 进化曲线。
- **例外**：只有当探针需要**改变生成行为**（如「只用库内证据答」需 prompt 层硬约束、屏蔽模型先验）时，
  才需要 probe 编排——但也应是 ask 里的一个 mode flag，不是平行系统。

## 四、信号回流约定

- 可裁定的假设 → 走 `dual_blind_forecast.py verdict`（带 stream/horizon/failure_mode）。
- 探针对话暴露的库缺口 → 进 ingest 待办（先落 source note，不直接写实体正文）。
- 稳定复现的教训（同一 failure_mode ≥3 次）→ 沉淀经验卡
  `intelligence/users/<user>/experience_cards.jsonl`；跨任务通用的 → `agent-memory/10_knowledge/`。
- 老题重问发现的检索问题 → 记 retrieval_audit 台账，别当认知问题处理。
