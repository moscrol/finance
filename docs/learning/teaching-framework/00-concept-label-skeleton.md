## 1. A 类：指数阶段词表（state 标签 `index_stage`）

### 1.1 词表已有的判据（用户此前口述，已进 `UBIQUITOUS_LANGUAGE.md`）

- 指数完整周期：**左底向下 → 左底向上 → 缩量右底 → 共建主线阶段 → 主流主升 → 高位震荡 → 回踩周均线**，或重新跌破进入左底向下循环。
- 周均线是区分 左底向下 / 共建主线阶段 / 主流主升 的分界线。
- 周均线偏离度接近 **+1.5** 时更容易进入高位震荡，接近 **−2.5** 时更容易进入左底向上。
- 成交量决定阶段性质：放量突破 → 共建主线阶段；逐步放量 → 主流主升；高位稳定量 → 高位横盘盘整；缩量回落 → 回踩周均线或缩量右底。
- 指数阶段判定必须回答三问：现在是什么阶段、从什么**来源状态**演变而来、下一步更可能延续还是切换。
- 左底向上不是主升，是低位超跌后的反抽，碰周均线大概率遇压；共建主线阶段是主线形成的突破段，不等于主流主升。

### 1.3 软判据怎么编码（用户 2026-09-06 拍板：+1.5 / −2.5 是软判据）

用户原话：「目前软判据吧，因为金融领域没有百分百，只是基于历史的大概率，我们本身就在做大概率事件的博弈。」

这句话决定 `index_stage` **不能编成硬 if / else 状态机**，但也不意味着它不可重算。软判据的确定性编码是三层：

1. **证据旗标**（point 标签，每个都是确定性布尔或档位）：例如 站上 / 跌破周均线、偏离度所在的带（不是一条线，是 ≥ +1.5 / 0 ~ +1.5 / −2.5 ~ 0 / ≤ −2.5 几个带）、是否跳空低开、量能状态、连续缩量 / 放量天数、主流成交占比是否扩大……每个旗标只说事实。涨家数 MA5 波峰波谷**不在定义里**（用户：配合看不参与定义），只作旁列。
2. **计分与置信档**（确定性规则）：每个阶段列出它「看」的旗标，命中几条就是几分；阶段 = 得分最高者，同时输出命中的旗标清单与置信档（例如「主流主升，3/4 条证据，缺逐步放量」）。同一天同一库两次算出的阶段、分数、清单逐字相同。
3. **四态收据**（`methodology_backtest`）：「大概率」到底多大，不由人说，由历史上的命中率、基准率、Wilson 区间、前后半段回答。软判据的「软」体现在这里——它允许被证伪、允许 `not_distinguishable`，而不是写死在代码里。

这样「软」与「可重算」不冲突：软的是结论的置信，硬的是计算过程。创始人给的不是权重，是**每个阶段最看的证据**——已在 §1.4 转录。

### 3.1 RPS 与偏离度：两条不同的轴（用户第四轮问「RPS 是什么，也是偏离度吗」）

### 4.1 「衔接」是一条可回测的候选规则（结构来自用户口述，口径已定）

用户说「高标断板日的低位**一般会有衔接**」——「一般会有」就是「大概率」，正是四态统计门要量的东西。它和 §4 的接力链是**同一个对象的两种输出**：接力链回答「每次是谁、什么形态、诞生环境如何」（事实），规则回答「下一任出自断板日附近低位这件事，历史上几成、比基准高多少」（统计）。

```text

  provenance.kind   teaching（用户 2026-09-06 口述 + 同日口径八答）

  outcome           handoff = true（leader_next ∈ candidates(T−1..T+1, limit_times ≤ 2)）

                    ——控制掉「任何最高标都曾是首板 / 二板」这条近乎必然的事实，只量「断板日附近」这个时点有没有超额
  numbers → B 类    无（k 已改为事件到事件；≥3 板与 ≤2 板是用户钦定的结构定义，不是待标阈值）
```

**补注二（09-07 第九段）：「衔接」不是二值判定，是关系描述；高标有两种载体。** 用户：「衔接就是看看上一个高标和下一个高标的关系，一个消亡另一个诞生是怎么衔接的，但不是每次都是高低连板的衔接，也要看区间涨幅，就是这个载体的形式。也可以理解成一段区间内的涨幅高的品种和后续涨幅高的品种，他们是怎么衔接转换的。」落法：(a) `LeaderSuccession` 的 `handoff` 布尔降为一个读数字段，节的主体改为**关系描述**——前任消亡日、继任诞生日、间隔天数、继任在前任消亡前后的形态（已有 `path / shape_tags`）、两者的板块 / 题材关系（同题材 / 同申万一级 / 无关，第二刀 C 类接上后可算）、继任者在候选窗内的位置（低位 / 已在高位）；(b) 高标载体加第二种——**区间涨幅高标**：一段区间（窗口待定，候选与平台「梯队高度」一致的 20 / 60 / 90 / 120 日之一，或本腿）内涨幅最高的一组品种，其消亡 = 跌出前列，诞生 = 进入前列，与连板高标各建一条链，两条链的交叉（某只既是连板高标又是区间涨幅高标）本身是读数；(c) 候选规则不再是「低位衔接成立与否」，而是先出「衔接的形式分布」（高低连板衔接 / 区间涨幅衔接 / 同题材接力 / 跨题材切换……各占多少），规则等分布看过再立。复盘会的「龙头梯队」页（连板梯队按题材分组、晋级 / 断板、梯队高度 20 / 60 / 90 / 120 日）是这条链在平台上的对应物（§8）。

**补注（09-07 第八段，用户问「outcome 定义是什么定义」）**：上面骨架里的 `outcome` 就是「这一节算不算成功」的那一行。每一次高标断板是一节；规则说「低位一般会有衔接」；要量「一般」有多大，就得先说清什么叫「衔接成立」，这行就是那个说法。现在写的是「下一任市场最高标里有一只出自断板日前后三天的 ≤2 板股票」，它在数据上几乎等于「继任者恰好以 3 板诞生」（因为断板时几乎总有 4–7 板的在位者会立刻接任最高标，低位股最快第三天才到 3 板），所以 `refuted` 量到的是「市场有没有断层」，不是「低位有没有衔接」。候选改法与要问的问题见 §1.5。

第二条随之而来、用户没说但接力链天然能量的：**诞生环境**——`context_birth` 里指数阶段 / 主流板块阶段 / 风格标量在诞生日的分布，与全样本日分布对照（纵扫 `cohort_compare` 的现成形状）。这条不作为规则登记，只出对照表，等用户看完再说它意味着什么。
