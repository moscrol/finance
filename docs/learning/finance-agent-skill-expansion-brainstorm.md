# 金融 Agent 技能扩展与市场痛点脑暴

这份文档不是实现计划，而是架构师视角的能力地图：从金融市场真实痛点出发，判断金融 Agent 后续还可以扩展哪些稳定技能，以及哪些能力应该坚持人工复核，不进入自动写库或自动交易。

当前优先级已经收敛为两条主线：

1. **顶级投研助理**：回答要像成熟研究员，有结论、有证据、有反证、有生命周期、有市场结构。
2. **可解释 RAG 系统样板**：每次回答都能解释查了什么、为什么查、命中了什么、证据有多硬、缺什么、质量如何。

暂不把“自动化 apply / 自动入库 / 自动交易”作为主目标。金融数据有误写风险，Agent 应先承担发现、组织、解释、质检和候选生成，关键事实沉淀仍保留人工检查。

## 一、金融市场的核心痛点

### 1. 信息太多，但真正增量太少

每天有公告、研报、晨汇、机构观点、龙虎榜、互动易、社媒截图、盘面异动。多数内容只是重复旧叙事，少数才是会改变预期的增量。

Agent 应解决的问题不是“多读材料”，而是回答：

- 这条信息相对昨天新增了什么？
- 它改变的是需求、供给、价格、产能、客户验证、利润率，还是只是情绪？
- 是一阶受益，还是二阶导机会？
- 是新 alpha，还是市场已经定价的旧共识？

### 2. 事实、推演、交易信号经常混在一起

金融分析最常见的错误是把不同层级证据混用：

- 公告/订单/量产是硬事实。
- 研报测算/产业链访谈是候选证据。
- 盘面涨停/新高/放量是市场信号。
- 模型总结和用户经验是推理辅助。

如果不分层，回答会看起来很完整，但实际在用弱证据支撑强结论。

### 3. 个股分析容易被题材标签绑架

很多回答会从“它属于某题材”直接跳到“它受益”。真正成熟的个股深挖需要先回答：

- 公司到底靠什么赚钱？
- 收入结构和毛利弹性在哪里？
- 当前题材和公司主营之间是强关系、弱关系，还是市场强行贴标签？
- 同题材里市场为什么选它，或者为什么不选它？

### 4. 题材生命周期难判断

题材不是静态概念，而是有生命周期：

- 新出现
- 旧逻辑唤醒
- 升温验证
- 加速定价
- 高位分歧
- 二阶段回流
- 衰退观察
- 证伪退出

痛点在于，很多 Agent 只会讲产业逻辑，不会判断“市场现在交易到哪一段”。

### 5. 市场结构会改变同一条逻辑的交易价值

同一个公司逻辑，在不同市场阶段价值完全不同：

- 放量主升时，市场奖励主线核心和高弹性。
- 缩量轮动时，市场奖励低位切换和预期差。
- 高位分歧时，硬证据不足的远期故事容易兑现。
- 冰点修复时，弱逻辑也可能短期反弹。

所以顶级投研助理必须把公司逻辑和市场结构合并，而不是孤立做基本面摘要。

### 6. RAG 命中不等于回答可信

RAG 是检索增强生成，意思是先检索证据，再让模型基于证据回答。它的核心风险是：检索到了很多文本，但没有判断证据质量。

Hybrid 检索是向量检索和 BM25 关键词检索的组合：

- **BM25** 适合精确词命中，比如公司名、产品名、公告关键词。
- **向量检索** 适合语义相似，比如“液冷服务器”和“数据中心热管理”。
- **rerank** 是二次重排，先粗召回一批，再用更精细模型重排。

但金融 Agent 不能只说“我查到了”。它还要说明命中的是实体页、概念页、研报原文、官方证据，还是历史经验卡。

## 二、建议扩展的 Agent 技能

下面的“技能”指稳定工作流能力，不一定是 Codex/Claude 的 Skill 文件。它们可以先作为 CLI/workflow/prompt contract 存在，成熟后再沉淀成正式 skill。

## P0：优先扩展技能

### 1. 证据分层审计技能

**要解决的痛点**：事实、研报推演、盘面信号混用。

输入：一次回答的证据链，或某个公司/题材的 RAG 命中结果。

输出：

- L1：研报/产业翻译
- L2：公司 baseline
- L3：公告、订单、互动易、认证、量产、产能等硬事实
- L4：市场信号
- 用户经验/模型推理：不作为事实，只作为回答风格或分析规则

价值：

- 防止弱证据支撑强结论。
- 让回答的“可信度”可解释。
- 可迁移到医疗、法律、企业知识库等高风险 RAG 场景。

替代方案：

- 只靠 prompt 要求模型分层：实现快，但稳定性差。
- 在 ingest 时一次性打标签：源头更干净，但历史数据补标成本高。
- **推荐混合方案**：ingest 时尽量保留 evidence_layer，回答时再做运行时审计和缺口提示。

### 2. 个股研究路径编排技能

**要解决的痛点**：个股深挖模板化、被题材标签绑架。

建议固定为一个研究路径：

1. 公司本体：主营、收入结构、毛利、产业链位置。
2. 题材暴露：当前市场给它贴了什么标签，标签和主营关系强弱如何。
3. 证据硬度：公告/互动易/年报/订单/客户验证是否存在。
4. 市场价值：CAR、相对强度、新高、成交承接、回撤半衰期。
5. 同链对比：同题材更强核心、替代标的、上游瓶颈、二阶导。
6. 生命周期：新出现、旧逻辑唤醒、升温验证、加速定价、高位分歧等。
7. 反证：价格抢跑、证据不足、低占比、客户不明、市场抛弃。
8. 条件化结论：升级、降级、证伪条件。

价值：

- 让“深挖某股”稳定达到高分样板。
- 同一套路径可复用到“还有上涨空间吗”“怎么看某股”“为什么今天涨”等问题。

替代方案：

- 按固定模板输出：覆盖完整，但容易机械。
- 让 LLM 自由发挥：自然，但容易漏项。
- **推荐混合方案**：编排层强制检查视角，输出层自然成文。

### 3. RAG 命中质量解释技能

**要解决的痛点**：RAG 命中了，但不知道命中质量如何。

在每次回答里输出一段可观测摘要：

- 检索模式：BM25 / dense / hybrid / rerank
- 索引类型：结构版 / 全文版
- 命中来源：entity / concept / source / synthesis / raw
- 命中数量、最高分、均分、是否邻居扩展
- 命中是否覆盖 L3 硬证据
- 是否发生索引降级或超时

价值：

- 用户知道答案是不是“查得扎实”。
- 后续可以做检索评估，如 recall@k、命中来源分布、失败样本复盘。
- 面试可讲成“RAG observability”：检索可观测性是高质量 RAG 的基础。

替代方案：

- 接 OpenTelemetry：标准化强，但对当前本地 CLI 过重。
- 用 structlog 全链路日志：适合服务化后，但现在会增加维护成本。
- **推荐当前方案**：轻量结构体 + 回答内摘要 + 测试覆盖，后续服务化再升级。

### 4. 反证与证伪点生成技能

**要解决的痛点**：回答只讲上涨逻辑，不讲哪里可能错。

每次深挖/题材/复盘前瞻后，自动生成：

- 最强反证是什么？
- 哪个事实出现会让结论降级？
- 哪个盘面信号出现说明市场不认可？
- 哪个 L3 证据缺失会限制逻辑高度？
- T+1 / T+3 / T+5 分别验证什么？

价值：

- 把回答从“观点”升级为“可验证假设”。
- 适合和 `checkpoint`、`forecast-review-ledger` 对接，但不需要自动交易。

替代方案：

- 人工复盘时再写反证：质量高，但容易漏。
- 回答时强制生成：覆盖稳定，但可能模板化。
- **推荐**：回答时先生成候选反证，人工在台账里挑选有效项。

## P1：中期扩展技能

### 5. 题材生命周期诊断技能

**要解决的痛点**：只讲产业逻辑，不判断交易阶段。

输入：

- D4 主线结构
- theme-candidates
- 涨停、新高、双红、边际量
- RAG 产业链证据
- 历史发酵复盘

输出：

- 当前生命周期阶段
- 和昨天/过去 N 天相比发生了什么变化
- 是主线、支线、补涨、轮动、兑现，还是反弹
- 市场奖励谁、抛弃谁、犹豫谁

价值：

- 提升题材分析和次日前瞻质量。
- 与个股深挖共享市场结构判断。

### 6. 卖方观点发散技能

**要解决的痛点**：晚间卖方材料多，但不能直接按推荐强度排序。

核心框架：

- 机构胜率
- 覆盖密度
- 证据硬度
- 盘面位置
- 二阶导空间
- 兑现风险

输出分三类：

- 优先发散：低覆盖、高证据硬度、盘面刚启动。
- 只作确认：高覆盖、盘面已主升。
- 反向谨慎：高覆盖、高拥挤、证据弱或兑现临近。

价值：

- 让 Agent 不只是总结卖方，而是判断卖方信息是否还有 alpha。

### 7. 公司证据缺口雷达

**要解决的痛点**：知道某公司重要，但不知道缺什么证据。

输出：

- 缺 baseline
- 缺收入结构
- 缺客户证据
- 缺公告/互动易
- 缺同链对比
- 缺市场价值验证

人工边界：

- 只生成缺口和候选任务。
- 不自动写实体正文。

价值：

- 支持人工研究优先级排序。
- 可与知识库 ingest 队列对接，但保持人工 review。

### 8. 市场结构状态机技能

**要解决的痛点**：大盘、情绪、风格、题材、个股经常被混为一谈。

建议把市场状态拆成多层：

- 指数：量价、位置、均线偏离。
- 情绪：涨家数、MA5、涨跌停。
- 风格：趋势大成交、连板情绪、低位切换、高位抱团。
- 行业容量：申万一级成交占比、聚散度。
- 题材：双红、新高、涨停、边际量。
- 个股：相对强度、成交承接、回撤、半衰期。

输出不是机械字段表，而是阶段判断：

- 主升扩散
- 顺势分歧
- 缩量轮动
- 高低切
- 高位兑现
- 冰点修复

## P2：后续增强技能

### 9. 事件冲击传导技能

用于新闻、政策、海外事件、公司公告：

事实抽取 -> 产业链传导 -> 财务科目 -> 公司弹性 -> 市场误分类 -> 验证路径。

这个技能适合接 `serenity-alpha`，但输出仍应是研究假设，不是交易指令。

### 10. 估值与预期差技能

目前系统更强在题材、证据、盘面，后续可补估值维度：

- 当前市值隐含什么预期？
- 逻辑兑现需要多少收入/利润？
- 市场是否已经提前定价？
- 同链公司市值/弹性如何比较？

注意：估值数据质量要求更高，初期只做框架和缺口提示，不强行给精确目标价。

### 11. 组合与风险暴露技能

如果未来有自选股/持仓场景，可扩展：

- 持仓题材集中度
- 同因子暴露
- 高位拥挤风险
- 事件风险
- 流动性风险

人工边界更重要：输出风险解释，不输出自动调仓。

### 12. 信息源可信度评分技能

对来源本身打分：

- 官方公告
- 年报/定期报告
- 互动易
- 卖方深度
- 晨汇转述
- PDF OCR
- 截图/社媒

价值：

- 解决“同一句话来自哪里”比“说了什么”更重要的问题。
- 能反向提升 RAG rerank 的排序逻辑。

## 三、建议的能力架构

建议把金融 Agent 拆成四层：

### 1. Intent Layer：问题理解层

判断用户问的是：

- 个股深挖
- 上涨空间
- 题材分析
- 市场前瞻
- 新闻冲击
- 回答质检
- 方法论讨论

输出 `QuestionPlan`，但不要停留在提示词，应逐步变成检索和质检的执行契约。

### 2. Retrieval Layer：证据召回层

统一管理：

- S：盘面快照
- G/R：图谱和证据
- W：Wiki RAG
- D1-D4：DuckDB 数据块
- L3：官方证据运行时补查
- E：经验卡/纠偏，只能作为风格和方法论辅助

关键优化：每个源都要有可观测字段，包括命中数、来源、质量、降级、缺口。

### 3. Reasoning Layer：投研推理层

按问题类型选择推理框架：

- 个股：公司本体 + 证据硬度 + 市场结构 + 生命周期 + 二阶导
- 题材：产业链 + 主线结构 + 强势股队列 + 生命周期
- 前瞻：四源合议 + 市场状态机 + 可验证假设
- 新闻：事实抽取 + 传导链 + 受益/受损分层

### 4. Review Layer：输出质检层

回答前检查：

- 是否用了本地最新数据
- 是否区分事实/推演/盘面/经验
- 是否有反证
- 是否有缺口
- 是否有可验证假设
- 是否把弱证据写成硬事实

## 四、人工复核边界

建议明确三条红线：

1. **不自动把研报判断写入 entity 正文**
   研报可以进入 report_context、graph_only、exposure_only 或 review_candidate。

2. **不自动把 L3 候选 apply 到知识库正式事实**
   L3 运行时查到的公告/互动易可以生成候选 source note，但正式写库需要人工看过。

3. **不输出个性化交易指令**
   可以输出条件化判断、风险、验证字段、观察优先级，但不写“买/卖/仓位”指令。

## 五、优先级建议

### 第一阶段：把个股深挖做成标杆

目标：任何“深挖/怎么看/还有空间吗”都稳定走高分路径。

应优先建设：

- 证据分层审计
- 个股研究路径编排
- RAG 命中质量解释
- 反证与证伪点生成

原因：个股深挖最能体现投研助理能力，也是后续题材和复盘前瞻的基础。

### 第二阶段：把题材生命周期做成标杆

目标：题材分析不只讲产业，而是判断市场交易阶段。

应优先建设：

- 题材生命周期诊断
- 市场结构状态机
- 卖方观点发散

原因：这会直接提升主线判断、次日前瞻和每日复盘质量。

### 第三阶段：把 RAG 评估做成工程样板

目标：每次回答的检索质量可解释、可复盘、可调参。

应优先建设：

- RAG telemetry 面板/文本摘要
- 失败样本集
- query -> retrieved sources -> final answer 的审计记录
- 证据来源覆盖率统计

原因：这是把“能回答”升级为“可验证系统”的关键。

## 六、推荐下一份实现设计的主题

如果要交给其他 IDE 落地，我建议下一份正式 spec 写：

**“个股深挖研究编排器：从 QuestionPlan 到 EvidenceAudit 到自然回答”**

最小可落地范围：

- 输入：用户问题 + 当前 AskResult 证据链。
- 输出：一个结构化 `StockResearchBrief`。
- 内容：公司本体、题材暴露、证据硬度、市场结构、生命周期、二阶导、反证、缺口、验证点。
- 不做：自动入库、自动交易、自动改知识库。

这个方向兼顾 A 和 C：既能提升回答质量，又能把 RAG 和证据分层做成可解释样板。
