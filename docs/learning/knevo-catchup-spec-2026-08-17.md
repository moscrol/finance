## §2 财务数字深度（目标：从 0 分打到反超——它有数没引用，我们有数带引用）

### KC-01 D7 财报多源 fallback 链（原台账 #3b 落地）

- **差距事实**：D7 现为东财 F10 单源；Knevo 是 ftshare→mx-finance→web 三级降级（逆向 §2.7），单源限流/改版即瞎。它的 provider 状态语义（ok/degraded/missing_config/NO_DATA 分列，不混成 failed）值得整套抄（探针 §6）。
- **方案要点**：`fetch_quarterly_financials` 加 provider 链：东财 F10 → 本机 a-stock-data 技能包的财务三表源（mootdx/腾讯，已自包含）→ efinance/AKShare。任一成功即返回并在引用里标注实际 provider；全败输出结构化状态（区分 degraded/NO_DATA），不落"查询失败"一句话。
- **验收**：单测拔掉主源走通链路；live 断源演练一发（mock 主源 402）；引用行含 provider 名与取数日。
- **规模**：M。**依赖**：无（可先于 #153 做，但 live 验收在 #153 之后才有意义）。

### KC-02 利润含金量科目扩展

- **差距事实**：Knevo 厦钨题的高光是"意外发现"——每股经营现金流 -1.62 恶化 + 股东人数 +68%，给 21% 毛利率打折扣（台账记录 3）。我方 D7 只有营收/归母/毛利率/净利率。
- **方案要点**：D7 增列经营现金流、合同负债、存货、股东户数变化；新增一条**确定性含金量对照**：毛利率改善但经营现金流反向 → 块内自动输出"利润质量待核"行（带两个数字与方向，不下结论）。把它的"意外发现"从模型灵感变成我们的固定检查。
- **验收**：单测覆盖"改善+反向"触发与不触发；用厦钨 2026Q1 实数回放，能产出与 Knevo 同方向的含金量提示。
- **规模**：M。**依赖**：KC-01（同一块代码）。

### KC-03 龙虎榜/席位块 [D10]

- **差距事实**：Knevo 深信服题给出龙虎榜席位拆解（台账 6 题基准 Q2 判负因素之一）；我方无此块，但本机 a-stock-data 已有龙虎榜数据源，料是现成的。
- **方案要点**：意图路由命中「龙虎榜/席位/游资/机构专用」且解析到个股才触发；输出近 N 个上榜日的买卖前五席位类型分布（机构/游资/量化标签沿用数据源口径）+口径声明。只列事实不推"跟单"。
- **验收**：意图负样本不触发；实取一只近期上榜股与东财页面对数；块内含口径声明句。
- **规模**：S-M。**依赖**：无。

### KC-04 资金面三件套（融资融券/大宗/解禁）

- **差距事实**：Knevo 经 datasvc/ifind 有两融、股东结构（探针 §6 路由表）；我方 D9 只有 L2 资金流。a-stock-data 已有融资融券/大宗/股东户数/解禁源。
- **方案要点**：并入 D9 或新开 [D12]：意图词（两融/融资盘/大宗/解禁）触发；解禁给未来 90 天时间表（这是催化剂日历的确定性素材，接 KC-13 的"未验证变量+时点"）。
- **验收**：三类意图各一发实取对数；负样本不触发。
- **规模**：M。**依赖**：无。

## §3 检索纪律（目标：把它的 prompt 纪律翻译成我们的代码纪律）

### KC-05 反方向检索口径

- **差距事实**：Knevo 硬规则"为每个核心逻辑假设构造反事实条件"，反方线索有最高优先保护（逆向 §3.1.1/§3.2.1）；我方 R/W 检索词只有 anchor+theme+query 正面口径，counterpoint 槽经常只能从正面证据里硬挤。
- **方案要点**：检索规划层对锚定实体/主题追加反方 target：风险词库按类型分桶（产能过剩/价格战/技术替代/需求不及/竞格恶化/政策），实体+风险词组合发 R/W 通道；反方命中在 evidence 行标 `[反]`，装配时保底 1-2 槽（与 max_evidence 决策单对齐，不冲突）。
- **验收**：单测：反方 target 生成正确、保底槽生效、无反方命中时显式披露"未检索到反方证据"而非沉默；live 一发对比前后 counterpoint 槽的证据绑定数。
- **规模**：M。**依赖**：#153 修完（装配层可信后再动槽位分配）、max_evidence 决策单结论。

### KC-06 两跳迭代检索（宽口径词从窄命中抽取）

- **差距事实**：Knevo 硬规则"宽口径词必须从窄口径命中结果里抽，不拍脑袋"（逆向 §3.1.1）；我方一轮定检索，主题词典没覆盖的关联环节（上游材料/设备)就漏。
- **方案要点**：第一轮 R/W 命中后，从 evidence 文本与图谱邻居抽 2-5 个高频实体/概念词（确定性抽取：词表交集+频次，不走 LLM），作第二轮检索 target；第二轮结果单独标注来源跳数。预算护栏：第二轮 target 上限 3、总证据行上限不变（挤占由排序决定，不加行）。
- **验收**：单测钉抽取确定性与上限；冻结题 B1（光刻胶，R15 曾 0 证据）复跑对比第二跳带来的证据增量。
- **规模**：M-L。**依赖**：#153、KC-05（同层代码，顺序做）。

### KC-07 召回自评四问

- **差距事实**：Knevo 检索是"发射→自评→定向补搜"闭环，四问：正反都有命中？产业链关系命中？30 天内有命中？≥3 独立来源？（逆向 §3.1.1）我方装配完直接进合成，缺什么由模型自己发现（经常发现不了）。
- **方案要点**：装配完成后跑确定性四问检查，结果写进合成上下文的"证据缺口披露"段（如"反方证据 0 条""最近 30 天证据 0 条"）；第一版**只披露不补搜**（补搜是第二版，避免预算失控）。模型被要求在答案的证据边界段转述缺口。
- **验收**：单测四问各自的判定；live 收据里答案含对应披露句。
- **规模**：S。**依赖**：#153。

### KC-08 独立来源计数进 claim 绑定

- **差距事实**：Knevo 六维漏斗有"独立记忆 ≥2 才能支撑结论"阈值（逆向 §3.2.1）；我方 claim 绑定只看有没有证据，不看几个独立来源。
- **方案要点**：claim 绑定元数据加 `independent_source_count`（按 source 文档去重）；=1 的结论性 claim 在呈现层自动带"单源"标记（不阻断，先观测）。与降桶标注同一套后处理管线。
- **验收**：单测：同源多条计 1、异源计 N；live 收据含单源标记实例。
- **规模**：M。**依赖**：#146 的 claim 标记教学门打开（`SYNTHESIS_PROMPT_TEACHES_CLAIM_MARKERS` 现为 False，是 tier note 同款前置）。

## §4 预测-验证闭环（目标：确定性反超——它的胜率是黑盒，我们的每一格可复算）

> 注意区分：`docs/prediction-ledger.md` 是**工程分诊**的修复预测账（agent-run-triage 资产），不是这里说的投资判断台账。两者不混库。

### KC-09 前瞻判断台账（judgment ledger）

- **差距事实**：Knevo 有 recommend_decision→八字段建档（判断原文/前提假设/情景分支/verify_by/推翻条件/置信度/依据/上下文快照，逆向 §4.0）；我方答案里的前瞻判断（如"若 Q2 单季 ≥25% 则升级"）说完就丢，无人记账。
- **方案要点**：per-user jsonl 台账（`judgments-ledger.jsonl`）。八字段照抄，两处改造：①置信度只准 高/中/低 档（不准数值概率，与情景树契约一致）②依据字段存引用编号+evidence hash（可回查）。写入路径抄它的**提案权隔离**：答案含可验证前瞻判断时确定性抽取候选（识别"若 X 则 Y"+verify_by 模式）→ pending 队列 → 用户 accept 才入账。agent 无直写权。
- **验收**：抽取器单测（正样本/无判断负样本/无 verify_by 不建档）；pending→accept 状态机单测；live 一发产出候选。
- **规模**：L。**依赖**：[M] 台账指向的用户裁决（§0）；交互形态（CLI 确认 or 批处理）**待用户拍**。

### KC-10 到期裁决 job

- **差距事实**：Knevo 靠用户手点命中/未命中；我们有盘面 DuckDB，**可以自动裁决**——这是赶超点而非追平点。
- **方案要点**：每日 job 扫台账中 verify_by 到期项；判据可机读（指标+阈值+数据集在盘面库有列）的自动裁决为 hit/miss/partial 并附证据行；判据不可机读的进人工队列。裁决结果写 verdicts 段，**不回改判断原文**（学运行时契约 §6：prediction_ledger 只追加验证结果）。
- **验收**：夹具台账跑 job：可机读项裁决正确、不可机读项入队、原文未动；空到期日 job 幂等。
- **规模**：M。**依赖**：KC-09。

### KC-11 裁决回流 [M]

- **差距事实**：Knevo 的记忆条目带 hitCount 但语义混（召回次数≠胜率，E-006 校正过）；我方可以给出干净版本。
- **方案要点**：[M] 块召回某历史判断/框架时，若其所属类别在 verdicts 里有 ≥N 条已裁决记录，附一行"同类判断历史 x/y 命中（分母=已裁决数）"；分母不足 N 不显示。**红线：召回次数、confidence 一律不得当胜率展示**。
- **验收**：单测三态（够 N/不够 N/零裁决）；live 收据含该行实例。
- **规模**：S。**依赖**：KC-09/10 + [M] 数据修复。

## §5 表达层残余（目标：补齐两个产品级空白）

### KC-12 猜你想问（suggest_options 等价物）

- **差距事实**：Knevo 每轮生成 ≤4 条用户口吻追问，四角度成套（纵深=报告缺口镜像/横向/操作/验证），点击即发（逆向 §5）；我方答完即止，追问引导为零。
- **方案要点**：呈现层新段"可继续问"：候选**来源确定性**——纵深从四问缺口清单与证据边界段生成、横向从图谱邻居题材、操作从替代路径槽、验证从 verify_by 候选；措辞一次 LLM 调用压成 ≤20 字用户口吻（LLM 只做措辞不做选题，失败降级为模板句）。≤4 条；澄清轮不生成。
- **验收**：单测选题确定性与负样本；live 收据含四角度各 ≤1 条；LLM 失败路径出模板句。
- **规模**：M。**依赖**：KC-07（缺口清单是纵深角的料源）。

### KC-13 结论五元素 lint

- **差距事实**：Knevo 结论段五元素配方（定性 ≤40 字/风险=变量+方向+信号/下一步分层/未验证变量+时点/替代路径）+梯度输出（逆向 §3C.3）；我方结论段结构靠模型自觉。
- **方案要点**：呈现层确定性 lint：检查结论段五元素在场性（关键词+结构模式匹配），缺项写进核验报告 warning（**不阻断**，先攒一个月在场率数据再定要不要进修订轮触发条件）。
- **验收**：五元素各自的正负样本单测；冻结题批跑出在场率基线报表。
- **规模**：S。**依赖**：无。

## §6 广度（目标：海外源从"接上了"到"常态可用"；多市场最小覆盖）

### KC-14 海外源第二梯队 + 别名表运营

- **差距事实**：Q4 PQC 题 Knevo 捞到特朗普行政令/国密标准/Google Q-day 分层可信度输出，我方当时零命中大败；#160 接了 Bing News+中英别名表后 54→82 分，但别名表是手维护的死表，源只有一个。
- **方案要点**：①W7 第二 provider 梯队：白名单 RSS（Reuters/CNBC/半导体行业英文源）走同一意图路由与降级语义；②别名表运营化：从 wiki 实体页/概念页自动生成中英候选对（确定性抽取），人工确认后入表，每月增量。附 Knevo 式来源可信度分级标注（权威机构/公司公告/媒体/自披露，探针 §13.5 的表直接抄进块内口径声明）。
- **验收**：PQC 同题复跑命中率不低于 #160 后基线；新增源的条目带可信度级别；别名表生成器单测。
- **规模**：M。**依赖**：无。

### KC-15 隔夜美股→A 股映射块 [D11]

- **差距事实**：Knevo 原生多市场，能答"美股 XX 走强对 A 股哪些板块有映射"；我方 ask 管线无此通道——但本机 fph2026 旁路库**已有**美股主题热度与隔夜主题对照 A 股板块的数据和逻辑，只是没接进 ask。
- **方案要点**：意图路由命中「隔夜/美股/纳指/映射/对标」触发 [D11]：读 fph2026 的隔夜对照产物，输出美股主题涨跌 → 对应 A 股板块 → 当日 A 股实际表现三列对照（全部带日期与数据源声明）。只列映射事实，不推"必然跟涨"。
- **验收**：意图正负样本；live 一发与 fph2026 CLI 直查结果一致。
- **规模**：M。**依赖**：无。

### KC-16 港股最小覆盖（可选，低优先）

- **差距事实**：Knevo A/港/美全覆盖；我方 A 股专注。港股经腾讯源（hk 前缀）可拿实时快照，成本低。
- **方案要点**：仅限「港股/恒生/H 股」意图：指数+个股快照（价格/涨跌/成交），块内声明"非主场市场，仅行情快照无深度证据"。不做港股知识库。
- **验收**：快照对数；越界问题（港股深度分析）显式声明能力边界。
- **规模**：S-M。**待用户拍**：做不做（投入小但战线拉宽，与"纵深路线"有张力）。

## §7 实体识别与日历（小而立竿见影）
