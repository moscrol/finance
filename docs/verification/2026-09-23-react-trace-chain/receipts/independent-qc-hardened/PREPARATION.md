## 已实现的硬检查

1. 自由 bash 被专用工具替代。`inspect` 只直接启动 rg/ls，rg 的进程预处理参数被拒；`run_tests` 由宿主构造固定解释器、pytest参数和独占临时目录，以 argv 直接启动，不解释shell。收据保存 target_exit_code、信号、是否终止、完整输出哈希、输入字节哈希和JUnit逐用例计数。stdout里打印EXIT=0不能覆盖实际exit1。
2. `submit_report` 是带 JSON Schema（结构约束）的终止工具。模型提供正文、逐项主张、发现和限制；宿主绑定身份与阶段，标准JSON序列化落 REPORT.json/REPORT.md 及必需阶段文档。没有合法交付就不能进入下一阶段，宿主不会修剪原终稿补签。结构合法仍不代表语义审查通过。
3. 工具阶段权限在调用前及execute内双检查：explore不能跑测试，execute才可跑；report不能写文件或补跑测试。操作在本轴内串行；首次探针写入不可覆盖，修正另文件。只有完整尝试三套执行才可提交execute完成，缺项须BLOCKED；PASS类报告必须逐项C1-C6 verified、引用证据且无findings。
4. 仅补旧批已验证的两个父目录metadata权限；写入、内容读取、凭据、跨轴与生产网络边界没有扩大。新准入实际执行pytest收集、嵌套tmp、文件SQLite/WAL、故意红、伪造stdout退出值与越界控制。两轴均通过。准入夹具及其原日志封存后，从空白reviewer probe目录移出，不混入自造探针数量。
