## 发现（Quality 轴）

### 发现 1（fail-open，中）：证据台账正则不辨否定语境

`scripts/check_answer_claims.py::_ledger_has_fund_flow` 对 `outcome.evidence` 全文匹配 `净流入|净流出|主力净|资金净|…`。证据一条 `detail="本次未取得主力资金净流入数据，仅有成交额 114.90 亿元"` 时 `fund_flow_evidence=True`，于是答案里「显示资金当日集中流入封测方向」**不再命中**（P2 否定语境：`rules=[]`）。

- 触发输入：工具回包 / 检索片段里以否定或缺失语气提到资金流名词（「未提供净流入」「无主力净流入字段」）。K3 再验时写手工具面正会产出这类文本。
- 错误输出：资金流规则静默，CLI 退 0。
- 与作者声明的关系：作者在 #854 里已说明加台账正则是为接住新闻里的「主力资金净流入 38 亿」（回测 13 例）；否定语境是这条放宽的直接副作用，PR 描述未列。
- 建议（后续单，不在本单改）：台账匹配前剔除含否定词（未 / 无 / 没有 / 缺 / 不含）的同句片段，或要求命中带数字量词（`净流入\s*[\d.]+\s*亿`）；夹具用本句。
- **L5 缓解**（已写进条件卡）：`context_diagnostics.fund_flow_in_evidence_ledger=True` 时人工读命中的证据原文，否定语境按「无资金流证据」重判。

### 发现 2（误报，低）：「无法确认」类免责句触发日期规则

`_LATEST_DAY_NEGATION` 收录「不能视为 / 并非 / 不是最新 / 尚未收盘…」，不含「无法确认 / 无法核验 / 无从核验」。P1-c「因未核对交易日历，是否为最近一个已收盘交易日无法确认。」命中 `latest_trading_day_unverified`，而这句正是规则想要的写法。advisory 档会多一条噪音，不放行任何越界，故为低。建议后续把「无法(?:确认|核验)|无从核验」并入否定词表并加回归夹具。
