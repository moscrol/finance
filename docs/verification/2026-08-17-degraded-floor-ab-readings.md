## 2. prompt 侧 `【降级回答章法】` 全文

`episode_rule` 在开关 on 时的注入文本，与 `skills/finance-degraded-fallback/SKILL.md` 去 frontmatter 后逐字节相接（先 `HEADING` 再正文）。off 时是空串。

```
【降级回答章法】
# 降级回答章法

本文件只含降级时的回答章法。不得夹带市场事实、数字或板块名。运行时在核验或证据不完整时拼进生成提示；缺口兜底路径由运行时按本章法确定性补齐透明段。

## 定位

拒答只留给做不了的动作与不能给的保证。查不到、来不及核验、核验没通过，都走降级回答：仍然回答，但降低确定性、标注缺口，不输出裸的「不知道」，也不输出裸的点估计。

## 总原则

降级是换源加标注，不是删信息。可信度降低时，透明度必须提高。

## 必备七项

降级回答缺一项即不合格：

- 尝试过什么：本轮做过哪些检索与核验、各自结果如何。用自然语言过程说明，不暴露内部工具名。
- 缺口是什么：哪个必需输出没完成、成因是什么、对判断有什么影响。
- 已核验与未核验分开：已核验部分标明「供参考，不构成完整结论」；未核验材料只报数量与来源，不引用其内容。
- 来源标注不降级：来源与数据截至日期照常写全。
- 最大可判层级：只能在「排除、倾向、确认」里如实取一档。证据不足就明说「信息不足」，不许强行二选一，不许补写缺失数据。
- 待补证清单与验证窗口：缺什么材料、什么时候可以复验。
- 推翻条件：什么信号出现时，当前倾向不再成立。

## 判断句纪律

降级后仍给出的判断，必须带显式分析标记，且与审查器词表逐字一致：据此判断、这说明、这意味着。把不确定性写成假设、可验证时点与推翻条件的组合。

## 红线

不补写缺失数据。未核验证据的具体内容一个字不得引用。不得为了凑完整而编造来源、支持性统计或触发阈值。
```

### 7.1 建议采纳，但理由要换个说法

「不翻默认」**成立**，但不是因为「翻了没收益」——§5 自己写明 `evidence_gap` /
`model_unavailable` 两臂 on 会多两段透明，**那是正收益**。

真正的理由是：**这个开关太粗，它把一份已测的收益和一份未测的改动绑在一起。**
`degraded_fallback.py` docstring 明写「两侧共用一个开关」——
翻它同时打开 ①输出侧确定性透明段（**已测，正收益**）
与 ②prompt 侧整段章法注入（**未测，改的是所有「还能写」的降级指令**）。
拿不到前者而不吃后者。

**所以正确的后续不是「永远别翻」，而是二选一：**

- 把开关拆成两个（输出侧 / prompt 侧各一），先翻已测那半；或
- 补 prompt 侧的 live 样本，再整体翻。

两条都要用户另拍，本轨不做。

### 7.2 ⚠ §6 第 4 条的形状是错的，按本节改

原文：「若要让瞬时复核答卷也带『尝试过什么 / 来源标注』，那是**再挂一层出口**」。

**不要再挂出口。** T-B（#134）刚把公开答案收敛成**一条** `view()`，
并加了棘轮门禁 `test_view_callers_are_registered`——
**新增一个未登记的 `view()` 出口会直接把测试打红**（已变异证伪）。

正确形状是**把透明段作为冻结事实喂进现有出口**：给 `TerminalFacts`
加一个字段（如 `transparency`），由 `view()` 在 `transient_verifier_outage`
分支决定拼不拼。出口仍是一条，输入变丰富——这才是 dsh
`ctx.sessionProjections` 的 `view(facts)` 契约。
