# 8792 同题组件对照：板块机会与历史相似阶段

日期：2026-09-17。类型：单题旁路诊断，**不是模型胜负评测，也不是修复验收**。

原题：

> 这里的行情哪个板块更有机会，历史上有相似的阶段吗

## 结论先行

8792 能查到市场、题材热度、历史类比和产业风险，并非没有研究组件。此次质量差距主要落在：**取数失败后的恢复、比较口径、证据解释、事实与方法论分离、以及发布校验的误删/漏检**。

我先独立调用同版组件并固定[组件答案](component-answer.md)，再读[8792 公开答案](workbench-answer.md)。双方排序不同本身不能判输赢：组件答案偏持续相对强度，8792 偏涨停热度，用户没有明确持有周期或“机会”的目标函数。但以下硬问题已复核：

1. **重复计数**：储能、锂电池、固态电池的 9+10+7 条涨停成员记录重叠，去重为 15 只；占全市场 32 只的 **46.875%**，不是回答中的约 81%。
2. **历史排序读反**：E1 表最小距离为 **2025-09-02—09-29，0.313**；回答却称 **2025-11-26—12-23，0.370** 最接近。
3. **量价标签矛盾**：PCB概念当日涨幅 +0.575%、边际量 +11.9183%，回答仍称“缩量强修复”，未说明“缩量”指整体市场而不是该板块。
4. **方法论冒充观测**：E26 只是“方向锚与高度锚同时恶化”的判读规则，不能证明回答中的“目前未出现”。
5. **确定性误删**：一句没有数值阈值的风险提醒，仅因引用编号 **E27 中的 27** 被数字门当数量而删除；同证据、同句子去掉引用后不再被该门拒绝。离线复现成立。

因此，不建议把优化目标写成“让 8792 也选 PCB”。应让它无论选什么，都完成可复核的比较，不能拿工具报错当研究完成，也不能把风险提醒删了却保留算错的占比。

## 2. 组件答案及双方结论为什么分叉

### 独立稿的核心判断

基于截至 09-15 的证据，研究优先级为：**PCB 的持续强线 → 风电设备的轮动延续 → 半导体设备/封测的修复确认**。强调“已表现出的持续强度”不等于“现在买入后的收益最大”，PCB 当日上涨成员仅 48.98%，须防指数强、内部弱。

9/3—9/15 同窗累计收益：PCB **+19.25%**，元器件 +15.47%，风电设备 +3.16%，半导体设备 -1.99%，封测 +2.82%；上证 -1.96%。`sector_period_rank_daily` 还显示 PCB 在 3/5/10 日档均列第一，分别 +7.03%/+11.93%/+17.60%（榜单档口径，不混同 9 日复算）。

历史组件按固定 9 个交易日窗口扫描，PCB 最近可比的特征窗口为 **2026-07-30—08-11**：PCB +20.22%、超额 +17.46 个百分点；但当时大盘 +2.76%，本轮大盘下跌，**仅强趋势局部类似，不是整个市场同阶段**。该例后五日 +4.17%，再五日 -8.71%，同时提示延续与失败路径。

扫描请求横跨 2025-01-02—2026-08-31，枚举 79 窗口；71 个 `no_comparable_features`，仅 8 个可比、投影 5 个。窗口重叠、历史板块覆盖稀疏，`research_only=true`、`decision_eligible=false`、`pit_grade=hindsight_reconstruction`。这些数不是跨年规律或概率。

### 8792 的有效补充

它优先提出储能—锂电链，依据是涨停热度的上升，而非板块指数持续走强。这提供了独立稿漏看的短线热度轴；它也拿到了 D10 **全市场情绪结构类比**，而独立稿主要完成了板块趋势局部类比。不能因我的答案不同就把这些证据判为无用。

读后用同组件补核：储能同窗 **-2.93%**、日均上涨成员占比 **37.55%**；锂电池概念 **-3.06% / 37.71%**。因此它们适合先描述为“涨停集中、板块整体偏弱的分化结构”，而不是未经解释地说机会第一。此补核是**看完答案后的挑战证据**，没有偷偷改写独立稿。

另外，**PCB `990026.FP` 与 PCB概念 `990027.FP` 不是一个篮子**，后者同窗 +4.35%。本题若混名不固定代码，两方会貌似谈同一板块，实则比较不同成分范围。

### 组件侧顺序

市场近窗 → 当日领涨与容量 → 候选多日收益/相对强度 → 区间榜核验 → 扩入 PCB/元器件 → 广度与逐日复核 → 固定特征历史扫描 → 反向核对历史环境与后续失败路径 → 风险检索 → 固定独立稿。

## 4. 已确认缺陷与证据定位

### F1：重叠集合相加，81% 错成市场集中度（高）

- 公共答案：“三者合计占全市场涨停约81%（E3、E4、E58）”。
- 9、10、7 个成员是三个可重叠集合；`theme_limit_stock_daily` 明细去重为 15 只，15/32=46.875%。
- 如诺德股份、华正新材等跨多个题材；固态电池这 7 只在另外两组并集内。
- 成员表 `limit_status` 字段为未知，本轮以题材涨停明细表的成员口径复核，与各组热度数一致；没有外部逐股重新验证封板状态。
- **46.9% 也只是标签覆盖率**，不能升级成“这些股票都由储能/锂电驱动”。
- 原件：`components/postcheck-{storage,lithium,solid}-limit-members.json`；复核：`replay-receipt.json.membership_overlap`。

### F2：历史距离排序读反，并把小样本写成“常见”（高）

E1 的距离越小越接近，顺序是：09-02—09-29（0.313）、11-26—12-23（0.370）、10-29—11-25（0.395）。公开答案反转前两名，突出第二例后10日 +4.16%，并说类似环境后“常见题材扩散”。原件明确禁止将三个相似样本外推为概率规律。

这不是历史工具没返回，**是已有证据解释错误**。不应仅在结尾补“不是概率预测”来抵消正文越界。类比排序应与后续结果隔离：先固定相似标准，再展示各样本的后续事实。

### F3：量价语义不一致（中）

E63=PCB概念 +0.575%、边际量 +11.9183%。回答称“缩量强修复”；同次 `mainline_context` 的说明把“正涨幅、负边际量”才称缩量强修复。本例正负号不符。可以说“在全市场缩量中局部放量”，不能省掉主语后混为一谈。

### F4：规则证据化，缺观测却说“目前未出现”（高）

`mainline_context` 把 FY-A01/SPT-A09 等通用判读句包装成 `L4_structured`、来源“本地 DuckDB · D4 同日主线结构”、日期 09-15 的证据卡。E26 描述的是规则，没有指出方向股/连板高标是谁、当天分别如何，不能支持“目前未出现”。E30 的拥挤度提醒也不是当日全市场一致性的观测。

代码定位（均为发布版）：`intelligence/services/episode_tools.py:1337` 的 `mainline_runner`，经 `block_lines_to_evidence` 转换。建议沿现有证据契约分清“方法论/事实/分析判断”，不是另造一份行业规则清单。

### F5：排序题未进入现有排序契约（结构性缺口）

TaskFrame 识别到 `comparison_analog / historical_comparison`，required outputs 仍只有 `direct_assessment/counterpoint/evidence_boundary`。`ranking_contract.ranking_intent=false`、矩阵/改判条件均为 0。

现有 `ranking_contract.py:83` 主要为多公司比较服务，群指代覆盖“公司/标的/个股”，本题“哪个板块更有机会”不命中。**不是项目没有排序契约**，而是该自然问法及板块对象不受其约束。修复要扩展对象类型与适用契约，不能只加一个正则触发后强迫板块填“收入/利润传导”的公司表头。

### F6：参数错误后未恢复，比较被单一热度轴替代（高）

事件24/26：区间榜查询出错，服务已给 `change_pct→...metric` 的精确提示。正确调用同版工具能够取得 PCB 的多档领先（独立稿的 `period-ranks.json`）。当前数据不是没有，产品没有完成修正查询。

结束时未耗尽工具额度，不能把缺数归为工具预算不足。仍需进一步配对实验区分模型选择、菜单提示、错误信封和合同要求分别影响多少；本轮不凭单样本给唯一根因。

### F7：语义校验误删引用编号，同时漏检核心错误（高）

公开稿丢失的原句：

> 储能链收跌但涨停家数高，是「涨停集中但板块指数走弱」的分歧组合，若后续出现利多不涨+连板高标走坏，按抱团踩踏前兆判读应降级（E27）；

`sentence_verdicts` 将其以 `novel_numeric_condition` 删除。发布版 `_ARABIC_QUANTITY_RE` 提取唯一数字 `27`；`_novel_numeric_condition_indexes` 没有先去证据引用。原证据适配后直接重放：

- 含 E27：拒绝句20。
- 仅去掉 E27、正文/证据/合同不变：不拒绝。

这只证明**数字门误报**，不表示该句通过了所有语义验证。定位：`episode_semantic_verifier.py:258,4165`。其他两句确含“连续两日/100%”等未授权阈值，不应为救它们全局关闭数值门；应区分新假设槽、事实槽和引用标记。

语义 judge 还对“近5日”提出问题，却没改公开句。工具实际给过 09-09 的第5天证据 E36，答案的序列只有4个点，引用也不齐：这更像**证据对齐和表述问题**，不能简化成数据库缺那一天。为了此问题触发通用知识库补搜，无法替代结构化日期核验。

F1—F4 均仍留在公开答案中。`judge_status=repaired` 不等于全文正确；传输 completed 更不等于研究完成，report 已诚实标 partial。

## 5. 优化次序及被否方案

| 顺序 | 建议切片 | 验收应证明什么 |
|---|---|---|
| P0a | 引用标记与数量词分离；保留真正未知数值条件的门 | E27 不再被当阈值；真实新阈值负样本仍拦；不得用删引用解决 |
| P0b | 查询错误闭环 + 类型明确的取数状态 | 错把 metric 塞 dimension 后能有界修正；修不动时比较结论降级，不以热度偷代相对强度 |
| P0c | 集合聚合与历史排序忠实度 | 重叠题材必须取成员并集或拒给总占比；相似排序不得随更漂亮的后续收益重排 |
| P1a | 方法论卡与观测卡分离 | 仅有规则时不得断言“今天已/未发生”；要具体对象、日期、观测 |
| P1b | 板块比较合同与假设槽 | 同窗矩阵、候选选择、强度/热度/位置差异、何时改判；明确未来条件只是待检验假设 |
| P2 | 历史可比覆盖改进 | 预检真实日期和代码覆盖，显式显示71/79不可比；不按同名拼旧代码、不补造历史 |

首个 manual 序列化崩溃另列运行可靠性问题，需拿失败 action 或栈做有界复现；目前不能说换 hybrid 已修复。

被否方案：

- **直接换模型/SDK**：本次非同模型、同预算，不能从一个样本归因执行壳优劣。
- **给 prompt 塞“优先推荐PCB”**：把结论硬编码，无法迁移到下一行情。
- **简单堆更多工具或扩大时限**：本例没耗尽额度，缺的是补查和推理约束；更多证据不自动修复重叠计数。
- **关闭语义门以保留跟踪条件**：会同时放过真正拍脑袋阈值；先局部修引用解析，区分假设授权。
- **把本轮组件稿当金标准**：它也缺热度轴、全面候选、宏观机制、实时催化，不能拿来强制观点一致。
- **本轮直接修改生产**：原工作树多人混改且任务先做旁路对照；保持部署不动，把证据交给下一修复切片。
