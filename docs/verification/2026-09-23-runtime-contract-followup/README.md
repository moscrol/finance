## 量具修复与首红

- 两个旧变异锚点已失效：中立 ModelTurn 新增 missing_finish_reason，SSE 终态补读改为 pending 分支。只修定义，不修产品迁就测试。
- 写者关闭测试原来等待一个锁观察钩子；撤掉锁后只是观察钩子没来，不能算安全语义证人。改为直接确认 close 没有提前返回，再确认竞争者仍 Busy。
- 初版宿主校验器误以为 JUnit 必含 type 属性；本环境只给 message/text，因而误拒真正的断言失败。首轮拒收记录保留。
- runtime 完整运行的原校验又拒收 `KeyError: '_finish_reason'`。该字段正是 nonstream 变异移除的必需字段：补了“变异id + 精确测试参数 + 精确KeyError”白名单及负面自测，不接受其他 KeyError。
- `runtime/accepted-audit.json` 是对保存原始输出的重新裁决，**不是再次执行测试**；原拒收仍在 `original-audit-rejected.json`，两份分开。
- 一次 inbox 命令传了短SHA，被前置身份校验拒绝，未创建输出/运行测试；改用完整SHA后才有表中收据。

所有28个锚点会在执行前检查唯一匹配与可编译性；默认测试也覆盖此检查。导入/收集错误、无关异常、变异存活、分母变化、旧输出覆盖均拒绝。

## 复跑与限制

复跑入口及参数见 `scripts/review_probes/runtime_identity_effects/README.md`。新命令 `scripts/review_probes/run_runtime_contract_checks.py --group runtime|writer|reentry|inbox` 使用干净、固定提交和新输出目录；macOS沙箱禁网、禁输出根之外写入，用户根逐阶段隔离。权限故障用例要求非root。

覆盖了本机真实子进程争锁/退出释放、实例重入、异常退出释放、关闭等待在途消息、磁盘身份/旧前缀拒绝、保存失败阻止新派发、截断与终态补发。多数为既有作者测试的宿主重放；只有新增收件箱小片由本场K3编写。

未验完整跨进程续跑driver、跨机锁、真实费用对账、生产应用金融问答及全部入口异常收口。不以注入 unlink 失败冒充真的进程崩溃恢复，更不声称 exactly-once；重复 spool_id 的重复送达是现有 at-least-once 行为。

`MANIFEST.json` 是选定原件的字节清单，不代表完整模型会话/实验目录已全部归档。完整原件根为 `~/.finance-runtime/reviews/runtime-contract-followup-20260923/` 和相邻 K3 写手场。原始日志尾部空白原样保留，不格式化证据。旧独审缺失27文件等历史限制不因本轮消失。
