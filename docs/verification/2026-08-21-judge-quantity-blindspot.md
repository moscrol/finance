## 三筛判定

| 筛 | 判 |
|---|---|
| 拦输入还是输出 | **拦输出**（对已产出的句子判无据并摘格） |
| 失效时变错还是变笨 | 变笨（真话与必填输出丢失，答案不假但残缺） |
| 模型变强一倍 | **会挡路**——答题模型越强、数字写得越精确，被误判越多 |

**封上限，且判据是「可判定的机械问题交给了概率正确的 LLM」。**
「这个数在不在证据里」是逐字节可判的；让 LLM 做大海捞针，等于把必然正确换成概率正确。

## 本刀改法

把机械那半从判官手里拿走，**直接投递结论**（`verified_quantities`），
判官只留语义判断（因果是否成立、口径有没有混用、日期对不对）。

不放宽任何东西：只有与已投递观察值**逐字节相等**的数才进清单，编造进不来。
系统提示同步写明用法（否则是「投递了没人读」）。

## 另一半：上游数据脏（本刀不修）

`922.49 / 1077.71 / 464.76` 确定性核对也判无据，原因不同——E1 里 **13 个交易日是同日两行**：

```
交易日=2026-07-08；涨跌幅=-2.94；成交额亿=922.49；边际量=8.64
交易日=2026-07-08；涨跌幅=-2.94；成交额亿=914.5 ；边际量=8.93
```

`钙钛矿电池` 挂 2 个 `sector_ts_code`。模型看到矛盾，**诚实地写成区间**「约914-922亿」，
逐字匹配自然对不上。全库 **3192 组 (板块名,日期) 会返回多行、涉及 128 个板块名**，
是系统性脏源，不是本题偶发。

**下一刀**：预取遇同日多行必须显性化（按 `sector_ts_code` 拆开标口径，或 fail closed 报缺口），
**不能把矛盾当事实投递**。修完模型就不必写区间，确定性核对也能覆盖这一半。

## 追加：契约层归属（2026-08-21，用户提出，已用生产数据验证）

**问题**：判官该不该审「输出是否符合契约」？契约层是不是该交给代码？

**答：不该，是。生产数据坐实。**

同一个 run `run_20260821_114642_385979`：

| 检查器 | 判定 |
|---|---|
| `structural_verifier`（**代码**） | `missing_outputs: []`，4/4 必填输出**全部达标**；`factual_grounding: fulfilled`、`task_coverage: fulfilled` |
| `semantic_verifier`（**LLM 判官**） | 重写公开稿，`direct_assessment` / `counterpoint` 掉实质 |

链条：

```
代码判 4/4 达标
  → 判官重写，掉 2 格
  → 兜底门槛 _repair_wiped_all_required 只认「全灭」，2/4 不触发
  → repair_cycles = 0，一次没跑
  → 残稿发布
```

**两个权威管同一件事，概率正确的那个覆盖了确定性的。**
注意 `rejected_claim_indexes: []`——判官一句没删，是**整篇重写**时把两格写没了。

### 修法尝试与回退（留作记录）

试过把兜底门槛从「全灭」放宽到「掉任一 evidence 必填格」。**打红三条存量测试，已回退**：

- `test_local_gate_still_redacts_when_condition_slot_is_evidence_bound`
- `test_semantic_repair_cannot_remove_a_visible_required_output_marker`
- `test_valuation_repair_cannot_leave_an_empty_scenario_table_completed`

原因：现有 withhold 路径的语义是「**保留重写前的原稿**」（见其 docstring）。放宽门槛后，
判官本该抹掉的无依据阈值（`3870点`）跟着原稿一起活了回来——**对的诊断配了错的兜底动作**。
三条测试守的是真不变量，不是过时断言。

### 正确形状（下一刀，未做）

按「降级/空输出 + repair」而不是「回滚原稿」：

1. 判官重写让代码侧已达标的必填格掉实质时，**该格**降级为显式空/缺口标记，
   而不是整篇回滚——回滚会让被正确抹掉的编造复活
2. 触发 repair 重做该格（当前 `repair_cycles=0`，说明这条链本身也没接上）
3. 契约完整性的最终裁定权归 `structural_verifier`，判官不得让它判定达标的格消失

第 3 条是本节的核心结论：**契约层交给代码，判官只做语义判断与兜底。**

## 追加：把「不可达」从观测升到行为——试了，退了（2026-08-21）

**想法**：cut 6 已经能判出「这一轮修复结构性补不上」，那就别开这一轮，省下那 40 秒。

**结果：判据错了，已回退。**

`intelligence/tests/test_repair_carry_just_written_finish.py` 的夹具正是我判据的形状——
`missing_answer_elements=("direct_assessment",)`、`unsupported_claims=()`、`remaining_calls=0`、
`reopen_tools=False`。而那个测试的全部意义是：**修复轮不用任何工具，也能把模型刚写出的
FINAL_JSON 捞回来**。

所以：

> **「取不到新证据」≠「什么都做不了」。**

修复轮至少还有一条不需要工具的路（salvage just-written finish），我的判据看不见它，
一刀切跳过会把这条路也砍掉。保留 cut 6 的**纯观测**（`unreachable_without_tools` 进 trace），
行为不动。

| 次 | 诊断（对） | 我配的处置（错） | 谁拦下的 |

| 1 | 判官重写掉格、兜底门槛只认「全灭」 | 放宽门槛 → 回滚原稿 | 3 条测试：回滚会让被正确抹掉的 `3870点` 复活 |

两次都是既有测试挡住的——它们守的是真不变量。

**下次的规矩**：诊断出一条限制之后，先问「这条路之外还剩哪些路」，把剩下的路列全了再谈处置；
列不全就只做观测，不动行为。
