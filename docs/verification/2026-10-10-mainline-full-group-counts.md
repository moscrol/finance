# 主线全量统计：让总体判断拿到分母与数量

## 根因

方法细化后的 R2/R3 仍把每组最多8行的预览写成总体或唯一判断。
继续加禁止句没有解决问题。`ask_blocks._load_mainline_context_snapshot` 已在 SQL 的 joined/coverage 阶段遍历全量，
但原输出只保留总数和非空数，价格/量能信号只由预览行生成。读者要判断总体，只能再补查或自己处理不完整观察。

## 修改范围

在原 coverage 聚合中增加 `full_group_counts`，不增加查询次数、不扩日期或授权范围：

- 组内不同板块代码数；用于核对登记行是否一对一对应板块。
- 价格上涨、下跌、持平、未知数量。
- 成交额环比增加、减少、持平、未知数量。
- 严格双红满足、不满足、未知数量；阈值仍引用 `market_feature_store.signals` 的唯一常量。
- NULL 与非有限数进入 unknown，不补零。

`MainlineGroupCoverage` 增加默认空的不可变计数元组，手工旧快照不会被冒充已统计。
`episode_tools` 将数量放入公开 query_basis，并说明“每组截取前、按主题板块登记行计”。
跨组不假设成员互斥，不能把计数相加当唯一板块或股票数量。

D4 现有 owned-result 解码器接受这一可选字段并校验键、非负整数、分类合计及不同代码数上限。
旧快照继续兼容；统计字段不获得新的 owned 文本角色，不替作者认证任意结论。
这里改的是分支上的领域数据出口，未部署或改动正在运行的 8792。

## 验证

四个新增见证在原实现上全红，收据 `20261009T181113Z-283bbf78-72ee46b8e5ef.json`：
预览外有涨跌/零/缺值、唯一双红在第九行、遗漏非有限值、共享阈值变化。
修复后本片及相邻生产工具/范围/owned-result/历史合同与 Pi 入口共338P；
收据 `20261009T181539Z-283bbf78-67de6b701c68.json` 是开发树定向读数，不是全仓。
额外五类坏统计会被解码器拒绝：负数、布尔、分类合计不符、不同代码超总数、未知字段。

独立只读重数同一冻结库，与来源 SQL 的聚合逐项一致：

| 日期 | 组 | 全量行 / 预览 | 上涨 / 下跌 | 成交增加 / 减少 | 双红 |
|---|---|---|---|---|---|
| 09-23 | AI算力 | 5 / 5 | 4 / 1 | 0 / 5 | 0 |
| 09-23 | 半导体 | 4 / 4 | 4 / 0 | 0 / 4 | 0 |
| 09-23 | 电子 | 26 / 8 | 20 / 6 | 3 / 23 | 0 |
| 09-23 | 计算机 | 28 / 8 | 1 / 27 | 0 / 28 | 0 |
| 09-24 | 传媒 | 11 / 8 | 1 / 10 | 1 / 10 | 0 |
| 09-24 | 半导体 | 4 / 4 | 0 / 4 | 1 / 3 | 0 |
| 09-24 | 电子 | 26 / 8 | 0 / 26 | 4 / 22 | 0 |
| 09-24 | 计算机 | 28 / 8 | 0 / 28 | 1 / 27 | 0 |

这些组内板块代码互异、上述指标均无未知。表格不把跨组加总当去重结果。
它直接否定 R2 的“半导体设备是全主线唯一逆势放量”：仅电子组已包含4个不同代码的下跌且成交增加板块。
R3 的“所有行都是上涨且成交下降”也不成立；“双红全为零”虽碰巧正确，旧预览不足以证明，新增统计才补足依据。
