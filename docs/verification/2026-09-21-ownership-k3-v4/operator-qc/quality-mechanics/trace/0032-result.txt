; 实测事故（2026-08-08）：在主树执行 `docs/layered-rebuild-roadmap.md` 写的那条
; 「每块完成后跑全量」，得到的是
;     !!! Interrupted: 1031 errors during collection !!!
; 一条测试都没跑。原因不是任何一份测试坏了——单独 collect `tmp/runtime-live-*/
; tests/test_paths.py` 是好的（6 tests collected）——而是 `tmp/` 下 4 个历史工作
; clone（7-28 ~ 8-02）各带一个 `tests/__init__.py`，与主树 `tests/` 解析成同一个
; 包名 `tests.test_paths`，import 时互撞。
;
; 这个洞能长期不被发现，是因为 08-07 的质检按 §7 在干净 worktree 里跑
; （`git worktree add --detach`，`tmp/` 已 gitignore 所以根本不存在），
; 那条路径上永远撞不到。于是「文档里的验收命令」和「主树上真能跑的命令」
; 分叉了两周没人知道——路线图记的基线 `3807 passed, 2 skipped` 也因此停在旧值，
; 实际是 `4385 passed, 3 skipped`。
;
; 为什么不是 .gitignore 的事：pytest 不读 .gitignore，`tmp/` 被 git 忽略不影响
; 它被收集。也不建议靠「记得加 --ignore=tmp」——那是提醒，到达率不可靠；
; 写进 ini 才是对所有调用方一律生效的那一层。
;
; norecursedirs 一旦显式设置就**整体覆盖**默认值，所以下面把 pytest 的默认项
; 逐个抄回来了，只在末尾加 tmp。删掉任何一项都是行为变更，不是清理。
; （`.*` 覆盖 `.venv-workbench` / `.git` 等所有点开头目录。）
