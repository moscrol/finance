## 3. 这对三轴架构意味着什么

`2026-08-01-three-harness-architecture.md` 的主张是 **价值 = 送达率 × 信息量 × 可信度**。
A 组基线是这个乘法的第一份实测，结果非常干净：

- **送达率轴 = 0.3**（10 题里 3 题产出可用答案）
- 信息量轴、可信度轴 **在这 7 题上根本没机会参与**

我们过去一段时间加的全是**信息量轴**的东西（D6 中期视角 / D7 财报 / D8 历史类比 /
D9 资金流 / W7 事件检索 / M 用户记忆 / 情景树契约，PR #153–#160）。
**但主力题型有 70% 送不出答案——乘数是 0，加多少块都还是 0。**

这条比任何 knevo 对比都更能说明「先补哪一轴」。**head-to-head 现在做没有意义**：
拿 7 份降级桩去跟 knevo 的完整答案比，比出来的不是差距是噪声。

### 修复顺序据此重排

1. **修路由**（任务 #10）——日期解析成功 + 盘面主题词即路由，不再要求复盘动词。
2. **复跑 A 组**——同一批题，看送达率从 0.3 到多少。这是干净的 A/B。
3. **再做 knevo head-to-head**（任务 #2）——等有真答案可比。
4. 判据侧两个独立缺陷另记：
   - 抽取器不认「减少 X%」→ 少算了 A1 的分
   - A8 相对时间题 + 固定期望值 → 该改成带日期，或改判据允许相对锚

## 6. 判官修复（任务 #11）：把假红从真缺口里摘出来

同一份 canary run，**不重跑、不烧配额**（`board` 从已存 run 重新评估）。

### 两个缺陷（实测确认，非推断）

```python
_alias_windows(A1答案, ("环比","较昨日"))  →  窗口长度 0，抽到 []
# 答案实际写法：「较上一交易日缩减 17.27%」
```

1. **别名未命中 → 静默判 FAIL。** 别名表是定位提示，命不中说明判官不知道该在哪儿看，
   **不等于产品答错**。原来会一路走到「数字不在空字符串里」再判失败，于是
   「别名表没跟上答案措辞」这种配置疏漏，长得和「产品答错」一模一样。
   改为判 `UNJUDGEABLE` 并写清原因。
2. **中文把符号放在方向词上。** 「缩减 17.27%」抽出来是 `+17.27`。
   只在**期望为负**时补一组减量方向词候选（`缩减|减少|下降|回落|下跌|收窄|…`），
   增量词一律不碰——期望负数而答案说「增加」就是答错，不该被兜回来。

### 效果

| 题 | 修判官前 | 修判官后 |
|---|---|---|
| A1 | ❌ `amount_vs_yesterday_pct=-17.27 not observed` | ❌ `limit_up=116 not observed` ← **换成真缺口了** |
| A9 | ❌ `strength_marginal_pct=-66.3 not observed` | ❔ `aliases ['边际强度','强度'] not found; cannot locate` |

**真值口径：失败 10 → 失败 7、不可判 3。** 三条假红被摘掉，剩下的 7 条都是真缺口。

顺带把 A1 的 `amount_vs_yesterday_pct` 别名从 `["环比","较昨日"]` 补到含
`较上一交易日/较前一交易日/较前一日/缩量/放量`。**别名是定位提示不是正确性标准**，
补它不改变要求的值——A1 补完仍然因为 `limit_up=116` 判失败，这正是它该有的样子。

### 突变验证（3/3）
