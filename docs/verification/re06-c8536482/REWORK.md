## W1（跨项抢 run）+ W2（陈旧坐标洗白）→ 运行中登记的完整归属检查

评测：两针同一入口缺陷，不重复计数。修法（`facade.py` `_link_run_event` 运行中分支）：

1. 写入前按 run 查**完整**既有归属：`list_run_links` 里任何 item、任何代际的登记行都构成矛盾来源 → 400。
   （上一轮只查「目标项有没有登记过这个 run」，漏了跨项。）
2. 源消息坐标核验：`_source_message_launch` 取 run 的用户消息坐标——声明了 (item, request) 但与
   当前 (项, 代际) 不一致 → 400。W2 形状（接受侧已正确拒登的陈旧坐标）正是靠这层拦住。
3. R7 合同保留：无坐标裸 run（RunStore 直造）仍可显式登记——「无来源」不等于「有矛盾来源」。

回归：探针 W1/W2 原样 + 仓内 `test_w1_*` / `test_w2_*` 镜像（带修订不动的负向断言）。

## W3（取消同伴的迟到成果关闭唯一剩余项）→ 历史唯一取代状态唯一

**「本会话有史以来只有本轮这一次 rejudge 动作记录」**。已取消的 A 仍是可能的生产者——
writer 无成果归属坐标时，只要会话里存在过第二次复核请求，同会话+时间窗就证明不了归属，
一律保持待复核、等显式确认（面板「确认成果」入口上一轮已闭环）。
Q2 合同（单请求自动关闭）不受影响：单请求即历史唯一。

回归：探针 W3 原样 + 仓内 `test_w3_*` 镜像；Q2 / r6 / e2e 自动关闭路径全绿。
