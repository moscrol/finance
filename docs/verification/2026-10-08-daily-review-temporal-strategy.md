# 从每日复盘到连续研究：人和 AI 共用的时间阅读策略

## 1. 先认准现有产品

本次实际读取：

- 本 checkout 有49份 `*-daily-review.html`，最新文件日期2026-08-25；这只是仓库归档范围，不是生产生成截止。
- 阅读8/25样本的实际目录：核心看板；指数/量能/偏离度/阶段；情绪与涨家数MA5；成交前三行业；1/3/5/10日板块涨幅；双红/单红；15日双红矩阵；行业个股发动机；120日新高；涨停矩阵；3板以上个股；市场强度；5日加权涨幅；覆盖检查；环境总评。

**不是“完全没有时间数据”，而是时间信息散落于单篇日报的滚动矩阵、排名和指标中，缺少统一、连续的阅读入口。**

## 2. 产品定位：同一批数据，点—线—段三种阅读方式

- 点：某一天的完整事实、原始日报和当时表述。
- 线：固定指标/实体在连续交易日的读数和变化。
- 段：人主动选定的时间区间，或有明确规则与版本的事件窗口；列起止、变化、缺口与反例，不强迫归入某个“行情剧本”。

日期只设一处主光标；看谁、看哪段、站在哪天三个选择独立。移动显示窗口不得悄悄改变知识截止。点击变化跳回点，点选实体展开线，框选区间形成段。

## 3. 每日HTML如何转为时间阅读

| 原栏目 | 连续视图 | 要回答的问题 |
|---|---|---|
| 指数、量能、偏离度、强度、涨家数MA5 | 对齐的小折线/数值行，单位各自标注 | 今天是在怎样的市场环境中变化？ |
| 成交前三行业与集中度 | 固定行业×日期的份额/排名矩阵，保留进出榜 | 资金集中到谁、是否持续、谁被替换？ |
| 1/3/5/10日涨幅排名 | 每个观察日自己的各期限排名与入退榜记录 | 是当天脉冲还是跨多个窗口都靠前？ |
| 双红、单红、涨停、新高 | 保留既有15日矩阵并统一日期光标；规则版本一致才计连续命中 | 活跃范围是否扩散，有无间断？ |
| 行业发动机、3板以上个股 | 固定个股的入榜/退出/排名/板高轨迹 | 同一批股票持续带动，还是每天换人？ |
| 市场阶段与环境总评 | 原始文字按日期并排，结构化标签单独成轨 | 当时怎么描述，后来哪些事实变化？ |
| 数据覆盖检查 | 同日期、同实体的覆盖带 | 图的断点是休市、无数据还是未满足条件？ |

不把不同统计单位强压成同一条轴；不把日涨幅连成收益曲线；多日收益仅由已核对的价格/复权口径计算，不能简单加总百分比。

## 4. 建议界面

```text
时间：近20/40/60日 | 自选起止      数据日光标 D      视角：归档 / 当前修订
对象：全市场 → 行业 → 子板块 → 个股               知识截止：可见且可核对

A. 当日变化摘要：事实变化 / 榜单进出 / 覆盖异常 / 待复查
B. 统一时间轴：市场环境 → 行业份额 → 双红/涨停/新高 → 个股接力
C. 同日证据抽屉：原读数、单位、来源、规则版本、时间限制、原日报位置
D. 所选区间对照：首尾读数、路径、连续性、缺口、支持与反对证据
```

首屏默认20个交易日，默认只展开核心轨道。逐日/压缩两种密度沿用现有TimelineViewport；固定指标/实体名称，日期列对齐。原始完整日报仍一键可达，不重排到让用户找不到熟悉栏目。

“变化摘要”由可复算规则产生，初期只做前一计划交易日差值、明确的榜单进出、按既有规则的命中与缺口，不新增未经确认的强弱阈值。缺前日则差值未知；不能拿前一条数据库记录冒充前一交易日。

## 5. 两种历史视角必须分开

### 归档视角：当日这份报告记录了什么

从结构化日报归档取原值、原结论和报告生成时间。报告后来生成/重算，并不证明交易日当天就可获得；用真实的形成时间，未知就标未知。

### 当前修订视角：现在的数据库如何描述那个交易日

读取canonical事实表/视图的当前可用版本，明确查询/版本身份。不能拿当前值覆盖原日报来伪造当时观察。

允许将两者并排比较，展示修订差异。没有修订历史时显示“历史版本不可重建”，不能用hash或交易日推断完整时点能力。

## 6. 时间化的最小合同：尽量复用而非另建事实库

在既有只读服务上补统一时间查询投影；先盘点可复用字段，不直接创建第二套台账。

每个可比较点至少需要：实体稳定标识与当日名称、指标标识、值与单位、数据日、统计窗口、来源引用、来源/公式/框架版本、可知时间（若有）、归档形成时间（若有）、数据状态及缺口原因。

注意两条不同的时间：
- **指标说的是哪天/哪段？** 例如“当日展示的近5日涨幅”。
- **系统何时获得这条值？** 不能用重算时间倒填可知时间。

窗口查询另外携带选定范围、知识截止、视角、过滤条件、返回范围、覆盖/截断说明与可复核版本身份。旧报告缺字段，允许为空，不凑出精度。

### 不能忽略的比较陷阱

- 原始HTML只作归档阅读入口；优先结构化JSON与canonical表。只有HTML的历史报告先登记覆盖缺口；必要时独立、版本化转换并抽样核对，不在每次查询现场抓DOM重算。
- 多篇日报重叠的15日矩阵，不能当15份独立事实。按指标/实体/数据日/版本对齐，同时保留报告来源与修订冲突。
- 某行业跌出Top3、某个股不再上榜，只代表退出榜单，不代表成交为零或没有上涨。
- 连续性在缺数据处中断判定；不跨缺口声称连续N日。
- 实体更名/供应商切换须用当日映射，不凭中文同名拼接。
- 回看时不只挑今天的赢家。默认每个交易日按当时的榜单，固定研究对象时再明确锁定实体。
- 不同指标统计窗口与规则版本不同，不能直接累加或解释为同一种“强”。

## 7. 人与AI共用一层事实，不共用一坨HTML

建议AI消费三个查询形状，名称待与已有工具注册表核对，不先承诺新增工具：

1. 点查询：D日、实体E，各指标与来源/缺口。
2. 线查询：实体E、日期范围R、指标集合M，返回有界序列及版本。
3. 变化查询：范围R或两个明确时点，返回可复算差异、榜单变化、支持与反例引用。

页面和AI使用同一只读服务与口径，不由前端和prompt分别计算。给模型的是：查询条件 + 数值/序列 + 原始结论引用 + 缺口/时间限制，而不是仅一段AI总结。

按需检索：先取市场概览，发现明确变化后再取目标行业/板块/个股区间。引用必须能跳回页面同一日期/实体/指标和版本。超预算分页或明确截断，限制语与数据不能被分离裁剪。PR75若后续批准合入，多维镜头可以作为“段比较”的消费者，不变成新事实源，也不将其历史候选嫁接到旧D10收益。

不必默认自动调用模型：日常看板和变化计算应确定性、只读、无模型成本；用户需要解释时再调用AI，并要求指出反例和缺口。

## 8. 推荐首个垂直切片

选最近20个交易日的：
- 市场成交额、涨家数MA5、市场强度；
- 各日成交前三行业及集中度；
- 固定行业/子板块的双红、涨停、新高矩阵；
- 行业个股发动机与高标更替。

先盘点20日数据与归档覆盖，不保证现库已齐全。以“一个行业的连续观察”贯穿：市场环境→份额/排名变化→子板块扩散→发动机更替→同日原报告。需要跨行业数据时查询完整观察集合，不用几天Top3名单猜全市场。

首版不接生产写入、不改每日生成流程、不自动命名行情阶段。先让一条人能核对的时间链成立，再扩展其他栏目和AI消费。

## 9. 验收不是图表数量

用户与AI应能基于同一输出回答：
1. 这个行业在所选20日里，是份额持续上升，还是只在某日脉冲？（可比日不足时说不足）
2. 活跃是多个子板块扩散还是个别股票带动？依据哪些可用读数，不能把共现说成因果。
3. 榜单中是同一批发动机还是不断更换？退出榜单与数据缺失是否区分？
4. 某天原报告的判断是什么？之后哪些事实支持、哪些反对，是否用了后来才获得的信息？
5. 任意一个显示数字能否定位原字段/报告；页面与AI返回的值、日期、窗口、缺口是否一致？

必须附红绿回归：缺交易日、跨月/跨年、重叠滚动窗口去重、单位/版本改变、TopN进退、实体更名、后补数据、旧请求晚返回、相同查询不同展示窗口不改历史点值。
