# finance-industry-track：行业全景与持续跟踪

本文件只含流程与骨架，不得夹带市场事实、数字或板块名。它在 finance-mode 之上加流程，不改其规则。

## 两个模式与分流

- **report（画森林）**：首次覆盖，或用户问「是什么 / 有多大 / 格局如何」。产出全景地图，结论段必须埋「跟踪信号清单」作为后续基线。
- **track（气象预报）**：用户问「最近 / 本周 / 更新 / 变化」，或个人记忆里已有该行业的 report 结论。只报 delta。
- 用户状态覆盖字面：昨天刚做过 report，今天同样问法转 track；记忆里没有基线却问「更新」，先做一个精简 report 建立基线，并说明这是首次建档。
- report 的有效期按本仓台账约定（几个月量级）；过期结论必须复核才能再引用。

## report 模式

检索（两批并行）：
1. 行业定义与边界：图谱里的概念映射、成分与上下游；行业指数与板块码（同名板块可能对应两个代码，按代码查）。
2. 市场空间与格局：知识库的行业页、研报线索（二手）、公告级事实（一手）。
3. 全量板块横截面：该行业相关板块的涨跌、成交、边际量、多周期共振，与一级行业对照。
4. 核心标的：从成分与主线表里识别两到四家，取同口径财务与行情。
5. 催化与政策：新闻 + 公告 + 事件日历。
6. 个人记忆与反方检索。

骨架：
```
## 结论（一句定位 + 当前阶段 + 核心矛盾）
## 产业链地图（环节 / 代表公司 / 议价与瓶颈）
## 市场空间与格局（口径与来源分列）
## 供需与价格（有数据才写；缺就写缺）
## 催化与政策日历
## 风险与反证
## 标的梳理（线索级，不是推荐）
## 证据边界与缺口
## 跟踪信号清单（三到五条，含触发条件、复查窗口）
## 追问建议（≤4）
```

## track 模式

参数：
- 记忆窗：近一到两周的个人记忆与上期结论。
- 图谱：只查**变化节点**（新增关系、新增实体、变更的映射），不重画全图。
- 新闻：近一周。
- 行情：上期基线日到今天的板块与核心标的变化。

骨架（delta-only）：
```
## 变化摘要（三句以内）
## 上期判断四态对照
   每条上期判断：支持 / 削弱 / 无变化 / 信息不足，各给依据
## 新增信号（只写变了的指标；无变化的跳过）
## 信号灯
   上期跟踪信号清单逐条：触发 / 未触发 / 无法观测
## 下期关注 + 触发条件
## 证据边界与缺口
## 追问建议（≤4）
```

## 防遗漏清单

- 同名板块两套代码：按代码聚合，不按名字；按名字聚合会双计。
- 概念板块重叠：按板块加总成交会大于全市，不用板块加总冒充行业成交。
- 一级行业与概念板块是两张表：行业涨跌用行业表，题材热度用板块或涨停热度表。
- 子集表不做全市排名；横截面有残缺段时先声明覆盖不足再给名次。
- 历史后验不当作当时已知：类比历史时同时列相似点与关键差异，并标明时间尺度。
- track 不复述背景、不凑字数；没有变化就说「无变化」，这本身是信息。
- 标的只到线索级：不写买卖建议，不承诺收益。

## 交付前自检（在 finance-mode 五项之上）

report：
1. 结论段埋了跟踪信号清单吗？每条有触发条件和复查窗口吗？
2. 市场空间与格局的口径与来源分列了吗？研报数据标了二手吗？
3. 板块按代码聚合了吗？

track：
1. 上期每条判断都做了四态对照吗？
2. 只写了变化吗？有没有把上期内容重抄一遍？
3. 信号灯逐条对应上期清单了吗？
4. 给了下期关注与触发条件吗？
