# finance-industry-track：行业全景与持续跟踪

只含流程与骨架，不携带市场事实。它在 finance-mode 之上加流程，不改其规则。

## 两个模式与分流

- **report（画森林）**：首次覆盖，或用户问「是什么 / 有多大 / 格局如何」。目标是可复核的研究框架、关键假设和证据缺口，不是堆叠新闻摘要。结论段必须埋「跟踪信号清单」作为后续基线。
- **track（气象预报）**：用户问「最近 / 本周 / 更新 / 变化」，或个人记忆里已有该行业的 report 结论。以上期基线为锚，只报 delta；本期的价值在「相对上期变了什么」。不得把短期信号包装成确定性结论。
- 用户状态覆盖字面：昨天刚做过 report，今天同样问法转 track；记忆里没有基线却问「更新」，先做一个精简 report 建立基线，并说明这是首次建档。
- 结论自带有效期：report 按季度量级、track 按月度量级写明建议复查日期；过期结论必须复核才能再引用。

## report 模式

标准流程（逐步推进，不要跳步）：
1. **锚定范围**：行业定义、地域、时间范围、目标读者、排除范围。
2. **查记忆**（不可省）：该行业的历史观点与研判框架，标为先验。
3. **查图谱**：产业链、重点公司关系与上下游；板块级问题也要查，空结果如实披露。
4. **联想**：相邻行业、替代品、补充品、历史类比（同时列相似点与关键差异）。
5. **补数据**（并行发射）：全量板块横截面（涨跌、成交、边际量、多周期共振）与一级行业对照；行业指数与板块码（同名板块可能对应两个代码，按代码查）；核心标的两到四家的同口径财务与行情；市场空间与格局用知识库行业页、研报线索（二手）、公告级事实（一手）；催化与政策用新闻 + 公告 + 事件日历；反方检索一次。
6. **成文**：按骨架。

分析框架：
- **行业概述**：边界、市场规模、发展阶段、政策背景。
- **产业链结构**：上中下游、各层参与方、核心壁垒、价值 / 利润分配。
- **市场空间与增速**：规模口径、渗透率、量价、周期位置；口径与来源分列。
- **供需格局 / 驱动因子**：产能、库存、订单、替代品、政策、技术；识别景气周期转折的核心变量与前瞻指标。
- **竞争格局**：集中度、主要玩家份额、技术路线、成本曲线、护城河。
- **代表标的**：各细分赛道的标的线索与估值锚，线索级不是推荐。
- **风险与反例**：政策、技术替代、需求收缩、数据缺口、周期反转。

输出骨架（标题逐字保留）：
```text
# 行业深度 — {行业}
> 数据截止：{日期} · 观点有效期：写明建议复查日期

## 1. 行业概述      — 边界、规模、阶段、政策背景
## 2. 产业链结构    — 上中下游 + 壁垒 + 价值分配
## 3. 驱动因子      — 供需关键变量 + 景气前瞻指标
## 4. 竞争格局      — 集中度 + 主要玩家 + 护城河
## 5. 代表标的      — 各赛道线索 + 估值锚（线索级）
## 6. 风险与展望    — 主要风险 + 中期路径判断 + 反证
## 证据边界与缺口
## 跟踪信号清单    — 三到五条，含触发条件、复查窗口（track 的基线接口）
## 🎯 核心结论      — 这个行业现在最值得关注的一件事
## 追问建议（≤4）
```

## track 模式

参数：记忆窗取近一到两周的个人记忆与上期结论；图谱只查**变化节点**（新增关系、新增实体、变更的映射），不重画全图；新闻取近一周；行情取上期基线日到今天的板块与核心标的变化。

标准流程：
1. **锚定上期基线**：跟踪对象、本期时间窗、上期结论、用户关注指标；读取上次跟踪记录。
2. **查记忆**（不可省）：上期观点与结论作为比对基线。
3. **补数据**：个股一次拿全（行情 + 新闻 + 梯队）；行业维度分项点名（行情 / 估值 / 成分 / 财务 / 宏观 / 新闻）。
4. **对比识别**：本期与上期逐项对比，**只保留有信息量的变化，不复述无变化项**。
5. **成文**：突出「变化 + 是否触发 thesis 修正」。

输出骨架（delta-only，标题逐字保留）：
```text
# 行业跟踪 — {行业} · {周期}
> 数据截止：{日期} · 基线：{上期日期} · 观点有效期：写明建议复查日期

## 1. 本期要点    — 最值得关注的三到五条核心动态
## 2. 数据速览    — 关键指标变化，用表格；无变化的指标跳过
## 3. 个股异动    — 涨跌显著或有重大事件的标的 + 异动原因（有数据才写原因）
## 4. 观点更新    — 对照上期逐条：支持 / 削弱 / 无变化 / 信息不足；改了就说改了什么
## 5. 信号灯      — 上期跟踪信号清单逐条：触发 / 未触发 / 无法观测
## 6. 下期关注    — 具体指标、时间节点、政策 / 公司动态 + 触发条件
## 证据边界与缺口
## 🎯 核心结论    — 本期一句话
## 追问建议（≤4）
```

## 防遗漏清单

- 同名板块两套代码：按代码聚合，不按名字；按名字聚合会双计。
- 概念板块重叠：按板块加总成交会大于全市，不用板块加总冒充行业成交。
- 一级行业与概念板块是两张表：行业涨跌用行业表，题材热度用板块或涨停热度表。
- 子集表不做全市排名；横截面有残缺段时先声明覆盖不足再给名次。
- 历史后验不当作当时已知：类比历史时同时列相似点与关键差异，并标明时间尺度。
- track 不复述背景、不凑字数；没有变化就说「无变化」，这本身是信息。
- 标的只到线索级：不写买卖建议，不承诺收益。

## 交付前自检（在 finance-mode 五项之上）

report：
1. 结论段埋了跟踪信号清单吗？每条有触发条件和复查窗口吗？
2. 市场空间与格局的口径与来源分列了吗？研报数据标了二手吗？
3. 板块按代码聚合了吗？

track：
1. 上期每条判断都做了四态对照吗？
2. 只写了变化吗？有没有把上期内容重抄一遍？
3. 信号灯逐条对应上期清单了吗？
4. 给了下期关注与触发条件吗？

## 输出契约与交付后

交付必须是完整报告正文（含全部章节与 🎯 核心结论），不得用「已写入文件」「详见附件」或摘要替代；作为子任务执行时返回正文同样自包含。交付后（用户触发）：可提示用 finance-review-check 复核；本期新增的可复用判断只在用户确认后提议写入记忆。
