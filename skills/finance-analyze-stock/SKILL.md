# finance-analyze-stock：个股深度与财报复盘

只含流程与骨架，不携带市场事实。它在 finance-mode 之上加流程，不改其规则：finance-mode 提供身份、来源词典和纪律，这里给出个股深度与财报复盘的具体流程与报告骨架。

## 适用与不适用

- 适用：首次完整覆盖一只股票；对一期财报做窄切面复盘；用户问估值、隐含预期、竞争格局、催化。
- 不适用：纯事实（现价、市值、某个财务数）——主线程直接查；多只标的横向比较——拆成并行子任务后主线程合并；行业全景——走 finance-industry-track；尚未披露、需要推演的财报——走 finance-forecast-event。
- 用户已有研究史（个人记忆里该标的条目充分、近期讨论过）：降级为增量更新，只写变化与新证据，不重复背景。
- 不得输出实盘下单建议或保证收益。

## 标准流程（按资深分析师习惯逐步推进，不要跳步）

1. **锚定时间与对象**：确认今天日期，把「最近 / 上季 / 去年」转成具体期间；确认标的、代码、市场和用户真正关心的问题。
2. **查记忆**（不可省，空结果也是信息）：该标的的历史观点、估值锚、已有结论，作为对比基线；标为先验。
3. **查图谱**：先实体解析消歧（避免同名不同公司），再取产业链、供应商、客户、竞对关系。只「想到要查」不算，必须实际调用；空结果说明图谱待补，如实披露。
4. **联想**（片刻即可）：有没有用户没问到但强相关的实体、矛盾的历史观点、相似的历史模式？有就自然融进分析，不单列。
5. **补数据**（并行发射，按授权清单点名工具）：行情快照与技术位；已披露财务（锚定报告期、披露日、累计 / 单季口径，多公司比较在同一次调用里把可比公司一起取）；估值用结构化估值字段，**禁止用现价除以记忆里的每股收益硬算**；公告与互动（经营事实、订单、产能、减持 / 解禁、监管）；两融 / 大宗 / 解禁（涉及筹码时）；知识库与证据索引（边际变化、研究线索，分层引用）；新闻（拆事实 / 解读 / 情绪）；反方检索（针对核心假设一次）。**价格、市值、估值须同源、同截至日。**
6. **综合分析**：按下方框架与骨架完整成文。

## 分析框架

- **公司概况**：业务模式、收入结构、地域、核心客户与供应链。
- **行业位置**：份额、主要竞对、替代品、上下游议价能力。图谱关系只证明登记过关联，不自动证明采购份额或受益强度。
- **财务质量**：增长、利润率、现金流、杠杆、一次性项目；给历史区间不只给单点。实际值、同口径上期值、披露前一致预期三列分开；一致预期缺失时写「未取得可比的一致预期」，不把同比增长或披露后研报当作超预期证明。用经营现金流、应收、存货、资本开支交叉检查利润质量；毛利率变动不单独证明定价权。
- **驱动因子 / 催化剂**：财报、产品、政策、订单、价格、并购、回购，标时间窗与定性可能性。
- **多空两面**：不是形式化的优缺点，而是「做多的核心逻辑是什么 / 做空的人在担心什么 / 我的判断」。
- **估值框架**：可比公司 + 历史区间，至少给一个估值锚；写清核心假设与敏感性；用倒推法写出「当前价格隐含了什么假设」。没有估值锚的推荐是空中楼阁；没有可比口径就只给区间推理并标推断。负市盈率不按越低越便宜解读。
- **风险**：必须具体到「哪个变量、往哪个方向变、影响多大」，不接受「宏观不确定性」。
- **情景与验证**：基准 / 乐观 / 悲观各给触发条件与可验证时点；对照用户此前判断说明支持 / 削弱 / 无变化 / 信息不足。

## 输出骨架（标题逐字保留）

```text
# 个股深度 — {公司 / 代码}
> 数据截止：{日期} · 核心数据报告期：{报告期} · 观点有效期：写明建议复查日期（深度报告按季度量级）

## 1. 摘要        — 核心投资逻辑与倾向结论，一眼看懂
## 2. 基本面      — 业务、收入结构、核心财务（报告期 / 实际 / 上期 / 预期）
## 3. 驱动因子    — 催化剂、行业趋势、竞争优势
## 4. 估值        — 估值锚 + 隐含假设 + 敏感性
## 5. 风险        — 对投资逻辑有实质威胁的具体变量
## 6. 结论与观点  — 明确倾向 + 情景与验证时点 + 反证
## 证据边界与缺口
## 跟踪信号清单
## 🎯 核心结论    — 一句话：如果只能记住一件事
## 追问建议（≤4）
```

### 财报复盘窄切面（用户只问某一期时用这个骨架）

```text
# 业绩点评 — {公司 / 代码} · {报告期}
## 1. 核心数据    — 本期 vs 一致预期（一句话定调；预期缺失明说）
## 2. 同比环比    — 核心指标变动幅度与趋势方向
## 3. 业绩拆解    — 分业务线超 / 不及预期的根因
## 4. 业绩质量    — 现金流 / 应收 / 存货，利润含金量
## 5. 指引 / 展望 — 管理层指引（待验证预期）+ 兑现可能性 + 下一披露窗口的可观测验证量
## 6. 观点        — 对照此前判断：支持 / 削弱 / 无变化 / 信息不足；改了什么、为什么
## 🎯 核心结论    — 这份财报最重要的一个信号
## 追问建议（≤4）
```

## 防遗漏清单

- 报告期锚定：每个财务数带报告期与披露日，不把三季报说成当前；累计 / 单季不混。
- 单季还原：工具只给累计口径，自己还原的单季数写明是推算。
- 多期比较同口径：币种、单位、会计口径一致后再谈差额。
- 公司级硬事实要公告：订单 / 中标 / 产能 / 量产只有新闻或研报来源时写「待验证线索」，点明缺的一手材料。
- 筹码数据的时间语义：解禁是未来日程，两融按交易日标记，不把抓取日当数据日。
- 新股 / 冷门标的：数据全空时如实写「来源覆盖不足」，不用同名或同题材公司冒充。
- 不给买卖建议、不承诺收益；「值多少」只写假设与区间。

## 来源标注与回复风格

关键结论、数据点、风险判断行内标来源层：用户记忆 / 共享来源 / 图谱 / 数据源名 / `[inference]`；不笼统写「记忆显示」。结论要有逻辑链，把中间推理摊开；矛盾信号主动暴露（「多头看 X，但要注意 Y」）；有观点、有立场，不确定处诚实说；跳过客套。

## 交付前自检（在 finance-mode 五项之上）

1. 每个财务数都带报告期了吗？累计与单季分开了吗？
2. 一致预期有来源吗？没有就写了「未取得」吗？
3. 估值判断给了估值锚、隐含假设和比较集吗？有没有现价除以记忆每股收益硬算？
4. 公司级硬事实有公告支撑吗？没有就标「待验证线索」了吗？
5. 三情景各有触发条件和可验证时点吗？风险具体到变量了吗？
6. 用户先验做了四态对照吗（有先验时）？

## 输出契约与交付后

交付必须是完整报告正文——含全部章节、数据来源、风险和 🎯 核心结论；不得用「分析完成」「已写入文件」「详见附件」或摘要短版替代。作为子任务执行时，返回的正文同样必须自包含。交付后（用户触发，不主动执行）：可提示用 finance-review-check 做事实审查；值得沉淀但用户未明确要求入库的结论，只在用户确认后提议写入记忆。
