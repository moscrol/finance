# finance-forecast-event：事件推演

本文件只含流程与骨架，不得夹带市场事实、数字或板块名。它在 finance-mode 之上加流程，不改其规则。

## 两种输入

- **已发生的消息 / 突发**：走六步法。
- **未来事件**：走情景树。
- 两者都先做：明确事件的截止时间、「怎样算发生」、可观测的判定信号；区分**事件发生的概率**与**发生后的条件影响**，两者不是一回事。

## 检索顺序（并行）

1. 溯源：新闻检索 + 公告 / 官方原文；拆出事实、解读、情绪三层，事实标来源、对象、时间、确认阶段。
2. 传导对象：图谱里的产业链与竞对关系（线索），受影响标的的行情与基础档。
3. 定价进度：相关板块与标的近期涨跌、成交、涨停热度，判断消息是否已被交易。
4. 历史类比：知识库与记忆里的同类事件（相似点与关键差异一起列）。
5. 市场定价参考：若有带时点的市场赔率或一致预期，作为参考而非真实概率；没有就写「无市场定价参考」。
6. 个人记忆与反方检索。

## 六步法（已发生的消息）

1. **判级**：事件级别（公司 / 行业 / 宏观）、确认阶段（传闻 / 媒体 / 官方）、是否一次性。
2. **溯源**：原始发布主体是谁；多家转载不构成交叉验证；来源缺失写「无法核实」，不判定事件没发生。
3. **拆传导链**：从事件到各受影响对象的路径，每一跳写附加假设；图谱关系只证明登记过关联。
4. **量级**：用可得数据给数量级或区间，标推断；没有可比基线和定价模型时，不用「实际涨幅减猜测的合理涨幅」量化情绪溢价。
5. **定价进度**：已交易了多少（板块与标的的近期表现、涨停热度），还剩什么没被定价。
6. **裁决**：带条件的判断——「基准情景 X，推翻条件 Y，验证窗口 Z」；已证实事实不自动成为交易指令。

## 情景树（未来事件）

- 用**互斥情景**区分主要结果，并保留一个「未覆盖结果」。
- 每个情景：触发条件、支持证据、反方证据、影响路径、观察窗口。
- 没有校准依据时用定性可能性（高 / 中 / 低），不硬编概率数字。
- 涉及关键决策者：只用可核验的历史行为、权限与当前约束解释可能选择；行为模拟标为推断，资料不足就说明无法模拟，不编造人物画像。
- 结尾：会改变判断的**领先信号**与失效条件。推演不自动登记为事实或记忆。

## 防遗漏清单

- 事实 / 解读 / 情绪三层分开，情绪与宣传措辞不充当业务进展证据。
- 传播次数与独立来源数分开。
- 事件日期可以晚于信息截止日（日历类），引用时写清它是计划日。
- 受益强度不能从图谱关系或题材归属推出，需要公司级证据。
- 「会不会」的问题改写为「沿哪条路径、看什么信号」。
- 不承诺收益，不给买卖指令。

## 交付前自检（在 finance-mode 五项之上）

1. 事件的截止时间与「怎样算发生」写了吗？
2. 发生概率与发生后影响分开了吗？
3. 每条传导跳都写了附加假设吗？
4. 定价进度有数据支撑吗？没有就写「未取得」了吗？
5. 领先信号与失效条件给了吗？

## 输出骨架

```
## 裁决（基准情景 / 推翻条件 / 验证窗口）
## 事件判级与溯源
## 传导链（路径 × 假设）
## 量级（区间 / 推断标注）
## 定价进度
## 情景树（未来事件时）
## 领先信号与失效条件
## 证据边界与缺口
## 追问建议（≤4）
```
