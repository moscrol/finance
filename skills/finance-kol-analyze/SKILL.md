# finance-kol-analyze：观点与作者分析

只含研究方法，不携带市场事实。它在 finance-mode 之上加流程，不改其规则。

## 两种用法，先分清

- **A 画像与行为模拟**：构建某作者的价值观框架、惯用逻辑链、典型观点、偏好与盲区、转折时机，再模拟其对当前事件的可能立场。
- **B 观点质量分析**：拆解一段具体观点的核心结论、隐含假设、时间范围、触发条件、证据质量、激励与偏见、反方线索、可监控指标。
- 仅有一段观点时只分析该段，不自动扩写成作者的长期画像。画像必须基于真实历史记录，记录不足时明说「数据不足，不强行模拟」，禁止凭空捏造。

## 标准流程（逐步推进，不要跳步）

1. **明确对象**：待分析的作者 / 观点、来源、发布时间、相关标的、用户关心的是画像模拟还是质量审查。记录作者、原文来源、发布时间和相关时间范围。
2. **查记忆与证据索引**（不可省，空结果也是信息）：该作者的历史观点、推理模式、行为特征、转折时机；同主题的其他观点。这是画像的事实基础；个人记忆标为先验。
3. **读原文**：读取用户提供的原文、截图转写、访谈纪要或报告。缺原文时不靠标题重建整条论证。
4. **核验**（并行发射）：关键事实、数字、时间线、反方证据先用结构化数据、公告查询、新闻检索；材料不足再网页检索与取页。
5. **成文**：A 模式按「画像 + 行为预测」输出；B 模式按「观点拆解 + 证据质量 + 偏见 + 反方 + 可监控指标」输出。

## 分析框架

- **观点拆解**：核心结论、隐含假设、时间范围、触发条件；事实与推断分行。
- **历史行为模式（画像）**：价值观框架、惯用逻辑链、典型观点、偏好与盲区、转折时机；只依据可追溯的历史记录。
- **证据质量**：一手 / 二手、数据新鲜度、可复核性、样本偏差；用户给的数字按本协议现查核验。
- **激励与偏见**：持仓、商业关系、叙事选择、幸存者偏差——**仅在有证据时陈述**，否则列为待核验因素，不能由观点方向臆断动机。
- **行为预测（画像模式）**：针对当前事件模拟其立场，标注置信度（高 / 中 / 低）及依据，与主流观点的偏差；模拟是推演不是真相。
- **反方线索 + 可监控指标**：能推翻该观点的事实 / 事件；后续验证要看的数据。保留作者前后矛盾与相反解释。
- 历史立场是先验，不覆盖当前证据；分析完成不等于批准写入画像。

## 输出骨架

```text
# 观点 / 作者分析 — {对象}
## 1. 基本画像 / 观点拆解   — 背景、机构、研究领域 / 核心结论 + 隐含假设
## 2. 历史行为模式          — 惯用逻辑、典型观点、转折时机（画像模式）
## 3. 证据质量与偏见        — 一手 / 二手、可复核性、激励与偏见（有证据才写）
## 4. 行为预测 / 反方线索    — 对当前事件的立场（含置信度）/ 能推翻的事实
## 5. 与主流观点的偏差 + 可监控指标
## 🎯 核心结论              — 一句话：如果只能记住一件事
## 追问建议（≤4）
```

## 来源标注

画像依据、行为预测、偏差判断必须行内标来源：历史记录标记忆来源（区分用户记忆与共享来源）、核验数据标数据源、推断标 `[inference]`。记录不足时标注「数据不足，不强行模拟」。

## 交付前自检

1. 分清了是 A 模式还是 B 模式吗？只有一段观点时有没有越界画像？
2. 画像的每条特征都能指回真实历史记录吗？
3. 激励与偏见有证据吗？没有的写成「待核验因素」了吗？
4. 反方线索与可监控指标给了吗？
5. 结论里有对该观点的修正、补充或保留意见吗（不只输出「他是对的」）？

## 输出契约与交付后

交付完整分析——含画像 / 拆解、证据质量、反方、🎯 核心结论；不得用摘要短版替代。交付后（用户触发）：新增的作者行为数据或画像更新只在用户确认后提议写入；本专项不写记忆。
