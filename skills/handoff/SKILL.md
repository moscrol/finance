# 回写交接（handoff）

`docs/handoffs/inflight/<当前分支名，/ 换 ->.md` 是给**接手干活的 agent** 读的活文档，回答「我现在卡在哪、你接着做要踩什么」，不是完工报告。
读侧是 `scripts/session_facts.sh`：SessionStart 时按 `## ` 切段，把「已验证」类回顾小节挪到末尾，再按约 2000 字符预算从尾部截断并声明砍了多少。
所以预算不够时先丢的是「我做完了什么」，保住的是「什么还没验 / 下一步 / 会咬人的坑」——**前提是文档本身 ≤3K 字节**；一超标，被砍的就是「下一步」和「坑」，指针行会标出实际字节数但救不回内容。

## 执行步骤

1. **定位文件**：不存在就以 `docs/handoffs/inflight/` 下任一现有文件为模板新建。
2. **核对真实状态，不凭记忆**：`git branch --show-current`、`git status --porcelain`（逐条认领：哪些是你改的、哪些是别人或 ingest 产物）、`git log --oneline -3`。
3. **覆写文档，只留这几节，总量 ≤3K 字节**：
   - `## 这个分支做什么` — 一句话目标。
   - `## 决策与被否方案` — 每行一个决策：选了什么 / 否了什么 / 一句话为什么。只放压缩表，展开留给日期快照。
   - `## 当前状态` — 已提交 / 未提交 / 卡在哪。写完就改，别让文档说过期的话。
   - `## 已验证` — 你实际跑过的检查。
   - `## 未验证 / 已知边界` — 具体到哪条路径没被压到（不写「没跑 live」这种笼统话），让接手者能判断「这个结论我能不能拿来用」。
   - `## 下一步` — 接手者接着做什么。
   - `## 踩过的坑` — 本分支特有的坑；可迁移的提炼进 `~/agent-memory/10_knowledge/`。
   写不下就别堆细节：结论进 inflight，展开留给 commit message 和日期快照。
4. **工具沉淀盘点**（交接不只交状态，还交能力）。逐条自问，有就归位，没有就一句话说明为什么没有：

   | 问 | 归位到 |
   |---|---|
   | 同一个手工排查这轮做了两次以上？ | 写成脚本 → `~/harness-reference/TOOLKIT.md` 对应档位 |
   | 建了脚本但只在 `/tmp` 或对话里跑过？ | 移进 `scripts/`，docstring 写清它防的失败形状 |
   | 发现了现有门禁的洞？ | 补上并变异验证，别只写进文档 |
   | 发现了可迁移的模式（换个项目也会犯）？ | `~/harness-reference/BUILD.md` 七模式那节 / `10_knowledge/` |
   | 沉淀成「手法」而非「工具」？ | 必须说明为什么（成本？需要语义判断？样本太少？） |

   收录判据：换一个完全不同的项目，这个失败还会不会发生？会才收。手法的到达率不可靠，工具才 100% 到达。
5. **提交**：`git add -- <该文件>` → `git commit -- <该文件>`。本仓多 agent 共享索引，不用 `git add .`。分支上有你不想提交的代码改动时，文档单独提交即可，它本来就该是最新的。

## 为什么必须写被否方案

只写「我选了 D」，接手者拿到的是一个没有来历的现状，要么当天条不敢碰，要么觉得没道理直接推翻，而你否掉 A/B/C 的理由他要重新踩一遍。
每条决策至少三样：

| 要素 | 不合格 | 合格 |
|---|---|---|
| 选了什么 | 「改了绑定闸」 | 「契约没下达就不问罪，判据从 prompt 自身算」 |
| 否了什么 | （不写） | 「否了直接删闸、否了补全 prompt」 |
| 为什么 | 「更好」 | 「删了回不来；补 prompt 治本但旧链是 fallback，投入产出不划算」 |

「用户拍的」是事实不是理由：连用户当时基于什么信息拍的一起写，那份信息过期时决定才跟着可复核。前提写错比结论写错更贵——结论错了下一任会验，前提错了他会拿它当地基。

## 什么时候另写日期快照

这一轮做了**非显然的决定**（多数轮次都算）时，除 inflight 外再写 `docs/handoffs/YYYY-MM-DD-<主题>.md`，不限长、写完不改：

- **背景**：不读这段会误判后面每个决定的那一段；别假设接手者读过前一个 PR。
- **按发现顺序**记做了什么（不按重要性）——发现顺序携带因果，后面的坑往往是前一步的直接后果。
- **每个决策的完整方案对比表**（方案 / 评价 / 结果），含被否的。
- **验证与收据**：跑了什么、收据在哪、哪些结论不成立（如 n=1 不许读快慢）。
- **后续要做的 + 不要做的**，后者写清理由，否则下一任会当成没来由的禁令绕过去。

inflight 的压缩表里写一行指针指到这份快照。做完、合并、归档的事从 inflight 里删掉，只留在快照。

## 红线

- 不写密钥 / token / 密码（PAT、`CC_REMOTE_EXEC_TOKEN` 等一律不进交接）。
- 不贴整段代码 diff，记结论和决策，代码看 commit / PR。
- 不删别的 agent 的交接；inflight 只覆写你自己分支的那份。
- 在动作完成之后写：先写「未提交」再去提交，文档当场失效。
- 不写「某某闸还兜着」这类前提，除非你这轮真的查过它还在。
- 不把 n=1 的样本写成趋势（「更快了」「吸收兑现」）；写清样本量和被什么主导，只断言结构性事实。
- 合入状态不手抄：哪些枝已进 main、哪些 worktree 只是 leftover，跑 `python3 scripts/worktree_board.py`（看 `git cherry`，不看 ahead 数）。不写进 `inflight/main.md` 或项目笔记「交接记录」，那两处会漂。

## 与项目笔记「交接记录」的分工

| | `inflight/<分支>.md`（本 skill 写） | `YYYY-MM-DD-<主题>.md`（本 skill 写） | 项目笔记「交接记录」 |
|---|---|---|---|
| 定位 | 在途状态 / 接手手册 | 决策留痕：背景 / 被否方案 / 理由 | 一行索引 / 时间线 |
| 长度 | ≤3K，写完即覆写 | 不限长，写完不改 | 一行 |
| 谁读 | 接手 agent（SessionStart 自动注入） | 要动这块、或要推翻某个决定的人 | 人翻历史、跨 agent 对账 |
| 何时写 | 每次 handoff | 做过非显然决定时 | 完工后，按 `~/agent-memory/40_playbooks/devin-writeback.md` |
