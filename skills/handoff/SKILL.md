# 回写交接（handoff）

用户说 **handoff** / **交接** / **交给下一个 agent** 时，立即把当前分支的**在途状态**写进
`docs/handoffs/inflight/<当前分支，/ 换 ->.md`。这是 inflight 活文档的**写侧入口**——
读侧由 `scripts/session_facts.sh` 在每次 SessionStart 自动注入（前 12 行），
下一个 agent 一开工就能看到你的交接，不需要你额外提醒。

## 为什么是"在途状态"而不是"完工报告"

inflight 文档是给**接手干活的 agent** 读的，不是给事后追溯的人看的。它要回答的是
「我现在卡在哪、你接着往下做要踩什么」，不是「我做完了什么」。

- 写完就改 `## 当前状态`：改了什么、**还没改什么**、哪些已验证、哪些**没验证**。
- 分支**没完成**的卡点、下一步、踩过的坑，比"已完成"更值钱——接手者真正需要的是这些。
- 做完的、合并的、归档的事，从 inflight 里**删掉**，转成 `docs/handoffs/YYYY-MM-DD-*.md` 日期快照。

## 为什么必须写被否方案（2026-08-17 新增）

只写「我选了 D」，接手者拿到的是一个**没有来历的现状**。他会做两件事之一：当成天条
不敢碰，或者觉得没道理直接推翻——而你否掉 A/B/C 的那些理由，他要重新踩一遍才知道。

真实代价（本轮实例）：#144 的设计文档写着「`llm_added_number` 仍是 error 的
fail-closed」，据此论证「只放松形式闸、事实闸还兜着」。实际那个 code 一个多月前就被
一次 refactor 删了。**下一任照着这句话做判断，会以为旧链还有数字幻觉闸守着。**
写清「当时基于什么判断」，就是让后来者能发现前提已经变了。

每条决策至少交代三样：

| 要素 | 不合格 | 合格 |
|---|---|---|
| 选了什么 | 「改了绑定闸」 | 「契约没下达就不问罪，判据从 prompt 自身算」 |
| 否了什么 | （不写） | 「否了直接删闸、否了补全 prompt」 |
| 为什么 | 「更好」 | 「删了回不来；补 prompt 治本但旧链是 fallback，投入产出不划算」 |

**「用户拍的」不是理由，是事实。** 要连用户当时基于什么信息拍的一起写——那份信息
过期时，决定才跟着可复核。

## 什么时候必须另写日期快照

inflight 有 3K 硬预算（见下），装不下完整理由。**这一轮做了非显然的决定时**，
除 inflight 外必须再写一份 `docs/handoffs/YYYY-MM-DD-<主题>.md`，它**没有预算**，
要写全：

- **背景**：不读这段会误判后面每个决定的那一段。别假设接手者读过前一个 PR。
- **按发现顺序**记做了什么（不是按重要性）——发现顺序本身携带因果，后面的坑往往是
  前面那步的直接后果。
- **每个决策的完整方案对比表**（方案 / 评价 / 结果），含被否的。
- **验证与收据**：跑了什么、收据在哪、**哪些结论不成立**（如 n=1 不许读快慢）。
- **后续要做的** + **不要做的**，后者写清理由，否则下一任会当成没来由的禁令绕过去。

inflight 那张压缩表里写一行指针指到这份快照。

## 执行步骤

1. **定位文件**：`docs/handoffs/inflight/<当前分支名，/ 换 ->.md`。不存在就新建（用 `docs/handoffs/inflight/` 下任一现有文件作模板）。
2. **核对真实状态**（不凭记忆）：
   - `git branch --show-current` — 当前分支
   - `git status --porcelain` — 未提交改动，**逐条认领**：哪些是你改的、哪些是别人/ingest 产物
   - `git log --oneline -3` — 最近提交
3. **覆写**文档，只留这几节：
   - `## 这个分支做什么` — 一句话目标
   - `## 决策与被否方案` — **每行一个决策：选了什么 / 否了什么 / 一句话为什么**
     （2026-08-17 新增，理由见下面「为什么必须写被否方案」）。inflight 里只放这张
     压缩表，**展开留给日期快照**。
   - `## 当前状态` — 已提交 / 未提交 / 卡在哪（**写完就改，别让文档说过期的话**）
   - `## 已验证` — 你实际跑过的检查
   - `## 未验证 / 已知边界` — 没跑的测试、可疑点、环境限制。
     **要具体到哪条路径没被压到**，不写「没跑 live」这种笼统话——接手者要能判断
     「我能不能拿这个结论用」，而不只是知道你没跑全。
   - `## 下一步` — 接手者接着做什么
   - `## 踩过的坑` — 本分支特有的坑（可迁移的提炼进 `10_knowledge/`）
   **≤3K 字节，这是硬约束不是建议**（2026-08-11 更新，注入逻辑已改）：

   SessionStart 注入的不再是「前 12 行」。`session_facts.sh` 现在把整篇按 `## ` 切段，
   **把「已验证」类回顾性小节挪到末尾**，其余保持原序，再按 2000 字符总预算从尾部截断
   并声明砍了多少。也就是说：**预算不够时先丢的是「我做完了什么」，保住的是
   「什么还没验 / 下一步 / 会咬人的坑」**——这正是接手者需要的部分。

   但预算总量是死的：工作区事实固定占 ~790 字符，留给交接正文约 1140 字符
   ≈ 3K 字节中文。**文档一超 3K，被砍掉的就不再是「已验证」，而是「下一步」和「坑」**
   （实测一份 5024 字节的交接，截断落在「未验证」中间，后两节全丢）。
   超标时注入会在指针行标注实际字节数，但标注救不回被砍的内容——**写的时候就要控制长度**。
   写不下就别堆细节：结论进 inflight，展开留给 commit message 和日期快照。
4. **工具沉淀盘点**（2026-08-12 新增，**别跳过**）。交接不只是交状态，还要交**能力**。
   逐条自问，有就归位，没有就一句话说明为什么没有：

   | 问 | 归位到 |
   |---|---|
   | 同一个手工排查这轮做了**两次以上**？ | 写成脚本 → `TOOLKIT.md` 对应档位 |
   | 建了脚本但只在 `/tmp` 或对话里跑过？ | 移进 `scripts/`，写 docstring 说明**它防的失败形状** |
   | 发现了现有门禁的**洞**？ | 补上并变异验证，别只写进文档 |
   | 发现了可迁移的**模式**（换个项目也会犯）？ | `BUILD.md` 七模式那节 / `10_knowledge/` |
   | 沉淀成「手法」而非「工具」？ | **必须说明为什么**（成本？需要语义判断？样本太少？），不能默认写进文档就算完 |

   收录判据照 `BUILD.md`：**换一个完全不同的项目，这个失败还会不会发生？** 会才收。

   > 为什么单列一步：2026-08-12 那轮建了两个可复用件
   > （`probe_tool_arguments.py`、`check_unread_fields.py`），**都是用户追问才归位的**——
   > 交接流程里没有这一问，它们本会留在「我这次是这么找的」里，下一个人重新发明。
   > 手法的到达率不可靠，这是 `BUILD.md` 模式 3 自己的话。

5. **提交**：`git add -- <该文件>` → `git commit`（禁 `git add .`，本仓多 agent 共索引）。
   如果分支有未提交代码改动且你不想提交它们，文档单独提交即可——它本来就该是**最新**的。

## 红线

- **不写密钥 / token / 密码**（PAT、CC_REMOTE_EXEC_TOKEN 等一律不进交接）。
- **不贴整段代码 diff** —— 记结论和决策，代码看 commit/PR。
- **不删别的 agent 的交接记录**；inflight 只覆写**你自己分支**的那份。
- **在动作完成之后写**——先写"未提交"再去提交，文档当场失效（2026-08-11 实测踩过）。
- **不写"某某闸还兜着"这类前提，除非你这轮真的去查过它还在。** 前提写错比结论写错
  更贵：结论错了下一任会验，前提错了他会拿它当地基（2026-08-17 实测踩过）。
- **不把 n=1 的样本写成趋势**（「更快了」「吸收兑现」）。写清样本量和被什么主导，
  只断言结构性事实（「那次调用没有发生」），不断言量级。
- **合入状态不要手抄**——哪些枝的补丁已经进 main、哪些 worktree 只是 leftover，跑 `python3 scripts/worktree_board.py`（看 `git cherry`，不是 ahead 提交数）。不要写进 `inflight/main.md` 或项目笔记「交接记录」；那两处会漂，SessionStart 也不会扫全仓。inflight 只写**本分支**卡点。

## 与项目笔记「交接记录」的分工

| | inflight/<分支>.md（本 skill 写） | YYYY-MM-DD-<主题>.md（本 skill 写） | 项目笔记「交接记录」 |
|---|---|---|---|
| 定位 | 在途状态 / 接手手册 | **决策留痕**：背景 / 被否方案 / 理由 | 一行索引 / 时间线 |
| 长度 | ≤3K，写完即覆写 | 不限长，写完不改（快照） | **一行** |
| 谁读 | 接手 agent（SessionStart 自动注入） | 要动这块地方、或要推翻某个决定的人 | 人翻历史、跨 agent 对账 |
| 何时写 | 每次 handoff | **做过非显然决定时**（多数轮次都算） | 完工后 |
| 提交 | 独立 commit，随时可写 | 同上 | 随其他回写一起 |

项目笔记那一行在 `devin-writeback.md` 里写，本 skill 只负责 inflight 正文。
