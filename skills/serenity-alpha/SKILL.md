# Serenity Alpha：个股弹性预期差分析

## 核心定位

本 skill 不是公告验证工具，也不是财报模型工具。

它回答的是：

```text
题材/新闻/产业链线索 -> 哪些环节产业逻辑最强 -> 哪些个股股价已经反映 -> 哪些个股还没充分定价 -> 补涨顺序与分歧反证
```

核心目标是做出类似：

```text
现在不是“泛 PCB”，而是 PCB 主线内部再分账。
如果要找补涨，优先看：胜宏科技、三孚新科、深南/沪电、生益科技。
一句话：补涨看胜宏，弹性看三孚，锚定看生益，确认看深南/沪电。
```

## 与原版 Serenity 的区别

原版 Serenity 强调：

```text
news -> demand -> financial statements -> small-cap elasticity -> validation path
```

本地版改为：

```text
news/theme -> wiki 产业链强弱 -> company exposure -> price reaction -> relative lag -> expectation gap -> trading meaning
```

不要把输出重点放在“等公告/等财报验证”。

可以提“后续观察”，但必须服务于交易预期差，而不是把分析退回到审计式验证。

## 分析框架

### 1. 先定主线，不先定股票

先回答：这次市场交易的不是哪个泛概念，而是哪条更细的链条。

示例：

```text
不是“无脑 PCB”，而是 PCB 主线内部再分账：
- 高阶 PCB 制造
- mSAP / TGV / 微蚀药水
- 高阶封装载板
- M10 / PTFE / CCL 材料
```

### 2. 产业证据强度排序

按知识库、题材雷达、研报/材料出现频次、海外对标、产业链位置排序。

不是按公告硬度排序，而是按“产业链逻辑强弱”排序。

可用维度：

| 维度 | 问题 |
|---|---|
| 主线强度 | 是否是本轮题材最核心的约束项？ |
| 环节稀缺性 | 是否供给少、壁垒高、替代难？ |
| 传导距离 | 是一阶受益，还是二三阶发散？ |
| 纯度 | 公司业务与该环节是否足够贴近？ |
| 叙事可迁移性 | 海外龙头/产业变化是否能反哺 A 股映射？ |
| 市场关注度 | 是否已被市场充分交易？ |
| 近端涨幅 | 股价是否已经反映该逻辑？ |

### 3. 股价反映度排序

尽量检查近 20 日 / 10 日 / 5 日涨幅。

输出时把候选分为：

```text
已充分反映：逻辑强，但涨幅已经高
核心承接：逻辑强，涨幅适中，作为方向锚
补涨候选：逻辑强或中强，但涨幅明显落后
弹性候选：逻辑有分歧，但一旦被确认弹性最大
产业锚：不一定最弹，但能确认主线是否成立
```

### 4. 找“强逻辑 × 低反映”

优先找：

```text
产业逻辑强，但近端涨幅弱于同链条核心公司的标的
```

不要只找最强龙头，也不要只找最低涨幅。

弹性预期差来自：

```text
逻辑强度 - 股价反映度 - 市场认知充分度
```

可以用定性分数：

| 分项 | 评分说明 |
|---|---|
| 产业逻辑强度 | 1-5 |
| 传导直接度 | 1-5 |
| 业务纯度 | 1-5 |
| 涨幅未反映 | 1-5，涨幅越低且逻辑越强越高 |
| 认知差 | 1-5，市场标签越旧越高 |
| 分歧/瑕疵 | 1-5，分歧越大扣分越多 |

最终不是机械加总，而是给出排序理由。

### 5. 最佳补涨迁移框架

当用户问“最优补涨”“还能买谁”“谁没被市场发现”时，不要只从概念相关公司里找低位票。

先按这个链条反推：

```text
已涨主线锚
-> 龙头/锚公司为什么涨
-> 龙头扩产或工艺升级会买谁的设备/材料/服务
-> 哪个二阶瓶颈环节刚被市场重新命名
-> 哪家公司仍被旧标签压住
-> 单位价值量是否提升
-> 客户/技术/股权绑定是否降低传导不确定性
-> 是否有收入、净利、订单或 ASP 测算
-> 近端涨幅是否仍未充分反映
```

最佳补涨不是“最低位”，而是：

```text
主线已被市场验证
× 明牌龙头已经上涨
× 二阶瓶颈刚被发现
× 公司旧标签压制新逻辑
× 单位价值量提升
× 客户/技术绑定明确
× 有利润测算或估值体系切换
× 股价尚未充分反映
```

必须区分四类角色：

| 角色 | 定义 | 排序含义 |
|---|---|---|
| 主线锚 | 已经涨出来、证明市场在交易这条线的公司 | 用来确认主线，不一定是补涨首选 |
| 二阶瓶颈 | 龙头扩产/工艺升级必须购买的设备、材料、化学品或零部件 | 最容易出补涨 |
| 旧标签重估 | 市场仍按旧主业理解，但新逻辑可能贡献独立利润池 | 最典型 Serenity Alpha |
| 扩散期权 | 逻辑有弹性但证据或流动性更弱 | 排在确认和补涨之后 |

示例：

```text
江海股份涨，说明市场认可 AI服务器高端电容；补涨不一定继续追江海，而要看江海/艾华扩产带动的上游电容化学品，新宙邦若仍被锂电材料标签压住，就是二阶瓶颈补涨。

帝尔激光涨，说明市场认可玻璃基板 TGV 设备；补涨不一定继续追帝尔，而要看 TGV 通孔填充、电镀、金属化等环节，东威科技若仍被复合铜箔/PCB电镀标签压住，就是旧标签重估补涨。
```

如果缺少行情，仍要先完成主线锚和传导链判断，并明确写“涨幅待刷新”。不能因为没有实时涨幅就退回泛概念罗列。

### 6. 防锚定与横向候选池

用户提供的材料、卖方点名、公众号强推、截图排序，只能作为候选增强，不能直接锁定最终答案。

必须区分：

```text
材料结论：某材料点名 A
我的解释：A 为什么可能是补涨候选
客观排序：A 需要和同链条其他候选重新横向比较
```

当用户问“某题材补涨是谁”时，不要因为最近一篇材料点名某公司，就默认它一定排第一。

必须重新构建候选池：

| 候选类型 | 要找什么 |
|---|---|
| 明牌产业锚 | 已经验证主线的龙头或高纯公司 |
| 旧标签补涨 | 被旧主业压住、可能被重新命名的公司 |
| 品类弹性 | 最直接受益某一价格、工艺、材料、设备品类变化的公司 |
| 二阶瓶颈 | 龙头扩产或工艺升级必须采购的设备、材料、耗材、服务 |
| 低位扩散 | 逻辑相关但证据、纯度或财务弹性较弱的公司 |
| 上游/远期扩散 | 传导更远、适合观察而非直接排第一的公司 |

排序时，材料点名是加分项，不是决定项。

示例：

```text
东北计算机点名远东股份，只能说明远东是光纤涨价线里的旧标签补涨候选。
如果再次问“光纤补涨是谁”，仍要把远东和长飞、亨通、中天、通光线缆、杭电股份、永鼎、特发、通鼎、上游材料等重新比较。

中信新材料点名菲沃泰，只能说明菲沃泰是纳米镀膜旧标签重估候选。
如果再次问“AI硬件功能膜补涨是谁”，仍要和液冷、AI眼镜、汽车电子、半导体设备链里的其他标的重新比较。
```

只有当点名公司同时满足以下条件，才能在客观排序里排第一：

```text
主线相关度高
× 传导直接
× 旧标签或低反映明确
× 业务纯度/利润弹性足够
× 客户/订单/价格/产能至少有一项硬验证
× 横向比较后仍优于其他候选
```

### 7. 市场误分类

必须回答：市场现在把它当什么，它可能被重新定价为什么。

示例：

```text
胜宏科技：市场可能仍按普通 PCB/高端 PCB 制造理解，但这轮应按 AI 服务器高阶 PCB 制造补涨锚理解。
三孚新科：市场可能按化学品/PCB药水小票理解，但如果 mSAP/HVLP/TGV 微蚀药水进入验证，会被按高弹性制程材料重估。
生益科技：市场按 CCL 大票/产业锚理解，不一定最弹，但能验证 M10/PTFE/高频高速材料链是否继续扩散。
```

### 8. 分歧与反证

这里不是“请去查公告”，而是列出会影响交易排序的反证。

示例：

```text
最大反证：PTFE/M10 路线没有继续扩散，或者正交背板并非全部 AI-PCB。
三孚新科需要证伪：检测通过后能否进入批量订单，而不是停留在弹性题材。
深南/沪电需要证伪：核心承接是否已被涨幅充分反映。
```

## 候选池横向比较

必须先列出候选池，避免被单篇材料点名锚定：

| 类型 | 候选 | 为什么纳入 | 为什么不直接排第一 |
|---|---|---|---|
| 明牌产业锚 | 公司A | 已验证主线 | 可能涨幅已反映 |
| 旧标签补涨 | 公司B | 市场仍按旧主业定价 | 需要验证业务占比和利润弹性 |
| 二阶瓶颈 | 公司C | 龙头扩产/工艺升级传导 | 需要验证客户和订单阶段 |
| 品类弹性 | 公司D | 直接受益价格/工艺/材料变化 | 需要验证是否进入利润表 |
| 扩散观察 | 公司E | 逻辑相关 | 证据弱或传导远 |

## 补涨迁移链

| 环节 | 结论 |
|---|---|
| 已涨主线锚 | 谁已经证明市场在交易这条线 |
| 龙头上涨原因 | 它到底交易的是需求、工艺、材料、设备还是订单 |
| 二阶传导 | 龙头扩产/工艺升级会买谁的设备、材料、化学品或服务 |
| 旧标签压制 | 哪家公司仍被旧主业标签定价 |
| 单位价值量 | 高端化后成本占比、设备价值量、ASP 或用量是否提升 |
| 绑定关系 | 是否有客户、技术、股权、合资、长期供货或全球份额支撑 |
| 利润测算 | 是否能落到收入、净利、订单、毛利率或估值切换 |

## 排序口径

排序优先级：

1. 主线逻辑强度
2. 已涨主线锚是否已经验证市场方向
3. 二阶瓶颈传导是否直接
4. 股价未反映程度
5. 业务纯度
6. 市场误分类程度
7. 单位价值量是否提升
8. 客户/技术/股权绑定是否明确
9. 利润测算或估值体系切换是否成立
10. 横向候选池比较后是否仍占优
11. 分歧大小
12. 可被近端行情确认的速度

禁止只因为“涨得少”排第一。

禁止只因为“龙头最强”排第一。

禁止只因为“概念相关”列入补涨，必须说明它和已涨主线锚之间的传导链。

禁止只因为“材料点名”或“卖方强推”排第一，必须重新构建候选池并横向比较。

必须解释：

```text
为什么它不是最高确定性，但可能是最大预期差。
为什么它是产业锚，但不是补涨首选。
为什么它涨幅高后只适合确认主线，不适合追弹性。
为什么它是二阶瓶颈，而不是泛概念扩散。
为什么旧标签会压制新逻辑估值。
为什么单位价值量、客户绑定或利润测算能支撑补涨。
为什么材料点名只是候选增强，而不是最终答案。
为什么横向比较后它仍然或并不排第一。
```

## 与交易复盘层的协同

当用户要求“用 Serenity Alpha 分析今天某票涨停/异动/补涨是否成立”时，必须把产业逻辑和交易复盘层分开。

交易复盘层使用 `market_feature_store`，默认只读查询，不直接同步、不写库。

可用入口：

```bash
python -m market_feature_store.cli daily-review --trade-date YYYY-MM-DD
python -m market_feature_store.cli stock-sectors 股票代码或名称 --trade-date YYYY-MM-DD
python -m market_feature_store.cli sector-stocks --sector 板块名 --trade-date YYYY-MM-DD --order-by pct_chg_20d
python -m market_feature_store.cli top-sectors --trade-date YYYY-MM-DD --order-by diff_ratio
python -m market_feature_store.cli weighted-gainers --start YYYY-MM-DD --end YYYY-MM-DD
python -m market_feature_store.cli query-limit-heat --trade-date YYYY-MM-DD --with-stocks
python -m market_feature_store.cli query-stock-high --trade-date YYYY-MM-DD
```

对应 Python API：

```text
market_feature_store.query.stock_sectors
market_feature_store.query.sector_stocks
market_feature_store.query.top_sectors
market_feature_store.query.weighted_gainers
market_feature_store.query.limit_heat
market_feature_store.query.stock_highs
market_feature_store.query.advancers_extrema
```

交易复盘层需要回答：

| 层级 | 要查什么 | 用途 |
|---|---|---|
| 个股 | 当日涨幅、3/5/10/20 日涨幅、成交额、涨停状态、新高状态 | 判断是首次启动、趋势加速还是高位兑现 |
| 板块 | 所属复盘会板块、板块涨幅、成交额、边际量 `diff_ratio` | 判断是单票材料驱动还是板块共振 |
| 扩散 | 同板块成分股涨幅、涨停热力、代表涨停股 | 判断分支是否被市场确认 |
| 市场 | 成交额、量能比、涨家数、涨停/跌停、市场阶段、偏离度 | 判断环境是转点、共振、退潮还是普通日 |
| 区间 | 区间加权涨幅、近端涨幅排名、板块内排序 | 判断股价是否已充分反映 |

输出时必须区分：

```text
产业证据：客户、订单、产能、价格、利润、技术壁垒
交易反馈：涨停、放量、板块扩散、边际量、新高、承接
```

涨停只是价格反馈，不是产业证据。

如果某票涨停但板块无跟随，结论应偏向“单票材料驱动/个股 Alpha”。

如果某票涨停且产业锚、同链条候选、涨停热力和边际量同步增强，才可上调为“分支被市场确认”。

如果明牌锚已涨、该票低位放量补涨，才可描述为“主线锚确认后的二阶补涨”。

示例：

```text
旭光电子涨停，不等于 AI 陶瓷主线已经成立。
需要同时看三环集团、国瓷材料、中瓷电子、博敏电子、昀冢科技是否跟涨，
陶瓷基板/HBM/光模块相关板块是否放量，
涨停热力是否出现 AI 陶瓷或上游材料，
以及旭光自身 5/10/20 日涨幅是否已经透支。
```

## 质量要求

- 默认先跑 `serenity_context.py` 拿上下文包，不要手动遍历 relations JSON 或批量读页面正文。
- 必须给出排序，不要只罗列公司。
- 必须区分“补涨”“弹性”“锚”“确认”。
- 必须说明股价是否已反映。
- 必须说明产业逻辑和股价反映之间的落差。
- 必须列反证，但不要把输出变成公告验证 checklist。
- 如果行情缺失，明确写“行情待刷新”，但继续完成产业逻辑排序。
- 如果知识库没有足够材料，输出“知识库证据不足，先做候选排序”，不要编造来源。
