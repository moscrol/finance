# Serenity Alpha：个股弹性预期差分析

## 核心定位

本 skill 不是公告验证工具，也不是财报模型工具。

它回答的是：

```text
题材/新闻/产业链线索 -> 哪些环节产业逻辑最强 -> 哪些个股股价已经反映 -> 哪些个股还没充分定价 -> 补涨顺序与分歧反证
```

核心目标是做出类似：

```text
现在不是“泛 PCB”，而是 PCB 主线内部再分账。
如果要找补涨，优先看：胜宏科技、三孚新科、深南/沪电、生益科技。
一句话：补涨看胜宏，弹性看三孚，锚定看生益，确认看深南/沪电。
```

## 与原版 Serenity 的区别

原版 Serenity 强调：

```text
news -> demand -> financial statements -> small-cap elasticity -> validation path
```

本地版改为：

```text
news/theme -> wiki 产业链强弱 -> company exposure -> price reaction -> relative lag -> expectation gap -> trading meaning
```

不要把输出重点放在“等公告/等财报验证”。

可以提“后续观察”，但必须服务于交易预期差，而不是把分析退回到审计式验证。

## 分析框架

### 1. 先定主线，不先定股票

先回答：这次市场交易的不是哪个泛概念，而是哪条更细的链条。

示例：

```text
不是“无脑 PCB”，而是 PCB 主线内部再分账：
- 高阶 PCB 制造
- mSAP / TGV / 微蚀药水
- 高阶封装载板
- M10 / PTFE / CCL 材料
```

### 2. 产业证据强度排序

按知识库、题材雷达、研报/材料出现频次、海外对标、产业链位置排序。

不是按公告硬度排序，而是按“产业链逻辑强弱”排序。

可用维度：

| 维度 | 问题 |
|---|---|
| 主线强度 | 是否是本轮题材最核心的约束项？ |
| 环节稀缺性 | 是否供给少、壁垒高、替代难？ |
| 传导距离 | 是一阶受益，还是二三阶发散？ |
| 纯度 | 公司业务与该环节是否足够贴近？ |
| 叙事可迁移性 | 海外龙头/产业变化是否能反哺 A 股映射？ |
| 市场关注度 | 是否已被市场充分交易？ |
| 近端涨幅 | 股价是否已经反映该逻辑？ |

### 3. 股价反映度排序

尽量检查近 20 日 / 10 日 / 5 日涨幅。

输出时把候选分为：

```text
已充分反映：逻辑强，但涨幅已经高
核心承接：逻辑强，涨幅适中，作为方向锚
补涨候选：逻辑强或中强，但涨幅明显落后
弹性候选：逻辑有分歧，但一旦被确认弹性最大
产业锚：不一定最弹，但能确认主线是否成立
```

### 4. 找“强逻辑 × 低反映”

优先找：

```text
产业逻辑强，但近端涨幅弱于同链条核心公司的标的
```

不要只找最强龙头，也不要只找最低涨幅。

弹性预期差来自：

```text
逻辑强度 - 股价反映度 - 市场认知充分度
```

可以用定性分数：

| 分项 | 评分说明 |
|---|---|
| 产业逻辑强度 | 1-5 |
| 传导直接度 | 1-5 |
| 业务纯度 | 1-5 |
| 涨幅未反映 | 1-5，涨幅越低且逻辑越强越高 |
| 认知差 | 1-5，市场标签越旧越高 |
| 分歧/瑕疵 | 1-5，分歧越大扣分越多 |

最终不是机械加总，而是给出排序理由。

### 5. 市场误分类

必须回答：市场现在把它当什么，它可能被重新定价为什么。

示例：

```text
胜宏科技：市场可能仍按普通 PCB/高端 PCB 制造理解，但这轮应按 AI 服务器高阶 PCB 制造补涨锚理解。
三孚新科：市场可能按化学品/PCB药水小票理解，但如果 mSAP/HVLP/TGV 微蚀药水进入验证，会被按高弹性制程材料重估。
生益科技：市场按 CCL 大票/产业锚理解，不一定最弹，但能验证 M10/PTFE/高频高速材料链是否继续扩散。
```

### 6. 分歧与反证

这里不是“请去查公告”，而是列出会影响交易排序的反证。

示例：

```text
最大反证：PTFE/M10 路线没有继续扩散，或者正交背板并非全部 AI-PCB。
三孚新科需要证伪：检测通过后能否进入批量订单，而不是停留在弹性题材。
深南/沪电需要证伪：核心承接是否已被涨幅充分反映。
```

每次输出必须尽量使用这个结构。

```markdown
## 结论

2. 公司B / 环节 —— 为什么排第二
3. 公司C / 环节 —— 为什么排第三
4. 公司D / 环节 —— 为什么只做锚或确认

## 问题

用一句话定义当前问题：

- 市场交易的到底是什么？
- 是泛题材，还是主线内部再分配？
- 是龙头继续强化，还是补涨扩散？

## 产业链强弱排序

| 环节 | 逻辑强度 | 代表公司 | 说明 |
|---|---:|---|---|
| 环节A | 5 | 公司A | 产业链最强约束项 |
| 环节B | 4 | 公司B | 弹性大但分歧更高 |
| 环节C | 3 | 公司C | 确认主线用 |

## 股票池

| 股票 | 近20日 | 验证状态/行情状态 | 角色 |
|---|---:|---|---|
| 公司A 代码 | +x% | confirmed / stale / pending | 补涨锚 |
| 公司B 代码 | +x% | confirmed / stale / pending | 弹性票 |

说明：

- confirmed：行情或知识库证据已能支持进入比较。
- stale：行情过旧或缺少近端价格，需要刷新。
- pending：逻辑存在，但股价/证据不足，暂列观察。

## 交易含义

用短句给出交易含义：

```text
现在不是“泛 PCB”，而是 PCB 主线内部再分账。
如果要找补涨，优先看 A；如果要找弹性，看 B；如果要看主线确认，看 C/D。
```

## 分歧/反证

列最大反证，不要写成公告任务清单。

```text
最大反证是：
- 路线并未扩散
- 高涨幅公司已透支
- 弹性小票只是材料逻辑，不能进入订单/利润想象
- 核心承接已充分定价
```

## 最后一句

一句话收束：

```text
补涨看A，弹性看B，锚定看C，确认看D。
```
```

## 排序口径

排序优先级：

1. 主线逻辑强度
2. 股价未反映程度
3. 业务纯度
4. 市场误分类程度
5. 传导距离
6. 分歧大小
7. 可被近端行情确认的速度

禁止只因为“涨得少”排第一。

禁止只因为“龙头最强”排第一。

必须解释：

```text
为什么它不是最高确定性，但可能是最大预期差。
为什么它是产业锚，但不是补涨首选。
为什么它涨幅高后只适合确认主线，不适合追弹性。
```

然后再用本 skill 做二次排序：

## 与公告/入库 skill 的边界

不要默认调用：

```text

company-baseline-ingest
```

除非用户明确说：

```text
补公告
入库

```

本 skill 默认只读、只分析、不写库。

## 质量要求

- 必须给出排序，不要只罗列公司。
- 必须区分“补涨”“弹性”“锚”“确认”。
- 必须说明股价是否已反映。
- 必须说明产业逻辑和股价反映之间的落差。
- 必须列反证，但不要把输出变成公告验证 checklist。
- 如果行情缺失，明确写“行情待刷新”，但继续完成产业逻辑排序。
- 如果知识库没有足够材料，输出“知识库证据不足，先做候选排序”，不要编造来源。
